# 如何改造成其他语言的课程

目标是复用讲稿、代码、图示、配音、字幕和分章渲染的流程。Rust 知识点本身不能直接套给另一种语言。

## 1. 修改教学内容与标题

在 `project.json` 修改课程名、封面、右上角说明以及章节的中英文名称。当前默认目录是“中文翻译 + 英文”。完整讲稿在 `content/审核通过文案.md`，使用以下结构：

```text
## 01 变量｜目标时间
### 01-1 保存一个分数
【画面】代码与中文注解
（此处放 fenced code block）
【口播】
先给一个具体例子，再解释其中的新写法。
【停顿】4 秒
随后讲解答案和原因。
```

`build_course.py` 当前识别 `rust` 代码围栏和 `rust-check` 元数据，章节为 00～15、每个主题一道题，总计 14 道。保留同样的课型时可以复用结构；改变语言或章节数量时，要修改代码围栏识别、`Targets`、`Titles`、题目拆分和最后的完整性断言。脚本中的 `Notes`、输出修正、`diagram`、逐步提示、跨屏代码和讲解定位词也需要按新内容调整。

不要把无关的 Rust 借用规则、生命周期图或 C/C++ 读法带到另一门课中。运行 `npm run preview` 后，检查每个新知识点的例子与图示是否一致。

## 2. 替换编译或执行验证

`approved_examples.json` 中的每条记录包括 `key`、完整 `code`、`kind`（run/error/panic）、预期 `output` 和可选 `error`。当前验证器使用 `rustc --edition=2024`，并核对 Rust 编译错误编号和 `panicked` 输出。

改成 Python 时应使用 Python 解释器，核对退出码、输出和异常；改成 Java 时需要 javac/java 和类名规则。更换执行器后，更新预期错误、跨屏完整程序以及 `verify_examples.py`。不要只凭视频中一小段代码判断整个程序正确。

`check.py` 的 14 个主题、Rust 版本、成片文件名、字幕恢复规则和时长目标也属于课程特定检查，须同步更新。

## 3. 修改画面

`src/video.tsx` 中 `Tokens` 为 Rust 语法着色，`Diagram` 为成绩、所有权、借用、泛型和生命周期提供图示。修改语言时先更新语法词表，再替换与新课程不相符的图示。`project.json` 已控制封面及章节品牌文字。

保留独立字幕区，避免代码和字幕重叠。长代码应在讲稿与 `build_course.py` 中分屏，而不是单纯缩小字号。用 `--qa` 先生成关键帧检查，再渲染所有变化帧。Windows 字体路径出现在 `check.py` 和 `qa_sheets.py`；其他系统请配置自己的字体文件。

## 4. 替换语音服务

`audio.py` 是一个适配器；其他服务应按每个场景输出 `public/audio/<场景key>.mp3` 和同名 JSON。JSON 需要 `fingerprint`、`duration` 以及 `words`，每个字/词含 `text`、`begin_time`、`end_time`，时间单位为毫秒。`fit_duration.py` 会保留原始声音并同步缩放这些时间点，`timeline.py` 再转换为帧和 SRT。

如果新服务不能返回字级时间戳，先实现语音对齐，不能用估计预览字幕来宣称正式同步。服务密钥、空间 ID、自定义音色和生成素材都由各使用者自行配置，不能放入源码仓库。当前百炼适配器默认采用系统音色。

## 5. 渲染与验证

内容生成 → 示例验证 → 小段语音测试 → 完整配音 → 实测时间轴 → 关键帧检查 → 分章渲染 → 全片检查。

`stills.mjs`、`render.py` 负责通用的画面、编码、字幕与音频合成，可以继续复用。场景尺寸目前固定为 1920×1080、30fps；修改时需要同步 TS 布局、时间轴、编码器、ASS 分辨率和检查器。新课程完成后重新抽看每章开头、中段、结尾、所有题目答案及拼接处。

每次正式渲染前确认时间轴由自己的真实配音生成，`previewOnly` 为 false 或不存在。不要上传私人语音和接口返回缓存；Git 忽略规则及公开文件审计需保留。
