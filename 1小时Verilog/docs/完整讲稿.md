### vl-01-03 模块的基本外形

代码：and_gate.v

```verilog
module and_gate(input wire a, b, output wire y);
  assign y = a & b;
endmodule
```

现在把与门写成一个模块。第一行给这个小电路起名字，并列出两个输入和一个输出。最后一行表示模块描述结束，中间放具体规则。你可以把模块理解为带接口的电路盒子：别人需要知道线从哪里进、从哪里出，内部怎样实现则写在盒子里面。文件名通常与模块名相近，但真正被其他模块引用的是代码里的模块名。

持续代码高亮：[1, 3]；要点：module和endmodule围住电路；端口列出输入与输出

再看中间这一行。右边把两个输入做按位与，左边接到输出，前面的关键词表示连续赋值。连续不是执行一次以后停止，而是描述输入变化时输出应当随之变化的关系。代码最后有分号，括号和模块结束的拼写也要完整。当前示例每个输入只有一位，因此这个运算直接对应我们刚才的与门规则，不涉及多位数据的逐位处理。

持续代码高亮：[2]；要点：assign描述持续连接关系；分号不能遗漏

### vl-01-04 多个电路同时工作

代码：parallel_gates.v

```verilog
module parallel_gates(input wire a, b,
  output wire y_and, y_or);
  assign y_and = a & b;
  assign y_or  = a | b;
endmodule
```

在同一个模块里再加一个或门，现在我们同时得到两个输出。两个输入送到两个电路分支，一个分支算与，另一个分支算或。先看两条支路，它们都由输入驱动，不需要等待另一个分支完成。这就是硬件描述与普通顺序操作很不一样的地方：模块中并排的连续赋值，描述的是同时存在的连接关系，不是一份按行排队的操作清单。

持续代码高亮：[3, 4]；要点：两条连续赋值描述两条支路；不是先算第一条再算第二条

当输入是一和零时，与门输出零，或门输出一。交换两条连续赋值在文件里的书写顺序，仍然是在描述这两个分支，不会让或门先做完再允许与门工作。不过不要把这个结论扩展到所有语句，后面过程块内部仍有自己的执行规则。初学时先区分两层：电路分支同时存在，某个过程被触发以后，内部语句又按照语言规则计算。

持续代码高亮：[3, 4]；要点：同一输入可以送到多个电路；过程内部另有执行规则

## 端口、信号与数值

### vl-02-01 端口与连接方向

代码：mux2.v

```verilog
module mux2(input wire a, b, sel,
  output wire y);
  assign y = sel ? b : a;
endmodule
```

模块的输入输出叫端口。看这只二选一电路，它有两个候选数据、一个选择信号和一个输出。选择信号为零时取第一个输入，为一时取第二个输入。端口方向是站在当前模块的边界上说的，输入表示信号从外面进来，输出表示信号由这个模块送出去。不要把信号名字本身当作方向，真正的方向由声明决定，名字只是帮助人阅读。

持续代码高亮：[1, 2]；要点：input进入模块，output离开模块；方向取决于端口声明

后面连接多个模块时，一根线可以把前一个模块的输出接到后一个模块的输入。先画出选择信号的作用：它控制输出究竟跟随哪条数据通路，而不是把两个输入相加。这个小模块叫选择器，也常写成多路选择器。现在先记住接口和功能，下一章会拆开条件表达式。信号名建议写出含义，避免把数据输入、时钟和复位都起成难以分辨的单字母。

持续代码高亮：[3]；要点：sel决定选择哪条数据；模块连接时先对接口

### vl-02-02 wire与reg

代码：mux_always.v

```verilog
module mux_always(input wire a, b, sel,
  output reg y);
  always @(*) begin
    if (sel) y = b;
    else     y = a;
  end
endmodule
```

初学时经常被两个声明名字困住。线网类型常用来表示连接关系，由连续赋值或模块输出驱动；过程变量则可以在过程块里被赋值。在传统Verilog里，我们会看到wire和reg。先按赋值位置选择声明，不要仅凭英文名字判断电路。现在这份代码把输出写在过程块里，因此输出声明为reg；这只是语言层面的声明要求，还没有证明它一定是一个存储器。

持续代码高亮：[1, 2]；要点：wire常表示连接，reg可在过程内赋值；reg不等于一定产生寄存器

观察完整的两个分支：选择信号为一时给输出第二个输入，否则给第一个输入。无论选择信号是哪种已知值，输出都有明确来源，因此这里描述的是组合选择逻辑。虽然输出写成reg，也不意味着一定出现触发器。真正判断有没有存储，要看过程的触发方式，以及有没有分支要求保留旧值。后面会专门用不完整赋值的例子解释这件事。

持续代码高亮：[3, 4, 5]；要点：完整分支仍可描述组合逻辑；根据行为判断电路

### vl-02-03 位宽与进制

一根一位信号只能表示零或一。把多位信号放在一起，就能表示更多组合，例如四位可以表示十六种不同的比特排列。数值前面写位数、单引号和进制标记，可以明确表达它的宽度与读法。画面中四位二进制的一零一零，和四位十六进制的字母A，表示的是同一组比特。进制只是写法不同，不能因为用了十六进制，就以为电路换了一套运算规则。

持续代码高亮：[]；要点：4'b1010与4'hA都是四位1010；位宽、进制、比特值分开看

写常量时尽量把位宽说明白，尤其是做加减、比较和拼接时。目标只有四位而计算结果需要五位，高出的那一位可能被截掉。先看四格能装下多少比特，再看结果需要几格，比死记某个数值更可靠。有符号与无符号也要明确区分，同样的比特排列可能有不同数值解释。今天先用小宽度观察结果，复杂的表达式尺寸规则以后再逐条补充。

持续代码高亮：[]；要点：结果放不下会截断；常量尽量写明位宽

### vl-02-04 位选、片选与拼接

代码：vector_demo.v

```verilog
module vector_demo(input wire [7:0] data,
  output wire [3:0] hi, lo,
  output wire [7:0] swapped);
  assign hi = data[7:4];
  assign lo = data[3:0];
  assign swapped = {lo, hi};
endmodule
```

八位数据可以拆成高四位和低四位。方括号里只有一个下标时，是选择某一位；写出一段下标范围时，是选择一组连续比特。这里声明的编号从七到零，因此七到四是高四位，三到零是低四位。下标是比特的位置，不是把整个数除以那个下标。阅读时先核对声明方向，再看选取的范围，这样不容易把高低位反过来。

持续代码高亮：[1, 2, 3, 4, 5]；要点：data[7:4]与data[3:0]；先确认下标方向

大括号表示把几组比特按顺序连接起来。看高低四位交换，把低四位放在左边、高四位放在右边，就形成新的八位结果。原数据是一零一零零一零一，也就是十六进制A五，交换后变成五A。拼接不是加法，也不会自动帮你保证目标宽度正确。先数每一部分有几位，再加起来核对总位数，是处理这类代码最稳妥的第一步。

持续代码高亮：[6]；要点：{lo,hi}按顺序拼接；A5交换为5A

### vl-02-05 未知值与高阻态

仿真中除了零和一，还可能看到未知值和高阻态。未知值用字母x表示，意思是当前无法确定它究竟为零还是一，例如尚未被正确初始化。高阻态用字母z表示，可以理解为当前没有主动驱动这条线。它们不是你期望正常计算的第三个、第四个数值，而是帮助我们发现连接、初始化或驱动状态的问题。看到未知值时，先追踪它最早从哪里出现。

持续代码高亮：[]；要点：x：未知；z：高阻；先找来源再改代码

不要一看到未知值就把显示颜色改掉，或者随便加一个初始值掩盖原因。检查有没有漏接端口，有没有多个来源冲突，时序电路是否已经经历复位。普通相等比较遇到未知值，结果也可能未知；测试平台若要明确检查一个值是否包含未知状态，可以使用按四态比较的运算。它的用途和普通功能比较要分开，后面测试章节会用实际例子说明。

## 运算符与连续赋值

### vl-03-01 按位、逻辑与归约

代码：operators.v

```verilog
module operators(input wire [3:0] a, b,
  output wire [3:0] bit_and,
  output wire logic_and, parity);
  assign bit_and = a & b;
  assign logic_and = a && b;
  assign parity = ^a;
endmodule
```

同样叫与运算，按位与和逻辑与的结果可能不同。按位与让对应位置的比特分别计算，因此四位输入得到四位结果。例如二进制零零一零与零零零一，没有任何位置同时为一，结果就是四个零。先把两排比特上下对齐，再一列一列判断。不要因为两个输入表示的数都不是零，就直接把按位与的结果判成一，这样会混淆两种不同规则。

持续代码高亮：[1, 4]；要点：a & b：逐位计算；0010 & 0001得到0000

逻辑与先把整个输入理解为真或假，再产生一位结果。两个已知数值只要都不是零，逻辑与就为真。再看单目归约异或，它把一个向量的所有位合成一个结果，常用于奇偶校验。运算符一样的字符，放在两个输入之间或放在一个向量前面，角色可能不同。读表达式时先判断输入数量、结果宽度和运算类别，再带入具体比特。

持续代码高亮：[5, 6]；要点：a && b得到一位真值；^a是归约异或

### vl-03-02 加法与进位

代码：adder.v

```verilog
module adder(input wire [3:0] a, b,
  output wire [3:0] low,
  output wire [4:0] full);
  assign low = a + b;
  assign full = {1'b0, a} + {1'b0, b};
endmodule
```

四位可以保存零到十五这些无符号值。十五加一在数学上等于十六，但十六的二进制需要五位。如果只保留四位，结果低四位全是零。观察进位有没有位置可放：代码不是不会算加法，而是你给结果准备的宽度不够。这个问题在计数器里尤其常见，最大值再加一会回到零。是否允许回绕，要由设计需求决定，不能默认它总是错误。

持续代码高亮：[1, 2, 4]；要点：15+1的低四位为0000；四位计数器可能回绕

想保留进位，就先把两个输入都扩成五位，再相加。这里在每个四位输入前面拼一个零，明确让计算覆盖五位。这样得到的完整结果是一零零零零，低四位仍是零，最高位保存进位。初学时建议把宽度写得清楚，不要靠某一次仿真的巧合猜工具怎样处理复杂表达式。看加法题时，输入宽度、计算宽度和接收结果的宽度都要检查。

持续代码高亮：[3, 5]；要点：先零扩展，再做五位加法；明确保留进位

### vl-03-03 选择表达式

代码：mux2.v

```verilog
module mux2(input wire a, b, sel,
  output wire y);
  assign y = sel ? b : a;
endmodule
```

问号和冒号组成条件选择表达式。先读选择条件，再看为真时取哪个值，为假时取哪个值。我们的电路规定选择信号为一时输出第二个输入，为零时输出第一个输入，因此不要把两个候选项的顺序写反。可以先带入两个最简单的场景，各检查一次，而不是盯着符号反复猜。一个短表达式就能描述一个组合选择器，但它仍然是电路关系。

持续代码高亮：[3]；要点：sel ? b : a：真取b，假取a；先代入零和一检查

## 阻塞与非阻塞赋值

### vl-06-01 阻塞赋值的计算顺序

代码：blocking_demo.v

```verilog
module blocking_demo(input wire clk, rst, d,
  output reg q1, q2);
  always @(posedge clk) begin
    if (rst) begin q1 = 0; q2 = 0; end
    else begin
      q1 = d;
      q2 = q1;
    end
  end
endmodule
```

现在专门拆开两种赋值。先看同一个过程块里的普通等号，它会先完成当前赋值，再继续后面的语句。假设原来两个输出都是零，这个边沿读到的数据是一。第一句把第一级改成一，第二句再读第一级，就会读到刚写进去的一。沿着本例的两句赋值看结果，两个输出在这次过程执行后都成为一，不会自动形成你想象的两拍传递。

持续代码高亮：[6, 7]；要点：同一过程内，=先更新再执行后句；后句可能读到刚写入的新值

这不是要求你把所有等号都删掉。组合过程中的中间计算，常常就是希望后面读到前面算出的值，因此适合使用阻塞赋值。问题是写时钟触发的流水存储时，你可能希望第二级保存的是第一级之前的值，而不是刚刚覆盖后的值。先说清期望的拍与拍关系，再选择写法，比把符号当作不需要理解的口诀更有用。这里的反例有确定的过程内顺序，不靠随机仿真顺序来说明。

持续代码高亮：[6, 7]；要点：组合计算可以使用阻塞赋值；时钟存储先明确逐拍关系

### vl-06-02 非阻塞赋值先读旧值

代码：pipeline.v

```verilog
module pipeline(input wire clk, rst, d,
  output reg q1, q2);
  always @(posedge clk) begin
    if (rst) begin q1 <= 0; q2 <= 0; end
    else begin
      q1 <= d;
      q2 <= q1;
    end
  end
endmodule
```

把时钟过程里的两句赋值改成非阻塞形式。它在语句执行到这里时读取右边的值，随后安排左边目标在对应的更新阶段改变。看同一个边沿上的旧值：第一级读取当前输入，第二级读取第一级原来的值。因为还没有把第一级立即覆盖，第二句不会误把新输入直接传到第二级。这个零延迟例子中，可以把它理解为先收集旧状态，再安排本拍更新。

持续代码高亮：[6, 7]；要点：<=先计算右边，再安排更新；本拍q2读取旧q1

如果原来两级都是零，第一次采到一以后，第一级变一，第二级仍是零；下一次边沿，第二级才有机会接到之前保存在第一级的一。这就表达了两级存储的逐拍传递。注意我们讨论的是这份时钟过程的仿真调度和电路意图，不是说所有带这个符号的语句在任何上下文中都绝对同时发生。初学时先在时钟寄存器更新中使用一致的非阻塞写法。

持续代码高亮：[6, 7]；要点：第一次采到1：q1=1，q2=0；下一拍再向后传递

### vl-06-03 用逐拍表推导输出

代码：pipeline.v

```verilog
module pipeline(input wire clk, rst, d,
  output reg q1, q2);
  always @(posedge clk) begin
    if (rst) begin q1 <= 0; q2 <= 0; end
    else begin
      q1 <= d;
      q2 <= q1;
    end
  end
endmodule
```

遇到流水寄存器题目，先画一张逐拍表。表格列出时钟边沿之前的数据和旧状态，然后单独写出边沿更新后的新状态。不要在算第二级时，把表里第一级的新值拿过去。跟着波形逐拍核对，输入依次给一、零、一，第一级依次接到这些输入，第二级则跟随前一拍的第一级。每一拍都先拍一张旧状态快照，能避免很多脑内覆盖造成的错误。

持续代码高亮：[6, 7]；要点：先列旧值，再列新值；算q2时不能偷用新q1

表格和波形应该说同一件事。波形的横向位置表示时间，竖直跳变表示值变化，时钟边沿帮助你定位采样时刻。输出在某一拍保持不变，不代表过程没有执行，也可能是计算出的新值刚好与旧值相同。做判断题时，不要仅仅数跳变次数，要核对每个边沿采到的输入和读取的旧状态。工程中的流水例子有实际检查，可以用它复核自己的逐拍表。

持续代码高亮：[6, 7]；要点：不跳变也可能已经执行更新；逐个边沿核对采样值

### vl-08-02 保存当前状态

代码：fsm.v · 节选

```verilog
module fsm(input wire clk, rst, go, done,
  output wire busy, output reg [1:0] state);
  localparam IDLE=2'd0, RUN=2'd1, WAIT=2'd2;
  reg [1:0] next_state;
  always @(posedge clk) begin
    if (rst) state <= IDLE;
    else     state <= next_state;
  end
```

看状态机的前半部分。状态名用本地常量表示，当前状态和下一状态分别有自己的信号。保存当前状态的过程只在时钟上升沿更新，复位时进入空闲，否则把已经算好的下一状态写进当前状态。这个部分和前面的寄存器没有神秘区别，只是寄存器里保存的数值，现在被我们解释成了不同控制阶段。把存储与计算分开，代码就更容易读。

持续代码高亮：[3, 4, 5, 6, 7]；要点：localparam给状态编码命名；state与next_state分开

### vl-10-02 终值计数与翻转

代码：blink.v

```verilog
module blink #(parameter LIMIT = 3)(
  input wire clk, rst, en,
  output reg led, output reg [3:0] count);
  always @(posedge clk) begin
    if (rst) begin count <= 0; led <= 0; end
    else if (en) begin
      if (count == LIMIT-1) begin
        count <= 0;
        led <= ~led;
      end else count <= count + 1'b1;
    end
  end
endmodule
```

看完整的时钟过程。复位优先把计数和灯状态清零；否则在使能有效时，先检查旧计数是否已经达到终值。达到终值就把计数清零，同时把灯取反；没有达到就只把计数加一。沿着三次有效边沿观察，旧计数依次为零、一、二，第三次触发翻转。因为计数从零开始，终值比较写的是限制次数减一，而不是直接写限制次数本身。

### vl-10-03 验证保持与再次启动

代码：blink.v

```verilog
module blink #(parameter LIMIT = 3)(
  input wire clk, rst, en,
  output reg led, output reg [3:0] count);
  always @(posedge clk) begin
    if (rst) begin count <= 0; led <= 0; end
    else if (en) begin
      if (count == LIMIT-1) begin
        count <= 0;
        led <= ~led;
      end else count <= count + 1'b1;
    end
  end
endmodule
```

验证这个小设计时，不能只看灯有没有翻过一次。先检查复位后的明确状态，再给足够多的有效边沿，确认计数按需求变化。接着关闭使能，让时钟继续走几拍。看暂停期间的计数和灯状态，它们都应该保持。然后重新打开使能，设计从保留的状态继续，不是自动又从零开始，除非你另外写了这样的功能要求。

持续代码高亮：[5, 6]；要点：时钟继续走，禁用时状态保持；恢复后从保留状态继续

这组刺激同时检查了正常更新、终值翻转、暂停和恢复。还可以在运行中再次复位，检查优先级是否符合要求。若只用一种一直有效的使能，很容易漏掉保持规则。我们把预期按有效更新次数计算，再与仿真逐拍比较，而不是从输出波形反过来编答案。测试通过后，你得到的是这些具体场景的证据，扩大使用范围时仍要补充参数边界和接口条件。

持续代码高亮：[5, 6, 7, 8, 9, 10]；要点：覆盖复位、终值、暂停与恢复；预期按需求独立计算
