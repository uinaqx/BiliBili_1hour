## 00:04:47 练习 · 结果有几行几列

### 题目

做第一道小题。客户表有四人，姓名和城市各在自己的列里。现在把城市选出来，起名 place，再把姓名作为第二项。接着从客户表读取，按编号升序，只看前两条。请先判断输出有几行几列，再在纸上写出第一行的内容。试着把列标题和值分别写下来，区分它们的位置。

```sql
SELECT city AS place, name
FROM customers
ORDER BY id
LIMIT 2;
```

### 解析

读答案时先从数据来源开始。编号最小的两位是小林和小周，城市分别是杭州和上海。列的显示顺序由第一行决定，先 place，后 name。按限制留下两行。最终第一行杭州、小林，第二行上海、小周。看这种题可以分三步，找表、数行、数列。今天看到的 SELECT、FROM 和排序限制，会在后面的示例里持续出现。

运行结果

```text
place | name
杭州 | 小林
上海 | 小周
```

## 00:10:21 练习 · 找出符合组合条件的订单

### 题目

这道题给两条规则。状态是已支付或待支付，金额在八十到一百二十元之间。IN 后放一组允许的状态。订单状态只要是括号中的某一个就通过。BETWEEN 从八十到一百二十，包含两端。停几秒，先从八行里找金额合适的，再去掉状态不符合的，写下留下的订单编号。

```sql
SELECT id, amount
FROM orders
WHERE status IN ('已支付', '待支付')
  AND amount BETWEEN 80 AND 120
ORDER BY id;
```

### 解析

金额合适的是编号一百零一、一百零二、一百零五、一百零七和一百零八。一百零五是已取消的订单，状态不在名单里，去掉。最后四个编号按顺序是第一、第二、第七和第八笔。这里按编号排序。可以发现八十元和一百二十元都在结果里。边界题最容易少算一项，做查询时记得挑一个刚好等于上界和下界的值测试。

运行结果

```text
id | amount
101 | 120
102 | 80
107 | 90
108 | 90
```

## 00:15:55 练习 · 给第二名加上明确的并列规则

### 题目

请预测第二名的订单编号。表里有两个一百二十元，还有更大的金额。先保留不超过一百二十的订单。剩下的按金额降序。同金额时，拿编号更大的排在前面。最后取前两行。给自己几秒钟，先圈出可能入选的两行，再确定它们的顺序。

```sql
SELECT id, amount
FROM orders
WHERE amount <= 120
ORDER BY amount DESC, id DESC
LIMIT 2;
```

### 解析

二百和一百六十超过上限，被过滤掉。接下来最高的两笔，都是一百二十元。这里编号也写了 DESC，编号一百零五在一百零一前面。所以第一行是一百零五，第二行是一百零一。只写金额排序时，这两笔并列，题目没有规定它们之间的先后。日常做分页时也要加这种明确的并列规则。

运行结果

```text
id | amount
105 | 120
101 | 120
```

## 00:21:00 练习 · 各客户有几笔已支付订单

### 题目

请找出有至少两笔已支付订单的客户。先划出已支付的五笔，可以在纸上写它们的客户编号。把相同编号放一组，计算组内的行数。组内有两行及以上才保留。给自己几秒钟，先写出客户编号和对应笔数，然后按照编号顺序排好。

```sql
SELECT customer_id, COUNT(*) AS n
FROM orders
WHERE status = '已支付'
GROUP BY customer_id
HAVING COUNT(*) >= 2
ORDER BY customer_id;
```

### 解析

已支付的行按订单编号是第一、第二、第四、第六、第七笔。对应客户编号是一、二、三、三、一。一号出现两次，二号一次，三号两次。按门槛保留一号和三号。最后结果是编号一、两笔，以及编号三、两笔。原始行、分组结果、筛完的结果，这三层分别写下来，复杂一点也容易检查。

运行结果

```text
customer_id | n
1 | 2
3 | 2
```

## 00:25:57 练习 · 分清 COUNT 的两个口径

### 题目

题目只看客户四号小吴。她在客户表里有一行，订单表里没有她的记录。查询用左连接按客户编号匹配，然后筛到四号。第一项 COUNT 星号，第二项 COUNT 订单的 id。请画一下连接后这一行长什么样，再判断两个计数各是多少。先写答案，几秒后一起核对。

```sql
SELECT COUNT(*) AS joined_rows,
       COUNT(o.id) AS old_orders
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id
WHERE c.id = 4;
```

### 解析

因为是左连接，小吴这一行会留下，右侧订单号为 NULL。COUNT 星号数行，所以是一个。COUNT 订单 id 跳过空值，结果是零。两列回答的是不同问题。需要统计实际订单时，使用右表主键计数。需要统计客户列表里保留的组合行时，用星号。这是连接和统计一起出现时很实用的检查方法。

运行结果

```text
joined_rows | old_orders
1 | 0
```

## 00:31:00 练习 · 从中间表挑出大客户

### 题目

这道题先用 WITH 算每个人的已支付总额。可以写下三个客户的总额，再看外层。外层读这个小表，只留总额至少两百的行，最后按总额从大到小显示。请先写出两个客户的编号和金额，再想想为什么这里直接使用 WHERE。等几秒我们核对。

```sql
WITH paid AS (
  SELECT customer_id, SUM(amount) AS total
  FROM orders WHERE status = '已支付'
  GROUP BY customer_id
)
SELECT customer_id, total
FROM paid
WHERE total >= 200
ORDER BY total DESC;
```

### 解析

中间表里一号二百一十、二号八十、三号三百六十。外层的一行已经是一个客户的统计结果。total 作为中间表的列，可以像普通列那样使用 WHERE。所以先显示三号三百六十，再显示一号二百一十。把复杂查询拆开读，关键是认清当前这一层的一行代表什么。

运行结果

```text
customer_id | total
3 | 360
1 | 210
```

## 00:37:40 练习 · 默认值会写成什么

### 题目

这里有自己的库存表，每条记录存商品编号和当前数量。数量是必填整数，同时默认值是零。插入语句只给出编号八，数量没有出现在插入列表里。请预测最后一行会看到什么。也想一想，把默认值从零改成五，再复制这段代码到一份新的数据库中，结果会怎样。

```sql
CREATE TABLE stock (
  id INTEGER PRIMARY KEY,
  units INTEGER NOT NULL DEFAULT 0
);
INSERT INTO stock (id) VALUES (8);
SELECT id, units FROM stock;
```

### 解析

字段定义给了默认值，因此省略数量时会填零。编号来自插入语句，仍是八。最后得到一行，编号八、数量零。把默认值定义改成五以后，在新建的表中执行同样的插入，就会显示五。默认值适合表达常见的起步状态，把常用状态写进表定义，录入代码就可以少填一项。

运行结果

```text
id | units
8 | 0
```

## 00:44:21 练习 · 一条 UPDATE 选中哪一单

### 题目

题目中两笔待支付订单，金额分别是六十和九十。请用两个条件逐行判断。更新目标的金额会加五，但后面的查询范围比更新宽。查询会列出所有待支付订单。你要写出两行结果，并在发生改变的那一行旁边画个圈。暂停几秒后一起核对。

```sql
UPDATE orders
SET amount = amount + 5
WHERE status = '待支付' AND amount < 80;

SELECT id, amount
FROM orders WHERE status = '待支付'
ORDER BY id;
```

### 解析

一百零三号是待支付且金额六十，通过两个条件。一百零八号虽然待支付，金额九十超过门槛。只有一百零三号加五，变成六十五。查看时两行都会出现，依次为一百零三、六十五，以及一百零八、九十。调试时可以同时看一笔命中和一笔刚好没命中的记录，确认更新范围。

运行结果

```text
id | amount
103 | 65
108 | 90
```

## 00:49:22 练习 · 回滚发生在查询前

### 题目

题目先打开事务，再删除一百零五号。删除语句本身会命中订单表中那一条已取消记录。看清回滚和查询的先后顺序。暂停几秒，分别写下回滚前能不能查到这条记录，回滚后屏幕会显示什么。想想把第三行换成提交以后，答案会怎样变化。

```sql
BEGIN;
DELETE FROM orders WHERE id = 105;
ROLLBACK;

SELECT id, status FROM orders WHERE id = 105;
```

### 解析

删除以后，同一连接立刻查这笔订单会查不到。接着回滚，删除被撤销。所以最终查询仍然返回一百零五号，状态是已取消。若把回滚改成提交，删除就会保留下来，查询返回零行。做事务题时，把开始点、每项写入和结束点划在时间线上，很容易看清最后保存了什么。

运行结果

```text
id | status
105 | 已取消
```

## 00:54:33 练习 · 每位客户最贵的一笔已支付订单

### 题目

最后一道题。先取已支付的订单，按客户分区，再按金额从高到低编号。外层只留每区的位置一。给自己几秒钟，写下每位客户留下的订单号，再检查哪位客户没有出现在最终表里。可以从第四章用过的五笔已付款订单开始找。

```sql
WITH ranked AS (
  SELECT customer_id, id, amount,
         ROW_NUMBER() OVER (
           PARTITION BY customer_id
           ORDER BY amount DESC, id
         ) AS pos
  FROM orders WHERE status = '已支付'
)
SELECT customer_id, id, amount
FROM ranked
WHERE pos = 1
ORDER BY customer_id;
```

### 解析

客户一号的位置一是一百零一，金额一百二十。二号只有一百零二，金额八十。三号的位置一是一百零四，金额两百。最终三行。小吴在基础订单集中没有付款记录，因此没有分区。到这里，从表与行列、条件和排序，到分组、连接、写入、事务和窗口都用过一遍。课后可以改用六月作为时间条件，跑出一份新的客户报表。

运行结果

```text
customer_id | id | amount
1 | 101 | 120
2 | 102 | 80
3 | 104 | 200
```
