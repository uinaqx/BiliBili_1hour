# 语义、声音与画面同步

## 三层分开

1. 人工语义计划：准确旁白短语指向哪些实际代码行或图示对象。
2. 最终音频时间：短语在实际音频里何时开始、何时说完。
3. 持续画面状态：从开始事件起保持，直到下一处讲解或换页。

平均分段不是语音起点；首行/关键词猜测不是语义对应；有非空高亮不代表选对。每页读完整旁白并对照实际代码，覆盖回跳和答案页；没有切换的纯讲题页可保持关键行并注明原因，不强行让每个名词都触发一次切换。

“第一行显示”可能是第一条 print，并非源文件第 1 行；“最后一行返回”可能是函数尾表达式，并非大括号。`//` 与 `/`、derive 与泛型里的 Debug 等会产生关键词误报，必须结合上下文复核。

## 明确坐标

- `startFrame`：页面在全片的绝对起始帧。
- `durationFrames`：页面长度；`leadFrames`：页面出现后到最终音频开始的片头。
- 音频元数据及字幕的 `start/end`：本页最终音频内秒数。
- 提示点 `beginFrame/endFrame`：页面内局部帧号。

切换帧为 `leadFrames + ceil(startSeconds * fps - 1e-6)`；合入全片才加 `startFrame`。`endFrame` 可保留作语义短语证据，代码高亮不以它截止。

词时间必须对应最终音频。变速、剪切、加停顿后要精确映射或重新对齐，记录音频 SHA-256 和来源，保留更准确的声学修订；不能按字符比例静默插值。时间元数据示例：

```json
{"timeBase":"final-audio","timeUnit":"seconds","words":[
  {"text":"读取","start":2.0,"end":2.5},
  {"text":"第一个元素","start":2.5,"end":3.6}
]}
```

工具 `resolve` 只给已经人工选好的短语定位。重复短语使用从 1 开始的 `occurrence`；找不到、歧义、逆序、越界或跨幕时失败，不把提示点设成零秒。手动定位须记录 `method: manual-audio-review`、起止时间及原因。

## 分幕与图示

换代码后有新的初始行与事件范围；可用 `panelId` 明确归属，旧幕的晚到事件也不能影响新幕。越界/空行应报错，不 clamp 成最后一行。

图示将强调与状态更新分开，例如 `{"beginFrame":530,"patch":{"focus":"alu","result":20}}`。之后寄存器写回、主存写入有独立事件，不能用段落百分比自动完成。当前幕不存在的对象是数据错误，不能取余映射。

若旁白只是扩展背景且没有当前对象，可维持相关状态；若核心讲解缺素材，则补齐必要小幕。例如讲二进制小数的前两幕提供位权与循环展开，后两幕才是浮点字段；DRAM/SRAM 也不能由读写分支代替。保留样式与声音、记录例外。

## 字幕

按实际说完时间结束，重点检查长句、术语、数字、拖音和增加的停顿。下一条字幕不能过早顶掉还没讲完的句子；目标偏差可设为 0.3 秒，但未测量不可声称达标。

字幕结束和代码选中结束是不同机制，不能一个 end 同时清空两者。ASS 的百分之一秒与 30fps 网格不同：VFR 除了代码事件，还需在字幕实际起止后的首个可显示网格帧采样。精确交点取整必要时保留后一帧并检查输出，不能让整句因长停帧而缺失。
