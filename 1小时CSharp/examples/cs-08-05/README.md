# 用事件连接通知与处理

运行：`dotnet run --project .`。


当某件事发生后，需要通知其他部分，可以使用事件。Alarm声明一个Action类型的事件Triggered，订阅者提供收到通知后要执行的方法。Raise在类内部触发它，问号点Invoke表示存在订阅方法时进行调用。可以把发布者理解成发出提醒的地方，把订阅者理解成接到提醒后采取行动的地方，双方通过事件连接。

外部创建Alarm，用加等号加入一段lambda，收到通知后显示预算提醒。随后调用Raise，订阅的方法被执行，最终显示预算提醒。按钮点击、状态更新和记录变化都可以用类似方式组织通知。订阅通常配合减等号取消，按对象使用周期管理。入门先看清订阅发生在哪里、触发发生在哪里，再跟踪被调用的处理方法，路线就很明确。

## 总结

- event 向外提供订阅通知的入口
- += 把处理方法加入订阅，-= 取消订阅
- 发布者在类内部触发事件，订阅者执行对应操作
- ?.Invoke 在存在处理方法时进行调用
