# 查询执行与 ToList 快照

运行：`dotnet run --project .`。


这一页观察时间顺序。amounts最初是十二和五，Where保存大于等于八的筛选规则。随后添加二十，再遍历query，当前数据源已经有二十，所以显示十二和二十。对这样的查询，建立规则和实际遍历发生在不同位置。读程序时，把哪一行开始真正取得结果标出来，后续变化就容易跟踪。

ToList会当场执行查询，把当前结果保存成一个新列表，得到十二和二十。之后往原列表添加三十，snapshot保留先前取得的那两项。再次遍历query，就会读取当前数据源，显示十二、二十、三十。需要保留某一时刻的结果，就把值取出来保存，需要按当前数据重新查询，就在相应位置再次遍历这份规则。

## 总结

- Where 保存查询规则，遍历时读取数据源
- 首次遍历已经能看到后来加入的 20
- ToList 当场执行查询，把结果保存成列表
- 再次遍历 query 时，会读取包含 30 的当前数据源
