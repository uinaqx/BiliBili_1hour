# 抛出异常与释放资源

运行：`dotnet run --project .`。


自己的方法也可以用throw报告失败。Spend要求金额大于等于零，收到负数就抛出参数范围异常。nameof取得参数名称，帮助调用者定位是哪一项数据需要处理。合法金额会继续执行后面的操作。这样方法把输入约定和检查放在一起，多个调用位置都能共用同一份规则，成功路径也保持直接。

本页传入负一，异常交给外层catch，最后显示金额应大于等于零。异常处理还可以配合finally完成收尾。文件流等对象通常提供释放资源的约定，可以用using把使用范围包起来，离开范围时安排释放。下一页先用简短的文件工具方法完成保存和读取，等需要逐行处理大文件时，再学习更完整的流和资源管理写法。

## 总结

- throw 把失败原因交给调用链上的处理位置
- nameof 取得参数名称，方便错误定位
- catch 处理对应类型的参数范围异常
- finally 安排收尾，using 常用于自动释放可释放资源
