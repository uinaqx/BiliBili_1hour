# 用异常传递失败原因

支付函数接收一个数字。业务要求金额大于等于零，所以负数进入这一行时，用 throw 抛出一个 Error，把清晰的原因一起带出去。合法金额会继续输出支付信息。这样函数可以把成功路径写在正常流程中，把失败原因交给调用它的地方统一处理。这个思路在请求失败和解析错误时也很常见。

把调用放进 try，故意传入负一，看看失败路线。抛出的值来到 catch。我们把它看作 unknown，也就是先保留具体类型，等检查后再使用。instanceof Error 确认它是错误对象，随后读取 message，控制台显示金额应大于等于零。实际页面也可以在这里把原因展示给用户。

## 本页总结

- throw 抛出异常，当前执行流程转到 catch
- try 包住可能抛出异常的调用
- catch 的 unknown 值先检查，再读取属性
- instanceof Error 后可以读取 message

## 预期输出

```text
金额应大于等于零
```
