## 第一个Python程序 · First Program

题目：这段程序把 print 最后的右括号删掉了，文字两边的引号还在。它会正常显示 Hello Python，还是先报告写法有问题？请把括号和引号分别配对，不要因为这一行很短，就觉得计算机一定能猜出我们想省略什么。换到下一行，也不能自动替我们补上这个右括号。给你四秒，先指出缺少的是哪种符号，再判断这段程序能不能正常开始运行。遇到长一点的程序时，这种先找最早一处写法错误的习惯，同样有用。

```python
print("Hello, Python!"
```

原题验证结果：
```text
语法检查失败：左括号没有对应的右括号
```

答案与原因：原题不能正常运行，会报告语法错误。语法可以先理解成这门语言规定的写法。这里 print 打开了一个括号，却没有把它关上，Python 会指出这个问题。补上右括号，再次运行，就会显示 Hello Python。注意，错误消息里的文件名和行号可以帮助我们回到代码，箭头不一定总落在真正漏写符号的地方，所以还要检查附近的配对关系。先不要把错误消息当成程序已经成功显示的另一种结果。这次显示文字的操作还没有执行，就因为写法问题停下来了。下一章我们会给数字和文字起名字，让程序不再只能显示一段固定内容。

核对、修正或对比代码：
```python
print("Hello, Python!")
```

上方对比代码的验证结果：
```text
Hello, Python!
```

## 变量与数据类型 · Variables and Types

题目：a 先得到十二，b 再得到 a 当时对应的整数。接着把 a 改成二十，最后一起显示 a 和 b，会得到二十和二十，还是二十和十二？请按先后顺序跟踪，不要只看最后出现的那个数字。b 等于 a 这一行执行时，a 还没有被重新赋值。给你四秒，分别写出最后两个名字对应的值。这一题只讨论整数以及重新赋值，后面学列表时，我们还会专门观察“修改数据里面的一项”和“给名字另一个值”有什么不同，先别把两种操作混在一起。

```python
a = 12
b = a
a = 20
print(a, b)
```

原题验证结果：
```text
20 12
```

答案与原因：结果是二十和十二。执行 b 等于 a 时，a 对应十二，b 也就对应这个整数。后来给 a 另一个整数二十，没有再次给 b 赋值，所以 b 仍然是十二。这里不要把 b 理解成一条会不断重新计算 a 的公式，也不要认为两个名字出现过赋值关系，以后就一定自动同步。要看后面到底执行了什么操作。当前只需要记住这个执行顺序。下一章我们把变量拿来计算余额，接收键盘输入，再显示带有说明的结果。名字的作用不是增加要背的英文，而是让程序中的数据能被反复使用，让每一步的意思更容易看清楚。

核对、修正或对比代码：
```python

b = a
a = 20
print(a, b)
```

上方对比代码的验证结果：
```text
20 12
```

## 运算符与输入输出 · Operators and Input Output

题目：现在从键盘输入十二。text 等于 input，所以 text 保存的是文字。第一行把它和有引号的八相加，第二行先用 int 转换，再和没有引号的八相加。两行结果一样吗？请先判断每一行正在处理文字还是整数，再决定加号是在连接，还是在做数值计算。不要因为两行最后都能显示出来，就以为它们经历了同样的操作。给你四秒，分别写下两个结果。这个习惯会帮助你理解很多初学输入问题：先认清拿到的数据，再选择下一步动作。

```python
text = input()
print(text + "8")
print(int(text) + 8)
```

原题验证结果：
```text
128
20
```

答案与原因：第一行显示一二八，第二行显示二十。第一行的两边都是字符串，所以把文字十二接上文字八。第二行先把十二这段文字变成整数，再加整数八，得到数值二十。如果把第一行写成字符串直接加整数八，Python不会自动替我们决定是想连接文字还是做算术，而会报告类型不匹配。本页保留的两行都能正常运行，是为了先把正确写法的区别看清。到这里，我们已经能保存数据、计算、接收输入和显示说明。接下来要让程序根据金额选择不同回答：没有超出预算是一种情况，超出预算是另一种情况。计算会给我们一个值，判断会告诉我们应该走哪一条路线。

核对、修正或对比代码：
```python
text = input()
print(text + "8")
print(int(text) + 8)
```

上方对比代码的验证结果：
```text
128
20
```

## 条件判断 · Conditional Statements

题目：需求是“不超过三十元就算在预算内”。现在花费刚好三十，代码却用了小于三十。它会显示 within 还是 over？实际写法是否符合需求？请分开做两件事：先按代码中的符号算出当前结果，再根据需求决定要不要修改。不要因为我们希望它显示 within，就把小于自动看成了小于等于。给你四秒，指出边界差在哪里。很多程序可以运行，也会显示一个结果，但刚好落在边界上的数据，可能暴露出条件没有表达准确的问题。

```python
spent = 30
budget = 30
if spent < budget:
    print("within")
else:
    print("over")
```

原题验证结果：
```text
over
```

答案与原因：原题显示 over，因为三十并不小于三十。按照不超过预算的需求，要把小于改成小于等于，刚好相等时才会显示 within。修正以后，二十九和三十都在预算内，三十一才超出。这样检查边界附近的几组数据，比只用一个相差很大的数来测试，更容易判断规则是否完整。程序不会自动把我们的中文需求补进条件中。它只执行实际写下的判断，所以先明确需求，再选正确符号，最后用具体数核对。这条方法后面写循环条件时也一样适用：该不该包含最后一个数，必须在条件或范围里表达出来。

核对、修正或对比代码：
```python
spent = 30
budget = 30
if spent <= budget:
    print("within")
else:
    print("over")
```

上方对比代码的验证结果：
```text
within
```

## 循环结构 · Loops

题目：我们希望把一、二、三加起来，代码却写成 range 括号一、三。total 最后是三还是六？先列出这次范围真正提供的数字，再把每个数加入 total。不要因为需求里提到三，就认为代码里的结束位置三也会自动被取到。给你四秒，先写出实际执行了几轮，再算总和。如果结果不符合需求，再指出范围应该怎样改。循环错误常常不是加法算错，而是根本少处理了最后一项。

```python
total = 0
for number in range(1, 3):
    total += number
print(total)
```

原题验证结果：
```text
3
```

答案与原因：原题结果是三，因为只执行了加入一和加入二这两轮。修正为 range 括号一、四，才会依次得到一、二、三，最后总和为六。这条范围规则后面访问列表和文字片段时还会遇到：开始位置可以包含，结束位置通常不包含。先通过小范围列出每个值，再慢慢形成直觉，不用第一次看到就强迫自己完全心算。现在我们已经会重复执行步骤。下一章把几笔开销集中保存在一份列表里，让循环不必只处理一段连续整数，而是读取真正记录过的数据。变量、加法和循环会一起完成一个更接近日常需求的统计。

核对、修正或对比代码：
```python
total = 0
for number in range(1, 4):
    total += number
print(total)
```

上方对比代码的验证结果：
```text
6
```

## 列表 · Lists

题目：列表有三项，len 得到三。直接用这个三作为位置，能读到最后的五吗，还是会在运行时报告错误？请先把有效位置零、一、二写出来，再看看 len 所在的那个位置有没有对应元素。长度是在回答一共有几项，位置是在回答要读哪一项，它们不能直接互换。给你四秒，先判断能否成功读取，再提出一种安全读取最后一项的思路。这一段写法本身符合语法，但是执行到读取时可能失败，和第一章漏括号的情况要区分开。

```python
expenses = [12, 8, 5]
print(expenses[len(expenses)])
```

原题验证结果：
```text
运行时异常：IndexError，位置 3 不存在
```

答案与原因：原题会报告 IndexError，因为位置三不存在。修正版先判断长度大于零，再用负一读取最后一项，结果是五。也可以使用长度减一得到位置二。为什么还要先判断？如果列表里一项都没有，负一也没有对应元素，不能因为它看起来像末尾，就忽略空列表。安全的读取，要先满足当前数据实际具有这项内容。现在把思路连起来：长度告诉我们数量，位置用来找某一项，切片用来取一段，循环可以逐项处理。遇到列表问题，先画出当前内容与位置，再跟踪每个操作改变了什么，比只记某行代码的输出更有用。

核对、修正或对比代码：
```python
expenses = [12, 8, 5]
if len(expenses) > 0:
    print(expenses[-1])
```

上方对比代码的验证结果：
```text
5
```

## 字符串 · Strings

题目：text 保存小写的 tea。下一行调用 upper，但没有把返回结果保存给任何名字，最后显示 text。会得到小写 tea，还是大写 TEA？请回想这一章强调的区别：得到处理后的新字符串，和直接把原字符串内部改掉，是不是同一件事？操作被调用过，并不一定意味着原来的变量自动接住了它的结果。给你四秒，先预测显示内容，再指出如果需要大写结果，调用处应该多做哪一步。后面写自己的函数时，也会遇到“结果已经算出来，但没有在需要的位置保存”的情况。

```python
text = "tea"
text.upper()
print(text)
```

原题验证结果：
```text

```

答案与原因：原题显示小写 tea。upper 已经得到一个大写的新结果，但代码没有接住它；text 仍然对应原来的小写字符串。修正版用 upper_text 保存返回值，再分别显示 text 和 upper_text，就能同时看到 tea 和 TEA。如果希望以后 text 这个名字就使用大写文字，也可以写 text 等于 text 点 upper，让它对应新结果。这两种保存方式都不会说明原来的字符串能被任意逐字符修改。关键是名字后来对应哪一个结果。先把数据和名字分开想，再看操作有没有返回值、调用处有没有使用它，很多看起来“明明调用了却没变化”的问题，就能找到原因。

核对、修正或对比代码：
```python

```

## 函数 · Functions

题目：add_fee 接收一个金额，把它加二，并返回结果。外面的 spent 最初是十二，调用函数以后，没有把返回值交给任何变量，最后显示 spent。会显示十二还是十四？请看清哪一次赋值发生在函数里面，哪一个名字写在调用的外面。函数算出了结果，并不意味着它会自动替调用处选择一个变量来接收。给你四秒，先预测结果，再指出如果希望更新 spent，调用这一行应该怎样写。这和字符串 upper 产生新结果却没被接住的题目，可以用相同的思路分析。

```python
def add_fee(amount):
    amount += 2
    return amount

spent = 12
add_fee(spent)
print(spent)
```

原题验证结果：
```text
12
```

答案与原因：原题显示十二。函数里面 amount 加二，最后返回十四，但外面的 spent 没有因为这次调用自动对应十四。修正版写 spent 等于 add_fee 括号 spent，让调用处接住这个新结果，最后就显示十四。先读取原来的十二，把它交进去，再把返回的十四交回外面的 spent，步骤非常明确。这里处理的是整数及重新赋值。如果函数接收到列表，并在里面追加元素，外面也可能观察到那一份列表的变化，原因和前面两个名字使用同一列表一样。不要把所有函数调用都简单理解成复制一份完整数据。当前先掌握明确输入、明确返回、调用处明确使用结果这条主线。

核对、修正或对比代码：

## 模块与文件 · Modules and Files

题目：本题开始时，expenses 点 txt 已经保存了十二和换行。现在用 w 模式打开，写入八和换行，再读出文件内容。最后会同时看到十二和八，还是只看到八？请特别看打开模式，不要只因为我们又调用了一次 write，就把它理解成一定接在旧内容后面。给你四秒，先预测最终文件里有什么，再说明如果想保留原来那笔十二，需要换成什么模式。练习目录提供了本题的初始文件，请只在这份独立例子里操作，方便准确观察变化。

## 异常处理 · Exceptions

题目：沿着这段程序看字母的显示顺序。先显示 A，再把 abc 转成整数，然后还有显示 B。except 里面显示 C，整个结构外面显示 D。转换失败时，最终会显示哪些字母？请注意，except 不是每次必定执行的另一组普通操作，失败以后也不会自动回到 try 里补做 B。给你四秒，在纸上画出正常向下和转去处理问题的两条路线，选择这次真正经过的那一条。用具体步骤检查执行顺序，比只背一串输出字母更有意义。

```python
try:
    print("A")
    int("abc")
    print("B")
except ValueError:
    print("C")
print("D")
```

原题验证结果：
```text
A
C
D
```

答案与原因：原题依次显示 A、C、D。转换前的 A 已经显示，int 失败以后跳到 except，显示 C，再执行结构外的 D。B 被跳过。画面改用合法的十二作为对照。转换成功后继续显示 B，不进入 except，所以这次是 A、B、D。把两种数据放在同样的结构里观察，能看清异常究竟改变了哪一步。以后遇到一长段错误提示，先读具体错误种类和自己代码对应的那一行，找到无法完成的操作。能改正写法或数据，就先修正；确实需要应对的失败，再设计合适提示或后续动作。不要用一个空处理把问题全部藏起来，程序没有报错显示，不等于已经做对了事情。

核对、修正或对比代码：
```python
try:
    print("A")
    int("12")
    print("B")
except ValueError:
    print("C")
print("D")
```

上方对比代码的验证结果：
```text
A
B
D
```
