# C++ 课堂练习与答案

每题朗读后保留四秒思考。完整上下文见 C++示例。

## C++基础 · C++ Basics

题目：a 是三，b 是八，引用 r 最初绑定 a。接下来写 r 等于 b，再把 b 改成九。最后打印 a 和 r，它们分别是多少？这里最容易误读的是 r 等于 b。这句话发生在引用已经建立之后，它是在给所引用的整数赋值，还是把引用重新绑定到 b？请先画出 r 最初对应哪一个格子，再执行后面两行。四秒之后，我们一起核对这两个名字是否还在访问同一份数据。

```cpp
int a = 3, b = 8;
int& r = a;
r = b;
b = 9;
cout << a << " " << r << '\n';
```

答案与原因：结果是八和八。r 建立时绑定 a，后面没有改绑。r 等于 b 的意思，是读取 b 当时的八，再通过 r 写进 a。因此 a 变成八，r 作为 a 的别名也读到八。接下来 b 改成九，修改的是另一个变量，并不会影响 a。这里的关系和普通数值复制、指针保存地址都有联系，但不要把引用当成一个随时可换目标的指针变量。遇到引用题时，先确认它建立时绑定谁，再逐行区分“修改被引用对象”和“修改其他对象”。这个习惯后面会帮助我们理解成员函数的 this，以及通过基类引用调用派生对象的行为。

核对或修正代码：
```cpp
int a = 3, b = 8;
int& r = a;
r = b;
b = 9;
cout << a << " " << r << '\n';
```

```text
8 8
```

## 类与对象 · Classes and Objects

题目：a 和 b 是两个独立的 Score 对象。我们先给 a 八十，给 b 九十，再把 a 改成八十五。最后读取 b，会得到九十还是八十五？请确认代码里有没有让这两个名字表示同一个对象。这里没有引用，也没有指针绑定，只是创建了两个相同类型的对象。四秒之后，我们把普通成员的归属再核对一遍，并为后面的静态成员留出对照。

```cpp
Score a, b;
a.set(80);
b.set(90);
a.set(85);
cout << b.get() << '\n';
```

答案与原因：b 仍然是九十。a 的 set 访问的是 a 的成员变量，b 的那份数据没有被修改。两个对象使用同一个类定义，并不意味着普通成员自动共享。如果把 b 声明成 a 的引用，关系就会不同；但当前代码没有这样写。我们始终根据程序实际建立的关系判断，而不是只看类型名和函数名相同。到这里，你已经可以区分类和对象：类是类型与接口的定义，对象则有自己的一份状态。下一章会让这份状态在对象刚建立时就准备好，避免总是先创建一个不完整状态，再靠后续调用补齐。负责这件事的，就是构造函数。

核对或修正代码：
```cpp
Score a, b;
a.set(80);
b.set(90);
a.set(85);
cout << b.get() << '\n';
```

```text
90
```

## 构造与析构 · Construction and Destruction

题目：这个 Score 类只有一个需要整数参数的构造函数。现在 main 却写 Score s，没有交给它整数。它能不能自动把成绩设成零，然后顺利打印八十？请只根据类已经提供的入口判断。不要因为成员是 int，就猜系统一定会帮我们补一个满足需求的创建方式。四秒之后，我们会先解释编译结果，再给出一个明确交入初值的修正版。

```cpp
Score s;
cout << s.get() << '\n';
```

答案与原因：原程序不能编译，因为这个类没有可用的无参数构造函数。带参数版本并不同时意味着无参数版本也存在。修正版写 Score s 括号八十，明确把八十交给已有构造函数，成员就被初始化成八十，读取结果也就是八十。如果需求是允许默认成绩零，也可以像前一页那样另外定义无参数构造函数。建立对象和后面修改对象是不同阶段。先确定对象能否按这组参数建立，再讨论成员函数会返回什么。这个顺序在派生类构造、成员对象构造中同样适用：每一部分都需要一个实际可用的初始化方式。

核对或修正代码：
```cpp
Score s(80);
cout << s.get() << '\n';
```

```text
80
```

## 封装与共享 · Encapsulation and Sharing

题目：Score 的 get 是 const 成员函数，set 是普通修改函数。现在对象 s 自己也声明成 const，随后调用 s 点 set，把分数改成九十。它能编译吗？请先看对象提供的使用条件，再看所调用的函数是否承诺只读。不要因为 set 本来是 public，就认为任何对象状态下都可以调用。四秒之后，我们分别说明“允许从外部看见这个名字”和“允许在 const 对象上调用”这两层检查。

```cpp
const Score s(80);
s.set(90);
```

答案与原因：这段不能编译。public 说明外部代码有权访问这个接口，而 const 对象只能调用适用于只读对象的成员函数。set 没有 const 承诺，不能拿 s 这样调用。如果需求只读取，使用 get 就能得到八十。如果确实要修改，就应当从一开始使用可修改对象，再通过受控接口修改，而不是随意去掉 const 约束。到这里，封装不仅是把字段藏起来，还包括准确表达接口的使用条件。this 说明当前对象是谁，const 说明这次访问能否修改，static 表达类共享数据，friend 则授予特定协作者访问许可。把这几种机制分别放回它解决的问题，就不会只剩下一张关键字表。

核对或修正代码：
```cpp
const Score s(80);
cout << s.get() << '\n';
```

```text
80
```

## 对象组合 · Object Composition

题目：Box 先声明 first，再声明 second，但初始化列表把 second 写在前面。创建时首先显示 A，还是首先显示 B？请先看类内成员的声明，再看各个成员接收的参数。初始化列表里的参数会交给对应成员，但书写顺序本身能不能改变它们的实际建立次序？四秒之后，我们把创建和销毁都用正确的顺序列出来，再把初始化列表也整理成容易阅读的版本。

```cpp
class Box {
    Part first_;
    Part second_;
public:
    Box() : second_('B'), first_('A') { cout << "Box "; }
};
```

答案与原因：先显示 A。因为 first 在类里面先声明，它先被构造；然后才是 second 的 B，再进入 Box 函数体。修正版把初始化列表也按 first、second 排好，只改善代码的表达，不改变原本的实际构造顺序。这个版本没有专门的 Box 析构输出，所以结束时只看到成员 B 和 A 依次收尾。这道题以后也能帮助你判断派生对象的构造：不要只看某一行列表怎么排，而要先确定语言对每一种对象部分规定了什么先后。先识别基类和成员，再看传入参数，最后才看构造函数体。

核对或修正代码：
```cpp
class Box {
    Part first_;
    Part second_;
public:
    Box() : first_('A'), second_('B') { cout << "Box "; }
};
```

```text
A B Box ~B ~A
```

## 继承 · Inheritance

题目：看这两行初始化。ref 是基类引用，copy 是一个独立的基类对象，它们都从同一个学生 s 得到。哪一个仍然引用原来的学生？哪一个只保存自己的 Person 部分？这里先不讨论虚函数，只判断有没有创建另一个对象。你可以数一数名字旁边有没有引用符号，再想一想引用在本课开头的含义。四秒以后，我们分别给这两个位置贴上“使用原对象”和“新建基类对象”的说明。继承的赋值兼容不等于所有对象都可以随意互换，这个区别会直接影响下一章多态的结果。

```cpp
Student s("Ana",80);
Person& ref = s;
Person copy = s;
ref.show();
copy.show();
```

答案与原因：ref 使用的仍然是 s，所以没有创建独立的 Person 对象。copy 则是新建的 Person，只接收 s 中的基类部分。两次 show 都显示 Ana，不代表这两种初始化完全一样。因为目前 show 只读取姓名，而这个姓名在两种情况下都存在，所以输出恰好相同。不能只凭一行相同输出就认为两个表达式语义相同。把这道题和最开始的引用联系起来：引用提供已有对象的另一个使用入口，按值初始化通常建立一个独立对象。继承又让这个独立对象可能只留下基类部分。等我们加入虚函数，保留实际对象的基类引用就有了更明显的用途。

核对或修正代码：
```cpp
Student s("Ana",80);
Person& ref = s;   // 使用原对象
Person copy = s;   // 新的基类对象
ref.show();
copy.show();
```

```text
Ana
Ana
```

## 多继承 · Multiple Inheritance

题目：C 的基类列表写 A、B，初始化列表写 B、A。创建一个 C，输出是 A B C，还是 B A C？先找到决定规则的那一处列表，而不是跟着构造函数里最后看见的顺序猜答案。参数可以在初始化列表中指定，但实际执行先后还有语言规定。请用四秒选出答案，再补一句理由：你依据的是基类列表，还是初始化列表。能说出依据，比只记住这一题的字母顺序更有用。

```cpp
class A { public: A() { cout << "A "; } };
class B { public: B() { cout << "B "; } };
class C : public A, public B {
public:
    C() : B(), A() { cout << "C\n"; }
};
```

答案与原因：答案是 A B C。A 在基类列表中先出现，先完成 A，再完成 B，最后才进入 C 的构造函数体。画面已经把初始化列表改成 A、B。输出没有变化，编译器的顺序警告却消失了，因为文字顺序现在符合真实执行顺序。多继承这一节到这里就够了。以后读到类似代码，先数直接基类，再看基类列表的先后；读到组合对象，则看成员声明的先后。把两种列表的作用分清，就不必靠猜测理解构造输出。

核对或修正代码：
```cpp
class A { public: A() { cout << "A "; } };
class B { public: B() { cout << "B "; } };
class C : public A, public B {
public:
    C() : A(), B() { cout << "C\n"; }
};
```

```text
A B C
```

## 重载 · Overloading

题目：a 的坐标是一和二，b 是三和四。执行 c 等于 a 加 b，再分别输出 c 和 a，会出现什么结果？请回到运算符函数内部，找一找有没有给当前对象的 x 或 y 赋新值。只出现加法表达式和返回新对象，是否等于把左边对象原地改掉？四秒以后，我们沿着返回值走一次。不要只看加号长什么样，而要根据函数实际执行的动作判断状态。不同程序可以为运算符写不同实现，这一道题的答案来自画面上明确给出的实现。

```cpp
Point a{1,2}, b{3,4};
Point c = a + b;
cout << c.x << " " << c.y << '\n';
cout << a.x << " " << a.y << '\n';
```

答案与原因：c 是四和六，a 仍然是一和二。这个 operator 加号只读取两个对象，然后返回包含结果的新对象。如果写 a 等于 a 加 b，情况才不同：先计算新点，再把结果赋给 a。导致 a 改变的是后面的赋值，不是这个加法函数在内部修改了 a。我们现在就多执行这一行。第二次输出 a 时，它才显示四和六。把计算、返回、赋值分开理解，能避免把所有符号都混成一个动作。函数重载和运算符重载最后都要回到同一个问题：选中了哪个函数，它读了哪些数据，是否修改对象，返回了什么。

核对或修正代码：
```cpp
Point a{1,2}, b{3,4};
Point c = a + b;
cout << c.x << " " << c.y << '\n';
cout << a.x << " " << a.y << '\n';
a = a + b;
cout << a.x << " " << a.y << '\n';
```

```text
4 6
1 2
4 6
```

## 多态 · Polymorphism

题目：基类 speak 已经是 virtual，派生类已经正确 override。现在先让 Base 引用指向 d，再创建一个 Base copy 等于 d，分别调用 speak，会显示什么？这一次不能只记住“有 virtual 就选派生类”。还要检查调用时真正存在的对象。ref 仍然关联 d，但 copy 是不是一个独立的基类对象？请用四秒把两次调用分开判断。我们在继承一章留下的“引用保留原对象，基类值对象只保存基类部分”，现在正好可以解释答案。

```cpp
Derived d;
Base& ref = d;
Base copy = d;
ref.speak();
copy.speak();
```

答案与原因：先显示 Derived，再显示 Base。ref 关联的是原来的派生对象，所以虚函数选择 Derived 的覆盖版本。copy 本身就是一个 Base 对象，学生或派生部分没有被保存进去，调用自然选择 Base。动态绑定不会把一个真实的 Base 对象凭空还原成 Derived。它根据调用当时实际对象的情况选择实现，而不是追溯这个对象最早从谁复制而来。把多态题分成三步就不容易乱：首先判断基类函数是不是 virtual，然后判断派生类是否正确覆盖，最后判断调用入口背后到底是哪一个对象。引用、指针和按值对象的区别，要放在这最后一步一起看。

核对或修正代码：
```cpp
Derived d;
Base& ref = d;
Base copy = d;
ref.speak();   // 原对象是 Derived
copy.speak();  // copy 自己是 Base
```

```text
Derived
Base
```

## 异常处理 · Exception Handling

题目：try 中先输出 A，再调用零除数的 divide，接着准备输出 B。catch 输出 C，整组结构之后输出 D。最终会出现哪几个字母？先从 A 出发，遇到 divide 时检查参数。它是正常返回，还是抛出异常？选定路线以后，再决定 B 有没有机会执行。四秒以后，我们再补上一个细节：函数里已经创建的自动对象，在异常离开作用域时也会按规则收尾。但先把本题的基本跳转看清，不要因为看见四条输出，就认为四条都一定执行。

```cpp
try {
    cout << "A ";
    divide(8,0);
    cout << "B ";
} catch (const std::exception& e) {
    cout << "C ";
}
cout << "D\n";
```

答案与原因：上一题输出 A C D。A 已经执行；零除数触发异常，B 被跳过；匹配 catch 显示 C；处理完成后再显示 D。本页增加一个带析构函数的局部对象。work 创建 Guard 以后抛出异常，在寻找外层处理者、离开这个函数作用域时，Guard 的析构函数会执行，先显示 cleanup，再由 catch 显示 caught。这种退出途中结束局部对象的过程称为栈展开，先理解现象即可。这也解释了为什么前面一直强调对象要自己负责收尾：把资源交给合适的对象管理，正常离开和异常离开都能沿着作用域规则处理。本课不展开复杂资源管理，只确认异常路线不是简单跳过所有清理动作。

核对或修正代码：
```cpp
struct Guard {
    ~Guard() { cout << "cleanup "; }
};
void work() {
    Guard g;
    throw std::runtime_error("failed");
}
```

```text
cleanup caught
```
