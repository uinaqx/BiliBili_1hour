## C++基础 · C++ Basics

### cpp-01-1 cout 与 cin

先从熟悉的成绩输入开始。cout 用来输出，两个小于号把后面的内容送到输出流。你可以连续接上文字、变量和换行，不必再为每一个整数写百分号格式。cin 用来输入，两个大于号把读到的值放进后面的变量。这里直接写 score，不像C语言的 scanf 那样再写取地址符号。我们输入八十，成功读取后显示 score 等于八十。输入也可能失败，所以代码检查这次提取是否成功。感叹号表示把成功状态反过来，失败时就提前结束。现在先把方向记清：cout 后面把内容送出去，cin 后面把值读进来。它们不是取代条件判断的特殊语法，而是标准库对象提供的输入输出操作。

```cpp
int score = 0;
if (!(cin >> score)) return 1;
cout << "score=" << score << '\n';
```

运行或编译检查结果：
```text
score=80
```

画面要点：本例输入：80；cout << 内容；cin >> 变量；读取后检查

### cpp-01-2 函数仍然先接收参数再返回

C++里面的普通函数，基本思路和C语言相同：接收参数，执行步骤，返回结果。这里的 add 接收两个整数，把和交回来，main 再把结果打印出来。函数名之前的 int 表示返回整数，括号里说明两个参数的类型。调用时给三和五，函数得到的就是这两份值，结果为八。定义函数不等于立即把函数体执行一遍，仍然是遇到调用才进入它。这一步看起来很熟悉，是为了让后面的变化有明确参照。普通整数参数复制传入的值；下一页出现的引用参数，则可以让函数直接使用原来的变量。先分清数据怎么进入函数，再学习类里的成员函数，就不会把所有新写法混成一件事。

```cpp
int add(int a, int b) {
    return a + b;
}
```

运行或编译检查结果：
```text
8
```

画面要点：参数说明交入什么；返回类型说明交回什么；先调用，再拿到结果

### cpp-01-3 引用是已有对象的别名

引用先用一个最短的例子理解。score 保存八十，接下来用 int 与符号声明 alias，并让它引用 score。可以把 alias 看成这同一个整数的另一个名字。给 alias 加五，修改的就是原来的 score，所以两个名字读出来都是八十五。这里没有新建一份独立的整数副本，也不是让两个数字以后自动同步。引用在建立时需要绑定目标，通常不能像指针变量那样改去指向另一份对象。看到等号也要注意：引用建立之后，给 alias 赋新值是在修改所引用的整数，不是在重新选择它的目标。先画一个格子，再给它标两个名字，这个图比画两个格子更准确。

```cpp
int score = 80;
int& alias = score;
alias += 5;
cout << score << " " << alias << '\n';
```

运行或编译检查结果：
```text
85 85
```

画面要点：一个整数，两个名字；引用初始化时绑定目标；通过别名修改原对象

### cpp-01-4 引用参数与 const 引用

把引用用在函数参数上，就能让函数访问调用者的原变量。这里 bonus 的参数写成 int 与符号，传入 score 后，函数内部加五，外面的 score 也变成八十五。如果只想读取一个对象，又希望避免复制，可以使用 const 引用。const 表示不能通过这条引用修改它。对于字符串或较大的类对象，这种参数形式经常能把“只读访问”的意图写清楚。注意，按引用访问不表示对象可以随意消失。被引用的那份数据在使用时必须仍然存在。今天的例子都让原变量留在 main 的作用域里，函数调用结束前目标有效。后面会再次看到 const，它不仅能修饰引用，还能声明一个成员函数承诺不通过自己修改普通成员。

```cpp
void bonus(int& score) {
    score += 5;
}
int read(const int& score) {
    return score;
}
```

运行或编译检查结果：
```text
85
```

画面要点：int&：可以修改原整数；const int&：通过此引用只读；使用时原对象必须仍然存在

### cpp-01-q 课堂练习：引用有没有改绑

a 是三，b 是八，引用 r 最初绑定 a。接下来写 r 等于 b，再把 b 改成九。最后打印 a 和 r，它们分别是多少？这里最容易误读的是 r 等于 b。这句话发生在引用已经建立之后，它是在给所引用的整数赋值，还是把引用重新绑定到 b？请先画出 r 最初对应哪一个格子，再执行后面两行。四秒之后，我们一起核对这两个名字是否还在访问同一份数据。

（四秒思考；随后核对答案）

```cpp
int a = 3, b = 8;
int& r = a;
r = b;
b = 9;
cout << a << " " << r << '\n';
```

运行或编译检查结果：
```text
8 8
```

画面要点：r 最初绑定 a；r = b 是赋值操作；随后只修改了 b

### cpp-01-a 答案：别名仍然对应 a

结果是八和八。r 建立时绑定 a，后面没有改绑。r 等于 b 的意思，是读取 b 当时的八，再通过 r 写进 a。因此 a 变成八，r 作为 a 的别名也读到八。接下来 b 改成九，修改的是另一个变量，并不会影响 a。这里的关系和普通数值复制、指针保存地址都有联系，但不要把引用当成一个随时可换目标的指针变量。遇到引用题时，先确认它建立时绑定谁，再逐行区分“修改被引用对象”和“修改其他对象”。这个习惯后面会帮助我们理解成员函数的 this，以及通过基类引用调用派生对象的行为。

```cpp
int a = 3, b = 8;
int& r = a;
r = b;
b = 9;
cout << a << " " << r << '\n';
```

运行或编译检查结果：
```text
8 8
```

画面要点：r 始终是 a 的别名；a 接收了 b 当时的 8；最后两项都读到 8

## 类与对象 · Classes and Objects

### cpp-02-1 把数据和操作放在同一个类里

现在把一份成绩和它允许进行的操作放在一起。class 后面是我们定义的类型名 Score，大括号里面声明成员变量和成员函数，最后用分号结束整个类的定义。value 下划线是保存成绩的成员变量，set 和 get 是成员函数。set 接收一个新分数，get 交回当前分数。名字后面的下划线只是本课用来区分成员的命名习惯，不是特殊运算符。private 和 public 表示访问权限。我们先把数据放进 private，让类外代码通过 public 的函数使用它。main 创建一个 Score 对象 s，调用 s 点 set 保存八十，再调用 s 点 get 得到八十。类说明这种记录怎样组成，对象则是按这份说明真正创建出来的一份记录。

```cpp
class Score {
private:
    int value_ = 0;
public:
    void set(int n) { value_ = n; }
    int get() const { return value_; }
};
```

运行或编译检查结果：
```text
80
```

画面要点：类描述数据与操作；对象是一份具体实例；class 定义结尾有分号

### cpp-02-2 不同对象有各自的状态

同一个类可以创建多个对象。屏幕上 a 和 b 都是 Score，但它们分别保存自己的成员变量。把 a 设置成八十，再把 b 设置成九十，读取时就得到八十和九十。成员函数的代码可以被不同对象使用，调用 a 点 set 时，它操作 a 的那份数据；调用 b 点 set 时，就操作 b 的那份数据。并不是一个类只对应一个公共的分数格子。这就是对象给我们的组织方式：同一套类型与操作规则，可以对应许多份独立状态。后面静态成员会介绍“一份数据由整个类共享”的另一种情况。现在先把普通成员和具体对象联系起来，看到一次成员函数调用，就问它是通过哪一个对象发出的。

```cpp
Score a, b;
a.set(80);
b.set(90);
cout << a.get() << " " << b.get() << '\n';
```

运行或编译检查结果：
```text
80 90
```

画面要点：a、b 各有一份 value_；函数通过哪个对象调用；普通成员不由全班对象共享

### cpp-02-3 public、private 与受控访问

如果类外代码直接访问 private 的 value 下划线，编译器会拒绝。private 不是把数据从程序里删除，而是限制哪些代码可以通过名字直接访问它。public 成员提供类的公开接口。我们可以让 set 检查输入范围，只接受零到一百的成绩，再把 getter 留给外面读取。这样，修改数据的规则集中在类里，调用者不用每次都重新记住全部检查步骤。画面故意从 main 直接访问私有成员，因此这是一道编译检查，没有运行结果。错误修正通常不是立刻把所有字段都改成 public，而是先想外面真正需要什么操作，再提供合适接口。把状态和维护状态的规则放在一起，就是封装最实际的起点。

```cpp
Score s;
s.value_ = 80;
```

运行或编译检查结果：
```text
编译失败：类外不能直接访问 private 成员。
```

画面要点：private：限制直接访问；public：面向外部的接口；错误示例不猜运行输出

### cpp-02-4 protected 为派生类留出访问范围

第三种权限是 protected。它和 private 一样，不允许普通类外代码直接访问；不同之处在于，派生类的成员在符合规则的情况下，可以访问继承来的 protected 成员。现在只看 Record 自己的成员函数，它可以同时读取 private 的 secret 和 protected 的 score，结果为八十七。到了继承章节，我们会让派生类使用 score，再看它为什么不能直接使用 secret。还要记住，class 中没有明确写权限标签的成员，默认是 private；struct 的默认成员权限则是 public。除了默认规则不同，C++的 struct 也可以有成员函数和构造函数。不要把“类只能有函数、结构体只能放数据”当成语言规则。选择权限时先看谁需要访问，先把数据保护好。

```cpp
class Record {
private:
    int secret_ = 7;
protected:
    int score_ = 80;
public:
    int read() const { return secret_ + score_; }
};
```

运行或编译检查结果：
```text
87
```

画面要点：protected：普通类外仍不可直接访问；派生类以后可以使用受保护部分；class 默认 private

### cpp-02-q 课堂练习：对象之间会自动同步吗

a 和 b 是两个独立的 Score 对象。我们先给 a 八十，给 b 九十，再把 a 改成八十五。最后读取 b，会得到九十还是八十五？请确认代码里有没有让这两个名字表示同一个对象。这里没有引用，也没有指针绑定，只是创建了两个相同类型的对象。四秒之后，我们把普通成员的归属再核对一遍，并为后面的静态成员留出对照。

（四秒思考；随后核对答案）

```cpp
Score a, b;
a.set(80);
b.set(90);
a.set(85);
cout << b.get() << '\n';
```

运行或编译检查结果：
```text
90
```

画面要点：类型相同不等于对象相同；这里没有引用别名；只修改了 a

### cpp-02-a 答案：b 保存自己的九十

b 仍然是九十。a 的 set 访问的是 a 的成员变量，b 的那份数据没有被修改。两个对象使用同一个类定义，并不意味着普通成员自动共享。如果把 b 声明成 a 的引用，关系就会不同；但当前代码没有这样写。我们始终根据程序实际建立的关系判断，而不是只看类型名和函数名相同。到这里，你已经可以区分类和对象：类是类型与接口的定义，对象则有自己的一份状态。下一章会让这份状态在对象刚建立时就准备好，避免总是先创建一个不完整状态，再靠后续调用补齐。负责这件事的，就是构造函数。

```cpp
Score a, b;
a.set(80);
b.set(90);
a.set(85);
cout << b.get() << '\n';
```

运行或编译检查结果：
```text
90
```

画面要点：b 未被修改，结果为 90；普通成员归具体对象所有；下一步：创建时就准备状态

## 构造与析构 · Construction and Destruction

### cpp-03-1 对象创建时准备初始状态

如果成绩对象一建立就应当有分数，可以用构造函数准备它。构造函数和类同名，没有返回类型，连 void 也不写。创建对象时，会调用与参数相匹配的构造函数。这里创建 Score 对象时传入八十，冒号后面的 value 下划线括号 n，把成员直接初始化成这个值。因此对象创建完成后，就能读取八十，不需要再补一次 set。把初始化和普通修改分开，会让对象状态更清楚。构造函数并不是 main 里随便调用的一段同名普通函数，而是建立对象过程中的一部分。你可以先把它看成新对象开始使用之前的准备步骤。下一页再让这个准备步骤有几种不同的入口。

```cpp
class Score {
    int value_;
public:
    Score(int n) : value_(n) {}
    int get() const { return value_; }
};
```

运行或编译检查结果：
```text
80
```

画面要点：构造函数与类同名；没有返回类型；创建对象时完成初始化

### cpp-03-2 构造函数可以有不同参数

一个类可以定义多个构造函数，只要参数列表能够区分。这里不传参数时，把成绩准备成零；传入一个整数时，就用这个整数作为初值。所以 Score a 调用无参数版本，Score b 括号八十调用整数版本。两个对象读取出来分别是零和八十。它们的准备方式不同，但创建完成后仍然都是 Score 对象。这就是构造函数重载。选择依据是传入参数的类型和数量，不是我们自己在对象建好之后再手工选择函数。另外，只要声明了带参数的构造函数，就不要假定编译器仍然会自动提供一个可用的无参数版本。如果你的类确实需要不传参数创建，就像屏幕这样明确写出合适的构造函数。

```cpp
class Score {
    int value_;
public:
    Score() : value_(0) {}
    Score(int n) : value_(n) {}
    int get() const { return value_; }
};
```

运行或编译检查结果：
```text
0 80
```

画面要点：不同参数，对应不同构造入口；无参数版本需要满足创建需求；不要把构造函数写上 void

### cpp-03-3 初始化列表先于函数体执行

构造函数参数后面的冒号，开始的是成员初始化列表。它负责直接建立成员的初始值，执行时间在构造函数体之前。屏幕用一个 const 整数成员表示及格线。const 成员必须在合适的初始化阶段得到值，不能先让它创建好，再在函数体里普通赋值。因此这里写成 limit 下划线括号 n，随后进入的空大括号没有额外工作。即使普通整数在构造函数体里赋值看起来也能工作，直接初始化仍然更能表达“对象一开始是什么”。当成员本身也是类对象时，初始化列表还决定调用它的哪个构造函数。稍后组合对象会专门展开这个过程。现在先记住两个阶段：先初始化成员，再执行构造函数体。

```cpp
class Limit {
    const int limit_;
public:
    Limit(int n) : limit_(n) {}
    int get() const { return limit_; }
};
```

运行或编译检查结果：
```text
60
```

画面要点：冒号后是初始化列表；先初始化成员，再执行函数体；const 成员在初始化时给值

### cpp-03-4 析构函数观察对象结束

析构函数在对象结束生命时做收尾，名字是波浪号加类名，也没有返回类型。本课只用一个打印例子观察它，不展开复杂资源管理。main 中进入一个小代码块，创建 Trace 对象，先显示 begin。代码块结束时，这个局部对象被销毁，析构函数显示 end。随后 main 继续显示 after，所以三段文字按这个顺序出现。普通局部对象不需要我们再手工调用一次析构函数。以后用标准库容器和资源管理类时，清理动作常会由它们的析构过程安排。今天先建立明确的时间线：构造负责开始，析构对应结束；对象离开作用域，会发生正常收尾，而不只是变量名字从屏幕上消失。

```cpp
class Trace {
public:
    Trace() { cout << "begin "; }
    ~Trace() { cout << "end "; }
};
```

运行或编译检查结果：
```text
begin end after
```

画面要点：~Trace 是析构函数；离开代码块时自动执行；本课只观察，不展开资源管理

### cpp-03-q 课堂练习：创建时传入什么

这个 Score 类只有一个需要整数参数的构造函数。现在 main 却写 Score s，没有交给它整数。它能不能自动把成绩设成零，然后顺利打印八十？请只根据类已经提供的入口判断。不要因为成员是 int，就猜系统一定会帮我们补一个满足需求的创建方式。四秒之后，我们会先解释编译结果，再给出一个明确交入初值的修正版。

（四秒思考；随后核对答案）

```cpp
Score s;
cout << s.get() << '\n';
```

运行或编译检查结果：
```text
编译失败：没有可用的无参数构造函数。
```

画面要点：类只提供 Score(int)；创建时没有传参数；先判断是否能构造对象

### cpp-03-a 答案：使用已有的整数构造入口

原程序不能编译，因为这个类没有可用的无参数构造函数。带参数版本并不同时意味着无参数版本也存在。修正版写 Score s 括号八十，明确把八十交给已有构造函数，成员就被初始化成八十，读取结果也就是八十。如果需求是允许默认成绩零，也可以像前一页那样另外定义无参数构造函数。建立对象和后面修改对象是不同阶段。先确定对象能否按这组参数建立，再讨论成员函数会返回什么。这个顺序在派生类构造、成员对象构造中同样适用：每一部分都需要一个实际可用的初始化方式。

```cpp
Score s(80);

```

## 封装与共享 · Encapsulation and Sharing

### cpp-04-1 this 指向当前对象

调用成员函数时，它需要知道正在操作哪一个对象。this 就是在普通非静态成员函数里，指向当前对象的指针。屏幕故意让参数和成员都叫 value。set 函数里的普通名字 value 优先表示参数，而 this 箭头 value 明确表示当前对象的成员。这样就把传进来的八十，写到 s 自己的成员里。调用 s 点 set 时，this 对应 s；如果换成另一个对象调用，就对应另一个对象。很多时候，成员名字不冲突，编译器允许省略 this，但概念上仍然是在访问当前对象。它不是一个所有对象共享的固定地址，而是这次成员调用所对应的对象位置。

```cpp
class Score {
    int value = 0;
public:
    void set(int value) { this->value = value; }
    int get() const { return value; }
};
```

运行或编译检查结果：
```text
80
```

画面要点：this：当前对象的指针；this->value 明确指向成员；同名参数与成员要区分

### cpp-04-2 const 成员函数表达只读操作

get 后面的 const，表示这个成员函数通过当前对象进行只读访问。它不能在函数体里普通地修改对象的非静态数据成员，也不能随意调用需要可修改对象的成员函数。因此，即使对象本身声明成 const，也可以调用 get 读取成绩。屏幕创建一份只读的八十分记录，输出就是八十。set 没有这个只读承诺，不能拿同一个 const 对象去调用它修改成绩。这能把“查询”和“修改”从接口上区分出来。const 成员函数不是承诺外界一切状态都不变，比如静态数据或指针所指的其他对象还需要分别判断。对于本课这个只保存整数的简单类，先抓住它保护当前对象普通成员的作用即可。

```cpp
const Score s(80);
cout << s.get() << '\n';
```

运行或编译检查结果：
```text
80
```

画面要点：查询函数可以标为 const；const 对象只能调用合适的只读接口；非 const set 不适用于此对象

### cpp-04-3 静态数据成员由类共享

普通成员属于每个对象，静态数据成员则不在每个对象里各放一份。本例的 count 下划线由 Counter 这个类共享，用来记录这些构造调用的累计次数。构造函数每执行一次，就把同一个计数加一。我们先创建 a，再创建 b，最后读取共享计数，得到二。它不是 a 保存一、b 也各保存一之后再自动求和，而是两次都访问同一份计数。在这里采用的C++十四写法中，类里面声明 static int count，类外再写一次带类名限定的定义并给零作为初值。不要把类外定义写成又声明了一个无关的普通变量。两个冒号把这个名字准确归到 Counter 类中。

```cpp
class Counter {
    static int count_;
public:
    Counter() { ++count_; }
    static int created() { return count_; }
};
int Counter::count_ = 0;
```

运行或编译检查结果：
```text
2
```

画面要点：count_ 是类共享的一份数据；每次本例构造调用都加 1；C++14 中在类外给出定义

### cpp-04-4 静态成员函数没有当前对象

created 前面也写着 static，它是静态成员函数。调用时可以用类名加两个冒号，不必先指定某一个对象。这种函数没有 this 指针，所以不能直接访问某个对象的普通成员。它可以直接访问类的静态成员，例如刚才那份共享计数。如果要处理普通成员，就需要另外得到一个具体对象，再通过那个对象访问。屏幕先读取零，创建一个对象后再读取一，说明计数在整个类的使用过程中被共享。静态函数并不是自动拥有所有对象的数据，它只是一个归属于类、却不依赖隐含当前对象的函数。把有没有 this 这个问题弄清楚，普通成员函数和静态成员函数的边界就很容易判断。

```cpp
cout << Counter::created() << " ";
Counter a;
cout << Counter::created() << '\n';
```

运行或编译检查结果：
```text
0 1
```

画面要点：用 Counter::created() 调用；静态成员函数没有 this；普通成员仍需要具体对象

### cpp-04-5 友元函数获得指定访问许可

有时一个普通函数需要参与某个类的紧密协作，但我们不想把数据向所有外部代码公开。这时可以在类中声明一个指定函数为 friend，也就是友元。inspect 仍然是普通函数，不是 Score 的成员函数。它通过参数 s 得到要查看的对象，而不是使用成员函数隐含的 this。因为 Score 明确授予它友元权限，它可以直接读取私有的 value。这个许可只给指定的友元，并不会让私有成员变成 public。调用时也不是 s 点 inspect，而是像普通函数一样写 inspect 括号 s。友元有明确用途，但不应该为了绕过所有接口限制而到处添加。先判断这种协作是否确实需要直接访问，再给出范围清楚的许可。

```cpp
class Score {
    int value_;
public:
    Score(int n) : value_(n) {}
    friend int inspect(const Score& s);
};
int inspect(const Score& s) { return s.value_; }
```

运行或编译检查结果：
```text
80
```

画面要点：friend 授权给指定函数；友元函数仍是普通函数；通过参数访问某个对象

### cpp-04-6 友元类把许可给一组成员函数

如果协作需要由一个类的成员完成，也可以声明友元类。Score 把 Auditor 声明为友元后，Auditor 的成员函数就可以访问 Score 的私有成员。屏幕上检查员对象通过 read 接收一份成绩记录，读取到八十。Score 里面没有把 value 改成 public，其他普通外部代码也没有因此得到相同权限。友元关系要由被访问的那个类主动声明，而且不是自动双向的。Score 信任 Auditor，不表示 Score 同时就能访问 Auditor 的私有数据。友元也不会自动传给友元的朋友或派生类。把它理解为有明确授予方向的访问许可，比理解成“两个类从此没有边界”更准确。

```cpp
class Score {
    int value_ = 80;
    friend class Auditor;
};
class Auditor {
public:
    int read(const Score& s) const { return s.value_; }
};
```

运行或编译检查结果：
```text
80
```

画面要点：许可由 Score 主动授予；Auditor 成员可以访问；不自动双向、传递或继承

### cpp-04-q 课堂练习：只读对象能否修改

Score 的 get 是 const 成员函数，set 是普通修改函数。现在对象 s 自己也声明成 const，随后调用 s 点 set，把分数改成九十。它能编译吗？请先看对象提供的使用条件，再看所调用的函数是否承诺只读。不要因为 set 本来是 public，就认为任何对象状态下都可以调用。四秒之后，我们分别说明“允许从外部看见这个名字”和“允许在 const 对象上调用”这两层检查。

（四秒思考；随后核对答案）

```cpp
const Score s(80);
s.set(90);
```

运行或编译检查结果：
```text
编译失败：不能用 const 对象调用此非 const 成员函数。
```

画面要点：public 不等于总能调用；对象是 const；set 会修改普通成员

### cpp-04-a 答案：const 约束也必须满足

这段不能编译。public 说明外部代码有权访问这个接口，而 const 对象只能调用适用于只读对象的成员函数。set 没有 const 承诺，不能拿 s 这样调用。如果需求只读取，使用 get 就能得到八十。如果确实要修改，就应当从一开始使用可修改对象，再通过受控接口修改，而不是随意去掉 const 约束。到这里，封装不仅是把字段藏起来，还包括准确表达接口的使用条件。this 说明当前对象是谁，const 说明这次访问能否修改，static 表达类共享数据，friend 则授予特定协作者访问许可。把这几种机制分别放回它解决的问题，就不会只剩下一张关键字表。

```cpp
const Score s(80);
cout << s.get() << '\n';
```

运行或编译检查结果：
```text
80
```

画面要点：原题违反 const 调用约束；只读对象使用 const 查询接口；访问权限与只读约束要一起检查

## 对象组合 · Object Composition

### cpp-05-1 一个对象里面可以有另一个对象

成员变量不必只是整数，也可以是我们定义的其他类对象。Student 里面放一个 Name 对象，就把“学生具有姓名”直接写进了组成关系。创建 Student 时，要先创建它的成员 name。Name 需要一个字符串参数，所以 Student 的初始化列表把 Ana 交给它。等 name 准备好，Student 才继续完成自己的构造过程。这里表达的是“学生有一个姓名部分”，不是“学生是一种姓名”。前一种关系用组合很自然，后一种才可能涉及继承。先根据含义选择数据关系，不要因为学会继承就把所有代码都改成继承。成员对象有自己的构造要求，包含它的对象需要把这些要求安排好。

```cpp
class Student {
    Name name_;
public:
    Student() : name_("Ana") {}
    void show() const { cout << name_.get() << '\n'; }
};
```

运行或编译检查结果：
```text
Ana
```

画面要点：Student 包含一个 Name 成员；先构造成员，再执行外层函数体；“有一个”适合考虑组合

### cpp-05-2 成员构造顺序看声明顺序

有多个成员对象时，先构造谁？关键依据是它们在类里面的声明顺序，不是初始化列表的书写先后。屏幕先声明 first，再声明 second。即使初始化列表把 second 写在前面，实际仍然先构造 A，再构造 B，最后进入 Box 构造函数体显示 Box。离开作用域时，成员再按相反顺序结束。这种不一致的写法还会得到编译器的顺序警告。实际写代码时，应当把初始化列表也写成声明的同样顺序，方便阅读。本页故意交换它们，只是为了让你看见规则：声明顺序决定成员对象的实际初始化顺序，不能通过在冒号后面重新排列来改变它。

```cpp
class Box {
    Part first_;
    Part second_;
public:
    Box() : second_('B'), first_('A') { cout << "Box "; }
};
```

运行或编译检查结果：
```text
A B Box ~B ~A
```

画面要点：实际顺序由成员声明决定；本例会给出初始化顺序警告；实践中让列表与声明保持一致

### cpp-05-3 先建内部，结束时反过来

把外层 Box 的析构函数也加上，就能看见完整顺序。创建时，先构造成员 A、成员 B，再执行 Box 构造函数体。销毁时，先执行 Box 析构函数体，再销毁成员 B、成员 A。注意析构函数体开始执行时，成员对象还没有被逐个销毁，所以顺序不是先把成员都清掉，再进入外层析构函数体。把组合对象想成由内到外准备、再由外到内收尾，就比较容易记住。这里没有涉及动态内存，全部对象都通过正常作用域结束。我们用打印观察先后关系，但真正管理资源时，成员对象自己的收尾动作也会沿着这个结构自动发生。

```cpp
class Box {
    Part first_;
    Part second_;
public:
    Box() : first_('A'), second_('B') { cout << "Box "; }
    ~Box() { cout << "~Box "; }
};
```

运行或编译检查结果：
```text
A B Box ~Box ~B ~A
```

画面要点：构造：A、B、Box 函数体；析构：Box 函数体、B、A；顺序来自对象的组成关系

### cpp-05-q 课堂练习：初始化列表能改顺序吗

Box 先声明 first，再声明 second，但初始化列表把 second 写在前面。创建时首先显示 A，还是首先显示 B？请先看类内成员的声明，再看各个成员接收的参数。初始化列表里的参数会交给对应成员，但书写顺序本身能不能改变它们的实际建立次序？四秒之后，我们把创建和销毁都用正确的顺序列出来，再把初始化列表也整理成容易阅读的版本。

（四秒思考；随后核对答案）

```cpp
class Box {
    Part first_;
    Part second_;
public:
    Box() : second_('B'), first_('A') { cout << "Box "; }
};
```

运行或编译检查结果：
```text
A B Box ~B ~A
```

画面要点：先声明 first_；first_ 的参数是 A；区分参数归属与执行顺序

### cpp-05-a 答案：first 仍然先创建

先显示 A。因为 first 在类里面先声明，它先被构造；然后才是 second 的 B，再进入 Box 函数体。修正版把初始化列表也按 first、second 排好，只改善代码的表达，不改变原本的实际构造顺序。这个版本没有专门的 Box 析构输出，所以结束时只看到成员 B 和 A 依次收尾。这道题以后也能帮助你判断派生对象的构造：不要只看某一行列表怎么排，而要先确定语言对每一种对象部分规定了什么先后。先识别基类和成员，再看传入参数，最后才看构造函数体。

```cpp
class Box {
    Part first_;
    Part second_;
public:

```

运行或编译检查结果：
```text

```

画面要点：A → B → Box；结束时 B → A；列表按声明顺序写清楚

## 继承 · Inheritance

### cpp-06-1 公有继承表达一种类型关系

现在考虑“学生也是一个人”。Person 保存姓名，Student 在人的基础上增加成绩，这就可以用公有继承表达。冒号后面写 public Person，表示 Student 公有继承 Person。Student 对象里面包含一个 Person 基类部分，除此之外再有自己的成绩成员。创建学生以后，可以调用从 Person 得到的公开 show 函数，也可以调用 Student 自己的 score 函数。不要把继承理解成简单复制几行代码。它还建立了类型之间的关系，稍后我们可以把学生交给接受 Person 引用的函数。如果只是“里面有一份资料”，用上一章的组合往往更直接；如果确实是“属于这一种类型”，才进一步考虑公有继承。

```cpp
class Student : public Person {
    int score_;
public:
    Student(string name, int score)
        : Person(name), score_(score) {}
    int score() const { return score_; }
};
```

运行或编译检查结果：
```text
Ana
80
```

画面要点：Student 是一种 Person；对象包含基类部分与新增成员；公有接口可以继续使用

### cpp-06-2 继承不会开放基类私有成员

继承后，基类的 private 成员仍然不能在派生类函数里直接访问。姓名虽然存在于学生对象的基类部分，但 Student 不能直接拿 name 下划线这个私有成员来使用。public、protected、private 三种继承方式，主要改变继承得到的公开成员和受保护成员在派生类中的访问级别。公有继承保持它们原来的级别；保护继承把两者都变为 protected；私有继承把两者都变为 private。基类私有成员不会因此变成可以直接访问。初学阶段先把公有继承用清楚。还有一个默认规则：class 后面如果省略继承方式，默认是 private；struct 则默认 public。为了让类型关系一眼看明白，本课都明确写出 public。

```cpp
class Student : public Person {
public:
    Student() : Person("Ana") {}
    void test() { cout << name_; }
};
```

运行或编译检查结果：
```text
编译失败：name_ 是 Person 的私有成员
```

画面要点：public 继承：公开仍公开、保护仍保护；基类 private 不能被派生类直接访问；class 默认私有继承；建议明确写出

### cpp-06-3 先准备基类，再完成派生类

派生类构造函数需要先把基类部分准备好。前面 Student 的初始化列表调用 Person，传入姓名，然后准备成绩，最后才进入 Student 构造函数体。这一页为了观察先后，只保留两个带输出的类。创建时先显示 Person，再显示 Student。离开作用域时先执行 Student 的析构函数体，再结束 Person 基类部分，所以看到相反的次序。如果还有成员对象，顺序就是先构造直接基类，再按声明顺序构造成员，最后执行派生类自己的构造函数体。这里全部是正常作用域内的对象，没有通过基类指针删除对象。先把这个建立和收尾的顺序理解清楚，就能读懂常见的构造题。

```cpp
class Person {
public:
    Person() { cout << "Person "; }
    ~Person() { cout << "~Person "; }
};
class Student : public Person {
public:
    Student() { cout << "Student "; }
    ~Student() { cout << "~Student "; }
};
```

运行或编译检查结果：
```text
Person Student ~Student ~Person
```

画面要点：先基类，再成员，最后派生类函数体；销毁方向相反；初始化列表负责传入基类参数

### cpp-06-4 基类引用与独立的基类对象

有一个 Student 对象时，可以让 Person 引用指向它，因为这里是公开而且没有歧义的继承关系。这个引用让我们通过人的接口使用原来的学生，没有新建另一个学生，也没有把原对象改成 Person。下一行 Person copy 等于 s，却创建了一个独立的 Person 对象。它只复制基类部分，学生新增的成绩没有进入 copy，这种现象通常叫对象切片。原来的 s 仍然完整存在。反过来，把普通 Person 自动当成 Student 则不成立，因为普通人未必有成绩等学生部分。读题时先看接收位置是引用、指针，还是一个按值保存的新对象。它们看起来都能接收 s，但代表的对象关系并不相同。

```cpp
Student s("Ana",80);
Person& ref = s;
ref.show();
Person copy = s;
copy.show();
cout << s.score() << '\n';
```

运行或编译检查结果：
```text
Ana
Ana
80
```

画面要点：基类引用：使用原来的派生对象；基类值对象：只保留基类部分；派生到基类可以；反向不自动成立

### cpp-06-q 课堂练习：基类引用会复制吗

看这两行初始化。ref 是基类引用，copy 是一个独立的基类对象，它们都从同一个学生 s 得到。哪一个仍然引用原来的学生？哪一个只保存自己的 Person 部分？这里先不讨论虚函数，只判断有没有创建另一个对象。你可以数一数名字旁边有没有引用符号，再想一想引用在本课开头的含义。四秒以后，我们分别给这两个位置贴上“使用原对象”和“新建基类对象”的说明。继承的赋值兼容不等于所有对象都可以随意互换，这个区别会直接影响下一章多态的结果。

（四秒思考；随后核对答案）

```cpp
Student s("Ana",80);
Person& ref = s;
Person copy = s;
ref.show();
copy.show();
```

运行或编译检查结果：
```text
Ana
Ana
```

画面要点：ref 的类型中有 &；copy 是单独的 Person 对象；先判断对象关系，再判断输出

### cpp-06-a 答案：引用保留原对象关系

ref 使用的仍然是 s，所以没有创建独立的 Person 对象。copy 则是新建的 Person，只接收 s 中的基类部分。两次 show 都显示 Ana，不代表这两种初始化完全一样。因为目前 show 只读取姓名，而这个姓名在两种情况下都存在，所以输出恰好相同。不能只凭一行相同输出就认为两个表达式语义相同。把这道题和最开始的引用联系起来：引用提供已有对象的另一个使用入口，按值初始化通常建立一个独立对象。继承又让这个独立对象可能只留下基类部分。等我们加入虚函数，保留实际对象的基类引用就有了更明显的用途。

```cpp
Student s("Ana",80);
Person& ref = s;   // 使用原对象
Person copy = s;   // 新的基类对象
ref.show();
copy.show();
```

运行或编译检查结果：
```text
Ana
Ana
```

画面要点：相同输出不代表相同对象关系；ref → s；copy 只保存 Person 部分

## 多继承 · Multiple Inheritance

### cpp-07-1 一个派生类可以有多个直接基类

多继承就是一个类直接继承多个基类。这里 Named 提供姓名显示，Graded 提供成绩读取，Student 同时公有继承两者，所以可以使用这两组公开功能。先把概念看懂即可，不需要马上在自己的程序里大量使用它。多个基类如果提供同名成员，调用时可能产生歧义，需要明确来自哪一个基类；更复杂的重复继承关系还会增加设计难度。本课不展开这些复杂结构。你只要认识逗号分隔的基类列表，并且知道每一个基类都有自己的对象部分和构造过程。实际设计时，如果只是把姓名资料和成绩资料装在一起，组合也可能更加清楚；多继承应当服务于明确的类型或接口关系。

```cpp
class Named {
public:
    void name() const { cout << "Ana "; }
};
class Graded {
public:
    int score() const { return 80; }
};
class Student : public Named, public Graded {};
```

运行或编译检查结果：
```text
Ana 80
```

画面要点：基类列表用逗号分隔；可以获得多组基类接口；本课只掌握基本含义与顺序

### cpp-07-2 直接基类按继承列表顺序构造

多个直接基类先构造谁，看类定义后的基类列表。本页先写 public A，再写 public B，所以先构造 A，再构造 B，最后执行 C 的构造函数体。即使初始化列表先写 B 再写 A，也不会改变这个顺序。和成员对象一样，编译器会提醒这种书写顺序不一致。正常程序应该把初始化列表也整理成 A、B，让阅读顺序符合实际顺序。现在把两条规则并排记住：多个直接基类看基类列表顺序，多个成员看类内声明顺序。它们都先于最外层构造函数体。这里讨论的是普通的直接基类，没有引入虚继承；不要把尚未学习的特殊结构混入这道基础顺序题。

```cpp
class A { public: A() { cout << "A "; } };
class B { public: B() { cout << "B "; } };
class C : public A, public B {
public:
    C() : B(), A() { cout << "C\n"; }
};
```

运行或编译检查结果：
```text
A B C
```

画面要点：基类列表：A 在 B 前；实际顺序：A → B → C 函数体；列表书写应与实际顺序一致

### cpp-07-q 课堂练习：先显示哪一个字母

C 的基类列表写 A、B，初始化列表写 B、A。创建一个 C，输出是 A B C，还是 B A C？先找到决定规则的那一处列表，而不是跟着构造函数里最后看见的顺序猜答案。参数可以在初始化列表中指定，但实际执行先后还有语言规定。请用四秒选出答案，再补一句理由：你依据的是基类列表，还是初始化列表。能说出依据，比只记住这一题的字母顺序更有用。

（四秒思考；随后核对答案）

```cpp
class A { public: A() { cout << "A "; } };
class B { public: B() { cout << "B "; } };
class C : public A, public B {
public:
    C() : B(), A() { cout << "C\n"; }
};
```

运行或编译检查结果：
```text
A B C
```

画面要点：class C : public A, public B；先找决定顺序的列表；不按初始化列表重新排序

### cpp-07-a 答案：按 A、B 的基类列表执行

答案是 A B C。A 在基类列表中先出现，先完成 A，再完成 B，最后才进入 C 的构造函数体。画面已经把初始化列表改成 A、B。输出没有变化，编译器的顺序警告却消失了，因为文字顺序现在符合真实执行顺序。多继承这一节到这里就够了。以后读到类似代码，先数直接基类，再看基类列表的先后；读到组合对象，则看成员声明的先后。把两种列表的作用分清，就不必靠猜测理解构造输出。

```cpp
class A { public: A() { cout << "A "; } };
class B { public: B() { cout << "B "; } };
class C : public A, public B {
public:
    C() : A(), B() { cout << "C\n"; }
};
```

运行或编译检查结果：
```text
A B C
```

画面要点：A → B → C；修改列表提高可读性；普通直接基类按继承列表构造

## 重载 · Overloading

### cpp-08-1 同一个函数名接收不同参数

函数重载允许多个函数使用同一个名字，只要参数列表能够区分。这里一个 twice 接收整数，一个接收 double。调用 twice 括号三，选择整数版本；传入三点五，选择 double 版本。编译器在编译时根据参数寻找适合的版本，不是运行以后随意挑选。你可以把重载理解成：同一个动作名字，为几种不同输入分别准备做法。实际代码还可能涉及类型转换和更复杂的候选比较。初学阶段先让调用清楚：参数类型尽量明确，不要把大量相近类型和默认参数混在一起制造歧义。这里显示六和七，都是乘二的结果，但函数接收到的数据种类不同。

```cpp
int twice(int x) { return x * 2; }
double twice(double x) { return x * 2; }
```

运行或编译检查结果：
```text
6
7
```

画面要点：函数名相同，参数列表有区别；根据调用参数选择版本；发生在编译阶段

### cpp-08-2 只改变返回类型不能重载

下面两个 read 都没有参数，一个返回 int，一个返回 double。它们不能仅凭返回类型组成重载，因为调用 read 括号时，参数并没有提供任何区别。不要以为左边变量是 double，编译器就会因此选出返回 double 的 read。对于这种普通函数重载，必须先从参数列表等合法差异区分函数，不能只让返回类型承担区别。参数个数不同、参数类型不同，都可以形成常见的重载。只有参数名字变了也不算区别，因为名字只是函数内部使用的称呼。本页会在编译阶段失败，没有运行结果；修正办法是改名，或者重新设计参数，使调用本身能清楚表达要做什么。

```cpp
int read() { return 1; }
double read() { return 1.5; }
```

运行或编译检查结果：
```text
编译失败：仅返回类型不同，不能重载
```

画面要点：返回类型不能单独区分重载；参数名字不同也不够；调用应当清楚表达意图

### cpp-08-3 让加号表达两个点相加

运算符重载把已有运算符与自定义类型的操作联系起来。Point 保存两个坐标，我们希望两个点相加时，把横坐标相加、纵坐标相加。operator 加号就是这个操作的函数名。左边的对象通过成员函数的当前对象提供坐标，右边的对象通过 other 引用传进来。函数返回一个新的 Point，不改变原来的两个点。参数使用 const 引用，表示读取右边对象；成员函数末尾再写 const，表示读取左边对象的普通成员。返回大括号里的两个值，会建立结果点。调用时可以写 a 加 b，但你仍然应该知道它背后执行了一个函数。先理解数据如何进入、结果如何返回，再看简洁写法。

```cpp
struct Point {
    int x;
    int y;
    Point operator+(const Point& other) const {
        return {x + other.x, y + other.y};
    }
};
```

运行或编译检查结果：
```text
4 6
```

画面要点：左边对象提供当前 x、y；other 提供右边坐标；返回新 Point，原对象不变

### cpp-08-4 重载沿用原有语法规则

运算符重载不是创造任意新符号。它不能把加号变成比乘号优先，也不能改变一个运算符需要几个操作数。我们只是在已有语法允许的位置，为自定义类型提供操作。本页把上一页的调用展开。a 点 operator 加号，传入 b，和 a 加 b 使用同一个成员运算函数。两种形式都会得到四和六。设计重载时，让含义接近日常直觉非常重要。点加点返回新点容易理解；如果加号暗中修改右边对象，读者就很容易误判。本课只演示加法，不追求一次写全所有运算符。掌握一个清楚的例子，比记一张符号列表更能帮助你阅读真实代码。

```cpp
Point a{1,2};
Point b{3,4};
Point c = a.operator+(b);
cout << c.x << " " << c.y << '\n';
cout << a.x << " " << a.y << '\n';
```

运行或编译检查结果：
```text
4 6
1 2
```

画面要点：a + b 调用对应的 operator+；优先级、操作数个数保持原规则；操作含义应当直观

### cpp-08-q 课堂练习：相加以后原对象变了吗

a 的坐标是一和二，b 是三和四。执行 c 等于 a 加 b，再分别输出 c 和 a，会出现什么结果？请回到运算符函数内部，找一找有没有给当前对象的 x 或 y 赋新值。只出现加法表达式和返回新对象，是否等于把左边对象原地改掉？四秒以后，我们沿着返回值走一次。不要只看加号长什么样，而要根据函数实际执行的动作判断状态。不同程序可以为运算符写不同实现，这一道题的答案来自画面上明确给出的实现。

（四秒思考；随后核对答案）

```cpp
Point a{1,2}, b{3,4};
Point c = a + b;
cout << c.x << " " << c.y << '\n';
cout << a.x << " " << a.y << '\n';
```

运行或编译检查结果：
```text
4 6
1 2
```

画面要点：看 operator+ 的实现；返回新对象不等于原地修改；分别跟踪 c 与 a

### cpp-08-a 答案：结果放进新的点

c 是四和六，a 仍然是一和二。这个 operator 加号只读取两个对象，然后返回包含结果的新对象。如果写 a 等于 a 加 b，情况才不同：先计算新点，再把结果赋给 a。导致 a 改变的是后面的赋值，不是这个加法函数在内部修改了 a。我们现在就多执行这一行。第二次输出 a 时，它才显示四和六。把计算、返回、赋值分开理解，能避免把所有符号都混成一个动作。函数重载和运算符重载最后都要回到同一个问题：选中了哪个函数，它读了哪些数据，是否修改对象，返回了什么。

```cpp
Point a{1,2}, b{3,4};
Point c = a + b;
cout << c.x << " " << c.y << '\n';
cout << a.x << " " << a.y << '\n';
a = a + b;
cout << a.x << " " << a.y << '\n';
```

运行或编译检查结果：
```text
4 6
1 2
4 6
```

画面要点：c：4、6；原 a：1、2；a = a + b 才把结果保存回 a；计算与赋值是两个步骤

## 多态 · Polymorphism

### cpp-09-1 同名隐藏不要求参数相同

先处理一个容易混淆的问题。Base 有一个接收整数的 show，Derived 又定义一个没有参数的 show。用 Derived 对象直接调用 show 括号七，会编译失败。原因是派生类里面出现了同名函数，直接从这个派生类名字查找时，基类的同名函数被隐藏了。即使参数不同，也可能发生隐藏，所以它不是我们上一章那种自动合并全部候选的情况。这还不是虚函数覆盖。基类 show 没有 virtual，而且两个函数参数不同。先把“查找时看不见基类同名函数”和“通过基类接口调用派生实现”分开。前一种叫隐藏；后一种需要虚函数等条件，我们马上逐步建立。

```cpp
class Base {
public:
    void show(int n) const { cout << n << '\n'; }
};
class Derived : public Base {
public:
    void show() const { cout << "Derived\n"; }
};
```

运行或编译检查结果：
```text
编译失败：Derived 的 show 隐藏了基类同名函数
```

画面要点：同名就可能发生隐藏；参数不同也不自动合并候选；隐藏与虚函数覆盖是不同概念

### cpp-09-2 把基类的同名函数引入作用域

如果希望 Derived 同时提供这两种 show，可以在它的公开部分写 using Base 双冒号 show。这一行把基类的同名函数引入当前作用域，参与调用选择。现在 d 点 show 没参数，使用派生类版本；带一个整数七，就能选择基类接收整数的版本。我们没有修改基类函数体，只是明确了派生类范围里允许使用哪些同名函数。也可以用明确的基类限定来调用指定函数，但这里先掌握 using 这一种常见整理方式。它帮助你理解隐藏和重载之间的关系：先找到可以考虑的名字，再根据参数选函数。它并不自动让函数变成 virtual，也不等于实现了运行时多态。

```cpp
class Base {
public:
    void show(int n) const { cout << n << '\n'; }
};
class Derived : public Base {
public:
    using Base::show;
    void show() const { cout << "Derived\n"; }
};
```

运行或编译检查结果：
```text
Derived
7
```

画面要点：using Base::show 引入基类函数；show() 与 show(int) 均可调用；这一步仍然不是动态绑定

### cpp-09-3 普通函数看使用入口的类型

现在让两个类都有完全同样参数的 speak，但暂时不写 virtual。直接用派生类对象 d 调用，显示 Derived。再让一个 Base 引用指向 d，通过这个引用调用，就显示 Base。这里引用没有复制对象，原对象仍然是 Derived。输出不同，是因为 speak 还只是普通成员函数，通过 Base 类型的入口调用时，选的是 Base 的这个函数。所以“基类引用指向派生对象”本身还不足以产生我们需要的多态。必须在基类接口中明确说明：这个函数允许根据实际对象选择派生实现。完成这项说明的关键字，就是下一页要加入的 virtual。先看清未使用它时的行为，才容易理解它改变了什么。

```cpp
class Base {
public:
    void speak() const { cout << "Base\n"; }
};
class Derived : public Base {
public:
    void speak() const { cout << "Derived\n"; }
};
```

运行或编译检查结果：
```text
Derived
Base
```

画面要点：d.speak()：Derived；Base 引用调用普通函数：Base；原对象类型并没有被引用改变

### cpp-09-4 虚函数按实际对象选择实现

给基类 speak 加上 virtual，再在派生类匹配的函数后写 override。现在同样通过 Base 引用调用，会显示 Derived。这就是这里要学习的动态绑定：调用入口是基类引用，实际关联的是派生对象，虚函数调用因此选择派生类提供的覆盖版本。引用仍然使用原对象，没有切出一个新 Base。override 的作用是让编译器检查我们确实覆盖了基类虚函数，写错参数或末尾的 const 时可以及时发现。基类还写了一个默认的虚析构函数，这是多态基类常见的接口写法，方便以后通过基类指针管理对象时正确收尾。本页不用手动申请或释放内存，重点只看 speak 的调用变化。

```cpp
class Base {
public:
    virtual void speak() const { cout << "Base\n"; }
    virtual ~Base() = default;
};
class Derived : public Base {
public:
    void speak() const override { cout << "Derived\n"; }
};
```

运行或编译检查结果：
```text
Derived
```

画面要点：基类 virtual 允许动态选择；派生类 override 要求编译器检查；Base 引用 → 实际 Derived → Derived::speak

### cpp-09-5 覆盖时 const 也必须匹配

这个版本故意漏掉派生类 speak 末尾的 const，却保留 override。编译器会指出它没有覆盖任何基类虚函数。基类承诺的是“可以在 const 对象上调用的 speak”，派生类只写一个没有 const 的函数，二者并不匹配。参数列表需要对应，成员函数的这些限定也不能随意省略。修正很直接：把 const 补回来。不要为了消除错误而直接删掉 override，因为那可能只是把本来希望覆盖的函数悄悄写成另一个函数。初学阶段把 override 当作编译器帮忙核对的标记：既然我认为这是覆盖，就请它检查。错误在编译阶段出现，比运行时才发现选错行为更容易定位。

```cpp
class Base {
public:
    virtual void speak() const { cout << "Base\n"; }
    virtual ~Base() = default;
};
class Derived : public Base {
public:
    void speak() override { cout << "Derived\n"; }
};
```

运行或编译检查结果：
```text
编译失败：缺少 const，override 检查不通过
```

画面要点：覆盖要匹配参数与成员函数限定；漏掉 const 会改变函数；保留 override，让错误尽早暴露

### cpp-09-6 抽象类规定共同接口

如果基类只想规定“每一种图形都应能计算面积”，却没有一个适用于所有图形的面积公式，可以把 area 声明为纯虚函数，在声明末尾写等于零。包含尚未实现的纯虚函数的类是抽象类，不能直接创建 Shape 对象。Square 给出了符合要求的 area 实现，边长乘边长，所以可以创建具体的正方形。函数可以接收 Shape 引用，调用共同的 area 接口，而实际对象是边长为四的 Square 时，得到十六。先用一句朴素的话理解：基类规定能做什么，具体类给出怎么做。等于零不是面积返回零，也不是在这里执行赋值，它是声明纯虚函数的专门语法。

```cpp
class Shape {
public:
    virtual int area() const = 0;
    virtual ~Shape() = default;
};
class Square : public Shape {
    int side_;
public:
    Square(int side) : side_(side) {}
    int area() const override { return side_ * side_; }
};
```

运行或编译检查结果：
```text
16
```

画面要点：纯虚函数：virtual ... = 0；抽象类不能直接实例化；具体类实现接口，再创建对象

### cpp-09-q 课堂练习：引用与按值保存的区别

基类 speak 已经是 virtual，派生类已经正确 override。现在先让 Base 引用指向 d，再创建一个 Base copy 等于 d，分别调用 speak，会显示什么？这一次不能只记住“有 virtual 就选派生类”。还要检查调用时真正存在的对象。ref 仍然关联 d，但 copy 是不是一个独立的基类对象？请用四秒把两次调用分开判断。我们在继承一章留下的“引用保留原对象，基类值对象只保存基类部分”，现在正好可以解释答案。

（四秒思考；随后核对答案）

```cpp
Derived d;
Base& ref = d;
Base copy = d;
ref.speak();
copy.speak();
```

运行或编译检查结果：
```text
Derived
Base
```

画面要点：先判断 ref 与 copy 关联的实际对象；virtual 根据实际对象选择实现；按值保存可能发生对象切片

### cpp-09-a 答案：引用调用派生版本，副本调用基类版本

先显示 Derived，再显示 Base。ref 关联的是原来的派生对象，所以虚函数选择 Derived 的覆盖版本。copy 本身就是一个 Base 对象，学生或派生部分没有被保存进去，调用自然选择 Base。动态绑定不会把一个真实的 Base 对象凭空还原成 Derived。它根据调用当时实际对象的情况选择实现，而不是追溯这个对象最早从谁复制而来。把多态题分成三步就不容易乱：首先判断基类函数是不是 virtual，然后判断派生类是否正确覆盖，最后判断调用入口背后到底是哪一个对象。引用、指针和按值对象的区别，要放在这最后一步一起看。

```cpp
Derived d;
Base& ref = d;
Base copy = d;
ref.speak();   // 原对象是 Derived
copy.speak();  // copy 自己是 Base
```

运行或编译检查结果：
```text
Derived
Base
```

画面要点：检查 virtual；检查 override 是否匹配；检查实际对象，留意切片

## 异常处理 · Exception Handling

### cpp-10-1 无法完成时把问题交给调用者

最后学习异常处理。计算函数接收到零作为除数时，没有一个正常的除法结果。这里不冒险继续计算，而是用 throw 抛出一个异常对象，说明参数不合适。抛出以后，当前函数不会继续执行后面的 return。调用者可以在合适的位置接住这个问题，再决定显示提示、重新输入，还是结束当前操作。这里选择标准库的 invalid argument，意思是传入的参数不符合要求。它需要对应的标准头文件。异常不是正常结果的另一种数字，也不是每一个普通分支都应该使用的手段。先把它理解成：当前步骤不能按约定完成，需要离开正常执行路线，把失败信息交给负责处理的位置。

```cpp
double divide(double a, double b) {
    if (b == 0) {
        throw std::invalid_argument("zero divisor");
    }
    return a / b;
}
```

运行或编译检查结果：
```text
4
```

画面要点：throw 离开正常执行路线；本例先检查零除数；正常输入仍然直接返回结果

### cpp-10-2 try 与 catch 安排处理位置

把可能抛出异常的调用放进 try。后面的 catch 写明愿意处理哪一类异常，本页用标准异常基类的 const 引用接收，避免为了接收问题再复制或切掉异常对象的一部分。divide 抛出以后，try 中余下的 after divide 不会执行。程序跳到匹配的 catch，显示 caught。这个 catch 正常结束以后，再执行整组 try catch 后面的 continue。因此异常并不意味着整台程序一定立刻结束。有没有匹配处理位置、处理完做什么，决定了接下来的路线。如果始终没有合适的处理者，程序可能终止；本例已经提供了处理位置，所以可以清楚观察跳转以后继续的地方。

```cpp
try {
    cout << divide(8,0) << '\n';
    cout << "after divide\n";
} catch (const std::exception& e) {
    cout << "caught\n";
}
cout << "continue\n";
```

运行或编译检查结果：
```text
caught
continue
```

画面要点：throw 后跳过 try 中余下语句；匹配 catch 负责处理；处理完成后从整组结构后继续

### cpp-10-3 正常路线与异常路线分开读

把除数改为二，divide 正常返回四，try 中下一条语句也会执行，然后跳过 catch，最后显示 continue。同样的程序结构因为输入不同，可以走两条不同路线。没有异常时，不会为了“检查一下”而执行 catch；已经进入 catch 时，也不会再回到刚才抛出的位置继续算那次除法。读题可以先在纸上画两条线：正常返回沿着 try 继续向下；抛出异常则寻找匹配 catch。这样就不会把正常输出和错误提示都机械地抄一遍。修复错误通常由处理者重新安排新的操作，而不是自动回到 throw 那一行反复重试。

```cpp
try {
    cout << divide(8,2) << '\n';
    cout << "after divide\n";
} catch (const std::exception& e) {
    cout << "caught\n";
}
cout << "continue\n";
```

运行或编译检查结果：
```text
4
after divide
continue
```

画面要点：正常返回：执行 try 剩余语句；没有异常：跳过 catch；异常处理不会自动重试原调用

### cpp-10-4 先接具体类型，再接共同基类

一组 try 可以配多个 catch。程序按出现顺序寻找第一个匹配的处理者，不会把每一个 catch 都执行一遍。invalid argument 属于标准异常体系，既能被自己这个具体类型的引用接收，也能被 exception 基类引用接收。所以应该先写具体类型，再写更一般的基类，给具体问题留下专门处理的机会。本例首先匹配第一个 catch，显示 argument error，第二个 catch 不再执行。变量 e 在真实程序中还可以用来读取错误说明，本页只输出固定文字，避免不同运行环境的提示内容干扰路线判断。类型关系和书写顺序一起决定谁先接到问题，和前面学过的公有继承又联系起来了。

```cpp
try {
    throw std::invalid_argument("bad score");
} catch (const std::invalid_argument& e) {
    cout << "argument error\n";
} catch (const std::exception& e) {
    cout << "other standard error\n";
}
```

运行或编译检查结果：
```text
argument error
```

画面要点：按顺序寻找第一个匹配的 catch；具体类型放在一般类型前；catch 通常使用 const 引用

### cpp-10-q 课堂练习：抛出后还执行哪几行

try 中先输出 A，再调用零除数的 divide，接着准备输出 B。catch 输出 C，整组结构之后输出 D。最终会出现哪几个字母？先从 A 出发，遇到 divide 时检查参数。它是正常返回，还是抛出异常？选定路线以后，再决定 B 有没有机会执行。四秒以后，我们再补上一个细节：函数里已经创建的自动对象，在异常离开作用域时也会按规则收尾。但先把本题的基本跳转看清，不要因为看见四条输出，就认为四条都一定执行。

（四秒思考；随后核对答案）

```cpp
try {
    cout << "A ";
    divide(8,0);
    cout << "B ";
} catch (const std::exception& e) {
    cout << "C ";
}
cout << "D\n";
```

运行或编译检查结果：
```text
A C D
```

画面要点：先判断 divide 是否返回；抛出后跳过 B；catch 之后继续到 D

### cpp-10-a 答案与收尾：跳过余下语句，释放局部对象

上一题输出 A C D。A 已经执行；零除数触发异常，B 被跳过；匹配 catch 显示 C；处理完成后再显示 D。本页增加一个带析构函数的局部对象。work 创建 Guard 以后抛出异常，在寻找外层处理者、离开这个函数作用域时，Guard 的析构函数会执行，先显示 cleanup，再由 catch 显示 caught。这种退出途中结束局部对象的过程称为栈展开，先理解现象即可。这也解释了为什么前面一直强调对象要自己负责收尾：把资源交给合适的对象管理，正常离开和异常离开都能沿着作用域规则处理。本课不展开复杂资源管理，只确认异常路线不是简单跳过所有清理动作。

```cpp
struct Guard {
    ~Guard() { cout << "cleanup "; }
};
void work() {
    Guard g;
    throw std::runtime_error("failed");
}
```

运行或编译检查结果：
```text
cleanup caught
```

画面要点：上一题：A → C → D；异常离开作用域时，局部对象析构；本页：cleanup → caught

## 综合回顾 · Review

### cpp-11-1 把十个主题连成一张学习地图

现在把这一小时连起来看。最开始，我们用输入输出和函数完成一个小动作，用引用表达对已有对象的访问。接着把数据和操作放进类，让构造函数建立初始状态，再用访问权限保护对象的使用方式。组合表达对象内部有哪些部分，继承表达类型之间的关系。它们都有明确的建立和收尾顺序。重载帮助同一个名字接收不同输入，多态则让基类接口根据实际对象选择具体实现。最后，异常处理为无法正常完成的步骤安排另一条路线。这些词不需要一次背熟。回到每个例子，问四个具体问题：对象在哪里创建？谁能访问它？这次调用选择哪个函数？离开作用域时怎样收尾？能沿着代码回答这四个问题，就已经在真正理解这一课。

画面要点：数据与操作 → 类和对象；初始状态与作用域 → 构造与析构；关系与接口 → 组合、继承、多态；失败路线 → throw、try、catch

### cpp-11-2 用一段小程序开始独立练习

最后用一段短程序收尾。Score 保存成绩，私有成员不能从外部随意修改。构造函数明确接收初始值，get 允许只读访问，print 通过 const 引用读取已有对象。构造函数前面还有一个 explicit，这里表示不希望一个普通整数在需要 Score 的位置被悄悄转换成对象。初学时先明确写 Score 括号八十，能够把对象在哪里创建表达得更清楚，不必在这一页展开更多转换规则。课后请亲手做三步：先把成绩类增加一个经过检查的修改函数；再把两个成绩放进同一个学生对象，练习组合；最后写一个带虚函数的显示接口，练习通过基类引用调用。每改一步就编译一次，对照实际输出解释原因。一小时帮助你建立地图，熟练使用还需要用这些小程序继续练习。

```cpp
class Score {
    int value_;
public:
    explicit Score(int value) : value_(value) {}
    int get() const { return value_; }
};
void print(const Score& score) {
    cout << score.get() << '\n';
}
```

运行或编译检查结果：
```text
80
```

画面要点：亲手编译，再解释结果；增加修改函数 → 练组合 → 练虚函数；逐步修改，每次只核对一个变化
