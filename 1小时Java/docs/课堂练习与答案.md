# Java 课堂练习与答案

面向完全零基础学生。每题朗读后保留四秒思考，完整上下文见 Java示例。

## 第一个Java程序 · First Program

题目：这一页故意删掉了显示语句最后的分号。其他地方看起来都没有变化，程序还能像刚才一样显示 Hello Java 吗？请先回想分号的作用。它不是装饰，也不是为了排版好看，而是这条语句写法的一部分。计算机并不会因为你换了行，就一定知道这条语句已经完整结束。给你四秒，先判断它能不能通过编译。如果不能，再指出需要补上符号的位置。我们不急着背错误提示的全部英文，只要能从第一处错误回到对应的代码行。

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, Java!")
    }
}
```

原题的验证结果：
```text
编译失败：显示语句末尾缺少分号
```

答案与原因：原程序不能通过编译，因为显示语句末尾缺少分号。补回去以后，再编译、再运行，才能看到 Hello Java。这说明读程序时要先检查它是否满足基本写法。不能把一个尚未编译成功的程序，当成已经运行过，只是输出可能有点不同。编译器指出的位置有时紧跟在真正漏写的地方后面，所以也要看看报错行的前一行。现在你已经知道最小的工作过程：在 Main 的入口里面写操作，保存源文件，编译检查，再观察运行结果。下面我们把引号里的固定文字，换成程序保存的数据，让它不再只是每次显示同一句话。

核对、修正或对比代码：
```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

上方对比代码的验证结果：
```text
Hello, Java!
```

## 变量与数据类型 · Variables and Types

题目：a 最初是三，b 最初是八。执行 a 等于 b，然后把 b 改成九，最后分别显示 a 和 b，会得到什么？请把两个整数变量画成两个格子。给 a 赋值时，是把 b 当时的数值读出来放进去，还是让两个名字从此必须保持相同？四秒以后，我们按每一行的先后顺序核对。这里不要只凭最后看见的九来回答，也不要把赋值当成数学里不会变化的等式。程序执行过哪一步，变量当前是什么，就从那一步继续往下看。

```java
int a = 3;
int b = 8;
a = b;
b = 9;
System.out.println(a + " " + b);
```

原题的验证结果：
```text
8 9
```

答案与原因：结果是八和九。a 等于 b 执行时，b 里面还是八，所以 a 得到八。后面只把 b 改成九，没有再次给 a 赋值，a 就继续保存八。这里不存在两个整数以后自动同步的关系。屏幕最后一行用空格把两个结果分开，这个连接文字的加号下一章还会专门讲。先把这一点记牢：看变量当前的值，要沿着已经执行过的赋值逐行跟踪。以后程序会增加条件和循环，有些赋值可能只在特定路线中执行。今天先从这两份整数建立最基本的习惯，再把它应用到更长的步骤里。

核对、修正或对比代码：
```java
int a = 3;
int b = 8;
a = b;
b = 9;
System.out.println(a + " " + b);
```

上方对比代码的验证结果：
```text
8 9
```

## 运算符与表达式 · Operators and Expressions

题目：a 是三，b 是五。第一行显示时，前面先出现字符串 sum 等于，后面直接连接 a 和 b。第二行则把 a 加 b 放在括号里。这两行会完全一样吗？先从左边开始，看第一步已经做的是数值加法，还是把数字连接到一段文字后面。再看括号是否要求我们先完成三加五。给你四秒，分别写出两行结果。这不是要求你猜加号的心情，而是提醒你：同一个符号的作用，要结合两边的数据类型和表达式的结构一起判断。

```java
int a = 3, b = 5;
System.out.println("sum=" + a + b);
System.out.println("sum=" + (a + b));
```

原题的验证结果：
```text
sum=35
sum=8
```

答案与原因：第一行显示 sum 等于三五，第二行显示 sum 等于八。第一行从左边开始，字符串先接上三，已经得到文字 sum 等于三，再接上五，就成为 sum 等于三五。第二行先把括号里的三加五算成八，然后再接到提示文字后面，所以显示 sum 等于八。这道题真正要练习的是观察“当前正在处理什么类型的数据”。数字八和文字八看起来都能显示成一个八，但后续能够怎样计算，并不一样。下一章从键盘读取输入时，我们会明确告诉读取工具：这一次期待整数，还是期待一整行文字。

核对、修正或对比代码：
```java
int a = 3, b = 5;
System.out.println("sum=" + a + b);
System.out.println("sum=" + (a + b));
```

上方对比代码的验证结果：
```text
sum=35
sum=8
```

## 输入与输出 · Input and Output

题目：这段程序等待一个整数。现在输入八十，读入 score 以后，下一行把它加五，再显示。最终结果是多少？请把“从键盘读到值”和“后面继续计算”分成两个步骤。输入的数据不会因为我们写了加五，就要求使用者先在键盘里输入八十五。给你四秒，沿着箭头从输入走到保存，再走到更新和输出。程序能否正确处理数据，取决于已经写出的步骤；这道题的输入明确是一个合法整数，我们暂时不把错误输入混进来猜测。

```java
Scanner sc = new Scanner(System.in);
int score = sc.nextInt();
score += 5;
System.out.println(score);
```

原题的验证结果：
```text
85
```

答案与原因：结果是八十五。nextInt 先把键盘读到的八十交给 score，随后加等于五读取这个旧值，算出八十五，再保存回去。输入步骤并没有把后面的操作预先做完。你也可以换成输入六十，程序就会显示六十五；写法相同，交进来的数据不同，结果也随之变化。配套例子可以用这两组输入分别运行。现在我们能显示文字、保存数据、做计算，也能接收外界提供的值。下一步就让程序根据分数选择不同的回答：达到及格线走一条路线，没有达到走另一条路线。这正是条件判断的作用。

核对、修正或对比代码：
```java
Scanner sc = new Scanner(System.in);
int score = sc.nextInt();
score += 5;
System.out.println(score);
```

上方对比代码的验证结果：
```text
85
```

## 分支结构 · Conditional Statements

题目：规则是六十分及格，代码里的条件却写成 score 大于六十。现在 score 刚好等于六十，会显示 pass 还是 retry？代码是否符合规则？请分开回答两件事：先按实际写出的符号判断执行结果，再根据中文需求决定有没有需要修改的地方。不要因为我们希望六十分及格，就自动把代码里的大于看成大于等于。给你四秒，找出这个边界差异。很多程序问题并不是完全不会运行，而是只在刚好等于某个数时，走了和需求不一致的路线。

```java
int score = 60;
if (score > 60) {
    System.out.println("pass");
} else {
    System.out.println("retry");
}
```

原题的验证结果：
```text
retry
```

答案与原因：原题会显示 retry，因为六十并不大于六十。修正时把符号改成大于等于，才能让刚好六十也进入及格分支。现在显示 pass。程序没有自动理解中文需求，是我们把需求准确翻译到了条件里。你可以再试试五十九，应该进入另一边；试六十一，仍然及格。这三组值能帮助我们确认门槛附近的行为。以后读判断题，先把当前条件算清楚，再看是否选中对应的大括号。写自己的程序时，则先用一句话说明规则，再选择合适的比较符号。下一章我们会让这些步骤重复执行，循环的结束条件也需要同样仔细地处理边界。

核对、修正或对比代码：
```java
int score = 60;
if (score >= 60) {
    System.out.println("pass");
} else {
    System.out.println("retry");
}
```

上方对比代码的验证结果：
```text
pass
```

## 循环结构 · Loops

题目：这段程序希望计算一加二加三，条件却写成 i 小于三。它实际会把三加进去吗？最后 total 是多少？先跟踪 i 等于一、二、三时，每一轮开始前的条件。不要因为三出现在条件里，就认为它一定会进入循环体。给你四秒，先写实际结果，再想一想为了包含最后这一项，应该修改哪个符号。这和上一章六十分的题很相似：条件里是否包含等于，会直接决定边界那一次有没有机会执行。

```java
int total = 0;
for (int i = 1; i < 3; i++) {
    total += i;
}
System.out.println(total);
```

原题的验证结果：
```text
3
```

答案与原因：原题的结果是三，因为只执行了一和二这两轮。i 更新成三以后，小于三已经是假，所以没有再把三加进总和。修正时改成小于等于三，就会多执行 i 等于三的那一轮，结果变成六。这里不是需要在循环外再手工加一次三，而是应该让循环范围准确表达希望处理哪些项。做循环题时，可以先列一个很小的表：本轮开始前变量是多少，条件是真是假，循环体改了什么，结束后怎样更新。等这个顺序熟悉了，再去处理更多数据。下一章数组会把一组成绩保存到一起，循环就能沿着它们逐项完成统计。

核对、修正或对比代码：
```java
int total = 0;
for (int i = 1; i <= 3; i++) {
    total += i;
}
System.out.println(total);
```

上方对比代码的验证结果：
```text
6
```

## 数组与字符串 · Arrays and Strings

题目：scores 保存三份成绩。现在用 scores 点 length 作为下标去取值，会得到最后一项一百吗？还是会遇到问题？先写出这份数组的长度，再写出从零开始的全部合法位置。把这两组数摆在一起，就不容易凭直觉把“共有三项”误解成“最后编号为三”。给你四秒。这道题的写法可以通过编译，所以还需要继续判断运行时实际访问的位置是否存在。我们会把结果明确标成运行时异常，再给出只改一个位置的正确版本。

```java
int[] scores = {60, 80, 100};
System.out.println(scores[scores.length]);
```

原题的验证结果：
```text
运行时异常：ArrayIndexOutOfBoundsException
```

答案与原因：原题运行时会发生数组下标越界异常，因为试图访问不存在的第四个位置。它不是读到一个自动补出来的零，也不是返回最后一项。把下标改成 scores 点 length 减一，本例就是二，才读到最后的一百。这个写法的前提是数组至少有一项；如果一项都没有，就需要先检查长度，不能继续套用最后一项的访问方式。我们现在只处理这份明确有三个元素的数组，所以结果确定是一百。以后遇到一组数据，先确认有没有内容，再确认要访问的位置，最后才读取数据。这个顺序比先访问、出了异常再猜哪里不对，更能帮助你写出清楚的小程序。

核对、修正或对比代码：
```java
int[] scores = {60, 80, 100};
if (scores.length > 0) {
    int last = scores.length - 1;
    System.out.println(scores[last]);
}
```

上方对比代码的验证结果：
```text
100
```

## 方法 · Methods

题目：score 是八十，交给 addFive 方法。方法内部给参数 value 加五，但没有把一个结果返回给调用者。方法结束后，外面的 score 会是八十还是八十五？先把方法参数和调用者的整数变量画成两个位置。调用时把整数值交进去，是否就意味着方法内部给参数赋值，会自动改掉外面的那一个变量？给你四秒。这里先只讨论整数值，不把后面对象的关系混进来。判断完以后，我们会用一个明确交回新值、再保存回原变量的版本完成真正的加分。

```java
static void addFive(int value) {
    value += 5;
}
public static void main(String[] args) {
    int score = 80;
    addFive(score);
    System.out.println(score);
}
```

原题的验证结果：
```text
80
```

答案与原因：原题显示八十。调用时，参数 value 得到一份整数值，方法内部把这个参数位置改成八十五，并没有自动给外面的 score 重新赋值。修正版让方法返回 value 加五的结果，再由调用者写 score 等于这次调用结果，外面的成绩才明确更新为八十五。读取旧值、计算新值、交回结果、保存回去，这四个步骤都有对应位置。Java的方法传参采用传值方式。遇到对象时，传递的值可以是对象引用，后面会再看它怎样影响对象内容。但参数本身都不是一个可以通过重新赋值就自动改绑调用者变量的神秘通道。今天先用整数把最基本的路线看懂。

核对、修正或对比代码：
```java
static int addFive(int value) {
    return value + 5;
}
public static void main(String[] args) {
    int score = 80;
    score = addFive(score);
    System.out.println(score);
}
```

上方对比代码的验证结果：
```text
85
```

## 类与对象 · Classes and Objects

题目：a 通过 new Student 创建了一位八十分的学生。下一行 b 等于 a，没有再写 new。通过 b 把成绩改成九十，最后通过 a 读取，会得到八十还是九十？请数一数真正创建对象的操作执行了几次。两个变量名字出现了，是否就一定代表两位互不相关的学生？给你四秒，试着画两个入口和它们通向的记录。我们这次不是给方法参数重新赋值，而是沿着 b 找到对象，再调用方法修改那份对象内部的数据。把“名字指向谁”和“对象里面有什么”分开，就能找出答案。

```java
Student a = new Student(80);
Student b = a;
b.setScore(90);
System.out.println(a.getScore());
```

原题的验证结果：
```text
90
```

答案与原因：原题显示九十，因为 a 和 b 都使用同一个学生对象。通过 b 改掉内部的成绩，通过 a 读取时，自然也看到这份记录的新状态。如果希望 b 使用独立记录，就要另外建立一个对象。修正版执行第二次 new，把 a 当前的八十分交给新对象，再修改 b，结果就是 a 仍然八十，b 是九十。这也和方法传值的规则相容：复制一个对象引用，可以让两个位置都找到同一个对象；通过它修改对象内容会被其他入口观察到。它不等于复制整份对象，也不等于给参数另一个引用就能自动改绑外面的变量。先画清入口和记录，再逐步跟踪具体修改。

核对、修正或对比代码：
```java
Student a = new Student(80);
Student b = new Student(a.getScore());
b.setScore(90);
System.out.println(a.getScore() + " " + b.getScore());
```

上方对比代码的验证结果：
```text
80 90
```

## 集合 · Collections

题目：一个列表先后放入 Ana 和 Bo。remove 括号零，删除位置零的那一项。随后读取位置零，再显示列表的数量，会得到什么？请不要把删除理解成原地留下一个空洞。先画出两个有顺序的格子，划掉第一个，再观察后面的元素应该排在哪里。给你四秒，分别预测第一行姓名和第二行数字。这里使用的是文字列表，remove 的整数参数明确表示要删除的位置。练习要检查的是删除以后的位置变化，而不是刚才那个姓名是否还保持原来的编号。

```java
ArrayList<String> names = new ArrayList<>();
names.add("Ana");
names.add("Bo");
names.remove(0);
System.out.println(names.get(0));
System.out.println(names.size());
```

原题的验证结果：
```text
Bo
1
```

答案与原因：原题第一行显示 Bo，第二行显示一。Ana 被删除以后，Bo 成为剩下的第一项，也就是位置零，数量减少为一。画面继续加上一个 Cy，帮助我们再核对一次。新元素接在最后，位置零仍然是 Bo，位置一是 Cy，数量回到二。可以看到，列表的位置反映当前排列，不是一张永远贴在某个人身上的编号。这也是为什么访问列表时，应当根据它现在的 size 判断边界。添加和删除都可能改变数量，删除还可能改变后续元素的位置。如果程序需要按稳定的姓名或编号查记录，就应该另外建立对应关系，不能把某次读到的位置当成永远有效的身份。

核对、修正或对比代码：
```java
ArrayList<String> names = new ArrayList<>();
names.add("Ana");
names.add("Bo");
names.remove(0);
names.add("Cy");
System.out.println(names.get(0) + " " + names.get(1));
System.out.println(names.size());
```

上方对比代码的验证结果：
```text
Bo Cy
2
```

## 异常处理 · Exceptions

题目：请沿着这段程序跟踪显示的字母。先显示 A，然后尝试把 abc 转成整数，后面还写着显示 B。catch 里面显示 C，整个处理结构之后显示 D。如果转换抛出了刚才学习的异常，A、B、C、D 哪些会真正显示，顺序又是什么？注意，catch 并不是无论成功失败都执行的一段代码，转换失败以后也不会自动回去补做 try 里面剩下的语句。给你四秒，在纸上画出正常向下和跳到 catch 的两条路线，选出本次实际走过的那一条。

```java
try {
    System.out.print("A ");
    Integer.parseInt("abc");
    System.out.print("B ");
} catch (NumberFormatException e) {
    System.out.print("C ");
}
System.out.println("D");
```

原题的验证结果：
```text
A C D
```

答案与原因：原题显示 A、C、D。A 在转换之前已经显示。转换失败后跳到 catch，try 里面剩下的 B 被跳过，显示 C，再执行结构后面的 D。画面把转换内容改成正常的八十，用另一条路线做对照。这次转换成功，继续执行 B，不进入 catch，所以显示 A、B、D。两种情况放在一起，更容易看清 catch 的作用。不要只记住一串字母，要记住执行过程：先按顺序做事，发生指定异常时转去相应处理，处理后继续往下。以后遇到错误信息，先找到失败的操作和具体原因，再决定怎样修正数据或者处理失败，比把所有问题都藏在一个空的 catch 里面更有帮助。

核对、修正或对比代码：
```java
try {
    System.out.print("A ");
    Integer.parseInt("80");
    System.out.print("B ");
} catch (NumberFormatException e) {
    System.out.print("C ");
}
System.out.println("D");
```

上方对比代码的验证结果：
```text
A B D
```
