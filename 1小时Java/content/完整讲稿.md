## 第一个Java程序 · First Program

### java-01-1 让屏幕显示第一句话

先看最里面这一行。双引号中间的 Hello Java，是我们希望显示的文字。println 这个操作把文字送到屏幕上，并在最后换到下一行。括号里写要显示的内容，行末的分号表示这条操作写完了。外面有两层大括号，帮助Java看清哪些内容属于同一个范围。Main 是本例的类名，main 是程序开始执行的位置。现在不用逐个解释 public、static 等词，先把这个外框保持原样，把要运行的步骤写在 main 的大括号里面。代码保存成 Main 点 java，文件名的大小写要和公开类名 Main 对应。运行后，屏幕只显示引号里面的那句话，不会把大括号或整份源代码都打印出来。先完成这一个可以看见的结果，就已经迈出了第一步。

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

运行或错误检查结果：

```text
Hello, Java!
```

## 变量与数据类型 · Variables and Types

### java-02-1 给一份数据起名字

如果想保存一位同学的成绩，可以写 int score 等于八十。int 表示这份数据按整数处理，score 是我们给它起的名字，等号右边的八十是最初存进去的值。变量可以暂时想成一个带名字的数据位置。后面显示 score，读到的是它当前保存的数值，不是显示 score 这几个字母。想显示字母本身，就需要像上一章一样放进双引号。下一行把 score 改成八十五，是给已经建立的变量保存新值，所以不用再写一次 int。显示结果也就变成八十五。这里的等号表示把右边的值保存到左边，并不是数学里描述两边永远相等。先建立名字，再按需要读取或更新它，这是很多程序的起点。

```java
int score = 80;
System.out.println(score);
score = 85;
System.out.println(score);
```

运行或错误检查结果：
```text
80
85
```

画面要点：int：整数类型；score：变量名；赋值会更新这个变量的当前值

### java-02-2 整数、小数和真假

数据有不同的种类。人数、次数和本课的整数分数，可以先用 int；身高或带小数的平均分，可以先用 double。boolean 保存的则是真或假，写成 true 或 false。它们不是随便可以互换的英文标签。声明一个整数位置，却直接放进去三点五，编译器会要求你说明怎样处理小数部分。我们下一章会讲计算时怎样得到小数结果。Java还有其他基本数据类型，比如保存更大整数范围的 long，以及 byte、short、float 和 char。本课不让你先背完整范围表，先把最常用的整数、小数、真假分清楚。选择类型是在说明“这份数据是什么”，给变量起名字是在说明“它用来干什么”，两件事配合起来，代码就容易读。

```java
int count = 3;
double average = 82.5;
boolean passed = true;
System.out.println(count);
System.out.println(average);
System.out.println(passed);
```

运行或错误检查结果：
```text
3
82.5
true
```

画面要点：int：整数；double：小数；boolean：true 或 false；先用常见类型，逐步扩展

### java-02-3 文字与单个字符

姓名是一段文字，我们先用 String 保存。String 的首字母是大写，内容写在双引号里。这里 name 保存 Ana，显示 name 就得到这段文字。char 可以先通过英文等级来认识。把大写 A 放进单引号，就可以作为这一页的等级值。单引号和双引号不是可有可无的排版区别，不要把一整段姓名塞进 char。String 和前面 int 这类基本类型在底层的处理方式不同，后面对象一章会再建立联系。现在先学会分辨屏幕上最常见的几种写法：数字通常不加引号，文字通常用双引号，像本页这种单个英文等级用单引号。名字相同、内容相同、写法相同，是三件需要分别观察的事情。

```java
String name = "Ana";
char grade = 'A';
System.out.println(name);
System.out.println(grade);
```

运行或错误检查结果：
```text
Ana
A
```

画面要点：String 首字母大写；文字：双引号；英文字符：单引号；变量名不需要放进引号

### java-02-4 名字、初始值与不能再赋值的量

变量名用来帮助人读懂程序。score 比随手写一个 x 更能说明保存的是分数。名字区分大小写，不能以数字开头，也不能拿 int、class 这些已经有规定用途的词来当名字。在方法里声明局部变量后，要先赋值，再读取它，不要以为计算机会自动猜出你想要的初值。屏幕上的 passLine 在声明时就得到六十，所以后面可以使用。前面的 final 表示这个变量完成初始化后，不能再给它另一个值。本例用它保存不会随意修改的及格线。对于这个整数例子，把它理解成“初值确定后不再赋值”就够了。本页先用整数来理解它：这个变量之后不能重新赋值。final 不是另一种整数类型，而是在说明这个变量可以怎样使用。

```java
final int passLine = 60;
int score = 80;
boolean passed = score >= passLine;
System.out.println(passed);
```

运行或错误检查结果：
```text
true
```

画面要点：局部变量先赋值，再读取；名字区分大小写；final int 完成初始化后不能再赋值

### java-02-q 课堂练习：两个变量会一起变吗

a 最初是三，b 最初是八。执行 a 等于 b，然后把 b 改成九，最后分别显示 a 和 b，会得到什么？请把两个整数变量画成两个格子。给 a 赋值时，是把 b 当时的数值读出来放进去，还是让两个名字从此必须保持相同？四秒以后，我们按每一行的先后顺序核对。这里不要只凭最后看见的九来回答，也不要把赋值当成数学里不会变化的等式。程序执行过哪一步，变量当前是什么，就从那一步继续往下看。

（朗读结束后，四秒独立思考）

```java
int a = 3;
int b = 8;
a = b;
b = 9;
System.out.println(a + " " + b);
```

运行或错误检查结果：
```text
8 9
```

画面要点：a 与 b 是两个整数位置；a = b 读取 b 当时的值；随后只给 b 保存了 9

### java-02-a 答案：读到的是赋值当时的八

结果是八和九。a 等于 b 执行时，b 里面还是八，所以 a 得到八。后面只把 b 改成九，没有再次给 a 赋值，a 就继续保存八。这里不存在两个整数以后自动同步的关系。屏幕最后一行用空格把两个结果分开，这个连接文字的加号下一章还会专门讲。先把这一点记牢：看变量当前的值，要沿着已经执行过的赋值逐行跟踪。以后程序会增加条件和循环，有些赋值可能只在特定路线中执行。今天先从这两份整数建立最基本的习惯，再把它应用到更长的步骤里。

```java
int a = 3;
int b = 8;
a = b;
b = 9;
System.out.println(a + " " + b);
```

运行或错误检查结果：
```text
8 9
```

画面要点：a 保存当时复制到的 8；b 后来单独变成 9；按执行顺序跟踪当前值

## 运算符与表达式 · Operators and Expressions

### java-03-1 先计算，再保存结果

现在让程序算一笔小账。单价是十二，数量是三，星号表示乘法。右边先算十二乘三，再把结果三十六保存进 total，最后显示 total。像 price 乘 count 这样，把数据与运算符组合起来、能够算出结果的写法，叫表达式。加、减、乘、除分别用加号、减号、星号和斜杠。Java不会把两个变量并排写着就自动理解为相乘，运算需要写清楚。通常先乘除、后加减，括号可以明确调整先后。对初学者来说，不用故意写很长的式子考验记忆；把一个大计算拆成几个有名字的小步骤，更容易核对。本课会一直沿用“先读数据，再计算，再把结果交给下一步”的方法。

```java
int price = 12;
int count = 3;
int total = price * count;
System.out.println(total);
System.out.println((2 + 3) * 4);
```

运行或错误检查结果：
```text
36
20
```

画面要点：* 表示乘法；先计算右边，再保存到左边；括号可以明确计算先后

### java-03-2 整数相除与小数相除

这里有一个很常见的疑问：七除以二为什么得到三？因为两边都是整数，这次整数除法不会保留小数部分。如果希望做小数计算，可以让其中一个数先成为 double，例如七点零除以二，就得到三点五。注意，只在最后用 double 变量接收七除以二，并不会把前面已经丢掉的小数部分补回来，得到的只是三点零。百分号表示取余数，七除以二剩一，所以七百分号二得到一。它常用来判断偶数，或处理一轮之后还剩多少项。先分清这三件事：除法选择什么类型的计算，余数回答什么问题，以及最后把计算结果保存在哪里。它们有关联，却不能只看接收变量就跳过前面的计算。

```java
System.out.println(7 / 2);
System.out.println(7.0 / 2);
double result = 7 / 2;
System.out.println(result);
System.out.println(7 % 2);
```

运行或错误检查结果：
```text
3
3.5
3.0
1
```

画面要点：整数除法不保留小数部分；7.0 / 2 才在这里做小数计算；% 取得余数

### java-03-3 比较与组合条件

如果想知道成绩是否达到六十，就写 score 大于等于六十。比较的结果不是另一个分数，而是真或假，能保存在 boolean 变量里。比较相等使用两个等号，普通赋值使用一个等号。大于、小于、大于等于、小于等于和不等于，也都有对应的符号。它们以后会成为条件判断的依据。两个与符号表示“同时满足”，两个竖线表示“至少一个满足”，感叹号把真假反过来。屏幕检查分数同时不小于零、不大于一百，八十分满足两个要求，结果为 true。这里的逻辑与还会在左边已经是假时跳过右边；现在先用没有额外动作的简单比较练习，把每个小条件本身看懂，再把它们合起来。

```java
int score = 80;
boolean passed = score >= 60;
boolean valid = score >= 0 && score <= 100;
System.out.println(passed);
System.out.println(valid);
System.out.println(score == 100);
```

运行或错误检查结果：
```text
true
true
false
```

画面要点：比较产生 true 或 false；== 比较；= 赋值；&& 同时满足，|| 至少一个满足

### java-03-4 更新数值与连接文字

程序经常要把原来的值增加一些。score 等于 score 加五，先读取旧分数，算出新分数，再保存回同一个变量。也可以简写为 score 加等于五。如果只增加一，单独写 score 加加就能表达这一步。本课把它作为独立语句使用，不把多个自增动作塞进一条复杂表达式。加号遇到字符串时，还可以连接文字。显示“score 等于”这段文字，再连接变量，就能同时说明结果的含义。计算从左往右逐步结合，已经进入文字连接以后，后面的数字也可能被接成文字。想先算出数值再接到提示后面，就把需要先计算的部分放进括号。这和上一页用括号明确计算先后的习惯是一致的。

```java
int score = 80;
score += 5;
score++;
System.out.println("score=" + score);
System.out.println("sum=" + (3 + 5));
```

运行或错误检查结果：
```text
score=86
sum=8
```

画面要点：+= 把计算结果保存回原变量；单独的 ++ 增加 1；提示文字后可连接计算结果

### java-03-q 课堂练习：结果是三十五还是八

a 是三，b 是五。第一行显示时，前面先出现字符串 sum 等于，后面直接连接 a 和 b。第二行则把 a 加 b 放在括号里。这两行会完全一样吗？先从左边开始，看第一步已经做的是数值加法，还是把数字连接到一段文字后面。再看括号是否要求我们先完成三加五。给你四秒，分别写出两行结果。这不是要求你猜加号的心情，而是提醒你：同一个符号的作用，要结合两边的数据类型和表达式的结构一起判断。

（朗读结束后，四秒独立思考）

```java
int a = 3, b = 5;
System.out.println("sum=" + a + b);
System.out.println("sum=" + (a + b));
```

运行或错误检查结果：
```text
sum=35
sum=8
```

画面要点：第一行先与文字连接；第二行先计算括号内的和；分别跟踪两种计算结构

### java-03-a 答案：括号明确了先做数值计算

第一行显示 sum 等于三五，第二行显示 sum 等于八。第一行从左边开始，字符串先接上三，已经得到文字 sum 等于三，再接上五，就成为 sum 等于三五。第二行先把括号里的三加五算成八，然后再接到提示文字后面，所以显示 sum 等于八。这道题真正要练习的是观察“当前正在处理什么类型的数据”。数字八和文字八看起来都能显示成一个八，但后续能够怎样计算，并不一样。下一章从键盘读取输入时，我们会明确告诉读取工具：这一次期待整数，还是期待一整行文字。

```java
int a = 3, b = 5;
System.out.println("sum=" + a + b);
System.out.println("sum=" + (a + b));
```

运行或错误检查结果：
```text
sum=35
sum=8
```

画面要点：文字依次连接：sum=35；先加数值再连接：sum=8；类型与括号共同决定含义

## 输入与输出 · Input and Output

### java-04-1 把键盘输入交给程序

前面的分数都写在代码里。现在让使用程序的人从键盘输入。Scanner 可以先理解成标准库提供的读取工具，我们创建一个叫 sc 的读取工具，让它从 System 点 in 代表的输入位置取数据。nextInt 表示这一次期待读到整数。键盘输入八十并按回车以后，读到的八十保存进 score，再由下一行显示出来。屏幕下方会注明本页使用的测试输入，避免把输入和输出混在一起。完整程序最上面还有一行 import，用来说明 Scanner 这个名字来自哪里，配套文件已经写好。先把这些写法当成准备工具和使用工具，不要求你现在就解释对象建立的全部细节。输入也必须符合期待的类型，随便输入一段文字并不会自动变成有效整数，后面的异常处理会再讲怎样应对。

```java
Scanner sc = new Scanner(System.in);
int score = sc.nextInt();
System.out.println("score=" + score);
```

运行或错误检查结果：
```text
score=80
```

画面要点：本页输入：80，然后回车；Scanner 创建读取工具；nextInt 读取一个整数

### java-04-2 读取一整行姓名

如果想读取姓名或一句话，可以使用 nextLine，它接收一整行文字。这里单独读取 Ana Lee，中间的空格也属于这行文字的一部分。读到的结果保存在 String 类型的 name 中，再连接到 name 等于的提示后面。输入内容和变量名是不同的东西：使用者输入 Ana Lee，不需要输入 String name，也不需要自己加上Java代码里的双引号。运行时如果程序暂时没有继续显示，有可能是在等你输入并回车，而不是已经坏了。先看当前执行的是不是读取操作。我们把输出当成程序向外说明情况，把输入当成外界把数据交进来。下一页会把读整数和读整行文字放在一起，解释一个初学者很常见的小问题。

```java
Scanner sc = new Scanner(System.in);
String name = sc.nextLine();
System.out.println("name=" + name);
```

运行或错误检查结果：
```text
name=Ana Lee
```

画面要点：本页输入：Ana Lee，然后回车；nextLine 读取整行内容；输入数据时不用输入源代码写法

### java-04-3 混合读取时留意行尾

如果先用 nextInt 读取八十，再想用 nextLine 读取下一行姓名，需要注意前一次输入留下的行尾。nextInt 取走整数本身，不会顺便把这一行后面所有内容都当成已经读完。所以本页在读完整数后，单独调用一次 nextLine，消费掉这一行剩余的部分。下一次 nextLine 才读取后面的 Ana Lee。否则，它可能立刻读到当前行剩余的空内容，看起来像把姓名输入跳过去了。先把输入按行想清楚，比机械地到处多加一次读取更好。只有已经知道这里要从“读一个整数”切换到“读下一整行”的时候，才按这个结构处理。以后也可以统一先读整行，再把其中的数字文字转换成整数；本课末尾会示范这种转换。

```java
Scanner sc = new Scanner(System.in);
int score = sc.nextInt();
sc.nextLine();
String name = sc.nextLine();
System.out.println(name + " " + score);
```

运行或错误检查结果：
```text
Ana Lee 80
```

画面要点：本页两行输入：80 / Ana Lee；单独 nextLine 读取本行剩余内容；随后 nextLine 才读下一整行

### java-04-q 课堂练习：输入后怎样计算

这段程序等待一个整数。现在输入八十，读入 score 以后，下一行把它加五，再显示。最终结果是多少？请把“从键盘读到值”和“后面继续计算”分成两个步骤。输入的数据不会因为我们写了加五，就要求使用者先在键盘里输入八十五。给你四秒，沿着箭头从输入走到保存，再走到更新和输出。程序能否正确处理数据，取决于已经写出的步骤；这道题的输入明确是一个合法整数，我们暂时不把错误输入混进来猜测。

### java-04-a 答案：程序保存八十，再更新为八十五

结果是八十五。nextInt 先把键盘读到的八十交给 score，随后加等于五读取这个旧值，算出八十五，再保存回去。输入步骤并没有把后面的操作预先做完。你也可以换成输入六十，程序就会显示六十五；写法相同，交进来的数据不同，结果也随之变化。配套例子可以用这两组输入分别运行。现在我们能显示文字、保存数据、做计算，也能接收外界提供的值。下一步就让程序根据分数选择不同的回答：达到及格线走一条路线，没有达到走另一条路线。这正是条件判断的作用。

## 分支结构 · Conditional Statements

### java-05-1 条件成立时才执行

假设分数是八十，达到六十分就显示 pass。if 后面的小括号里放条件，这里 score 大于等于六十会得到 true，于是执行后面大括号里的显示语句。条件如果是假，就跳过这组大括号里的步骤，继续执行后面的内容。因此最后的 done 不管是否及格都会显示，因为它已经写在 if 的范围之外。缩进帮助人看清层次，大括号才明确规定哪些操作归这一组。初学阶段即使里面只有一条语句，也建议保留大括号。读代码时先找条件，再找对应的范围，最后看范围以外的步骤。不要认为某一行离 if 很近，就一定跟着它一起执行。

```java
int score = 80;
if (score >= 60) {
    System.out.println("pass");
}
System.out.println("done");
```

运行或错误检查结果：
```text
pass
done
```

画面要点：if 条件需要 true 或 false；大括号标出受条件控制的范围；范围外的 done 继续执行

### java-05-2 两条路线选择一条

如果希望不及格时也有明确回答，就加上 else。条件为真，执行 if 的那一块；条件为假，执行 else 的那一块。屏幕把分数改成五十五，所以只显示 retry，不会先显示 pass 再显示 retry。同一组 if else 是两条互相对应的路线，这一次只选其中一条。这是程序把不同情况分开处理的最基本方式。你可以在脑中先把条件算成 true 或 false，再用手指沿着选中的那条路线往下走。暂时不要把未选中分支里的内容也算作已经执行。等这组结构结束，程序再回到两条路线后面的共同位置，继续后续步骤。

```java
int score = 55;
if (score >= 60) {
    System.out.println("pass");
} else {
    System.out.println("retry");
}
```

运行或错误检查结果：
```text
retry
```

画面要点：同一组 if / else 只选一边；55 >= 60 为 false；本页只显示 retry

### java-05-3 多种等级按顺序判断

如果要分成优秀、及格、继续练习三种情况，可以继续写 else if。这里先检查是否达到九十；没有达到，再检查是否达到六十；都不满足，才走最后的 else。分数是八十，第一个条件是假，第二个条件是真，于是显示 pass，后面不再继续选择这一组的其他分支。把较高的门槛先检查，是这段分级规则的重要部分。如果一开始就写大于等于六十，九十五也会满足它，可能在更早的分支就结束选择。不是计算机没有看见后面的九十，而是我们给出的判断顺序已经决定了路线。先用几组边界值，比如五十九、六十、八十九和九十，检查规则是否符合自己的意思。

```java
int score = 80;
if (score >= 90) {
    System.out.println("excellent");
} else if (score >= 60) {
    System.out.println("pass");
} else {
    System.out.println("retry");
}
```

运行或错误检查结果：
```text
pass
```

画面要点：按书写顺序寻找匹配分支；先检查较高门槛；用边界值检查分级规则

### java-05-4 按固定选项选择操作

还有一种常见情况：菜单输入一、二或其他编号，分别选择不同操作。switch 可以把这些固定选项列出来，每个 case 后面写要匹配的值。本页选择二，就从 case 二进入，显示 list。后面的 break 表示离开这组 switch。default 处理前面都没有匹配到的情况。这里演示的是带冒号和 break 的传统写法。漏掉 break 后，有时会继续执行后面分支的语句，所以不要只记住 case 长什么样，还要看从入口进去后在哪里离开。if 更适合表达大小范围和组合条件；switch 在这里把一组固定菜单值列得很清楚。先根据问题选择容易表达的结构。

```java
int choice = 2;
switch (choice) {
    case 1: System.out.println("add"); break;
    case 2: System.out.println("list"); break;
    default: System.out.println("invalid");
}
```

运行或错误检查结果：
```text
list
```

画面要点：case 匹配固定选项；break 在这里离开 switch；default 处理其他值

### java-05-q 课堂练习：六十分走哪边

规则是六十分及格，代码里的条件却写成 score 大于六十。现在 score 刚好等于六十，会显示 pass 还是 retry？代码是否符合规则？请分开回答两件事：先按实际写出的符号判断执行结果，再根据中文需求决定有没有需要修改的地方。不要因为我们希望六十分及格，就自动把代码里的大于看成大于等于。给你四秒，找出这个边界差异。很多程序问题并不是完全不会运行，而是只在刚好等于某个数时，走了和需求不一致的路线。

```java

if (score > 60) {
    System.out.println("pass");

```

### java-05-a 答案：把边界写进条件

原题会显示 retry，因为六十并不大于六十。修正时把符号改成大于等于，才能让刚好六十也进入及格分支。现在显示 pass。程序没有自动理解中文需求，是我们把需求准确翻译到了条件里。你可以再试试五十九，应该进入另一边；试六十一，仍然及格。这三组值能帮助我们确认门槛附近的行为。以后读判断题，先把当前条件算清楚，再看是否选中对应的大括号。写自己的程序时，则先用一句话说明规则，再选择合适的比较符号。下一章我们会让这些步骤重复执行，循环的结束条件也需要同样仔细地处理边界。

## 循环结构 · Loops

### java-06-1 重复三次，不必抄三遍

如果要显示一、二、三，可以让同一条显示语句重复执行。for 小括号里的三部分，分别负责开始时的准备、每轮之前的条件、以及每轮之后的更新。本页先让 i 从一开始。只要 i 不大于三，就进入大括号显示它；这一轮结束后，i 增加一，再回去检查条件。于是依次显示一、二、三。更新到四以后，条件为假，循环才结束。不要把小括号里三部分当成每次都从左到右重新建立一次变量。初始化通常只在进入这次 for 时执行一次，后面不断重复的是判断、循环体和更新。我们会在右边把这几个位置连成箭头，跟着一轮一轮走，比先背一句术语更容易。

```java
for (int i = 1; i <= 3; i++) {
    System.out.println(i);
}
```

运行或错误检查结果：
```text
1
2
3
```

画面要点：准备一次：i = 1；每轮前判断；每轮后更新；条件为 false 时离开

### java-06-2 把每一项加进总和

现在让循环做一点工作：计算一加二加三。循环开始以前，把 total 设为零。每一轮把当前的 i 加进去，再把新总和保存回 total。第一轮总和从零变成一，第二轮再加二得到三，第三轮再加三得到六。循环结束后再显示 total，所以屏幕只看到最后的六，而不是把每个中间结果都显示一遍。这里总和必须放在循环外面建立。如果每一轮都重新把 total 设为零，就丢掉了前面累积的结果。读循环时不仅看它重复几次，也要看哪些值跨过一轮仍然保留，哪些值每轮重新准备。把当前项和累计结果分开，是很多统计程序共同的做法。

```java
int total = 0;
for (int i = 1; i <= 3; i++) {
    total += i;
}
System.out.println(total);
```

运行或错误检查结果：
```text
6
```

画面要点：total 在循环外初始化一次；每轮保留旧总和，再加当前项；最后统一显示结果

### java-06-3 先检查条件的 while

如果重复次数更适合由一个条件来控制，可以写 while。它每次都先检查小括号里的条件，成立才执行循环体，然后再回去检查。本页让 n 从三开始，每轮显示当前值，再减一，所以得到三、二、一。n 变成零以后，不再进入下一轮。这里的减减是独立语句，表示把 n 减少一。和前面的 for 相比，开始值写在前面，更新操作写在循环体里面。形式变了，“准备、判断、执行、更新”的思路仍然可以帮助你理解。尤其要检查循环体有没有让条件逐步发生变化；如果 n 一直大于零又永远不改变，程序就可能一直重复，不能自己等到条件变假。

```java
int n = 3;
while (n > 0) {
    System.out.println(n);
    n--;
}
```

运行或错误检查结果：
```text
3
2
1
```

画面要点：while 每次先检查条件；本页 n 每轮减少 1；确认循环能够逐步结束

### java-06-4 先做一轮的 do while

do while 把条件判断放在循环体之后，所以即使一开始条件就不成立，也会先执行一次循环体。这里 n 是零，先进入 do 的大括号，显示一次 zero。然后检查 n 大于零，结果是假，才结束循环。如果换成普通 while，条件在前面检查，这次就不会进入循环体。这种结构适合表达“至少先做一次，再决定要不要继续”的过程。注意末尾 while 条件后面还有分号，它属于这套写法。现在不用强行为每个需求都写三个版本，只要分清第一次检查条件发生在执行之前还是之后，就能判断它们最关键的差别。

```java
int n = 0;
do {
    System.out.println("zero");
} while (n > 0);
```

运行或错误检查结果：
```text
zero
```

画面要点：do while 至少先执行一轮；条件在循环体之后检查；末尾条件后有分号

### java-06-5 提前结束与跳过这一轮

循环中还有两个常见控制词。break 提前结束当前这一层循环；continue 则跳过这一轮余下的步骤，进入下一轮应当进行的更新或判断。本页 i 从一走到五，遇到三时执行 continue，所以不显示三。其他时候继续往下显示，结果是一、二、四、五。对于这个 for，continue 之后仍然会按规则执行小括号里的 i 加加，再检查条件。不要把 continue 理解成“再从当前这行接着显示”，也不要把 break 理解成“只跳过这一个数”。它们改变的位置不同。刚开始写循环，可以先把普通路线写对，再在确实需要时加入这两个控制词，让每一个提前跳转都有清楚的理由。

```java
for (int i = 1; i <= 5; i++) {
    if (i == 3) {
        continue;
    }
    System.out.print(i + " ");
}
System.out.println();
```

运行或错误检查结果：
```text
1 2 4 5
```

画面要点：continue 跳过本轮剩余步骤；break 结束当前循环；本例跳过 3，继续到 4、5

### java-06-q 课堂练习：三有没有被加进去

这段程序希望计算一加二加三，条件却写成 i 小于三。它实际会把三加进去吗？最后 total 是多少？先跟踪 i 等于一、二、三时，每一轮开始前的条件。不要因为三出现在条件里，就认为它一定会进入循环体。给你四秒，先写实际结果，再想一想为了包含最后这一项，应该修改哪个符号。这和上一章六十分的题很相似：条件里是否包含等于，会直接决定边界那一次有没有机会执行。

（朗读结束后，四秒独立思考）

```java
int total = 0;
for (int i = 1; i < 3; i++) {
    total += i;
}
System.out.println(total);
```

运行或错误检查结果：
```text
3
```

画面要点：i = 1、2 时进入循环体；i = 3 时先检查条件；区分 < 与 <=

### java-06-a 答案：原题只加了一和二

原题的结果是三，因为只执行了一和二这两轮。i 更新成三以后，小于三已经是假，所以没有再把三加进总和。修正时改成小于等于三，就会多执行 i 等于三的那一轮，结果变成六。这里不是需要在循环外再手工加一次三，而是应该让循环范围准确表达希望处理哪些项。做循环题时，可以先列一个很小的表：本轮开始前变量是多少，条件是真是假，循环体改了什么，结束后怎样更新。等这个顺序熟悉了，再去处理更多数据。下一章数组会把一组成绩保存到一起，循环就能沿着它们逐项完成统计。

```java
int total = 0;
for (int i = 1; i <= 3; i++) {
    total += i;
}
System.out.println(total);
```

运行或错误检查结果：
```text
6
```

画面要点：原题只计算 1 + 2；<= 3 包含最后一项；先确定范围，再执行统计

## 数组与字符串 · Arrays and Strings

### java-07-1 把一组成绩放在一起

如果有三份成绩，不必为它们分别起 score 一、score 二、score 三这样的名字，可以用数组保存同一种类型的一组值。int 后面的方括号表示这里准备保存一组整数。大括号里依次放六十、八十、一百。要读取某一项，在数组名字后面写方括号和位置编号。特别注意，第一项的编号是零，所以 scores 方括号零读到六十。位置编号也叫下标。它不是成绩本身，而是告诉程序这次要访问哪一个位置。给 scores 方括号一赋八十五，改的是第二项，其他项不会跟着变化。先画出几个并排的格子，把零、一、二写在上方，再把成绩写在格子里面，就能分清位置和内容。

```java
int[] scores = {60, 80, 100};
System.out.println(scores[0]);
scores[1] = 85;
System.out.println(scores[1]);
```

运行或错误检查结果：
```text
60
85
```

画面要点：数组保存同种类型的一组值；第一项下标是 0；下标指定位置，赋值修改该项

### java-07-2 数组长度和最后一个位置

数组的 length 表示里面有多少项。本例有三项，所以长度是三。但位置从零开始，合法下标依次是零、一、二，最后一项并不是编号三。因此最后一项可以用长度减一来取得，读取结果是一百。数组一旦创建，这份数组的长度就固定了；修改其中的分数，并不会凭空多出第四个位置。如果提前知道有三个位置，也可以用 new int 方括号三创建它，再逐项填写。新建的整数数组初始元素为零，但这不等于每一个方法里的普通局部变量也会自动得到可读取的零值。先把本页的两件事分清：length 说明数量，下标说明位置。访问前要确认位置在这份数组的有效范围内。

```java
int[] scores = {60, 80, 100};
System.out.println(scores.length);
System.out.println(scores[scores.length - 1]);
int[] empty = new int[3];
System.out.println(empty[0]);
```

运行或错误检查结果：
```text
3
100
0
```

画面要点：长度是数量：3；合法下标：0、1、2；最后一项下标：length - 1

### java-07-3 用循环逐项完成统计

有了数组，循环就能沿着位置逐项读取。i 从零开始，只要还小于数组长度，就读取 scores 方括号 i，把这一项加到 total 中。这里用小于长度，正好覆盖零到长度减一，不会访问不存在的下一项。总和是二百四十，平均分用小数除法计算，得到八十点零。前面学过的变量、循环和除法，现在就在完成同一个小任务。如果只想依次读每一项，不关心位置编号，也可以使用增强 for，写成 for 括号 int score 冒号 scores。它会依次把每个整数值交给 score。配套例子还提供这种写法。本页先保留下标版本，因为它最能帮助我们看清循环范围和数组有效位置之间的关系。

```java
int[] scores = {60, 80, 100};
int total = 0;
for (int i = 0; i < scores.length; i++) {
    total += scores[i];
}
double average = total / 3.0;
System.out.println(total);
System.out.println(average);
```

运行或错误检查结果：
```text
240
80.0
```

画面要点：i 从 0 到 length - 1；逐项读取，再累加；平均分使用小数计算

### java-07-4 读取文字的长度与一段内容

字符串也提供了一些现成操作。name 点 length 括号，取得本页这段英文姓名的长度，Ana 得到三。charAt 括号零，读取第一个位置的字符，得到大写 A。substring 括号一逗号三，取得从位置一开始、到位置三之前的那一段，所以结果是 n 和 a。右边界不包含在结果里，这个范围规则需要特别看清。这里有一个写法差别：数组长度用 length，不带括号；字符串取得长度用 length 括号。后者是在调用字符串提供的方法。我们先用简单英文内容练习这些操作，复杂文字的字符表示留到后续学习，不把这个长度直接当成所有文字里人眼看到的字符个数。

```java
String name = "Ana";
System.out.println(name.length());
System.out.println(name.charAt(0));
System.out.println(name.substring(1, 3));
```

运行或错误检查结果：
```text
3
A
na
```

画面要点：字符串 length() 带括号；charAt 从下标 0 开始；substring 包含左端，不包含右端

### java-07-5 比较文字内容，接住新结果

比较两段文字内容是否相同，可以调用 equals。name 保存 Ana，name 点 equals 括号 Ana 的结果就是 true。不要把前面比较两个整数的双等号，直接当成比较字符串内容的通用办法。字符串还可以交回大小写转换后的结果。toUpperCase 返回全部转成大写的文字，我们把它保存进 upper，得到 ANA。原来的 name 仍然显示 Ana，因为这次操作没有把原字符串内容原地改掉。对初学者来说，先记住一个很实用的检查方法：调用一个操作以后，问它是改变已有对象，还是交回一个新结果。如果它交回结果而我们没有接住，后面继续读取原变量，可能仍然看到原来的内容。本页正好用两个变量把这种差别摆出来。

```java
String name = "Ana";
System.out.println(name.equals("Ana"));
String upper = name.toUpperCase();
System.out.println(name);
System.out.println(upper);
```

运行或错误检查结果：
```text
true
Ana
ANA
```

画面要点：文字内容比较使用 equals；转换操作交回新字符串；name 保持 Ana，upper 保存 ANA

### java-07-q 课堂练习：长度能当最后下标吗

scores 保存三份成绩。现在用 scores 点 length 作为下标去取值，会得到最后一项一百吗？还是会遇到问题？先写出这份数组的长度，再写出从零开始的全部合法位置。把这两组数摆在一起，就不容易凭直觉把“共有三项”误解成“最后编号为三”。给你四秒。这道题的写法可以通过编译，所以还需要继续判断运行时实际访问的位置是否存在。我们会把结果明确标成运行时异常，再给出只改一个位置的正确版本。

（朗读结束后，四秒独立思考）

```java
int[] scores = {60, 80, 100};
System.out.println(scores[scores.length]);
```

运行或错误检查结果：
```text
运行时异常：ArrayIndexOutOfBoundsException
```

画面要点：length 是 3；合法位置只有 0、1、2；区分能编译与访问有效

### java-07-a 答案：最后一个下标要减一

原题运行时会发生数组下标越界异常，因为试图访问不存在的第四个位置。它不是读到一个自动补出来的零，也不是返回最后一项。把下标改成 scores 点 length 减一，本例就是二，才读到最后的一百。这个写法的前提是数组至少有一项；如果一项都没有，就需要先检查长度，不能继续套用最后一项的访问方式。我们现在只处理这份明确有三个元素的数组，所以结果确定是一百。以后遇到一组数据，先确认有没有内容，再确认要访问的位置，最后才读取数据。这个顺序比先访问、出了异常再猜哪里不对，更能帮助你写出清楚的小程序。

```java
int[] scores = {60, 80, 100};
if (scores.length > 0) {
    int last = scores.length - 1;
    System.out.println(scores[last]);
}
```

运行或错误检查结果：
```text
100
```

画面要点：先确认数组不是空的；最后一项位于 length - 1；本例读取下标 2，得到 100

## 方法 · Methods

### java-08-1 给一组步骤起名字

假设程序里多次需要显示同一句欢迎语。可以把这条操作放进一个方法，给它起名 greet。后面写 greet 括号，就是调用它，进入方法里面完成那组步骤。本页的方法写在 Main 类里面、main 方法外面，完整文件会显示这个位置关系。定义方法时说明步骤是什么，遇到调用时才真正执行，所以不会因为我们写了定义，就先自动显示一遍。这里 static 暂时配合 Main 里的调用方式使用，表示方法属于这个类，不必先建立一个 Main 对象。void 表示它不交回一个需要接收的计算值。本页只做显示动作。先把方法理解成一个有名字的小任务，下一页再让它接收数据、交回结果。

```java
static void greet() {
    System.out.println("Hello!");
}
```

运行或错误检查结果：
```text
Hello!
Hello!
```

画面要点：方法把一组步骤组织起来；定义不等于立即执行；写 greet() 才发起调用

### java-08-2 交入参数，再交回结果

add 这个方法负责把两个整数相加。括号里的 a 和 b 是本次调用接收数据的位置，前面的 int 说明它们接收整数。调用 add 括号三逗号五时，三交给 a，五交给 b。return 把算出的八交回调用位置，我们再把它保存到 result，或者直接交给显示操作。方法名前面的 int 表示这个方法会返回整数，和上一页的 void 不同。参数名字可以帮助方法内部表达步骤，不要求调用者也必须使用同样名字的变量。关键是传入的顺序、数量和类型符合要求。把箭头画成“调用者交入三和五，方法计算，再交回八”，就能看清数据怎样经过这个小任务，而不是把函数名字当成凭空得到答案的词。

```java
static int add(int a, int b) {
    return a + b;
}
```

运行或错误检查结果：
```text
8
```

画面要点：参数接收本次调用的数据；返回类型 int 表示交回整数；return 把结果交回调用位置

### java-08-3 把判断规则放进方法

方法不只会做算术，也可以把一条判断规则集中写清楚。isPassed 接收一个成绩，返回这个成绩是否至少达到六十。返回类型是 boolean，所以调用结果是真或假。给它五十九，得到 false；给它六十，得到 true。如果程序里多个地方都需要及格规则，调用同一个方法，就不用在不同位置反复手抄条件。return 会结束这一次方法调用，把结果交回去；它不是让所有程序都立刻停止。接收到结果以后，main 还可以继续显示、作条件判断，或者执行下一次调用。把常用规则交给一个小方法，也方便以后只在一个清楚的位置调整规则，再重新检查各处调用是否得到合适的结果。

```java
static boolean isPassed(int score) {
    return score >= 60;
}
```

运行或错误检查结果：
```text
false
true
```

画面要点：方法也可以返回判断结果；同一规则集中表达；return 结束本次方法调用

### java-08-4 变量有自己的使用范围

再回头看看大括号对名字的影响。bonus 在 if 的大括号里面声明，只能在它所属的有效范围里使用。走出这组大括号以后，外面的显示语句不能直接继续使用这个局部名字。所以本页会编译失败。不是条件明明成立却不肯执行，而是编译器先发现外面这一处 bonus 没有可用的声明，整个程序还不能开始运行。如果后面确实也要用到它，就应该在合适的外层先声明并准备初值，再让里面的分支按需要修改。不要因为看到一个地方出现过名字，就认为整个文件里任何位置都能使用。方法的参数和局部变量，也要结合它们所属的方法和大括号范围来理解。

```java
int score = 80;
if (score >= 60) {
    int bonus = 5;
    System.out.println(score + bonus);
}
System.out.println(bonus);
```

运行或错误检查结果：
```text
编译失败：bonus 在外层语句中不可用
```

画面要点：局部名字有使用范围；if 内声明的 bonus 不供外层使用；先通过编译，再讨论运行路线

### java-08-q 课堂练习：外面的成绩变了吗

score 是八十，交给 addFive 方法。方法内部给参数 value 加五，但没有把一个结果返回给调用者。方法结束后，外面的 score 会是八十还是八十五？先把方法参数和调用者的整数变量画成两个位置。调用时把整数值交进去，是否就意味着方法内部给参数赋值，会自动改掉外面的那一个变量？给你四秒。这里先只讨论整数值，不把后面对象的关系混进来。判断完以后，我们会用一个明确交回新值、再保存回原变量的版本完成真正的加分。

（朗读结束后，四秒独立思考）

```java
static void addFive(int value) {
    value += 5;
}
public static void main(String[] args) {
    int score = 80;
    addFive(score);
    System.out.println(score);
}
```

运行或错误检查结果：
```text
80
```

画面要点：调用时传入整数的值；value 是方法自己的参数位置；观察是否把结果保存回 score

### java-08-a 答案：交回新值，再保存回去

原题显示八十。调用时，参数 value 得到一份整数值，方法内部把这个参数位置改成八十五，并没有自动给外面的 score 重新赋值。修正版让方法返回 value 加五的结果，再由调用者写 score 等于这次调用结果，外面的成绩才明确更新为八十五。读取旧值、计算新值、交回结果、保存回去，这四个步骤都有对应位置。Java的方法传参采用传值方式。遇到对象时，传递的值可以是对象引用，后面会再看它怎样影响对象内容。但参数本身都不是一个可以通过重新赋值就自动改绑调用者变量的神秘通道。今天先用整数把最基本的路线看懂。

```java
static int addFive(int value) {
    return value + 5;
}
public static void main(String[] args) {
    int score = 80;
    score = addFive(score);
    System.out.println(score);
}
```

运行或错误检查结果：
```text
85
```

画面要点：原题只修改方法内的整数参数；修正后返回 85；调用者明确保存新结果

## 类与对象 · Classes and Objects

### java-09-1 把同一位学生的数据放在一起

现在一位学生既有姓名，又有成绩。把这些相关数据和显示它们的方法放在同一个定义里，就可以用 class 声明一个 Student 类。类说明这种记录由什么组成，对象则是一份实际建立出来的记录。Main 里面写 new Student，就创建一个学生对象，再通过变量 s 使用它。写 s 点 name 或 s 点 score，访问的是这一位学生对应的字段。字段可以先理解成对象内部有名字的数据。show 则是操作这份数据的方法。调用 s 点 show，显示它自己的姓名和成绩。前面先分别学习变量、方法和使用范围，是为了让现在这组结构不再突然出现很多无法解释的词。类就是把有关联的东西组织到一起，让它们围绕同一个对象工作。

```java
class Student {
    String name;
    int score;
    void show() {
        System.out.println(name + " " + score);
    }
}
```

运行或错误检查结果：
```text
Ana 80
```

画面要点：类定义相关数据与操作；new Student 创建一个具体对象；s.show() 使用这份对象的数据

### java-09-2 两个对象各有一份成绩

同一个 Student 类可以创建多个对象。a 使用一位学生对象，b 使用另一位。分别给它们准备姓名和成绩，修改 a 的分数，并不会自动把 b 的分数也改掉。屏幕最后显示 a 是八十五，b 仍然是九十。这和前面整数变量分别保存值有相似的观察方法，但这里两份成绩分别放在各自的对象内部。特别留意，建立了两份对象，是因为这里执行了两次 new Student。类型定义没有重新抄两遍，也能得到多份不同的状态。以后你会看到很多同一种类的对象放进集合里，每一份都按同样规则使用，又保存各自的信息。先把类作为说明、对象作为实际记录的关系分清，就能继续理解创建时的准备工作。

```java
Student a = new Student();
Student b = new Student();
a.name = "Ana"; a.score = 80;
b.name = "Bo"; b.score = 90;
a.score = 85;
System.out.println(a.score + " " + b.score);
```

运行或错误检查结果：
```text
85 90
```

画面要点：两次 new，创建两个对象；对象内部各有自己的字段；只修改 a，不会自动修改 b

### java-09-3 构造方法准备对象的初始值

为了看清创建过程，暂时只保留成绩字段。Student 里面这个和类同名、没有返回类型的方法，是构造方法。new Student 括号八十，会在建立对象时把初始分数交进来。构造方法把参数保存进对象的 score 字段，对象准备好以后，就可以通过 getScore 读取八十。不要在构造方法前面补一个 void，那会把它写成另一种普通方法，而不是这里的创建入口。前面 Main 里的静态小方法可以直接通过类来使用；这里 getScore 通过某个 Student 对象调用，才知道读取的是哪位学生的成绩。它没有 static。先用“有没有需要操作的具体对象”理解这种差别，比把 static 机械地加在每一个方法前面更清楚。

```java
class Student {
    int score;
    Student(int initialScore) {
        score = initialScore;
    }
    int getScore() { return score; }
}
```

运行或错误检查结果：
```text
80
```

画面要点：构造方法与类同名，无返回类型；创建时交入初始成绩；getScore 通过具体对象读取字段

### java-09-4 通过公开方法使用内部数据

把 score 字段前面加上 private，就不让类外代码直接随意读写它。外面通过公开的 getScore 和 setScore 使用成绩，类自己可以把读取或修改的规则集中放在这些入口里。参数和字段现在都叫 score，所以 this 点 score 明确表示当前对象自己的字段，普通 score 表示这次传入的参数。this 可以先理解成“正在使用的这个对象”，不用把它当成所有对象共享的另一个分数。还有一件重要的事：Student 变量保存的是使用对象的引用，可以先把它想成通向对象的入口。给另一个 Student 变量赋同一个引用，并不等于又执行了一次 new 创建新学生。下一道题就专门观察这两种情况，避免把复制整数值的印象不加区分地套到对象上。

```java
class Student {
    private int score;
    Student(int score) { this.score = score; }
    public int getScore() { return score; }
    public void setScore(int score) {
        this.score = score;
    }
}
```

运行或错误检查结果：
```text
85
```

画面要点：private 字段通过公开方法使用；this.score 指当前对象的字段；对象变量保存通向对象的引用

### java-09-q 课堂练习：一个对象还是两个对象

a 通过 new Student 创建了一位八十分的学生。下一行 b 等于 a，没有再写 new。通过 b 把成绩改成九十，最后通过 a 读取，会得到八十还是九十？请数一数真正创建对象的操作执行了几次。两个变量名字出现了，是否就一定代表两位互不相关的学生？给你四秒，试着画两个入口和它们通向的记录。我们这次不是给方法参数重新赋值，而是沿着 b 找到对象，再调用方法修改那份对象内部的数据。把“名字指向谁”和“对象里面有什么”分开，就能找出答案。

（朗读结束后，四秒独立思考）

```java
Student a = new Student(80);
Student b = a;
b.setScore(90);
System.out.println(a.getScore());
```

运行或错误检查结果：
```text
90
```

画面要点：只执行了一次 new Student；a、b 通向同一个对象；setScore 修改对象内部的成绩

### java-09-a 答案：两条入口对应同一份记录

原题显示九十，因为 a 和 b 都使用同一个学生对象。通过 b 改掉内部的成绩，通过 a 读取时，自然也看到这份记录的新状态。如果希望 b 使用独立记录，就要另外建立一个对象。修正版执行第二次 new，把 a 当前的八十分交给新对象，再修改 b，结果就是 a 仍然八十，b 是九十。这也和方法传值的规则相容：复制一个对象引用，可以让两个位置都找到同一个对象；通过它修改对象内容会被其他入口观察到。它不等于复制整份对象，也不等于给参数另一个引用就能自动改绑外面的变量。先画清入口和记录，再逐步跟踪具体修改。

```java

```

运行或错误检查结果：
```text
80 90
```

画面要点：原题共享一份对象，所以读到 90；修正版再次 new，建立独立对象；修改 b 的成绩后，a 保持 80

### java-10-3 按照姓名查找成绩

列表适合按照位置读取。如果需求变成“查询 Ana 的成绩”，每次都靠自己记住 Ana 在第几个位置，就容易弄错。HashMap 可以建立姓名和成绩之间的对应关系。这里尖括号里的两个类型，前一个 String 是用来查找的姓名，后一个 Integer 是对应的分数。姓名叫作键，分数叫作值。put 把一组对应关系保存进去，get 用姓名取出对应分数，所以查询 Ana 会得到八十。可以把这份表理解成通讯录：输入姓名，找到相关信息。它不依靠第零个、第一个这样的顺序，也不应该用它来保证显示顺序。先按真实需要选工具：保存一串有先后位置的数据，可以考虑列表；用唯一名字查对应信息，可以考虑这种映射表。

```java
HashMap<String, Integer> scores = new HashMap<>();

```

运行或错误检查结果：
```text
80
2
```

画面要点：姓名是键，成绩是值；put 保存对应关系，get 按键查询；HashMap 不保证显示顺序

### java-10-4 重复姓名与查不到的情况

同一个键再次放入一个值，会替换原来的对应值，不会自动变成两位同名学生。代码先把 Ana 记为八十，再记为八十五，所以表里仍然只有一项，读到的分数是八十五。查不到的时候也要提前想清楚。containsKey 可以判断某个键是否存在。getOrDefault 则允许我们给一个备用结果，这里查询没有保存过的 Cy，返回自己指定的零。这个零不等于已经录入了 Cy 的真实成绩，只是这次查询采用的默认值。如果零分本身也是合法成绩，就不能仅凭返回零断定有没有记录；应该配合是否存在的判断。先明确程序想表达什么，再选择合适的分支处理，避免把缺少数据和真实数据混为一谈。

```java
HashMap<String, Integer> scores = new HashMap<>();
scores.put("Ana", 80);
scores.put("Ana", 85);
System.out.println(scores.size() + " " + scores.get("Ana"));
System.out.println(scores.containsKey("Cy"));
System.out.println(scores.getOrDefault("Cy", 0));
```

运行或错误检查结果：
```text
1 85
false
0
```

画面要点：同一个键再次 put，会替换旧值；containsKey 判断是否存在；默认值不代表真实录入的数据

## 异常处理 · Exceptions

### java-11-1 文字不一定能转换成整数

最后学习程序遇到问题时的一种处理方法。Integer 点 parseInt 可以把表示整数的文字变成整数。比如文字八十可以转换，但 abc 并不表示一个整数，这次操作就无法正常完成。Java 会报告一个叫 NumberFormatException 的异常。把可能失败的操作放在 try 里面，用 catch 接住这种具体问题，就可以显示自己的提示，然后继续执行后面的语句。看这段代码：转换失败后，不会得到一个假装成功的数字，而是跳到对应的 catch，显示 not a number。处理完以后，继续显示 continue。如果把文字改为八十，转换成功，显示八十，catch 里面的提示就不会执行。先分清正常路线和失败路线，异常处理就有了具体含义，不只是多背一组括号。

```java
String text = "abc";
try {
    int value = Integer.parseInt(text);
    System.out.println(value);
} catch (NumberFormatException e) {
    System.out.println("not a number");
}
System.out.println("continue");
```

运行或错误检查结果：
```text
not a number
continue
```

画面要点：try 放可能无法完成的操作；catch 处理指定种类的异常；处理后继续执行后面的语句

### java-11-2 用明确规则拒绝不合理的值

程序自己的规则也可能要求拒绝某个值。这里的方法接收成绩，如果小于零或者大于一百，就用 throw 报告参数不合适，后面的正常返回不会继续执行。IllegalArgumentException 这个名字表示传入的参数不符合要求。完整示例在调用处尝试交入一百二十，并用对应的 catch 显示 bad score。换成八十，就会正常返回八十。并不是每一个判断都必须写成异常。普通的“及格还是不及格”，用 if 分支表达就足够。这里想强调的是，方法不能按约定完成任务时，应当清楚报告失败，调用的一方再根据需要处理。暂时不展开所有异常类别，只要看懂从报告问题到处理问题的这条路线，就能阅读很多入门程序。

```java
static int requireScore(int value) {
    if (value < 0 || value > 100) {
        throw new IllegalArgumentException("bad score");
    }
    return value;
}
```

运行或错误检查结果：
```text
bad score
```

画面要点：范围外的成绩不符合方法约定；throw 报告这次操作无法完成；调用处 catch 对应异常并提示

### java-11-q 课堂练习：异常改变哪一步

### java-11-a 答案：失败路线跳过 B

原题显示 A、C、D。A 在转换之前已经显示。转换失败后跳到 catch，try 里面剩下的 B 被跳过，显示 C，再执行结构后面的 D。画面把转换内容改成正常的八十，用另一条路线做对照。这次转换成功，继续执行 B，不进入 catch，所以显示 A、B、D。两种情况放在一起，更容易看清 catch 的作用。不要只记住一串字母，要记住执行过程：先按顺序做事，发生指定异常时转去相应处理，处理后继续往下。以后遇到错误信息，先找到失败的操作和具体原因，再决定怎样修正数据或者处理失败，比把所有问题都藏在一个空的 catch 里面更有帮助。

```java
System.out.println("D");
```
