### net-01-02 计算机网络是什么

1. 网络边缘

手机、电脑和服务器等端系统，产生和接收数据

2. 网络核心

交换机与路由器等转发设备，负责把数据送过去

3. 网络分类

按覆盖范围分为局域网、城域网和广域网

先看一个小场景：你在宿舍用手机打开学校的选课网站。手机是通信的一端，学校服务器是另一端，中间经过无线接入点、交换机和路由器。手机和服务器这类真正产生数据的设备，叫网络边缘，也叫端系统；中间负责转发数据的设备，叫网络核心。网络就是用硬件和规则，让边缘这些设备互相传递数据。

### net-01-03 性能指标：带宽、吞吐量与时延

1. 带宽与吞吐量

带宽是链路能力上限，吞吐量是实际传送量

2. 发送时延

分组长度除以链路带宽，与数据量和速率有关

3. 传播时延

链路长度除以传播速度，与距离和介质有关

衡量网络快慢，先分清几个指标。带宽描述一条链路在单位时间内的传送能力上限，吞吐量是实际传送成功的多少。真正感受到的端到端时延由四部分相加：发送时延、传播时延、处理时延和排队时延。例如一个一千字节的分组就是八千比特，经过一条一兆比特每秒的链路，发送时延等于八千除以一兆，结果是八毫秒。

### net-01-04 分层思想与协议栈

1. 分层

把复杂问题拆成若干层，每层只解决一类问题

2. 协议

同层对等实体之间通信时遵守的规则

3. 封装与解封装

逐层加首部，接收方再逐层去掉首部

分层是把复杂问题拆开的办法。想象寄快递：你只负责把物品装进箱子、写清收件地址；快递公司负责运输和中转；收件人负责拆箱验货。每一方只关心自己的任务，不需要知道别人的全部细节。网络也一样，应用层产生数据，传输层负责端到端交付，网络层负责寻址和转发，链路层负责送过一段链路。

同一层的两个对等实体之间通信，要遵守共同的规则，这就是协议。相邻两层通过接口交换数据：上层把整块数据交给下层，下层把它当作数据部分，再加上自己的首部，这叫封装。接收方从物理层向上，每层去掉自己的首部交给上层，叫解封装。每一层都在为上层提供服务，同时使用下层提供的服务。

### net-01-05 OSI七层与TCP/IP四层

1. OSI参考模型

物理、数据链路、网络、传输、会话、表示、应用

2. TCP/IP四层

网络接口、网际、传输、应用

3. 对应关系

会话与表示并入应用层，物理与链路合为网络接口层

教材里常出现两套分层模型。OSI参考模型分为七层：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。它的好处是概念清楚，便于描述每层职责，但它更多是理论参考，不等于实际运行的协议栈。互联网实际使用TCP/IP模型，把会话层和表示层并入应用层，把物理层和数据链路层合称网络接口层，于是变成四层。

### net-01-06 封装与解封装的完整过程

1. 发送方

应用数据逐层加首部，形成各层的数据单元

2. 接收方

逐层检查并去掉首部，交给上一层

3. 地址的作用范围

MAC地址管同一链路，IP地址管跨网络，端口号管进程

现在把封装过程走一遍。你在浏览器里请求网页，应用层生成HTTP请求报文。传输层加上TCP首部，标明源端口和目的端口，形成报文段。网络层加上IP首部，标明源IP和目的IP，形成IP分组。链路层再加帧首部和帧尾，标明源MAC和目的MAC，形成帧。物理层把帧变成信号发送出去，每往下一层就多一层首部。

## 物理层与数据编码

### net-02-01 物理层的任务：比特与信号

1. 比特

计算机里的0和1，是数据最终的存在形式

2. 信号

用电压、光强或电磁波的变化来承载比特

3. 传输介质

双绞线、光纤和空气等承载信号的物理通道

先看一个最基础的场景。你敲下一个字母，计算机里先出现一串零和一，物理层要做的，就是把这串比特变成能沿线路传出去的信号。比如用高电平表示一，低电平表示零，接收方再把电压变化读回成零和一。比特是数据，信号是它在介质上的表现形式。

持续高亮：[1, 2]；显示到第2行；提示：比特是数据，信号是表现形式；物理层只负责比特流

物理层只负责比特流的透明传输，不关心这些比特是帧、分组还是网页内容。它规定接口的机械和电气特性，比如用几根线、电压范围多大、什么时候采样。这里有个常考点，物理层传的是比特而不是帧，帧是数据链路层的单位。信号会衰减，也会受噪声干扰，所以传输距离有限。

### net-02-02 数据编码与调制

1. 编码

把0和1映射成电压高低等离散电平的波形

2. 调制

把基带信号搬到高频载波上，便于远距离和无线传输

3. 码元与比特率

一个码元可带多个比特，比特率等于波特率乘每码元比特数

先看网线里的编码。发送端先把零和一画成高低电平的波形，把要发的比特按固定时间长度切成一段一段，每一段叫一个码元。最简单的办法是高电平表示一，低电平表示零。为了让接收方提取时钟，工程上常用曼彻斯特编码，让每个码元中间都有一次电平跳变。

### net-02-03 传输介质：双绞线、光纤与无线

1. 双绞线

四对铜线两两绞合，价格低，适合室内短距离布线

2. 光纤

纤芯靠全反射传光，带宽大，抗电磁干扰

3. 无线

以空气为介质，灵活但容易受遮挡和同频干扰

先看宿舍到机房这一段。墙里走的大多是双绞线，里面是四对铜线，两两绞合在一起，绞合能让外界干扰在两根线上产生的效果互相抵消。铜线便宜，施工也方便，但距离一长信号就衰减，所以一段网线通常不超过一百米。光纤用玻璃纤芯传光，带宽大，也不怕电磁干扰。

### net-02-04 信道复用：频分、时分、波分与码分

1. 频分

把频带切成互不重叠的子频带，每路长期占用一段

2. 时分

把时间切成时隙，各路轮流占用整个频带

3. 波分与码分

波分是光纤上的频分，码分靠不同码序列区分用户

先看一条要同时承载很多路电话的干线。如果每路都独占一根线，成本太高，于是把线路资源分给多路信号同时使用，这叫信道复用。频分最直观，把可用频带切成若干互不重叠的小段，每路固定占一段，一直占用，就像不同的广播电台各用一个频率。

持续高亮：[1]；显示到第1行；提示：复用是把线路资源分给多路；频分每路固定占一段

时分是把时间切成小片，各路轮流占用整个频带，每一路只在属于自己的时隙里发送。光纤上用波分，本质是按不同波长分路。码分让所有用户同时同频发送，靠不同的正交码序列区分。辨析时记住，频分是同时不同频，时分是同频不同时，码分是同时同频不同码。

### net-02-05 奈氏准则与香农定理

1. 奈氏准则

理想低通信道每秒最多传2W个码元，W是带宽

2. 香农定理

有噪声时容量为 W×log2(1+S/N)

3. 例题

3 kHz、16种码元：2×3000×4=24000 bps

先看一个理想化的计算。一条带宽为三千赫兹的理想低通信道，每秒最多能传过六千个码元，这个上限来自奈氏准则，也就是带宽的两倍。每个码元能带多少比特，取决于码元有多少种状态。如果每个码元有十六种状态，就相当于四比特，最高数据率就是六千乘以四，等于两万四千比特每秒。

持续高亮：[1]；显示到第1行；提示：无噪声看码元数量；带宽两倍是码元速率上限

真实信道一定有噪声，这时用香农定理。容量等于带宽乘以以二为底一加信噪比的对数。信噪比常用分贝表示，三十分贝换算成比值正好是一千。三千赫兹带宽、一千倍信噪比，容量约等于三千乘以十，也就是约三十千比特每秒。做题时先看条件，给码元数用奈氏，给信噪比用香农。

### net-02-06 数据交换方式：电路、报文与分组

1. 电路交换

先建立连接，通信期间独占通路，时延稳定

2. 报文交换

整个报文存储转发，不建连接，时延较大

3. 分组交换

报文切成小分组存储转发，共享链路，效率高

### net-05-02 分片规则

1. MTU

链路一次能承载的最大IP数据报长度，以太网常为1500字节

2. 8 字节单位

除最后一片外，每片数据长度必须是8字节的整数倍

3. 偏移计算

片偏移等于本片数据起点除以8，单位是8字节

数据从以太网发出，长度受链路限制。以太网一帧最多携带一千五百字节的IP数据报，这个上限叫MTU，也就是最大传输单元。若一个数据报总长超过MTU，路由器就要把它切成几片。切的时候每片配二十字节的IP首部，数据尽量取满，最后一片装剩下的部分。

持续高亮：[1, 2]；显示到第2行；提示：MTU限制一次能传多长；每片都要重新加IP首部

分片有两条硬规则。第一，除最后一片外，每片数据长度必须是八字节的整数倍，因为片偏移字段只记录八字节单位的个数。第二，片偏移等于本片数据起点除以八，第一片从零开始。做计算题时先算每片能装多少数据，再算偏移和MF，别把首部的二十字节算进数据里。

### net-06-03 转发过程与默认路由

1. 查表

取出目的地址，按最长前缀匹配找到表项

2. 默认路由

0.0.0.0/0匹配任何目的地址，作为最后的兜底

3. 逐跳转发

每台路由器只决定下一跳，不掌握完整路径

把一次转发拆成几步。路由器收到帧，先校验并去掉帧首尾，取出IP分组，读出目的地址。然后拿目的地址查路由表，按最长前缀匹配确定出接口和下一跳。接着把TTL减一，重新计算首部校验和，再用出接口的MAC地址重新封装成帧发出去。整个过程在毫秒级内完成。

### net-07-02 UDP 的特点

1. 无连接

发送前不建立连接，直接把数据交给网络层

2. 不可靠

不确认、不重传，丢了就丢了

3. 开销小

### net-07-03 TCP 的特点

1. 面向连接

通信前三次握手建连接，结束后四次挥手释放

2. 可靠有序

确认与重传保证数据不丢不乱，按序号重排

3. 字节流

### net-07-05 四次挥手与 TIME_WAIT

1. FIN 与 ACK

主动方发FIN，被动方先回ACK，再发自己的FIN

2. 半关闭

一方停止发送后，另一方还可以继续发数据

3. TIME_WAIT

主动关闭方等2MSL，保证最后ACK送到并清掉旧报文

连接用完要释放。假设客户端先关，它发一个FIN，序号两千，表示没有数据要发了。服务器先回ACK，确认号两千零一，但它可能还有数据没发完，所以等数据发完再发一个FIN，序号六千。客户端回ACK，确认号六千零一。整个过程四个报文，因此叫四次挥手。

持续高亮：[1, 2]；显示到第2行；提示：主动方发FIN表示不再发送；服务器可能还有数据要发

四次挥手的关键在半关闭。TCP两个方向独立关闭，一方发了FIN只是这个方向不再发数据，另一个方向还可以继续发，所以中间的ACK和FIN不能合并。主动关闭方进入TIME_WAIT状态，等两倍报文最大生存时间，也就是2MSL。这样有两个作用：保证最后那个ACK能到达，以及让旧连接的残留报文消失。

## TCP可靠传输与流量控制

### net-08-01 序号与确认机制

1. 序号

TCP 把字节流逐个编号，序号字段填本报文段第一个字节的编号

2. 确认号

确认号是期望收到的下一个字节编号，收到 1 到 2000 就回 2001

3. 累积确认

确认号之前的字节都已收到，一次确认能覆盖好几个报文段

先看一个具体场景。发送方把要发的数据看成一串连续的字节，从第一个字节开始编号。假设每段带 1000 个字节，第一段的序号是 1，第二段是 1001，第三段是 2001。接收方按编号拼回去，再回一个确认，告诉发送方下一步想收哪个字节。

持续高亮：[1, 2]；显示到第2行；提示：先按字节编号；序号不是报文段编号

确认号填的是期望收到的下一个字节编号。前面 2000 个字节都到了，接收方就回 2001，而不是回 2000。一次确认覆盖多个报文段的做法叫累积确认，中间某段丢了，后面的确认会重复同一个编号。这里有个常考点：序号和确认号都按字节编号，不是按段数编号。

### net-08-02 超时重传与 RTT 估计

1. RTO

重传超时时间，发出后超过这段时间还没收到确认就重发

2. 加权平均

平滑往返时间和偏差一起决定 RTO，公式是 RTTs 加四倍 RTTd

3. 退避

超时后把 RTO 翻倍，连续超时就一次次把间隔拉长

再看丢包怎么办。发送方每发出一段就启动一个计时器，时间到了还没收到确认，就认为这一段可能丢了，于是重发一遍，这叫超时重传。计时器的时长叫 RTO。RTO 定得太短，确认还在路上就重发，白白浪费带宽；定得太长，丢包要等很久才补上，传输就慢。

持续高亮：[1]；显示到第1行；提示：计时器到期就重发；RTO 不能乱定

所以 RTO 要根据往返时间动态估计。做法是先算平滑值 RTTs，再算偏差 RTTd，最后用 RTTs 加四倍 RTTd 得到 RTO。超时后通常把 RTO 翻倍，这叫退避，避免网络已经堵了还不停重发。超时重传要等计时器到期，快重传靠重复确认触发，不用等。

持续高亮：[2, 3]；显示到第3行；提示：RTO 按往返时间估计；超时后要退避

## TCP拥塞控制

### net-09-01 拥塞控制与流量控制的区别

1. 控制对象

流量控制管接收方缓存，拥塞控制管整个网络的承载能力

2. 判断依据

流量控制看接收窗口，拥塞控制看丢包和往返时间的变化

3. 结果

流量控制限制发送量，拥塞控制调整拥塞窗口和发送速率

先分清两个容易混的概念。假设接收方缓存还很空，可中间链路和路由器已经排长队，分组开始被丢弃，这时只盯着接收窗口就不够了。网络本身也会堵，拥塞控制就是让发送方根据网络拥堵程度调整发送量，避免把更多分组塞进堵住的链路。

持续高亮：[1]；显示到第1行；提示：网络本身也会堵；不能只看接收方

流量控制和拥塞控制管的对象不同。流量控制看接收方，依据是接收方通告的接收窗口，怕把接收方缓存撑爆；拥塞控制看网络，依据是超时和重复确认这类丢包信号，靠调整拥塞窗口改变速率。发送窗口取两者中较小的那个，两个机制是配合，不是替代，两者要一起看。

### net-09-03 快重传与快恢复

1. 三个重复 ACK

接收方收到失序段就重复确认同一个编号，连发三次

2. 快重传

发送方收到三个重复确认，立即重发丢失的那一段，不等超时

3. 快恢复

门限设为当前窗口的一半，窗口降到门限，直接进入拥塞避免

再看一种更常见的情况。某一段在网络里丢了，后面几段却到了，接收方每收到一个失序段，就重复回同一个确认号，意思是这里还缺一段。发送方连着收到三个重复确认，就知道不是偶发的乱序，而是真丢了，可以马上重传，不必等到计时器超时。

这套动作叫快重传加快恢复。快重传是立刻重发丢失段；快恢复是把慢启动门限减半，窗口降到门限，然后直接进入拥塞避免，不必回到 1。对比一下：超时说明情况更严重，窗口打回 1 重新慢启动；三个重复确认只减半，两者触发条件不同，不要混用。

### net-10-02 HTTP 与 HTTPS

浏览器发请求行和首部，服务器回状态码和网页内容

2. 持久连接

一个 TCP 连接上可以连续发多个请求，减少握手开销

3. TLS 加密

HTTPS 在 HTTP 下面加一层 TLS，端口从 80 变成 443

解析完域名，浏览器和服务器建立 TCP 连接，然后在上面发 HTTP 请求。请求里有方法、路径和首部，服务器回状态码和网页内容。HTTP 是无状态的，请求独立处理。早期每个请求都新建连接，后来用持久连接，一个连接上可以连续发多个请求，省掉反复握手。

HTTP 的内容是明文传的，中间节点能看到，于是有了 HTTPS。HTTPS 等于 HTTP 加上 TLS，端口从 80 变成 443，多了一层加密。它多了一次 TLS 握手，用来协商密钥、验证服务器身份。易错点：HTTPS 不是新协议，是 HTTP 套上安全层。

### net-10-03 访问一个网页的完整过程

1. DNS 查询

先把域名换成 IP 地址，可能要经过缓存和多次查询

2. TCP 握手

和服务器建立连接，三次握手用掉一个往返时间

3. 请求与响应

发 HTTP 请求，收到响应后浏览器解析并加载资源

把访问网页的过程完整走一遍。输入网址后，浏览器先查缓存，没有就让本地域名服务器把域名解析成 IP 地址。拿到 IP 后，浏览器和服务器建立 TCP 连接，完成三次握手；如果是 HTTPS，还要再做 TLS 握手。连接建好，才发送 HTTP 请求。

持续高亮：[1, 2]；显示到第2行；提示：先解析域名再握手；HTTPS 多一次 TLS 握手

响应回来后，浏览器解析网页，遇到图片、样式和脚本，还要再对相应的服务器发请求，每个新资源都可能重复解析和请求。打开一个网页的耗时，往往是多次往返叠加的结果。易错点：域名解析在 TCP 握手之前，TLS 握手在 TCP 握手之后。

### net-10-04 DHCP、FTP 与邮件协议

1. DHCP 四步

发现、提供、请求、确认，自动拿到 IP 地址和网关

2. FTP 双连接

控制连接用 21 端口，数据连接用 20 端口，命令和数据分开

3. SMTP 与 POP3

SMTP 用 25 端口发邮件，POP3 用 110 端口把邮件收回来

再串几个常考协议。新电脑接入网络时，先由 DHCP 自动分配地址，过程分四步：发现、提供、请求、确认，服务器把 IP 地址、网关和域名服务器一起交给主机。文件传输用 FTP，它开两条连接，控制连接走 21 端口，数据连接走 20 端口。

持续高亮：[1, 2]；显示到第2行；提示：DHCP 四步拿地址；FTP 控制和数据分开

电子邮件也有分工。发邮件用 SMTP，端口 25，负责把邮件从客户端推到服务器；收邮件用 POP3，端口 110，把邮件取回本地。容易错的是以为 SMTP 能发也能收，其实收信要靠 POP3 或 IMAP。记忆时把协议和端口成对记。
