# Agent Harness 机制速查

模型根据当前输入提出下一步。运行时负责把这个提议转成受约束、可记录、可恢复的实际执行。不同产品会拆分、合并或扩展这些职责。

| 问题 | 应检查什么 | 常见误解 |
| --- | --- | --- |
| 模型怎么操作文件？ | 工具目录、调用对象、分发、实际结果 | 输出“已修改”就等于文件已变 |
| 为什么能连续修错？ | 工具结果追加上下文，再次调用模型 | 一轮对话只有一次模型调用 |
| 参数合法就能执行吗？ | 结构、权限、业务结果三道独立判断 | 通过 JSON 校验即获授权 |
| 模型为什么忘了文件？ | 本轮上下文选择与外部检索 | 磁盘有文件，模型就自动知道 |
| 摘要写通过就可靠吗？ | 测试记录、对应版本、当前产物 | 摘要是一份无损且永不过期的记忆 |
| 远程工具受本地限制吗？ | 本地隔离范围及远程服务自身权限 | 本地沙箱自动覆盖所有连接器 |
| 工具超时可直接重发吗？ | 实际执行状态、接收方幂等与核对 | 超时一定表示没有执行 |
| 检查点能解决一切吗？ | 持久落盘、外部副作用、去重/事务/补偿 | 恢复记录等于回滚现实 |
| 能否让多个工具并行？ | 依赖、输入版本、共享状态和冲突 | 并行总比顺序更快更安全 |
| 取消会撤销操作吗？ | 后续任务、已提交请求与补偿结果 | 点击取消等于业务回滚 |
| 终答算成功了吗？ | 应用明确的验收条件与实际证据 | 最后一条消息出现即成功 |
| 怎么定位失败？ | 关联标识、参数、错误、耗时与恢复路径 | 只看最终聊天文本即可 |

## 最小控制流

1. 读取任务状态，选择本轮上下文与可用工具。
2. 调用模型，解析它的回复。
3. 若请求工具，校验结构、检查授权，然后执行。
4. 保存真实结果及状态，带反馈进入下一次循环。
5. 若产生终答，按应用条件验收；若等待、失败、取消或预算耗尽，记录对应状态。

以上是解释框架的简化控制流。生产系统还需考虑流式事件、资源回收、并发一致性、数据保护及外部服务故障。

## 画面怎样阅读

蓝色为请求或输入，橙色为正在推进的动作，绿色为确认结果，红色为失败、拒绝或停止，紫色为状态与版本。具体节点文字优先于配色。移动圆点表示请求或证据沿路径传递，不表示模型隐藏推理。箭头走完后保留当前状态，右侧要点与当前段旁白对应。
