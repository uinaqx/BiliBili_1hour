# 一小时学习C语言：完整讲稿

面向没有编程经验的学生；C11。章节时间按实际配音生成。

## 课程导学 · Introduction

### c-00-1 程序是一组清楚的步骤

同学们好，这一小时，我们从零开始学习C语言。你不需要事先认识任何程序，也不用先记住一长串英文名词。我们从一个小需求出发：保存几位同学的成绩，判断是否及格，算出平均分，最后把结果写进文件。你可以把程序理解成写给电脑的一组步骤。比如先拿到分数，再和六十分比较，根据比较结果显示一句话。电脑不会猜我们的意思，所以步骤需要用它认识的形式表达，这种表达方式就是编程语言。屏幕左边是代码，下方是程序真正运行后的结果，右边是当前这一步的提示。每次先看看我们想完成什么，再看哪一行负责完成它。练习出现时，会留四秒让你先预测，随后我们一起解释。先把一个个小例子看懂，再慢慢连成完整程序。

画面要点：从显示一句话开始；围绕姓名与成绩写程序；看代码 → 预测 → 验证

### c-00-2 第一段完整的 C 程序

先看这段完整的小程序。它只做一件事，在屏幕上显示一句问候。双引号里的 Hello，C，是我们想显示的文字。打印函数 printf 负责把这段文字送到屏幕上，括号里面放它需要使用的内容。第一行以井号开头，写的是引入标准输入输出头文件。先把它理解为告诉编译器，我们会用到打印等现成工具的说明。接下来，main 是程序正常开始执行的位置，后面这对大括号包住我们要做的事。打印语句末尾的分号，表示这条语句结束。双引号里反斜杠后面的小写字母 n 表示换行，它不是要打印两个普通字符。最后的 return 零表示程序正常结束。现在不要求你一次理解所有符号，先记住：从 main 开始，执行打印，然后结束。

```c
#include <stdio.h>
int main(void) {
    printf("Hello, C!\n");
    return 0;
}
```

运行结果或操作说明：
```text
Hello, C!
```

画面要点：main 是执行入口；printf 显示文字；分号表示语句结束

### c-00-3 从源文件到运行结果

我们写下来的文字叫源代码，通常保存在扩展名为点 c 的文件里。电脑不能直接把这些文字当成处理器指令运行，需要先交给编译器转换。转换成功后，才运行生成的程序。如果你使用带运行按钮的编辑器，按钮背后也包含编译和运行这两步。屏幕上的命令只是展示这个过程：先把 main 点 c 编译成名为 hello 的程序，再执行它。具体安装可以参考交付资料里的练习环境说明，现在先跟着画面理解。编译错误通常意味着代码的写法不符合规则，例如少了分号。运行结果不对，则可能是步骤写错，例如本来要加法却写了减法。遇到问题，先看错误指向的文件和行，再找第一条具体原因。不要一下子被后面很多提示吓住，我们会通过小程序逐步确认每一步。

```powershell
gcc -std=c11 -Wall -Wextra main.c -o hello.exe
.\hello.exe
```

运行结果或操作说明：
```text
编译成功后运行：Hello, C!
```

画面要点：保存 main.c；先编译，再运行；优先读第一条错误

## 变量、常量与数据类型 · Variables and Types

### c-01-1 给一份数据起名字

假设我们要保存一位同学的成绩。直接在不同地方写八十分，过一会儿就很难记住这个数字代表什么。变量就是给这份数据起一个名字，后面用名字来取出或修改它。这行声明从左往右读：int 表示我们现在准备保存整数，score 是自己取的名字，等号右边的八十是初始值。这里的等号表示把右边的值保存到左边，不是数学里“两边永远相等”的意思。下一行打印这个成绩。双引号里的百分号 d 先理解成一个整数位置，逗号后面的 score 会填到这个位置上，所以结果是八十。给变量起名时，可以用字母、数字和下划线，但不要用数字开头，也不要占用 int 这样的语言关键字。用有意义的名字，比只用一个字母更容易读懂。

```c
int score = 80;
printf("%d\n", score);
```

运行结果或操作说明：
```text
80
```

画面要点：类型 + 名字 + 初始值；等号把值存到左边；score 表示成绩

### c-01-2 变量的值可以改变

变量之所以叫变量，是因为它保存的值可以改变。现在成绩最初是八十，下一行让它增加五分。先算右边的 score 加五，也就是八十五，再把八十五存回 score。所以同一个名字，前后可以对应不同的值。它并没有同时保存八十和八十五，也不是在要求八十等于八十五。程序按顺序执行，更新之后再打印，看到的自然是新值。第一次准备这个变量时，需要写类型并声明它。后面只是修改已有变量，就直接使用名字，不必再写一次 int。另一个常见问题是只声明一个局部变量，却还没有给它值就拿来计算。这样的初值不能靠猜，写程序时应该先初始化。我们始终让小例子里的每份数据都有明确的起点。

```c
int score = 80;
score = score + 5;
printf("%d\n", score);
```

运行结果或操作说明：
```text
85
```

画面要点：先算右边，再更新左边；修改时不重复声明；使用前先给明确的值

### c-01-3 整数与带小数的数

成绩可以是八十这样的整数，平均分却可能是八十一点五。数据类型帮助我们选择合适的保存方式。int 用来保存一定范围内的整数，double 用来保存带小数的数。屏幕上 count 保存三位同学，average 保存八十一点五。打印整数用百分号 d；这里打印小数用百分号点一 f，意思是显示一位小数。你不需要现在记住所有格式，先把这两种情况对应起来。类型也会影响后面的计算。整数计算和小数计算并不总是得到一样的结果，我们下一章会亲自比较。还要记住，类型能保存的范围是有限的，不能把 int 当成无限大的整数盒子。不同环境里具体大小也可能有差别，不能单凭名字认定它永远占几个字节。初学时先选择合适的类型，并使用小而清楚的数字。

```c
int count = 3;
double average = 81.5;
printf("%d %.1f\n", count, average);
```

运行结果或操作说明：
```text
3 81.5
```

画面要点：int 保存整数；double 保存带小数的数；打印格式要与类型配合

### c-01-4 一个字符与一段文字

除了数字，我们还会遇到文字。先从最小的例子开始：一个英文字母 A，可以用 char 类型保存。字符两侧使用单引号，表示这里是一个字符值。打印这个字符使用百分号 c，所以结果是字母 A。注意单引号和双引号的区别：单引号包住的 A 是字符，双引号包住的 A 则是一段字符串的写法。它们看起来相似，在程序里却不是同一种东西。后面讲数组时，我们会正式学习怎样保存姓名和句子。现在先别把 char 当成可以保存任意长度文字的容器。尤其是中文，常见的文本编码会用多个字节表示一个汉字，不能简单认定一个汉字就能放进一个 char。为了先把语法弄清楚，本课的程序输入输出优先使用容易核对的英文和数字，中文解释放在旁边。

```c
char grade = 'A';
printf("%c\n", grade);
```

运行结果或操作说明：
```text
A
```

画面要点：char 示例：单个英文字母；字符用单引号；字符串用双引号

### c-01-5 不希望改变的值

有些值在这段程序里不希望改变，比如及格线六十分。可以在类型前面加上 const，表示通过这个名字不能再给它赋新值。屏幕上把及格线命名为 pass，后面读到这个名字，就知道六十代表什么。这比在很多地方到处写六十更容易维护。如果规则改了，我们能找到集中表达规则的位置。你也可能看到井号 define 的写法，它属于预处理阶段的文字替换，和 const 变量不是同一套机制。初学时先用 const 表达只读数据，等熟悉之后再系统区分常量表达式与预处理。本课不把它们混在一起。比如后面固定长度的数组，我们会直接写清楚元素个数，不会假定任意 const 变量都能在C语言里当作同一种编译时数组长度。现在先牢牢记住：普通变量可以更新，只读名字用来保护不该变化的规则。

```c
const int pass = 60;
int score = 80;
printf("pass=%d score=%d\n", pass, score);
```

运行结果或操作说明：
```text
pass=60 score=80
```

画面要点：const 表达只读约定；规则用有意义的名字；不同于 #define 文字替换

### c-01-q 课堂练习：按顺序跟踪变量

现在请你自己跟踪一次。变量 a 最初是三，变量 b 一开始取走 a 当时的值。随后我们把 a 改成八。最后打印 a 和 b，会看到八和八，还是八和三？这里最值得观察的是：给 b 保存初值时，是复制当时的数字，还是把两个变量永久绑在一起？暂时不要用后面还没学的指针来想，只看普通整数变量。可以在纸上给 a、b 各画一个格子，执行一行就更新对应的格子。不要从最后一行倒猜，也不要把等号看成数学方程。等四秒之后，我们把每一步的值一起列出来。

（四秒思考；随后核对答案）

```c
int a = 3;
int b = a;
a = 8;
printf("%d %d\n", a, b);
```

运行结果或操作说明：
```text
8 3
```

画面要点：a、b 分别保存一份整数；看 b 初始化时的值；最后才执行打印

### c-01-a 答案：复制的是当时的值

答案是八和三。第一行让 a 保存三，第二行读取 a 当时保存的三，再把这个三放进 b。到这里，两个变量各自都有一份值。第三行只把 a 改成八，没有任何一条语句去修改 b，所以 b 仍然是三。最后打印时，按逗号后面的顺序，先显示 a，再显示 b。这道题想帮你建立最重要的阅读习惯：程序是在执行步骤，数据也会随着步骤变化。每遇到一次赋值，都问自己右边现在是多少，算完之后写到谁里面。普通变量的值复制，不会自动形成以后一直同步的关系。等我们学到指针时，才会看到“通过地址访问同一份数据”的另一种情况。先把这两种情况留出区别，后面会更容易理解。

```c
int a = 3;
int b = a;
a = 8;
printf("%d %d\n", a, b);
```

运行结果或操作说明：
```text
8 3
```

画面要点：b 复制当时的 3；修改 a 不会自动修改 b；输出：8 3

## 运算符与表达式 · Operators and Expressions

### c-02-1 让数字参与计算

现在我们已经会保存数字，可以让它们参与计算了。加号、减号、星号和斜杠分别表示加、减、乘、除。像 a 加 b 这样能够算出一个结果的组合，就叫表达式。先看七除以二。如果两边都是整数，C语言会做整数除法，这里得到三，小数部分不会保留。再看百分号，它在这段算式里不是打印占位符，而是求余数。七除以二剩一，所以第二行结果是一。同一个符号放在不同位置，含义也可能不同。双引号内的百分号 d 属于打印格式，双引号外的 a 百分号 b 才是取余计算。判断一个数是不是偶数，就可以检查它除以二的余数是不是零。先看清符号所在的位置，再问它在这句话里负责什么。

```c
int a = 7, b = 2;
printf("%d\n", a / b);
printf("%d\n", a % b);
```

运行结果或操作说明：
```text
3
1
```

画面要点：整数除法：7 / 2 得 3；取余：7 % 2 得 1；除数不能是 0

### c-02-2 需要小数时要提前说明

如果我们真的想得到三点五，应该怎么办？让参与除法的数中至少有一个按小数类型处理，比如七点零除以二。这样就不再是刚才的整数除法。屏幕上的第一个结果是三点五，第二个结果却是三点零。原因是第二个表达式先用两个整数做完除法，已经得到三，然后才把三保存进 double。用更大的小数盒子接住结果，并不能把已经丢掉的小数部分找回来。以后计算平均分时，这个区别非常重要。可以用总分除以人数，再让其中一项参与小数运算，比如乘以一点零之后再除。读表达式时先看运算本身使用了什么类型，再看结果存进哪里。不是最后出现 double，前面所有计算就会自动变成小数计算。

```c
double a = 7.0 / 2;
double b = 7 / 2;
printf("%.1f %.1f\n", a, b);
```

运行结果或操作说明：
```text
3.5 3.0
```

画面要点：7.0 / 2 是小数运算；7 / 2 先得到整数 3；保存类型无法补回小数

### c-02-3 比较与判断

除了算出一个数，我们还需要回答一个问题：八十分是否达到六十分？大于等于这个比较符号，会产生一个表示真假的结果。条件成立时结果为一，不成立时为零。屏幕先判断 score 是否大于等于六十，得到一；再判断它是否等于六十，得到零。这里表示相等要连续写两个等号，一个等号仍然是赋值。它们的作用完全不同，后面写判断时一定要分清。其他比较还有大于、小于、小于等于，以及感叹号加等号表示不等于。读这些符号时，可以直接翻译成问题：当前成绩等于六十吗？不等于六十吗？先让问题明确，再看对应符号。我们马上会用 if，让电脑根据这个真假结果选择接下来执行哪一步。

```c
int score = 80;
printf("%d\n", score >= 60);
printf("%d\n", score == 60);
```

运行结果或操作说明：
```text
1
0
```

画面要点：比较结果：成立 1，不成立 0；== 判断相等；= 保存新的值

### c-02-4 把条件组合起来

有时一个条件还不够。比如合法成绩应当不小于零，同时不大于一百。这两个要求都要满足，就用两个与符号连接，读成“并且”。八十分满足两边，所以整个结果为一。两个竖线表示“或者”，只要两边至少有一个条件成立，整体就成立。感叹号则表示“不是”，把真假结果反过来。这里不用一次把所有组合背熟，先用中文把需求说清楚，再写成相应表达式。计算顺序不确定时，主动加括号。例如先算两项的和再乘二，就把加法放进括号。不要为了让代码显得短而堆很多运算。还要避免在一个复杂表达式里反复修改同一个变量，这容易让含义不清甚至失去可靠结果。初学时把计算分成几行，往往更容易检查。

```c
int score = 80;
int valid = (score >= 0) && (score <= 100);
printf("%d\n", valid);
printf("%d\n", (2 + 3) * 2);
```

运行结果或操作说明：
```text
1
10
```

画面要点：&&：两个条件都成立；||：至少一个条件成立；括号让顺序更清楚

### c-02-q 课堂练习：平均分为什么不对

三次记录的总分是七分，记录数量是二。我们希望平均数是三点五，于是准备一个 double 变量来保存。但是这行代码把七除以二的结果直接赋给它，最后显示多少？请先看除号两边的数据，不要只盯着左边的 double。再想一想，计算发生在保存之前还是之后。如果结果不符合需求，你会在表达式哪里做一个小修改？我们保留一位小数来显示。四秒之后，不仅核对输出，还会给出一种让计算真正保留小数的写法。

（四秒思考；随后核对答案）

```c
int total = 7;
int count = 2;
double average = total / count;
printf("%.1f\n", average);
```

运行结果或操作说明：
```text
3.0
```

画面要点：除号两边都是 int；先运算，再保存；怎样让计算包含小数

### c-02-a 答案：在除法前转成小数运算

原来的写法输出三点零。因为总分和人数都是整数，先做整数除法得到三，再保存进小数变量。格式要求一位小数，所以看见的是三点零。现在把表达式改成 total 乘以一点零，再除以 count。乘以一点零会让这一步按小数参与后续运算，因此七除以二能够得到三点五。屏幕上的修正版就是这个结果。还要加一个现实条件：人数不能是零。如果没有任何成绩，就不应该直接除以人数。等我们学会分支，就可以先检查人数是否大于零，再决定要不要计算。写程序并不是只挑一个公式，还需要想清楚公式什么时候可以使用。这种先检查、再计算的习惯，会一直贯穿后面的输入、指针和文件操作。

```c
int total = 7;
int count = 2;
double average = total * 1.0 / count;
printf("%.1f\n", average);
```

运行结果或操作说明：
```text
3.5
```

画面要点：修正版输出：3.5；先转成小数运算；人数为 0 时不能直接除

## 输入与输出 · Input and Output

### c-03-1 用格式把结果说清楚

前面我们一直在使用 printf，现在把它稍微展开。双引号里的内容是输出格式，里面既可以有固定文字，也可以有等待数据填入的位置。逗号后面的值，按顺序填进这些位置。这个例子先显示姓名前面的提示，再显示字符等级，最后显示平均分。百分号 d 对应整数，百分号 c 对应字符，百分号 f 在这里显示小数。点后一位说明只显示一位小数，但不会改变变量里面保存的数据。格式位置的数量、先后次序和数据类型要和后面的参数配合。比如声明的是整数，就不要随意拿小数格式去打印它。想把一段话写到下一行，用反斜杠 n。想直接显示一个百分号，可以在格式里连续写两个百分号。把格式看成一张有空位的句子模板，会比机械背函数调用更容易理解。

```c
int score = 80;
char grade = 'B';
double average = 81.5;
printf("score=%d grade=%c\n", score, grade);
printf("average=%.1f\n", average);
printf("progress=100%%\n");
```

运行结果或操作说明：
```text
score=80 grade=B
average=81.5
progress=100%
```

画面要点：格式与数据按顺序配对；%d 整数，%c 字符，%f 小数；两个百分号显示一个 %

### c-03-2 把键盘输入放进变量

只把分数写死在代码里，每换一个数字都要重新改程序。scanf 可以从输入中读取内容，让用户运行时提供分数。现在假设我们输入八十，然后按回车。百分号 d 告诉 scanf 这次要按整数来读。后面的与符号加 score，表示 score 这份存储的地址。你可以先把地址理解为一个明确的位置：这次读到的整数应该放在哪里。打印时只是取出值，读取时却需要找到位置写进去，所以两种调用的样子不同。scanf 自己还会返回一个数字，这里用 result 接住。成功读入一个整数时，它返回一，所以屏幕显示读取数量为一，成绩为八十。地址的细节到指针一章再画图展开，现在先把这三个角色对应起来：格式说明读什么，地址说明写哪里，返回值说明读成了几项。

```c
int score = 0;
int result = scanf("%d", &score);
printf("read=%d score=%d\n", result, score);
```

运行结果或操作说明：
```text
read=1 score=80
```

画面要点：本例键盘输入：80；%d 读取一个整数；&score 指明存放位置

### c-03-3 先确认输入成功

如果要求整数，用户却输入字母，不能假定读取一定成功。这段程序先检查 scanf 的返回值是否等于一。如果不是一，就显示输入无效并结束；只有读对了，才继续显示成绩。这里的 if 先理解成“如果”：条件成立才执行后面大括号里的步骤。下一章会系统学习它。我们现在输入字母 x，整数没有读成，结果就是显示 invalid input，而不是拿一个不确定的成绩继续计算。读取多个值时，返回值表示成功赋值的项数，也不应该只看是否非零。比如期待读入两项，就应当检查是不是二。本课的整数输入练习使用类型范围内的小整数；如果以后要做面向任意文本的完整输入程序，还需要逐行读取并检查数值范围。现在先建立最基本的习惯：先验证这次读取成功，再使用结果。

```c
int score = 0;
if (scanf("%d", &score) != 1) {
    printf("invalid input\n");
    return 1;
}
printf("score=%d\n", score);
```

运行结果或操作说明：
```text
invalid input
```

画面要点：本例输入：x；一个整数应当成功读入 1 项；读失败时不继续计算

### c-03-4 整数、小数和字符的读取

读不同类型时，格式也要配合。读 int 用百分号 d，读 double 用百分号 lf。注意这里读取 double 的格式比打印 double 多了字母 l，不能因为打印时用 f，就直接照抄到 scanf。字符读取还有一个常见细节。百分号 c 本身会读取下一个字符，空格和回车也可能成为那个字符。如果希望跳过之前留下的空白，可以在格式的百分号 c 前放一个空格。屏幕上的输入是八十一点五和一个等级字母 A，中间可以用空格或换行分开。检查成功读入两项之后，程序再显示这两个值。这里的空格是在说明先跳过空白，不是强制用户恰好敲一个空格。把输入过程想成依次取数据，再按格式放进相应变量，就能理解为什么每一项都需要配好类型和位置。

```c
double average = 0.0;
char grade = '?';
if (scanf("%lf %c", &average, &grade) != 2) {
    return 1;
}
printf("%.1f %c\n", average, grade);
```

运行结果或操作说明：
```text
81.5 A
```

画面要点：本例输入：81.5 A；scanf 读 double 用 %lf；%c 前空格会跳过空白

### c-03-q 课堂练习：为什么要传地址

看这段已经写对的程序。输入六十以后，它会显示六十。现在只问一个问题：scanf 后面为什么是与符号加 score，而不是像 printf 那样直接写 score？从这两个函数想完成的事出发。一个只是把已有数字显示出来，另一个需要把新读到的数字保存进变量。后者究竟需要一份数字，还是需要知道变量所在的位置？你可以用“查看格子里有什么”和“往指定格子里放东西”来区分。先不用记住指针类型的完整写法，四秒后我们只把地址的作用讲清楚。

```c
int score = 0;
```

运行结果或操作说明：

画面要点：本例输入：60；输出读取已有的值；输入需要写入的位置

### c-03-a 答案：写入需要准确的位置

答案是，scanf 要修改 score 里面保存的内容，所以需要知道它的位置。与符号放在变量前面，就是取得这个变量的地址。读到六十之后，函数根据地址把六十写进去。printf 只负责显示当前的值，因此打印整数时直接传 score。这里两种传法的差别，来自任务的差别，不是随便约定的标点习惯。不要为了试错，去运行把整数值误当地址传入 scanf 的程序，那不一定只是显示错误结果，还可能访问错误的位置。我们保留正确写法，用图来理解这个动作：输入先变成数字，再沿着位置标记写入 score。等指针一章学完，你就能自己写一个函数，通过同样的方式修改外面的变量。

```c
int score = 0;
if (scanf("%d", &score) != 1) return 1;
printf("%d\n", score);
```


画面要点：&score：变量的地址；scanf 按地址写入 60；printf 读取已有的 60

## 分支结构 · Branches

### c-04-1 满足条件才执行

现在让程序根据分数做决定。如果成绩不小于六十，就显示及格；否则显示未及格。if 后面的括号里放条件，紧接着的大括号放条件成立时要执行的步骤。else 的意思是“否则”，它对应条件不成立的那一种情况。一次运行会走其中一边，不是先显示及格，再显示未及格。屏幕上成绩是五十八，比较结果不成立，所以只看到 fail。在C语言的条件里，零按假处理，非零按真处理。我们优先写清楚比较表达式，让它直接表达需求。初学时也建议保留大括号，即使里面只有一条语句。这样以后增加新步骤，不容易误以为后面的语句也自动受这个条件控制。先问清楚条件，再看哪一块代码会被执行。

```c
int score = 58;
if (score >= 60) {
    printf("pass\n");
} else {
    printf("fail\n");
}
```

运行结果或操作说明：
```text
fail
```

画面要点：if：条件成立时执行；else：条件不成立时执行；每次只走其中一条路

### c-04-2 多种情况按顺序判断

如果不仅区分及格和未及格，还要把九十分以上标记为优秀，可以在中间加 else if。程序先检查第一条，没满足才检查下一条；一旦某一条满足，就执行对应部分并跳过后面的这组分支。所以条件的先后次序很重要。屏幕上先检查九十分，再检查六十分。八十五没有达到九十，但达到了六十，于是输出 pass。如果反过来，先把所有六十分以上都放进第一条，那么九十五也会先被它接住，后面优秀的条件就没有机会执行了。写多分支之前，可以先拿五十九、六十、八十九、九十这些边界值试一试。边界值能帮助我们确认大于和大于等于有没有写对。代码写出来之后，验证实际行为也是学习的一部分。

```c
int score = 85;
if (score >= 90) {
    printf("excellent\n");
} else if (score >= 60) {
    printf("pass\n");
} else {
    printf("fail\n");
}
```

运行结果或操作说明：
```text
pass
```

画面要点：从上往下依次判断；先检查较高的分数要求；特别检查 60 与 90

### c-04-3 用 switch 处理固定选项

还有一类判断：用户输入一个菜单编号，一表示查成绩，二表示算平均分，其余编号无效。对于这种根据一个整数值选择固定选项的需求，可以用 switch。括号里是要查看的值，case 后面是某一个固定选项。程序找到匹配的 case 后，从那个位置开始执行。default 则处理没有任何选项匹配的情况。这里选择二，所以显示 average。每个选项后面放 break，表示做完后退出这个 switch。注意 switch 不是把每个 case 都当成独立的 if。没有退出时，它可能继续往下执行。它适合菜单编号、字符选项等离散值的选择，而像分数大于等于某条线这样的范围判断，使用 if 往往更直观。

```c
int choice = 2;
switch (choice) {
case 1: printf("score\n"); break;
case 2: printf("average\n"); break;
default: printf("invalid\n"); break;
}
```

运行结果或操作说明：
```text
average
```

画面要点：case 对应固定选项；break 结束本次选择；default 处理其余情况

### c-04-4 漏写 break 会发生什么

把刚才的程序缩小一点，我们来观察一个常见现象。现在 choice 是一，程序从 case 一开始执行，先显示 A。但是第一项后面没有 break，所以执行继续落到下一项，又显示 B，直到遇到 break 才退出。这个过程常被叫作贯穿。重点不是先记术语，而是看清执行路线：匹配只决定从哪里进入，break 才决定在这里离开。它不会因为下一行写着 case 二，就自动重新检查 choice 是否等于二。有时开发者会故意让多个选项共享同一段处理，但初学时更常见的是忘记退出。如果本意是选一只显示 A，就在第一项处理后补上 break。不要把这样的逻辑问题和编译错误混为一谈；这段代码可以编译，只是行为可能不符合你原本的需求。

```c
int choice = 1;
switch (choice) {
case 1: printf("A\n");
case 2: printf("B\n"); break;
default: printf("C\n"); break;
}
```

运行结果或操作说明：
```text
A
B
```

画面要点：从 case 1 进入；未退出就继续到下一项；遇到 break 才离开

### c-04-q 课堂练习：及格线的边界

这一题成绩恰好六十。需求说六十分及格，但条件写成严格大于六十。程序现在会显示 pass，还是 fail？如果结果不符合需求，应该修改哪个符号？先在脑中把 score 换成六十，再读这个问题：“六十比六十更大吗？”不要把“大于”和“不小于”当成同一句话。也可以顺便想想五十九和六十一。一个正确的及格判断，应当把这三个边界附近的输入分别安排到哪一边？四秒后我们一起修正条件。

```c
int score = 60;
if (score > 60) {
```

原程序会输出 fail，因为六十并不严格大于六十。条件不成立，就进入 else。要符合“六十分及格”的规则，应该改成大于等于。屏幕上的修正版在六十分时显示 pass。再拿五十九试，比较不成立；拿六十一试，比较成立。这样我们就把临界点两边都核对了一遍。写程序时，代码能编译只是第一步。像这里的符号都合法，编译器不能代替你判断学校的及格规则。真正需要我们做的是，把中文需求翻译成明确条件，再用具体数据检查。后面数组的最后一个位置、循环的结束条件、文件是否打开成功，也都需要这样检查边界。现在就把六十这一题当成练习这种习惯的起点。

```c
int score = 60;
```

## 循环结构 · Loops

### c-05-1 for：重复执行同一组步骤

假设要显示一、二、三，当然可以写三次打印。但如果要显示一百次，重复抄写就很麻烦。循环让电脑反复执行同一组步骤，只在每轮更新必要的数据。先看 for 括号里的三个部分。开始时让 i 等于一；每次准备执行循环体前，检查 i 是否不大于三；执行完一轮后，再让 i 增加一。i 后面两个加号，在这个独立位置上就是把它加一。所以第一次打印一，更新为二，再检查、打印二，再更新为三。第三次之后变成四，条件不成立，循环才结束。最容易漏掉的是：更新之后还要重新判断，不是直接继续打印。你可以把它读成“准备一次，判断一次，执行一轮，更新一下，再回到判断”。

```c
for (int i = 1; i <= 3; i++) {
    printf("%d\n", i);
}
```

运行结果或操作说明：
```text
1
2
3
```

画面要点：准备 → 判断 → 执行 → 更新；每轮开始前检查条件；i++ 在这里让 i 加 1

### c-05-2 用循环逐步累加

循环不仅能打印，也能把一组数累加起来。我们先让 sum 从零开始，再依次加上一、二、三。零是加法累积的自然起点，不能让 sum 没有初值就参与计算。第一轮，原来的零加一，变成一。第二轮，一加二，变成三。第三轮，三加三，变成六。等循环完全结束之后，我们才打印最终的六。注意打印的位置。如果把打印放进循环体，就会看到每一轮变化的中间结果；放在循环后面，只看见最后的总和。理解大括号包住哪些语句，对判断程序行为非常关键。还有一种常见错误，是把 sum 等于零放进循环体，每次都重新清空，这样就无法保留前面已经加过的内容。先准备累计值，再重复更新，是我们以后处理一组成绩的基本模式。

```c
int sum = 0;
for (int i = 1; i <= 3; i++) {
    sum = sum + i;
}
printf("%d\n", sum);
```

运行结果或操作说明：
```text
6
```

画面要点：sum 从 0 开始；每一轮保留之前的结果；循环结束后显示总和

### c-05-3 while：条件成立就继续

有些重复任务，很难一开始就说清楚要做几次，只知道什么时候应该继续。这时可以用 while，读成“当条件成立时，继续执行”。现在用倒计数做例子。n 最初是三，条件是 n 大于零。每轮先显示当前的 n，再把它减少一。依次显示三、二、一，等 n 变成零，条件不成立，就退出。这里检查条件的动作在执行循环体之前。如果一开始 n 就是零，循环体一次也不会执行。还要注意让某个步骤推动循环接近结束；如果忘了减少 n，它会一直保持三，条件就一直成立。for 和 while 都可以表达许多相同任务，选择时先看哪种写法更容易把开始、继续条件和更新动作交代清楚。

```c
int n = 3;
while (n > 0) {
    printf("%d\n", n);
    n = n - 1;
}
```

运行结果或操作说明：
```text
3
2
1
```

画面要点：先判断，再执行；n 逐步接近 0；忘记更新可能一直循环

### c-05-4 do while：先做一次再判断

第三种写法是 do while。它和 while 最明显的不同，是把条件检查放到了循环体后面。因此，无论一开始条件怎样，循环体都会先执行一次。屏幕把 n 初始化为零。普通 while 如果检查 n 大于零，会一次也不进入；这里的 do 却先打印一次零，再减少 n，最后才发现条件不成立。所以结果仍然出现一行零。这种形式适合先显示一次菜单、再问要不要继续的场景。结尾 while 括号后面有分号，不要把它漏掉。学习这三种循环时，不必马上争论哪种更高级；先判断重复次数是否明确，条件在前还是在后，再选择最容易表达需求的写法。关键是你能自己按执行顺序跟出数据变化。

```c
int n = 0;
do {
    printf("%d\n", n);
    n--;
} while (n > 0);
```

运行结果或操作说明：
```text
0
```

画面要点：先执行，再检查条件；至少执行一次；结尾 while 后有分号

### c-05-5 提前结束与跳过这一轮

循环里还可以根据情况改变执行路线。break 表示直接结束当前这一层循环；continue 则表示这一轮剩下的步骤先不做，转入下一轮的流程。屏幕从一数到五，但遇到二时执行 continue，所以二不会被打印。遇到五时执行 break，整个循环立即结束，也就不会打印五。最终看到的是一、三、四。在 for 循环中，continue 之后仍然会执行括号里的更新，再重新检查条件。不要把它理解成完全不更新就跳回开头。初学时可以先用普通条件写出清楚的版本，再判断 break 或 continue 能否让意图更明显。如果循环套着循环，break 也只会退出它所在的那一层，不会自动跳出所有层。先从单层小例子看懂，就足够开始使用。

```c
for (int i = 1; i <= 5; i++) {
    if (i == 2) continue;
    if (i == 5) break;
    printf("%d\n", i);
}
```

运行结果或操作说明：
```text
1
3
4
```

画面要点：continue：跳过本轮后续步骤；break：退出当前循环；for 的更新仍会正常进行

### c-05-q 课堂练习：循环到底执行几次

这一题 i 从零开始，只要它小于三就执行。每次把 sum 加一，循环后再打印 sum。请问循环体执行几次，最终的和是多少？不要看到三就马上猜答案。依次列出进入循环体时 i 的值，再问 i 等于三的时候条件是否成立。这里用的是小于，而不是小于等于。下一章数组的第一个位置恰好也是从零编号，这种写法会频繁出现。先用四秒把零、一、二、三分别判断一遍，之后我们一起核对哪些值真的进入了循环体。

（四秒思考；随后核对答案）

```c
int sum = 0;
for (int i = 0; i < 3; i++) {
    sum++;
}
printf("%d\n", sum);
```

运行结果或操作说明：
```text
3
```

画面要点：从 0 开始；条件是 i < 3；先列出真正进入的 i

### c-05-a 答案：零、一、二共三次

循环体执行三次，所以最后输出三。进入时的 i 依次是零、一、二。第二次更新后是二，仍然小于三；第三次执行后更新成三，再检查条件时不成立，于是结束。如果误写成小于等于三，就会多执行一次，让零、一、二、三都进入循环体。对于只有三个元素的数组，这种多出来的一次就可能造成越界。因此，循环次数和数字看起来多大不是一回事，要同时看起点、比较符号和每次更新。最可靠的方法是先用几个具体值模拟。刚开始可以画表，把 i、条件和 sum 分三列写下来。等这个过程熟悉后，你会逐渐一眼认出“从零到小于元素个数”表示遍历所有合法位置。

```c
int sum = 0;
for (int i = 0; i < 3; i++) {
    sum++;
}
printf("%d\n", sum);
```

运行结果或操作说明：
```text
3
```

画面要点：进入时 i 为 0、1、2；i 为 3 时退出；总共执行 3 次

## 数组与字符串 · Arrays and Strings

### c-06-1 把同类数据排在一起

要保存三位同学的成绩，可以声明三个变量，但人数一多，名字就难管理。数组可以把同一种类型的多个元素放在一起，再用位置编号区分它们。这行 int 后面的 scores 是数组名，方括号里的三表示有三个整数位置，大括号列出它们的初始值。这里最重要的一条规则是：编号从零开始，所以三个位置分别是零、一、二。我们通过 scores 方括号零取出第一个成绩六十，再通过方括号二取出第三个成绩九十。三不是这个数组的最后一个编号，而是它的元素个数。访问编号三已经超出范围，C语言不会替你可靠地拦下来。不要靠运行后有没有崩溃判断访问是否正确，始终把编号限制在零到元素个数减一之间。

```c
int scores[3] = {60, 80, 90};
printf("%d %d\n", scores[0], scores[2]);
```

运行结果或操作说明：
```text
60 90
```

画面要点：三个元素，编号 0、1、2；scores[0] 是第一个；最后位置不是 scores[3]

### c-06-2 让循环遍历数组

数组和循环放在一起，就能自动处理每一个成绩。我们让 i 从零开始，只要 i 小于三就继续，每轮把 scores 的第 i 项加进 total。第一轮拿到六十，第二轮拿到八十，第三轮拿到九十，最后总分是二百三十。算平均分时先乘以一点零，让除法保留小数，保留一位后显示七十六点七。这段程序没有为每个位置单独写一行相加，处理人数改变时也更容易调整。但循环里的上限必须和数组实际大小一致。如果只有三个位置却循环到编号三，就不是多读一份可靠的成绩。把“位置从零开始”和“条件小于元素个数”联系起来，就能理解这种写法为什么常见，而不只是背一个循环模板。

```c
int scores[3] = {60, 80, 90};
int total = 0;
for (int i = 0; i < 3; i++) {
    total += scores[i];
}
printf("total=%d\n", total);
printf("average=%.1f\n", total * 1.0 / 3);
```

运行结果或操作说明：
```text
total=230
average=76.7
```

画面要点：total += x 等于 total = total + x；循环访问所有合法位置；平均分使用小数运算

### c-06-3 字符串需要结束标记

现在来看怎样保存姓名。C语言常用字符数组保存字符串。屏幕用双引号写下 Ana，编译器会依次保存 A、n、a，并在后面加上一个值为零的结束字符。这个结束字符常写作反斜杠零，它不显示成普通数字零，而是告诉字符串函数：文字到这里结束了。因此三个可见字母，至少需要四个 char 位置。这里让编译器根据初始文字自动确定数组大小。打印整段字符串用百分号 s，打印其中某一个字符仍然用百分号 c。第二行输出姓名 Ana，第三行读取编号一，所以看到字母 n。字符串也是一个个字符组成的数据，不是只能整体拿来显示的神秘对象。先看清字符和结束标记分别占在哪里，后面就更容易理解输入时为什么必须预留空间。

```c
char name[] = "Ana";
printf("%s\n", name);
printf("%c\n", name[1]);
```

运行结果或操作说明：
```text
Ana
n
```

画面要点：三个字母加一个结束字符；%s 显示整个字符串；name[1] 是第二个字符

### c-06-4 读取姓名时限制长度

如果姓名由用户输入，要先准备足够的数组空间。屏幕准备十六个 char 位置，但 scanf 的字符串格式写的是百分号十五 s。为什么不是十六？因为最后还要留一个位置保存字符串结束标记。输入 Ana 时，读取成功一项，就把姓名显示出来。这里直接传 name，没有再写取地址符号。数组名在这个调用位置会提供第一个元素的地址，指针一章会用图把它展开。还要知道，百分号 s 遇到空白就停止，所以适合这里不含空格的简单英文姓名。如果想读取包含空格的一整行，可以使用 fgets，并处理它可能保留的换行。今天先把这一种输入控制清楚：容量是十六，最多接收十五个字符单位，并检查成功项数。限制长度是输入规则的一部分，不能等数组被写出界后再补救。

```c
char name[16];
if (scanf("%15s", name) != 1) {
    return 1;
}
printf("%s\n", name);
```

运行结果或操作说明：
```text
Ana
```

画面要点：本例输入：Ana；16 个位置，最多读入 15；%s 不读取包含空格的整行

### c-06-5 长度与容量不是一回事

一个字符串占了多少文字，和它所在数组能放多少东西，是两个问题。strlen 用来数结束标记前面有多少个字节，使用前引入 string 点 h。对于这里的英文字母 Ana，它返回三。sizeof name 在这里查看整个数组占的字节数。我们准备了十六个 char 位置，所以它是十六。打印这类长度结果使用百分号 zu，它对应库函数和 sizeof 使用的长度类型。假设数组里只放三个字母，容量也不会自动缩小成三。反过来，数组容量有十六，也不表示姓名真的有十六个可见字符。对中文等文本，strlen 数的是字节，不一定等于人眼看到的字符个数。初学时用短英文把“内容长度”和“可用容量”区分清楚，已经能避免很多字符串错误。

```c
#include <stdio.h>
#include <string.h>
int main(void) {
    char name[16] = "Ana";
    printf("%zu %zu\n", strlen(name), sizeof name);
    return 0;
}
```

运行结果或操作说明：
```text
3 16
```

画面要点：strlen：结束标记之前的字节数；sizeof name：此数组的容量字节；这里结果是 3 与 16

### c-06-q 课堂练习：四个位置怎么分配

字符数组 word 有四个位置，初始文字是 cat。请判断，第零、第一、第二和第三个位置分别保存什么？最后一个位置能不能再随便放一个普通字母，然后仍然当成同样的字符串打印？这题不需要猜实际内存地址，只要把三个英文字母按顺序排好，再给结束标记找一个位置。想想刚才读取十五个字符时，为什么总是给数组空出最后一格。屏幕会打印原来的字符串。四秒之后，我们再检查第四格是不是“没有用”，以及破坏结束标记为什么会让字符串函数失去明确的停止位置。

（四秒思考；随后核对答案）

```c
char word[4] = "cat";
printf("%s\n", word);
```

运行结果或操作说明：
```text
cat
```

画面要点：第一个位置编号为 0；三个字母占前三格；还有一个必要的结束标记

### c-06-a 答案：最后一格保存结束标记

四个位置依次是 c、a、t 和结束字符。最后一格不是浪费，而是在告诉字符串函数应该到哪里停止。这里打印百分号 s，会显示 cat，不会把结束字符当成可见字母显示出来。修正版的观察代码还检查了编号三是不是结束字符，结果为一，表示判断成立。请注意，结束字符和普通数字字符零不同；我们用单引号包住反斜杠零，表达那个值为零的字符。如果把这最后一格改成普通字母，却没有在后面准备新的合法结束位置，再当字符串打印，就不能期待一个固定可靠的结果。我们不运行这样的越界风险来猜答案，而是从容量规则判断。字符串内容加结束标记都必须放在数组内部，这个结论比背住某一次运行现象更重要。

```c
char word[4] = "cat";
printf("%s\n", word);
printf("%d\n", word[3] == '\0');
```

运行结果或操作说明：
```text
cat
1
```

画面要点：word[3] 是结束字符；结束标记也需要一个位置；容量必须包含这个位置

## 函数与递归 · Functions and Recursion

### c-07-1 给一组步骤起名字

当同一组步骤要在不同地方使用，可以把它们整理成函数。函数像一个有名字的小工具：交给它需要的数据，它完成工作，再把结果交回来。前面使用的 printf 也是库提供的函数，现在我们自己写一个。屏幕上的 add 接收两个整数 a 和 b，把它们相加，然后 return 这个和。函数名前面的 int 表示它会交回一个整数结果。main 调用 add，并把三和五交进去，因此拿回八，再显示八。注意，定义函数是在说明工具怎样工作，并不是从文件第一行就把所有函数体依次跑一遍。程序仍然从 main 开始，遇到调用时才进入 add，拿到返回结果后再回到原来的位置继续。先抓住“交入数据、执行步骤、交回结果”这条路线，函数就不会只是一些新的括号和关键字。

```c
#include <stdio.h>
int add(int a, int b) {
    return a + b;
}
int main(void) {
    int result = add(3, 5);
    printf("%d\n", result);
    return 0;
}
```

运行结果或操作说明：
```text
8
```

画面要点：参数：交给函数的数据；return：交回结果；main 调用 add 后继续

### c-07-2 复用同一个函数

函数写好之后，可以给它不同的数据，多次调用。这里的 passed 接收一个成绩，判断是否至少六十，并把比较结果作为整数返回。main 先把五十九交进去，拿回零；再把六十交进去，拿回一。两次都使用同一份规则，不需要把及格判断抄两遍。以后规则调整，也更容易保持不同位置使用的判断一致。函数放在调用它的位置之前，编译器就已经知道它叫什么、接收什么、返回什么。较大的程序也常先写声明、再把具体定义放到后面，本课先用最直接的顺序，避免一次引入太多结构。函数名尽量说明目的，参数名说明这份数据是什么。把任务拆成可以单独解释的小工具，会比把所有逻辑挤进 main 更方便阅读和检查。

```c
#include <stdio.h>
int passed(int score) {
    return score >= 60;
}
int main(void) {
    printf("%d %d\n", passed(59), passed(60));
    return 0;
}
```

运行结果或操作说明：
```text
0 1
```

画面要点：同一规则，多次调用；每次参数可以不同；函数名表达具体目的

### c-07-3 函数参数接收的是一份值

现在用一个问题检查函数怎样传数据。main 里有一个 score，值是八十。调用 bonus 时，函数的参数也叫 score，但它接收到的是八十这份值的副本。函数内部把自己的那份值加五，打印得到八十五。回到 main，原来的 score 没被修改，所以又打印八十。名字相同，并不意味着它们就是同一个变量。这里 bonus 前面的 void 表示函数不交回一个结果值，它只是执行打印动作。要让外面的变量改变，可以返回新值让外面接住，也可以使用后面要学的地址。先不急着改写，先把每个函数自己的数据范围看清楚。函数里面声明的普通局部变量，通常只在对应的代码块内使用；不要把同名误读成自动连接。

```c
#include <stdio.h>
void bonus(int score) {
    score += 5;
    printf("inside=%d\n", score);
}
int main(void) {
    int score = 80;
    bonus(score);
    printf("outside=%d\n", score);
    return 0;
}
```

运行结果或操作说明：
```text
inside=85
outside=80
```

画面要点：普通参数复制传入的值；内部改副本，外部不变；void：不交回结果值

### c-07-4 递归：函数再次使用自己

递归就是函数在完成任务时，再调用一次自己。这个概念先用很小的数字理解。我们想算一加二加三，如果已经知道一加二的结果，只要再加三，就得到答案。屏幕上的 sum_to 把这个想法写出来：当 n 是零时，结果直接是零；否则返回 n 加上 sum_to 的 n 减一。注意第二次调用的问题比前一次更小，从三变二，再变一，最后到零。这里最重要的是有一个能直接回答的结束情况，而且每次调用都朝它前进。本例只给函数非负的小整数。不能拿它处理负数却还沿同样方向减一，否则不会按我们想要的路径到达零。递归不是让函数神奇地无限重复，而是把大一点的问题拆成同样形式的小问题，再逐层拿回答案。

```c
#include <stdio.h>
int sum_to(int n) {
    if (n == 0) return 0;
    return n + sum_to(n - 1);
}
int main(void) {
    printf("%d\n", sum_to(3));
    return 0;
}
```

运行结果或操作说明：
```text
6
```

画面要点：sum_to(0) 直接返回 0；每次把 n 减 1；本例只处理非负小整数

### c-07-5 答案怎样一层层返回

我们把刚才的递归展开看。调用三时，需要等二的结果；二需要等一；一需要等零。零不再继续调用，直接交回零。随后沿相反方向回来：一加零得到一，交给上一层；二加一得到三，再交给上一层；三加三最终得到六。每一层保留自己的 n 和尚未完成的加法，不会因为下一层开始就把上一层的 n 覆盖掉。这也是为什么递归通常需要额外的调用记录。问题过大或没有正确终点，都可能让调用层数不断增长。我们用递归是为了让拆分关系清楚，不是为了替代所有循环。求这个简单总和，用刚才的循环同样能完成。现在先学会跟踪“往下问更小的问题，回来拼成答案”，以后遇到树形结构时，这种方法会更自然。

```c
#include <stdio.h>
int sum_to(int n) {
    if (n == 0) return 0;
    int smaller = sum_to(n - 1);
    return n + smaller;
}
int main(void) {
    printf("%d\n", sum_to(3));
    return 0;
}
```

运行结果或操作说明：
```text
6
```

画面要点：向下：3 → 2 → 1 → 0；返回：0 → 1 → 3 → 6；每层有自己的 n

### c-07-q 课堂练习：返回值有没有接住

函数 add_one 会把传入的整数加一，并交回结果。main 里的 x 是四，调用一次函数之后，直接打印 x，没有用等号接住返回值。这个 x 现在是四还是五？先区分两个动作：函数算出了一个新值，不等于自动把外面的变量改了。你可以回想刚才内部成绩八十五、外部仍然八十的例子。如果需求就是把 x 更新成五，外面应该怎样使用这次调用的结果？四秒之后，我们一起给 main 加上需要的保存动作。

（四秒思考；随后核对答案）

```c
#include <stdio.h>
int add_one(int n) { return n + 1; }
int main(void) {
    int x = 4;
    add_one(x);
    printf("%d\n", x);
    return 0;
}
```

运行结果或操作说明：
```text
4
```

画面要点：add_one 算出新值；main 是否保存了结果；普通参数仍是值复制

### c-07-a 答案：把返回结果赋给 x

原程序会显示四。add_one 的确算出了五，但 main 没有保存这个返回结果，原来的 x 自然还是四。调用一次函数，并不表示原变量必然会变化。现在改成 x 等于 add_one 括号 x。先读取旧 x 的四交给函数，函数返回五，再把五写回 x。最终打印才会显示五。这个写法把每一步都明确表达出来，也和最初的 score 等于 score 加五是同一种思路。函数调用可以放在表达式里面，因为它能产生一个返回值。读这样的语句时，可以先在纸上算出调用结果，再完成赋值。下一章我们会看到另一种方式：把 x 的地址交出去，让函数通过地址直接修改原来的 x。现在先把返回值方式用熟，就更容易对比两条路线。

```c
#include <stdio.h>
int add_one(int n) { return n + 1; }
int main(void) {
    int x = 4;
    x = add_one(x);
    printf("%d\n", x);
    return 0;
}
```

运行结果或操作说明：
```text
5
```

画面要点：原题输出 4；修正：x = add_one(x)；修正后输出 5

## 指针 · Pointers

### c-08-1 数据有内容，也有位置

现在进入指针。先不用背抽象定义，想象一个带编号的存储格子。score 这个格子里放着八十。八十是内容，格子所在的位置是地址，这两个东西不是同一回事。与符号加 score 取得地址。声明 int 星号 p，表示 p 是一个保存整数地址的变量。我们把 score 的地址放进 p，于是 p 指向 score。屏幕上的箭头表示这种关系，不依赖某个真实地址数字。最后比较 p 和 score 的地址是否相同，结果为一。你不需要记住地址会显示成什么样，换一次运行它也可能变化。先记住三件事：score 保存分数，取地址动作得到位置，p 保存这个位置。指针本身也是变量，只不过它的值用来指出某份数据在哪里。

```c
int score = 80;
int *p = &score;
printf("%d\n", p == &score);
```

运行结果或操作说明：
```text
1
```

画面要点：score：数据内容；&score：数据所在地址；p：保存地址的变量

### c-08-2 沿着地址读取和修改

既然 p 已经指向 score，我们可以沿着这个位置找到原来的整数。表达式里，星号加 p 的意思是访问 p 指向的数据，这个动作常叫解引用。先打印星号 p，看到八十；再让星号 p 等于八十五，相当于到 p 指向的那个位置写入八十五。最后直接打印 score，也看到八十五，因为被修改的就是同一份数据。注意星号出现的位置。声明 int 星号 p，是说明 p 的类型；后面表达式里的星号 p，则是在使用它指向的数据。不要把 p 等于某个数字和星号 p 等于某个数字混在一起，前者改变指针保存的位置，后者修改那个位置上的内容。沿着图中的箭头走一遍，通常比只盯着符号更容易分清。

```c
int score = 80;
int *p = &score;
printf("%d\n", *p);
*p = 85;
printf("%d\n", score);
```

运行结果或操作说明：
```text
80
85
```

画面要点：*p 访问所指整数；*p = 85 修改原来的 score；位置与内容分开理解

### c-08-3 地址必须有效才能访问

指针不是任意一个数字都能拿来用。访问星号 p 之前，p 必须指向仍然存在、类型和使用方式合适的数据。只声明一个未初始化的指针，然后直接写星号 p，是不可靠的。如果暂时没有要指向的数据，可以先把指针初始化为 NULL，表示当前没有目标。NULL 不是一个可以放心访问的空格子，不能因为它有名字就解引用。我们先检查 p 是否不等于 NULL，只有找到目标时才访问。屏幕先把 p 设为空，然后让它指向仍在当前代码块里的 score，检查后打印八十。还有一种错误，是把函数里临时局部变量的地址交出来，等函数结束后继续使用；原来的那份局部数据已经结束生存，地址就不能继续当作有效目标。初学时始终先追问：这根箭头现在指向谁，那份数据还在吗？

```c
int score = 80;
int *p = NULL;
p = &score;
if (p != NULL) {
    printf("%d\n", *p);
}
```

运行结果或操作说明：
```text
80
```

画面要点：不使用未初始化的指针；NULL 表示当前没有目标；访问前确认目标仍有效

### c-08-4 把地址交给函数修改原值

现在我们自己写一个会修改外部数据的函数：交换两个整数。main 里 x 是三，y 是八，调用时把它们的地址交给 swap。参数 a、b 接收到的仍然是值的副本，但这一次复制的是地址。地址都指向 main 中真正的 x 和 y，所以函数通过星号 a、星号 b，就能修改外面的数据。C语言这里仍然是值传递，并没有突然换成另一套传参规则。交换时需要一个临时位置。先保存原来的 x，也就是三；再把 y 的八写进 x；最后把暂存的三写进 y。少了这一步暂存，直接前后赋值就可能丢掉原来的三。最终 x 变八，y 变三。回头看 scanf，它需要地址来写入新值，道理也已经和这一页连起来了。

```c
#include <stdio.h>
void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}
int main(void) {
    int x = 3, y = 8;
    swap(&x, &y);
    printf("%d %d\n", x, y);
    return 0;
}
```

运行结果或操作说明：
```text
8 3
```

画面要点：传入 &x、&y；复制地址，访问同一份数据；临时变量保留被覆盖的值

### c-08-5 数组与指针的联系

前面读取字符串时，数组名后面没有额外加取地址符号，现在可以解释了。在很多表达式中，数组名会转换成指向第一个元素的指针。这里把 scores 赋给 p，p 就指向第零项。星号 p 读到第一项六十，星号括号 p 加一读到下一项八十。这里加一表示向后移动一个对应类型的元素，不是固定向后挪一个字节。访问必须仍在合法元素范围里。但数组和指针不是完全相同的东西。数组本身带着实际的一组存储位置，指针变量只保存地址。尤其是把数组交给函数后，通常还要把元素个数一并交进去，不能指望函数从一个指针自动知道整个数组多长。初学时优先使用数组下标来遍历，再用这一页理解底下的位置关系，就不会把指针计算当成必用技巧。

```c
int scores[3] = {60, 80, 90};
int *p = scores;
printf("%d %d\n", *p, *(p + 1));
```

运行结果或操作说明：
```text
60 80
```

画面要点：此处 scores 提供首元素地址；p + 1 指向下一个整数元素；数组与指针不是同一个概念

### c-08-q 课堂练习：谁真的被修改

屏幕上 x 最初是十，y 先复制 x 的值，p 则保存 x 的地址。之后通过星号 p 把那个位置改成二十。最后打印 x 和 y，分别会是多少？这题把第一章的普通变量复制，与本章的地址访问放在一起。请先给 x、y 各画一个格子，再从 p 画一根箭头，看看修改动作究竟沿箭头走到哪一个格子。不要因为 y 也曾经从 x 得到初始值，就认定它以后会一直跟着 x 变化。四秒之后，我们把两种关系分别检查。

（四秒思考；随后核对答案）

```c
int x = 10;
int y = x;
int *p = &x;
*p = 20;
printf("%d %d\n", x, y);
```

运行结果或操作说明：
```text
20 10
```

画面要点：y 得到一份数值副本；p 保存 x 的地址；*p 修改哪个格子

### c-08-a 答案：地址通向 x，不通向 y

答案是二十和十。y 初始化时复制的是当时的数字十，所以它有自己的一份值。p 保存的则是 x 的地址，星号 p 等于二十，修改的是 x 对应的那一格。没有任何语句去修改 y，因此它还是十。这个结果把“复制内容”和“复制地址”分得很清楚。都是值复制，但被复制的值代表什么，会决定后面能做什么。理解指针时可以一直用三个问题帮助自己：指针保存哪个地址，那个地址对应哪份数据，这一次是在改指针还是在改它指向的内容？如果你能用这些问题解释这道题，再回看 scanf、交换函数和数组首元素，就已经形成了同一套解释，而不是分别死记几种奇怪写法。

```c
int x = 10;
int y = x;
int *p = &x;
*p = 20;
printf("%d %d\n", x, y);
```

运行结果或操作说明：
```text
20 10
```

画面要点：x 被修改成 20；y 保留自己的 10；p 的箭头只指向 x

## 结构体 · Structures

### c-09-1 把相关信息放在一起

数组适合放一组同类型数据，但一位同学的信息可能同时有姓名和成绩。结构体可以把这些相关字段组合起来，形成一条更完整的记录。屏幕先定义 Student 这个结构，里面有十六个字符位置的 name 和一个整数 score。注意定义结束的大括号后面有分号。接下来声明一位同学 s，并按字段顺序给出姓名 Ana 和成绩八十。访问某个字段，用变量名加点，再写字段名。所以 s 点 name 表示这位同学的姓名，s 点 score 表示他的成绩。输出就能把两者放在同一行。结构体不要求里面的字段类型相同，但它们应该在含义上属于同一个对象。这样读代码时，不必靠几个平行数组猜哪份姓名对应哪份成绩，关系可以直接写在数据组织里。

```c
struct Student {
    char name[16];
    int score;
};
struct Student s = {"Ana", 80};
printf("%s %d\n", s.name, s.score);
```

运行结果或操作说明：
```text
Ana 80
```

画面要点：结构体组合相关字段；定义结束后有分号；变量.字段 访问数据

### c-09-2 结构体也可以组成数组

一个结构体保存一位同学，多位同学就可以放进结构体数组。屏幕上有两条记录，第一位 Ana 八十分，第二位 Ben 九十分。我们用循环访问编号零和一。students 的第 i 项先找到某一条记录，再用点 name、点 score 取出这位同学的字段。结果按顺序显示两个人的信息。这里没有新的访问魔法，只是把已经学过的两步连起来：方括号选哪一位，点号选哪一项信息。给第一位同学加五分，也只是把编号零的 score 更新一下。把一个新需求拆回熟悉的小动作，是学习编程很有用的方法。先分清自己现在处理的是整条记录，还是其中某个字段，再选择对应写法。

```c
struct Student { char name[16]; int score; };
struct Student students[2] = {{"Ana", 80}, {"Ben", 90}};
for (int i = 0; i < 2; i++) {
    printf("%s %d\n", students[i].name, students[i].score);
}
```

运行结果或操作说明：
```text
Ana 80
Ben 90
```

画面要点：数组选记录，点号选字段；students[0] 是第一位；姓名与成绩放在同一条记录

### c-09-3 通过结构体指针修改字段

如果函数需要修改一位同学的原始成绩，也可以把整个结构体的地址交进去。参数 p 是指向 Student 记录的指针，调用时传入 s 的地址。对于结构体指针，箭头符号用来访问所指记录的字段。所以 p 箭头 score，表示沿着 p 找到这位同学，再访问他的成绩。这里加五后，main 中的 s 也变成八十五。点号和箭头怎么选，可以看手里拿的是什么：直接拿到结构体变量，用点号；拿到指向结构体的指针，用箭头。箭头访问也可以展开成先对 p 解引用，再访问字段，不过直接写箭头通常更清楚。所有指针访问仍然要保证目标有效。本例的 s 一直在 main 里，函数返回前都还存在，所以沿地址修改有明确对象。

```c
#include <stdio.h>
struct Student { char name[16]; int score; };
void bonus(struct Student *p) {
    p->score += 5;
}
int main(void) {
    struct Student s = {"Ana", 80};
    bonus(&s);
    printf("%s %d\n", s.name, s.score);
    return 0;
}
```

运行结果或操作说明：
```text
Ana 85
```

画面要点：传入结构体的地址；变量用点号，指针用箭头；原来的记录被修改

### c-09-q 课堂练习：复制记录以后

现在结构体 a 保存 Ana 和八十分，随后把整条记录复制给 b。接下来只把 b 的成绩改成九十分。最后 a 和 b 的成绩分别是多少？请留意这两个变量本身都是结构体，不是指向同一条记录的两个指针。这个结构体的姓名数组和成绩都直接放在记录里，赋值会复制这些字段的内容。你可以回想普通整数变量的那一题。先复制，再只修改副本，会不会自动把原件也改掉？四秒之后，我们把结构体赋值和通过地址修改再区分一次。

（四秒思考；随后核对答案）

```c
struct Student { char name[16]; int score; };
struct Student a = {"Ana", 80};
struct Student b = a;
b.score = 90;
printf("%d %d\n", a.score, b.score);
```

运行结果或操作说明：
```text
80 90
```

画面要点：a、b 是两条独立记录；这次没有共享目标的指针；只修改 b.score

### c-09-a 答案：原记录与副本分别保存

答案是八十和九十。b 等于 a 时，复制了这个结构体里面的字段内容。后面修改 b 的成绩，只影响 b，不影响 a。这里姓名数组直接属于结构体，所以姓名内容也随记录一起复制。先不要把这个结论随意推广到所有复杂结构：如果某个字段保存的是指针，复制那个字段时复制的是地址，仍需要追踪它指向谁。本课的 Student 使用固定字符数组和整数，关系比较直接。到现在，我们已经会用变量保存一个数字，用数组保存一组同类型数据，用结构体把不同但相关的信息合起来。看到一个需求时，不一定马上开始写循环，也可以先想数据应该怎样组织。把姓名和成绩的关系表达清楚，后面的计算与输出就会少一些容易混淆的对应关系。

```c
struct Student { char name[16]; int score; };
struct Student a = {"Ana", 80};
struct Student b = a;
b.score = 90;
printf("%d %d\n", a.score, b.score);
```

运行结果或操作说明：
```text
80 90
```

画面要点：a.score 保留 80；b.score 变成 90；要分清字段是数据还是地址

## 文件操作 · Files

### c-10-1 打开、写入、关闭

程序结束以后，普通变量里的成绩不会自动变成可以下次再读的文件。想保存到磁盘，需要明确打开一个文件，向它写内容，最后关闭。fopen 接收文件名和打开方式，返回一个文件使用凭据，类型写作 FILE 星号。我们把它保存在 fp 中，后面读写时传给相应函数。如果返回 NULL，表示没有成功打开，不能继续把它当成有效文件。这里的 w 表示为写入打开。它会创建不存在的文件；如果同名文件已经存在，会清空原有内容再写，所以使用前要确认这是你要的行为。fprintf 很像 printf，只是前面多了文件对象参数。它把八十和换行写入 scores 点 txt。最后 fclose 关闭文件并检查结果。屏幕上的 saved 是给人看的确认消息，文件里真正保存的是八十这一行。

```c
FILE *fp = fopen("scores.txt", "w");
if (fp == NULL) { printf("open failed\n"); return 1; }
if (fprintf(fp, "%d\n", 80) < 0) {
    fclose(fp); return 1;
}
if (fclose(fp) != 0) return 1;
printf("saved\n");
```

运行结果或操作说明：
```text
saved
```

画面要点：w：创建或清空后写入；先检查 fp 是否为 NULL；文件内容：80 和换行

### c-10-2 从文件里读回一个成绩

再打开同一个文件，这一次方式写成 r，表示读取已有内容。文件中的八十是一段数字文字，fscanf 按整数格式把它读回 score。你会发现，fscanf 和 scanf 的形式很相似：前面多一个文件对象，后面仍然需要说明格式和变量地址。它也会返回成功赋值的项目数量。本例想读一个整数，就检查结果是不是一。无论读取结果是否符合要求，已经打开的文件都应该安排关闭。所以这里先保存读取结果，再关闭文件，最后统一检查；成功后才显示成绩。相对文件名是相对于程序的工作目录，不一定就是源代码所在目录。练习时，把要读的文件放在约定的运行目录，并核对文件内容，能减少“明明存在却找不到”的困惑。

```c
FILE *fp = fopen("scores.txt", "r");
if (fp == NULL) return 1;
int score = 0;
int read = fscanf(fp, "%d", &score);
int closed = fclose(fp);
if (read != 1 || closed != 0) return 1;
printf("%d\n", score);
```

运行结果或操作说明：
```text
80
```

画面要点：r：读取已有文件；fscanf 也检查成功项数；本例文件内容：80

### c-10-3 保留旧内容，再追加一行

如果文件已经有八十，想在后面再保存九十，就不能用刚才会清空文件的 w。可以使用 a，表示追加写入，新的内容会放到文件末尾。屏幕这段程序打开已有的 scores 文件，追加九十和换行，然后关闭。完成后，文件从原来一行八十，变成第一行八十、第二行九十。程序显示 appended，表示这次追加步骤完成。把 r、w、a 和具体任务联系起来：r 取出已有内容，w 准备一份新的写入内容，a 在旧内容后继续加。不要把打开方式当成随手抄的一个字母，它直接决定对已有资料做什么。我们这里练习的是简单文本文件，后面还可以学习逐行读取、完整格式校验，以及更复杂的文件结构；先把这三个基本动作写对就很好。

```c
FILE *fp = fopen("scores.txt", "a");
if (fp == NULL) return 1;
if (fprintf(fp, "%d\n", 90) < 0) {
    fclose(fp); return 1;
}
if (fclose(fp) != 0) return 1;
printf("appended\n");
```

运行结果或操作说明：
```text
appended
```

画面要点：a：在文件末尾追加；原有 80 得到保留；最终文件两行：80、90

### c-10-4 失败也是正常的执行情况

文件名写错、文件不存在，或者没有相应权限，都可能导致打开失败。这不是只会发生在新手身上的特殊情况，而是程序应该预先考虑的一条路径。屏幕故意读取一个没有创建的目录里的文件，fopen 返回空指针，程序显示 open failed 并结束。它没有继续读，也没有对这个空目标执行关闭。读写成功与否也要检查。写入函数出现负值，或者关闭文件返回错误，都不能仅凭前面已经执行到这一行就认定保存一定成功。今天的例子把必要检查保留在完整程序里，画面只展示当前要理解的一小段。这样既不会让初学者一次盯着几十行，也不会把真实程序里的失败情况藏起来。以后遇到更复杂需求，再在这些清楚的分支上扩展提示和恢复策略。

```c
FILE *fp = fopen("not_created_dir/scores.txt", "r");
if (fp == NULL) {
    printf("open failed\n");
    return 1;
}
if (fclose(fp) != 0) return 1;
```

运行结果或操作说明：
```text
open failed
```

画面要点：目标文件和目录尚未创建；打开失败不继续读写；读、写、关闭都有结果

### c-10-q 课堂练习：覆盖还是追加

文件已经保存了八十分，接下来要把九十分接在后面，保留旧记录。屏幕上现在用的是 w，它能保留旧记录吗？应该改成 r、w 还是 a 打开？请按打开方式的含义判断，不用去猜某个编辑器是否给你保留了副本。程序要明确向文件系统提出哪一种请求，就会影响现有文件内容。四秒之后，我们使用正确方式执行一次，并同时检查程序结果和文件本身。看见一条成功提示还不够，也要确认保存下来的内容确实符合需求。

### c-10-a 答案：追加使用 a

应该使用 a。原文件里的八十得到保留，新写入的九十追加在后面。我们既核对了程序显示 appended，也实际核对了文件现在有八十和九十两行。如果改成 w，成功打开原文件时就会清空旧内容，随后写入九十，原来的八十不会因为它也是一份成绩就自动留下。r 则是为了读取，不符合这次写入的目的。这道题也把整个程序的思路收了回来：先明确需求，选合适的数据和操作，检查是否成功，再验证最终结果。文件是一个特别容易看见后果的地方，打开模式必须认真选择。现在你可以把一位同学的输入、成绩判断和保存操作连起来，再逐步扩展为多位同学的记录。不要一开始就追求很大的系统，先让最小的一条路径可靠地工作。

### c-11-1 把已经学过的动作连起来

最后把几个熟悉的动作连起来。结构体描述一位同学，结构体数组保存两位同学，循环依次取出每条记录，passed 函数根据六十分规则交回判断结果，再把姓名和结果显示出来。完整配套程序还会把同样的结果写进 report 点 txt，并检查打开、写入和关闭。画面先只展示处理记录的核心几行，不要求你在最后一分钟突然读懂一大页代码。你可以把每一步指回前面的章节：哪个是数据，哪个是重复动作，哪个是判断工具，结果最后到哪里。程序显示 Ana 对应一，Ben 对应零。这不是一种全新的技巧，而是用清楚的数据关系，把已经练过的小步骤组装起来。自己练习时，可以先只处理一位同学，确认结果后再加数组；先只输出到屏幕，确认内容后再加文件。一次增加一个能验证的小功能，比同时堆上所有代码更容易找到问题。

```c
for (int i = 0; i < 2; i++) {
    int ok = passed(students[i].score);
    printf("%s %d\n", students[i].name, ok);
}
```

运行结果或操作说明：
```text
Ana 1
Ben 0
```

画面要点：结构体数组组织记录；循环与函数处理每一位；完整程序同时写入文件

### c-11-2 从看懂走向自己写出来

回顾这一小时，我们先用变量和类型表达数据，用运算符算出结果，用输入输出和使用者交换信息。然后用分支做选择，用循环重复步骤，用数组和字符串管理一组内容。函数帮我们整理步骤，递归把同类问题逐步缩小，指针让我们按地址访问原数据，结构体组合相关信息，文件把结果保存下来。你现在可以把一个小程序拆成这些熟悉的部分，再逐项解释它为什么这样运行。课后建议按三个动作练习：先预测一个例子的输出，再真正运行，最后只改一个条件或一份输入，看变化是否符合自己的判断。优先把输入检查、循环边界、字符串结束标记和有效指针这几个点练扎实。交付资料里有完整示例和课堂题，可以从最短的开始逐个修改。学习编程不靠一次把所有符号背熟，而是反复完成“提出一个小需求、写出步骤、验证结果”。我们下一次再从这些已经看得见的基础上往前走。

画面要点：先预测，再运行，再小改动；重点检查输入、边界与地址；从一个能验证的小功能开始
