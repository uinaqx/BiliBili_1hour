# 从零运行第一个 C 程序

这份资料用于课后上机。学习 C 示例只需要文本编辑器和 C 编译器；视频制作工程里的 Node.js、Python、配音账号等，是重制视频时才需要的。

## Windows：准备编译器

一种做法是安装 MSYS2，再在它的 UCRT64 终端中使用 GCC。按 [MSYS2 官方入门说明](https://www.msys2.org/) 安装，安装后从开始菜单打开 **MSYS2 UCRT64**。

在这个终端输入：

```sh
pacman -Syu
```

如果更新过程要求关闭终端，关闭后重新打开同一个 UCRT64 终端，再执行一次更新命令，直到完成更新。然后安装编译器：

```sh
pacman -S mingw-w64-ucrt-x86_64-gcc
gcc --version
```

安装时按提示确认。最后一条显示版本信息，表示终端能找到编译器。这条安装命令也见 [mingw-w64 官方 MSYS2 说明](https://www.mingw-w64.org/getting-started/msys2/)。安装界面或系统要求有变化时，以对应官方页面为准。

## 运行课程里的问候程序

1. 在 Windows 中建立 `C:\c_lessons\00-2` 文件夹。
2. 把交付资料 `C示例/00-2/main.c` 复制到该文件夹。
3. 在 **MSYS2 UCRT64** 终端进入这个目录。MSYS2 中 `/c/` 对应 Windows 的 C 盘：

```sh
cd /c/c_lessons/00-2
gcc -std=c11 -Wall -Wextra main.c -o example.exe
./example.exe
```

看到 `Hello, C!`，就完成了“源代码 → 编译 → 运行”。终端路径或提示符前面的 `$` 不是命令的一部分，不要抄进去。

也可以用记事本打开 `main.c`，把问候文字改成自己的短英文句子，保存后重新编译、运行。自己另存新文件时，选择 UTF-8 和“所有文件”，确认文件名是 `main.c`，而不是 `main.c.txt`。修改代码后需要重新编译，运行旧的可执行文件不会自动包含新改动。

## 两种终端写法的区别

课程画面使用 Windows 终端的运行写法。下面两种写法分别用于对应终端，不要把路径格式混用：

| 环境 | 进入目录的例子 | 运行程序 |
|---|---|---|
| MSYS2 UCRT64 | `cd /c/c_lessons/00-2` | `./example.exe` |
| 已配置 GCC 的 PowerShell | `cd C:\c_lessons\00-2` | `.\example.exe` |

第一次学习可以一直使用 UCRT64 终端，避免额外配置编辑器或系统环境变量。拥有自己的编译环境后，再决定是否换成带按钮的编辑器。

## 输入与文件练习

- `03-2` 需要输入 `80` 再回车；程序在等待时不一定显示提示，先看对应例题的输入说明。
- 每个例题目录的 `测试输入与预期.json` 保存输入、输出及退出码。普通文本输入直接照着数值或字母输入即可，不要把 JSON 的引号和字段名一起输入。
- 文件练习始终进入对应例题目录再运行；目录中有需要的初始文件样本。`w` 会清空同名旧文件，`a` 在末尾追加，所以不要放在自己的重要资料目录里试验。
- 某些例题故意输入字母而不是整数，或者读取不存在的文件；显示失败提示、返回非零是预期行为。
- 先预测输出，再运行验证，最后只改一处。越界、除零、空指针和失效地址不能靠“试试看会打印什么”学习，本课也不运行这些没有可靠结果的写法。

课程例题在 MinGW GCC 6.3.0、C11 模式下实际验证。新编译器可能对故意省略 `break` 的贯穿示例给出额外警告；该例用于讲解执行顺序，正常跟读时使用上面的命令，不需要把警告一律当成编译失败。
