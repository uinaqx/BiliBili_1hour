# 课堂练习与答案

每题在成片中保留四秒思考。完整上下文与输入样本见 C示例。

## 变量、常量与数据类型 · Variables and Types

题目：现在请你自己跟踪一次。变量 a 最初是三，变量 b 一开始取走 a 当时的值。随后我们把 a 改成八。最后打印 a 和 b，会看到八和八，还是八和三？这里最值得观察的是：给 b 保存初值时，是复制当时的数字，还是把两个变量永久绑在一起？暂时不要用后面还没学的指针来想，只看普通整数变量。可以在纸上给 a、b 各画一个格子，执行一行就更新对应的格子。不要从最后一行倒猜，也不要把等号看成数学方程。等四秒之后，我们把每一步的值一起列出来。

```c
int a = 3;
int b = a;
a = 8;
printf("%d %d\n", a, b);
```

答案与原因：答案是八和三。第一行让 a 保存三，第二行读取 a 当时保存的三，再把这个三放进 b。到这里，两个变量各自都有一份值。第三行只把 a 改成八，没有任何一条语句去修改 b，所以 b 仍然是三。最后打印时，按逗号后面的顺序，先显示 a，再显示 b。这道题想帮你建立最重要的阅读习惯：程序是在执行步骤，数据也会随着步骤变化。每遇到一次赋值，都问自己右边现在是多少，算完之后写到谁里面。普通变量的值复制，不会自动形成以后一直同步的关系。等我们学到指针时，才会看到“通过地址访问同一份数据”的另一种情况。先把这两种情况留出区别，后面会更容易理解。

修正或核对代码：
```c
int a = 3;
int b = a;
a = 8;
printf("%d %d\n", a, b);
```

```text
8 3
```

## 运算符与表达式 · Operators and Expressions

题目：三次记录的总分是七分，记录数量是二。我们希望平均数是三点五，于是准备一个 double 变量来保存。但是这行代码把七除以二的结果直接赋给它，最后显示多少？请先看除号两边的数据，不要只盯着左边的 double。再想一想，计算发生在保存之前还是之后。如果结果不符合需求，你会在表达式哪里做一个小修改？我们保留一位小数来显示。四秒之后，不仅核对输出，还会给出一种让计算真正保留小数的写法。

```c
int total = 7;
int count = 2;
double average = total / count;
printf("%.1f\n", average);
```

答案与原因：原来的写法输出三点零。因为总分和人数都是整数，先做整数除法得到三，再保存进小数变量。格式要求一位小数，所以看见的是三点零。现在把表达式改成 total 乘以一点零，再除以 count。乘以一点零会让这一步按小数参与后续运算，因此七除以二能够得到三点五。屏幕上的修正版就是这个结果。还要加一个现实条件：人数不能是零。如果没有任何成绩，就不应该直接除以人数。等我们学会分支，就可以先检查人数是否大于零，再决定要不要计算。写程序并不是只挑一个公式，还需要想清楚公式什么时候可以使用。这种先检查、再计算的习惯，会一直贯穿后面的输入、指针和文件操作。

修正或核对代码：
```c
int total = 7;
int count = 2;
double average = total * 1.0 / count;
printf("%.1f\n", average);
```

```text
3.5
```

## 输入与输出 · Input and Output

题目：看这段已经写对的程序。输入六十以后，它会显示六十。现在只问一个问题：scanf 后面为什么是与符号加 score，而不是像 printf 那样直接写 score？从这两个函数想完成的事出发。一个只是把已有数字显示出来，另一个需要把新读到的数字保存进变量。后者究竟需要一份数字，还是需要知道变量所在的位置？你可以用“查看格子里有什么”和“往指定格子里放东西”来区分。先不用记住指针类型的完整写法，四秒后我们只把地址的作用讲清楚。

```c
int score = 0;
if (scanf("%d", &score) != 1) return 1;
printf("%d\n", score);
```

答案与原因：答案是，scanf 要修改 score 里面保存的内容，所以需要知道它的位置。与符号放在变量前面，就是取得这个变量的地址。读到六十之后，函数根据地址把六十写进去。printf 只负责显示当前的值，因此打印整数时直接传 score。这里两种传法的差别，来自任务的差别，不是随便约定的标点习惯。不要为了试错，去运行把整数值误当地址传入 scanf 的程序，那不一定只是显示错误结果，还可能访问错误的位置。我们保留正确写法，用图来理解这个动作：输入先变成数字，再沿着位置标记写入 score。等指针一章学完，你就能自己写一个函数，通过同样的方式修改外面的变量。

修正或核对代码：
```c
int score = 0;
if (scanf("%d", &score) != 1) return 1;
printf("%d\n", score);
```

```text
60
```

## 分支结构 · Branches

题目：这一题成绩恰好六十。需求说六十分及格，但条件写成严格大于六十。程序现在会显示 pass，还是 fail？如果结果不符合需求，应该修改哪个符号？先在脑中把 score 换成六十，再读这个问题：“六十比六十更大吗？”不要把“大于”和“不小于”当成同一句话。也可以顺便想想五十九和六十一。一个正确的及格判断，应当把这三个边界附近的输入分别安排到哪一边？四秒后我们一起修正条件。

```c
int score = 60;
if (score > 60) {
    printf("pass\n");
} else {
    printf("fail\n");
}
```

答案与原因：原程序会输出 fail，因为六十并不严格大于六十。条件不成立，就进入 else。要符合“六十分及格”的规则，应该改成大于等于。屏幕上的修正版在六十分时显示 pass。再拿五十九试，比较不成立；拿六十一试，比较成立。这样我们就把临界点两边都核对了一遍。写程序时，代码能编译只是第一步。像这里的符号都合法，编译器不能代替你判断学校的及格规则。真正需要我们做的是，把中文需求翻译成明确条件，再用具体数据检查。后面数组的最后一个位置、循环的结束条件、文件是否打开成功，也都需要这样检查边界。现在就把六十这一题当成练习这种习惯的起点。

修正或核对代码：
```c
int score = 60;
if (score >= 60) {
    printf("pass\n");
} else {
    printf("fail\n");
}
```

```text
pass
```

## 循环结构 · Loops

题目：这一题 i 从零开始，只要它小于三就执行。每次把 sum 加一，循环后再打印 sum。请问循环体执行几次，最终的和是多少？不要看到三就马上猜答案。依次列出进入循环体时 i 的值，再问 i 等于三的时候条件是否成立。这里用的是小于，而不是小于等于。下一章数组的第一个位置恰好也是从零编号，这种写法会频繁出现。先用四秒把零、一、二、三分别判断一遍，之后我们一起核对哪些值真的进入了循环体。

```c
int sum = 0;
for (int i = 0; i < 3; i++) {
    sum++;
}
printf("%d\n", sum);
```

答案与原因：循环体执行三次，所以最后输出三。进入时的 i 依次是零、一、二。第二次更新后是二，仍然小于三；第三次执行后更新成三，再检查条件时不成立，于是结束。如果误写成小于等于三，就会多执行一次，让零、一、二、三都进入循环体。对于只有三个元素的数组，这种多出来的一次就可能造成越界。因此，循环次数和数字看起来多大不是一回事，要同时看起点、比较符号和每次更新。最可靠的方法是先用几个具体值模拟。刚开始可以画表，把 i、条件和 sum 分三列写下来。等这个过程熟悉后，你会逐渐一眼认出“从零到小于元素个数”表示遍历所有合法位置。

修正或核对代码：
```c
int sum = 0;
for (int i = 0; i < 3; i++) {
    sum++;
}
printf("%d\n", sum);
```

```text
3
```

## 数组与字符串 · Arrays and Strings

题目：字符数组 word 有四个位置，初始文字是 cat。请判断，第零、第一、第二和第三个位置分别保存什么？最后一个位置能不能再随便放一个普通字母，然后仍然当成同样的字符串打印？这题不需要猜实际内存地址，只要把三个英文字母按顺序排好，再给结束标记找一个位置。想想刚才读取十五个字符时，为什么总是给数组空出最后一格。屏幕会打印原来的字符串。四秒之后，我们再检查第四格是不是“没有用”，以及破坏结束标记为什么会让字符串函数失去明确的停止位置。

```c
char word[4] = "cat";
printf("%s\n", word);
```

答案与原因：四个位置依次是 c、a、t 和结束字符。最后一格不是浪费，而是在告诉字符串函数应该到哪里停止。这里打印百分号 s，会显示 cat，不会把结束字符当成可见字母显示出来。修正版的观察代码还检查了编号三是不是结束字符，结果为一，表示判断成立。请注意，结束字符和普通数字字符零不同；我们用单引号包住反斜杠零，表达那个值为零的字符。如果把这最后一格改成普通字母，却没有在后面准备新的合法结束位置，再当字符串打印，就不能期待一个固定可靠的结果。我们不运行这样的越界风险来猜答案，而是从容量规则判断。字符串内容加结束标记都必须放在数组内部，这个结论比背住某一次运行现象更重要。

修正或核对代码：
```c
char word[4] = "cat";
printf("%s\n", word);
printf("%d\n", word[3] == '\0');
```

```text
cat
1
```

## 函数与递归 · Functions and Recursion

题目：函数 add_one 会把传入的整数加一，并交回结果。main 里的 x 是四，调用一次函数之后，直接打印 x，没有用等号接住返回值。这个 x 现在是四还是五？先区分两个动作：函数算出了一个新值，不等于自动把外面的变量改了。你可以回想刚才内部成绩八十五、外部仍然八十的例子。如果需求就是把 x 更新成五，外面应该怎样使用这次调用的结果？四秒之后，我们一起给 main 加上需要的保存动作。

```c
#include <stdio.h>
int add_one(int n) { return n + 1; }
int main(void) {
    int x = 4;
    add_one(x);
    printf("%d\n", x);
    return 0;
}
```

答案与原因：原程序会显示四。add_one 的确算出了五，但 main 没有保存这个返回结果，原来的 x 自然还是四。调用一次函数，并不表示原变量必然会变化。现在改成 x 等于 add_one 括号 x。先读取旧 x 的四交给函数，函数返回五，再把五写回 x。最终打印才会显示五。这个写法把每一步都明确表达出来，也和最初的 score 等于 score 加五是同一种思路。函数调用可以放在表达式里面，因为它能产生一个返回值。读这样的语句时，可以先在纸上算出调用结果，再完成赋值。下一章我们会看到另一种方式：把 x 的地址交出去，让函数通过地址直接修改原来的 x。现在先把返回值方式用熟，就更容易对比两条路线。

修正或核对代码：
```c
#include <stdio.h>
int add_one(int n) { return n + 1; }
int main(void) {
    int x = 4;
    x = add_one(x);
    printf("%d\n", x);
    return 0;
}
```

```text
5
```

## 指针 · Pointers

题目：屏幕上 x 最初是十，y 先复制 x 的值，p 则保存 x 的地址。之后通过星号 p 把那个位置改成二十。最后打印 x 和 y，分别会是多少？这题把第一章的普通变量复制，与本章的地址访问放在一起。请先给 x、y 各画一个格子，再从 p 画一根箭头，看看修改动作究竟沿箭头走到哪一个格子。不要因为 y 也曾经从 x 得到初始值，就认定它以后会一直跟着 x 变化。四秒之后，我们把两种关系分别检查。

```c
int x = 10;
int y = x;
int *p = &x;
*p = 20;
printf("%d %d\n", x, y);
```

答案与原因：答案是二十和十。y 初始化时复制的是当时的数字十，所以它有自己的一份值。p 保存的则是 x 的地址，星号 p 等于二十，修改的是 x 对应的那一格。没有任何语句去修改 y，因此它还是十。这个结果把“复制内容”和“复制地址”分得很清楚。都是值复制，但被复制的值代表什么，会决定后面能做什么。理解指针时可以一直用三个问题帮助自己：指针保存哪个地址，那个地址对应哪份数据，这一次是在改指针还是在改它指向的内容？如果你能用这些问题解释这道题，再回看 scanf、交换函数和数组首元素，就已经形成了同一套解释，而不是分别死记几种奇怪写法。

修正或核对代码：
```c
int x = 10;
int y = x;
int *p = &x;
*p = 20;
printf("%d %d\n", x, y);
```

```text
20 10
```

## 结构体 · Structures

题目：现在结构体 a 保存 Ana 和八十分，随后把整条记录复制给 b。接下来只把 b 的成绩改成九十分。最后 a 和 b 的成绩分别是多少？请留意这两个变量本身都是结构体，不是指向同一条记录的两个指针。这个结构体的姓名数组和成绩都直接放在记录里，赋值会复制这些字段的内容。你可以回想普通整数变量的那一题。先复制，再只修改副本，会不会自动把原件也改掉？四秒之后，我们把结构体赋值和通过地址修改再区分一次。

```c
struct Student { char name[16]; int score; };
struct Student a = {"Ana", 80};
struct Student b = a;
b.score = 90;
printf("%d %d\n", a.score, b.score);
```

答案与原因：答案是八十和九十。b 等于 a 时，复制了这个结构体里面的字段内容。后面修改 b 的成绩，只影响 b，不影响 a。这里姓名数组直接属于结构体，所以姓名内容也随记录一起复制。先不要把这个结论随意推广到所有复杂结构：如果某个字段保存的是指针，复制那个字段时复制的是地址，仍需要追踪它指向谁。本课的 Student 使用固定字符数组和整数，关系比较直接。到现在，我们已经会用变量保存一个数字，用数组保存一组同类型数据，用结构体把不同但相关的信息合起来。看到一个需求时，不一定马上开始写循环，也可以先想数据应该怎样组织。把姓名和成绩的关系表达清楚，后面的计算与输出就会少一些容易混淆的对应关系。

修正或核对代码：
```c
struct Student { char name[16]; int score; };
struct Student a = {"Ana", 80};
struct Student b = a;
b.score = 90;
printf("%d %d\n", a.score, b.score);
```

```text
80 90
```

## 文件操作 · Files

题目：文件已经保存了八十分，接下来要把九十分接在后面，保留旧记录。屏幕上现在用的是 w，它能保留旧记录吗？应该改成 r、w 还是 a 打开？请按打开方式的含义判断，不用去猜某个编辑器是否给你保留了副本。程序要明确向文件系统提出哪一种请求，就会影响现有文件内容。四秒之后，我们使用正确方式执行一次，并同时检查程序结果和文件本身。看见一条成功提示还不够，也要确认保存下来的内容确实符合需求。

```c
FILE *fp = fopen("scores.txt", "w");
if (fp == NULL) return 1;
if (fprintf(fp, "%d\n", 90) < 0) {
    fclose(fp); return 1;
}
if (fclose(fp) != 0) return 1;
printf("written\n");
```

答案与原因：应该使用 a。原文件里的八十得到保留，新写入的九十追加在后面。我们既核对了程序显示 appended，也实际核对了文件现在有八十和九十两行。如果改成 w，成功打开原文件时就会清空旧内容，随后写入九十，原来的八十不会因为它也是一份成绩就自动留下。r 则是为了读取，不符合这次写入的目的。这道题也把整个程序的思路收了回来：先明确需求，选合适的数据和操作，检查是否成功，再验证最终结果。文件是一个特别容易看见后果的地方，打开模式必须认真选择。现在你可以把一位同学的输入、成绩判断和保存操作连起来，再逐步扩展为多位同学的记录。不要一开始就追求很大的系统，先让最小的一条路径可靠地工作。

修正或核对代码：
```c
FILE *fp = fopen("scores.txt", "a");
if (fp == NULL) return 1;
if (fprintf(fp, "%d\n", 90) < 0) {
    fclose(fp); return 1;
}
if (fclose(fp) != 0) return 1;
printf("appended\n");
```

```text
appended
```
