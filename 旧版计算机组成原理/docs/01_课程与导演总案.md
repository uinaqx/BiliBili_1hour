# 两小时建立计算机组成原理的完整框架

## 定位与学习成果

观众是正在大学学习计算机组成原理、具备变量/数组/循环基础的学生。目的为理解课程、连接知识和开展小实验，不涉及考研，不编造某校期末考点覆盖率。标题建议用“2小时串起计算机组成原理：从一段程序到整台计算机”；副标题“数据表示·运算·存储·指令·CPU·流水线·I/O”。“学完”指完成这次有边界的主干导学，不等于替代整学期的推导、实验与习题。

完成后应能独立做到：

1. 对给定位宽完成无符号/补码解释，识别溢出，解释浮点范围与精度。
2. 说明组合逻辑、时序逻辑、ALU、寄存器与控制信号的协作。
3. 在明确假设下计算存储扩展、Cache地址字段、命中率及平均访问时间。
4. 追踪教学指令的寄存器、内存与PC变化，区分ISA与微架构。
5. 为短指令序列画出五级流水时间表，解释转发、停顿和冲刷。
6. 使用IC、CPI、频率、Amdahl公式分析给定模型，说明单位与统计边界。
7. 区分轮询、中断与DMA的责任，解释数值到屏幕输出之间的软件/硬件链路。

不在主片内展开：完整布尔化简方法、所有补码乘除算法手算、完整IEEE 754边界证明、完整RV32I二进制解码、复杂微程序控制字设计、DRAM控制器细节、乱序调度算法、多核一致性协议、详细页表容量与操作系统页面置换。对应先修/拓展材料在阅读清单里列出，不能暗示已经讲透。

## 主线与统一模型

主线：`sum([3,5,7,9])=24`。数组基地址0x100，结果地址0x200，每元素32位，小端、字节编址。示例指令采用RV32I语义子集，不启用压缩扩展。通用寄存器32个，x0不可写。教学程序不遵守完整ABI，不能当作可直接链接的函数。多字节字访问要求4字节对齐，越界和非对齐显式拒绝。

唯一权威数据源是 `data/course.json`；作者源文件为 `build_content.py`。文案修改必须改作者源后重新生成，避免讲稿与播放器分叉。模拟器输出实验轨迹，播放器读取它；动画不得自行伪造数据来配合旁白。

五级流水使用独立模型：IF/ID/EX/MEM/WB，单发射、顺序推进、指令数据资源不冲突；ALU结果EX末产生，load数据MEM末产生，消费者EX需要输入；有常见EX输入转发；相邻load-use停顿1周期。分支示意单独声明EX末判定、猜不跳、错误路径2条、额外恢复成本忽略。它不是CPU语义模拟器的实测时钟模型。

## 120分钟结构

完整时间码见 `00_时间轴.md`。11章、60个120秒镜头，严格合计7200秒。每章不是只展示若干标题：60个镜头均有可朗读旁白、专用画面说明、屏显文字、预测问题和答案。

|分钟|章节|教学作用|
|---|---|---|
|00–04|导学与整机地图|明确问题、模型与学习方法|
|04–18|数据表示|建立位串与数值的解释规则|
|18–32|运算与数字逻辑|从全加器走到状态更新|
|32–48|存储系统|容量、局部性、地址划分与访问成本|
|48–62|指令系统|连接程序与硬件可见行为|
|62–78|CPU数据通路与控制|让指令沿部件运行|
|78–90|流水线|理解重叠、依赖和停顿|
|90–98|性能分析|把行为转成有边界的时间模型|
|98–108|总线与I/O|连接设备通知与数据搬运|
|108–116|整机串联与综合实验|把各层接回同一段程序|
|116–120|知识重建与课后学习|主动回忆、安排后续练习|

## 叙事与教学节奏

每镜头：先提问题→画机制→算一个数/走一个状态→留至少6秒预测→解释答案→连接下一镜。每个公式必须随附前提、符号含义、单位和代入实例。同一问题先让学生预测，不先把答案挂在题旁。段内不采用“大家都知道”“显然”等跳步话术。

每镜头的五拍是剪辑槽位，不是已测得的旁白时长。全文约2.7万含标点字符；专业术语读法、公式口述会影响真实时长，不能用字符数证明配音一定适配。参考口播密度约250–280中文字符/分钟，预留6秒独立作答和4–10秒演算观察。实际配音后测时长，再做语义切句与剪辑；若超出可用窗口，先精简重复语句，保留定义、前提与推导，不自动加速或截断。最后仍需逐镜锁定120秒。

S57有三道综合题，应在60–90秒的实例段逐题揭示，把90–102秒留给Cache字段最终自测。S58的两张时间表应全程保持同一周期尺度。S60末尾约5秒完整地图静止，属于120秒预算内部。

## 视觉与屏显语言

- 1920×1080、16:9；精剪母版目标30fps，本轮静音状态保持版使用VFR，短样片恒定30fps；主片1080p即可，不把4K作为学习质量指标。
- 背景#101827；正文#EAF0FA；数据流#45C4FF；控制流#F6BB55；地址#B99CFF；正确/命中#57D3A0；停顿/失效#FF7C86。颜色必须配文字或形状，不只靠红绿区分。
- 中文字体优先Noto Sans CJK SC/思源黑体；代码用DejaVu Sans Mono等宽字体。标题54–64px，正文34–40px，注释不低于26px；公式按可读性放大。留左右96px、顶部72px、底部字幕安全区140px。
- 顶部：章名、镜头标题；中央：机制图；右侧：最多3条当前结论；底部：条件/单位和字幕。代码超过12行时分屏或滚动聚焦，不整体缩小到无法阅读。
- 二进制每4位分组，十六进制一律加0x；十进制PC注明“十进制”。地址与数据使用不同形状，避免仅靠色彩。
- 位运算每次移动1位；时序图每列一个周期；寄存器只在定义的状态更新点改变；Cache命中与替换由轨迹驱动；禁止同时点亮全部数据通路。
- 常规对象动画0.4–0.8秒，观察停留2–4秒；无需频繁镜头推拉、粒子、3D机箱或装饰性“代码雨”。章节切换短于2秒并纳入镜头时长。

## 制作阶段与完成定义

1. 文案锁定：60镜完整脚本、章节目标、例题答案与假设齐全。
2. 工程实现：标准库实验模型、可复现JSON轨迹、离线SVG播放器、时间轴检查、配音接口。
3. 样片：至少1段30秒无配音预览，展示实际状态动画而非纯标题轮播；生成关键帧供检查。此时不宣称两小时成片完成。
4. 全量视觉：逐镜落实专用分镜；所有60镜审阅，模板覆盖不足的镜头逐个列入待办，不把通用卡片当成已完成的专业动画。
5. 配音与精剪：接入用户音频，按语义对齐，人工确认公式发音、停顿与字幕，锁定7200秒。
6. 成片验收：FFprobe检查时长、分辨率、帧率；抽查与全片审看相结合，片尾/章节边界/无声区间检查；导出MP4、SRT及无字幕母版。
