### kt-01-02 第一行程序

先看左边这个完整的小程序。第一行的 fun 表示这里定义了一个函数，main 是程序开始执行的位置。函数暂时可以理解成一个有名字的步骤集合。程序运行后，会从 main 的大括号里面开始做事。大括号把属于这一部分的代码圈起来。现在先认识入口，不急着背函数的完整定义。

第二行让屏幕显示一句话。println 后面的小括号装着要显示的内容，双引号表示这是文字。运行后，左下方出现你好，Kotlin。它不会把双引号本身打印出来。Kotlin 通常不要求在每行末尾写分号。我们把一条清楚的指令放在一行，缩进是为了让人看清代码的层次。英文标点和中文标点也要区分。

## 变量与数据类型

### kt-02-01 给数据起一个名字

如果成绩要使用好几次，每次都直接写八十，会很难看出它表示什么。我们可以先给数据起名字。这里的 name 保存姓名，score 保存成绩。左边的名字帮助人理解用途，右边是最初保存的值。等号在这里表示把右边的值交给左边这个名字，和数学里的等式不是一回事。变量名尽量说明用途，不要全都叫字母甲乙丙。

下面输出 name 和 score 时，没有给它们加双引号，所以程序会取出它们保存的内容，依次显示小林和八十。若写成引号里的 score，显示的就只是这个英文单词。val 是声明这种名字的关键字，后面还会看到 var。名字、数据和引号这三件事分清楚，很多初学者常见的小错误就容易发现了。

```kotlin
fun main() {
    val name = "小林"
    val score = 80
    println(name)
    println(score)
}
```

预期结果：
```text
小林
80
```

画面要点：名字用来表达数据用途；等号在这里表示赋值；变量名外面不加引号

### kt-02-02 val 与 var

姓名暂时不需要重新赋值，所以这里用 val。成绩可能录入有误，需要修改，因此这里用 var。可以先记住一个实用习惯：默认用 val，确实需要重新赋值时再用 var。这让读代码的人能少猜一些。val 的名字一旦完成初始化，就不能再指向另一个值；var 则允许在原来的类型范围内换一个值。

第四行把成绩改成八十五。它没有再写 var，因为不是重新声明一个新变量，而是在修改已有变量。输出里的美元符号表示把变量当前的内容放进文字，这叫字符串模板。此时显示的是修改后的成绩。不要把 val 简单理解成任何东西都绝对不能变化，后面集合一章会说明：不能重新赋值，和对象内部能不能修改，是两层不同的事情。

```kotlin
fun main() {
    val name = "小林"
    var score = 80
    score = 85
    println("$name：$score")
}
```

预期结果：
```text
小林：85
```

画面要点：默认 val，需要改值再用 var；重新赋值不用重复声明；输出读取当前值

### kt-02-03 整数、小数与真假

数据除了有名字，还有种类。人数通常是整数，这里写 Int；平均分可能带小数，这里写 Double。变量名后面的冒号用于说明类型。类型帮助程序判断哪些操作是合理的，例如两个成绩可以相加，而姓名不能拿去求平均。很多时候 Kotlin 能根据右边的值推断类型，所以之前没有写冒号也能运行。省略类型不等于没有类型。

是否及格适合用 Boolean，它只有 true 和 false 两种值，表示真与假。注意它们没有双引号。带引号的真假单词是文字，不能直接替代布尔值。运行结果分别显示三、八十六点五和 true。初学时先熟悉 Int、Double 和 Boolean 就够了。Long 可以容纳更大范围的整数，Float 是另一种浮点数，本课不展开它们的存储细节。

```kotlin
fun main() {
    val count: Int = 3
    val average: Double = 86.5
    val passed: Boolean = true
    println(count)
    println(average)
    println(passed)
}
```

预期结果：
```text
3
86.5
true
```

画面要点：Int 保存常见整数；Double 保存常见小数；Boolean 表示真或假

### kt-02-04 字符与字符串

文字也有两种常见写法。单引号里的 A 是一个字符，类型叫 Char；双引号里的小林是一段字符串，类型叫 String。不要把两个汉字一起塞进单引号。字符串可以很长，字符用于一个字符单位。Kotlin 的 Char 不是所有可见符号的通用计数办法，例如某些表情会占用两个这样的单位。现在先按普通姓名和等级来练习。

第四行把姓名和等级放进一句完整的话。美元符号后面直接写变量名就能取值。如果要在模板中计算，则用美元符号加一对大括号，把表达式装进去。这里没有计算，只是把两份数据组合成文字。最后输出消息变量。给文字取一个名字，也可以让长句更好维护，不必把所有内容都挤进输出函数的小括号。

```kotlin
fun main() {
    val grade: Char = 'A'
    val name: String = "小林"
    val message = "姓名：$name，等级：$grade"
    println(message)
}
```

预期结果：
```text
姓名：小林，等级：A
```

画面要点：单引号用于 Char；双引号用于 String；字符串模板插入变量内容

### kt-02-05 类型转换要写清楚

假设三人的总分是二百五十一。要算带小数的平均分，可以先把 total 转成 Double，再做除法。toDouble 后面的小括号表示调用一个现成的方法。转换会产生一个新的值，不会把原来 total 的类型永久改掉。Kotlin 不会在所有赋值和传参场合自动替我们把整数变成小数，遇到类型要求不同时，要把转换意图写清楚。

第一项结果带有小数。最后一行则把文字八十五转换成整数，再加一，显示八十六。文字转数字有前提：文字确实得符合数字格式。如果写的是你好，直接调用 toInt 会出运行错误。我们先用合法输入认识转换，后面再用可能为空的结果和异常处理应对不确定输入。不要把转换函数当成可以猜出任意文字含义的工具。

```kotlin
fun main() {
    val total = 251
    val count = 3
    val average = total.toDouble() / count
    println(average)
    println("85".toInt() + 1)
}
```

预期结果：
```text
83.66666666666667
86
```

画面要点：先转换，再进行需要的小数运算；转换不会改变原变量类型；文字转数值需要合法格式

请判断这段代码能不能运行并显示九十。第一行保存八十，第二行看上去只是换成九十。重点检查声明时使用的是哪个关键字。若你认为有问题，再想一个最小的修改办法。这里不用改变输出语句，也不用给数字加双引号。判断时先问能否通过编译，再讨论运行结果。

（四秒独立思考，答案在下一页揭晓）

```kotlin
fun main() {
    val score = 80
    score = 90
    println(score)
}
```

画面要点：先检查声明方式；区分编译错误与运行结果

### kt-02-07 答案：需要重新赋值就用 var

原题不能通过编译，因为 val 声明的 score 已经有值，不能再次赋值。修正办法是，如果业务确实要求改成绩，就把声明中的 val 改成 var。现在左边展示的是修正版本，运行后会显示九十。另一种合理设计是保留旧成绩，再用另一个 val 保存修正后的成绩，这取决于是否需要同时保留两份数据。

不要从这个练习得出所有变量都应该用 var 的结论。能不变的名字保持不变，能帮助你更早发现误改。还有一条规则：var 允许重新赋值，不代表允许随时换类型。若一开始推断为 Int，后面仍然不能直接赋给它一段文字。我们已经认识名字、值、类型和重新赋值，下一章开始让这些值参与计算。

```kotlin
fun main() {
    var score = 80
    score = 90
    println(score)
}
```

预期结果：
```text
90
```

画面要点：原题是编译错误；修正后输出 90；var 也要遵守原来的类型

## 运算符与输入输出

### kt-03-01 常见计算与运算顺序

加减乘除可以把已有数值变成计算结果。乘法和除法通常先于加法和减法，所以第一行先算九十乘二，再加八十。第二行用小括号明确要求先算括号里面。初学时，不确定顺序就加上能表达意图的小括号，别让读者靠心算猜你的目的。注意程序里乘法使用星号，不能直接照搬纸上写的乘号。

前两项分别得到二百六十和三百四十。最后的百分号不是百分比，而是求余数。十七除以五，能完整分出三组，还剩二，所以余数是二。它经常用于判断奇偶或每隔几次做一件事。现在先使用非负整数理解余数，涉及负数时再仔细核对规则。运算之前先确认数据类型，通常比盲目修改符号更有效。

```kotlin
fun main() {
    val total = 80 + 90 * 2
    val grouped = (80 + 90) * 2
    println(total)
    println(grouped)
    println(17 % 5)
}
```

预期结果：
```text
260
340
2
```

画面要点：先乘除，后加减；括号明确计算顺序；百分号在这里表示余数

### kt-03-02 整数除法为什么没有小数

看第一行，五除以二，为什么结果是二，而不是二点五？因为这里的两个操作数都是整数，执行的是整数除法，小数部分被截去。这个行为不是输出窗口把小数藏起来了，而是这一步计算的结果本来就是整数。把它保存进变量后再转成 Double，只会得到二点零，丢掉的小数不会重新回来。

后两行把至少一边变成 Double，再参与除法，结果都是二点五。写平均分时，正确顺序是先让除法按小数方式计算，再保存结果。不要先做整数除法，最后才想补救。这是一个很适合自己动手改的例子：依次修改数字、括号和转换的位置，观察结果。看见一个意外结果时，沿着计算发生的顺序往前找原因。

```kotlin
fun main() {
    println(5 / 2)
    println(5.0 / 2)
    println(5 / 2.toDouble())
}
```

预期结果：
```text
2
2.5
2.5
```

画面要点：两个整数相除仍是整数；小数部分在计算时被截去；需要小数时先转换

### kt-03-03 比较与逻辑判断

程序还可以比较两个值。大于等于六十，会得到一个真或假的结果。判断相等通常使用两个等号，单个等号用于赋值，这一点要特别分清。比较结果可以保存成 Boolean，也可以直接交给后面要学的条件判断。这里成绩是八十五，所以是否及格这件事的结果为真。比较是在提出问题，不是在修改成绩。

两个与号表示并且：成绩及格，而且到场，整个条件才成立。两个竖线表示或者：只要一边成立，条件就成立。感叹号表示把真假反过来。最后一句问，是否不及格，或者没有到场，这里两者都不是，所以输出 false。初学时先把复杂条件拆成有名字的小条件，再组合起来，比在一行堆很多符号更容易检查。

```kotlin
fun main() {
    val score = 85
    val attended = true
    println(score >= 60)
    println(score >= 60 && attended)
    println(score < 60 || !attended)
}
```

预期结果：
```text
true
true
false
```

画面要点：比较产生 Boolean；两个等号判断相等；并且、或者、取反组合条件

### kt-03-04 从键盘读取一行

之前的数据都由我们写在代码里。现在让使用程序的人输入。先用 print 显示提示，因为没有自动换行，输入通常会接在提示后面。readln 会等待用户输入一整行，并把这行内容作为 String 交回来。名字只是变量 name，真正的输入动作发生在等号右边。运行时停在这里等待，不表示程序卡死了。

假设键盘输入小林，再按回车，程序会显示你好，小林。不同运行工具会不会同时显示你键入的文字，属于终端的显示方式；左下方主要列程序自己输出的内容。readln 读取的是文字，即使输入的是八十五，也仍然是字符串。要参与数字运算，还要明确转换。真实程序也可能遇到输入结束等情况，入门时先按正常交互路径练习。

```kotlin
fun main() {
    print("请输入姓名：")
    val name = readln()
    println("你好，$name")
}
```

预期结果：
```text
请输入姓名：你好，小林
```

画面要点：readln 等待一整行输入；返回值是 String；按回车后继续执行

### kt-03-05 读取成绩再计算

这段代码把输入和计算分成两个小步骤。先读到文字，再把合法的整数文字转换成 Int。这样写比把所有方法挤在同一行更方便初学者追踪数据。假设输入八十，text 保存的是文字，score 保存的是整数。名字可以不同，关键是你能说清每一步得到的数据是什么。调用转换函数时，小括号不能省略。

下一步给成绩加五，再输出加分后的八十五。如果没有先转成整数，而是把文字和数字直接拼在一起，得到的可能是文字连接，而不是想要的算术结果。输入是程序边界，用户不一定会按要求操作。这里我们明确假设输入合法；后面学到空安全和错误处理，就会把这个假设去掉，让程序在输入不合法时也能给出清楚的反馈。

```kotlin
fun main() {
    val text = readln()
    val score = text.toInt()
    val nextScore = score + 5
    println("加分后：$nextScore")
}
```

预期结果：
```text
加分后：85
```

画面要点：输入先得到文字；转换后才能做数值计算；合法输入是假设，不是保证

### kt-03-06 练习：两个加号的结果

请预测两条输出分别是什么。它们看上去都在做八加二，但第一条的左边仍然是字符串，第二条先调用了 toInt。先辨认参与加号运算的数据类型，再判断这一步是在连接文字，还是在做加法。不要只看文字长得像数字就把它当成数值。四秒之后，我们逐行核对。

（四秒独立思考，答案在下一页揭晓）

```kotlin
fun main() {
    val text = "8"
    println(text + 2)
    println(text.toInt() + 2)

```

画面要点：先看类型，再判断运算；注意转换发生的位置

### kt-03-07 答案：连接文字与整数相加

第一条输出八十二，也就是先有字符八，再接上字符二。这里说的是两个字符连成的文字，不是八加二的数学结果。字符串左边的加号能把后面的值转成文字再连接。为了避免朗读数字造成混淆，请同时看左下方：第一行写的是八二，第二行写的是一零。

第二条先得到整数八，再和整数二相加，所以结果是十。两个表达式都可以通过编译，也都能运行，但含义不同。这提醒我们，程序没有报错不等于业务逻辑正确。判断代码时分三步：能否编译，能否正常运行，最后结果是否符合需求。接下来用比较产生的真假值，让程序根据不同情况走不同的路线。

```kotlin
fun main() {
    val text = "8"
    println(text + 2)
    println(text.toInt() + 2)
}
```

预期结果：
```text
82
10
```

画面要点：第一条是字符串连接；第二条是整数加法；能运行不等于符合需求

## 分支与循环

### kt-04-01 用 if 选择一条路线

程序不一定永远从头到尾执行所有代码。这里先检查成绩是否至少六十。如果条件为真，就执行 if 后面大括号里的输出。成绩是七十五，因此会走到及格这一支。括号里需要一个 Boolean 结果，不能随便放一个整数来表示成立。把条件先念成一句完整的问题，有助于你发现比较符号是否写反了。

如果条件为假，才执行 else 后面的部分。两条路线在这里互相排斥，不会把两个提示都输出。若不需要在失败时做任何事，else 可以省略。代码中缩进向右的部分属于分支内部，结束的大括号表示回到外层。检查时不仅看 if 这一行，也要看你打算控制的语句是否真的放进了对应的大括号。

```kotlin
fun main() {
    val score = 75
    if (score >= 60) {
        println("及格")
    } else {
        println("继续努力")
    }
}
```

预期结果：
```text
及格
```

画面要点：条件必须产生真假值；成立走 if，不成立走 else；大括号明确分支范围

### kt-04-02 if 也能产生一个值

刚才在两条分支里各写一次输出。现在让 if 先选择一段文字，再把选中的文字交给 label。条件为真时选及格，否则选未及格。这种能产生值的写法，叫作表达式。你可以先理解为，一个可以放在等号右边、最终得到结果的小结构。不是所有语言都这样写，所以不必用别的语言习惯来猜它。

这里的两条分支都得到字符串，因此 label 可以保存选中的文字。用于赋值时，需要把情况覆盖完整，所以不能只写成立时得到什么，却不说明其他情况。不要为了缩短代码，把很多层 if 嵌在同一行。简单选择适合简写，复杂处理仍然分行写清楚。我们最看重的是下一次再读时，能否迅速解释条件与结果之间的关系。

```kotlin
fun main() {
    val score = 75
    val label = if (score >= 60) "及格" else "未及格"
    println(label)
}
```

预期结果：
```text
及格
```

画面要点：if 可以作为表达式；赋值时要覆盖其他情况；简单选择可简写

### kt-04-03 用 when 处理多种情况

需要分成多档时，可以使用 when。这里先检查是否至少九十，若不满足，再检查下一项。箭头右边是这一项成立时产生的结果。你可以把它看成按顺序排列的判断清单。八十八不够九十，所以第一项没有选中。程序继续往下检查，而不是因为第一项不成立就结束整个 when。

八十八至少六十，于是选中及格，不会继续把其他项也执行一遍。else 用来接住前面都不满足的情况。这个例子用的是不带括号目标值的 when，也可以写成针对某个具体值逐项匹配的形式。入门先掌握一种，再按需求扩充。分档条件的顺序很重要，如果把至少六十放在最前面，九十五也会先被那一项接住。

```kotlin
fun main() {
    val score = 88
    val level = when {
        score >= 90 -> "优秀"
        score >= 60 -> "及格"
        else -> "未及格"
    }
    println(level)
}
```

预期结果：
```text
及格
```

画面要点：从上到下选择第一项成立条件；箭头右边给出结果；else 覆盖其余情况

### kt-04-04 for 与数字范围

当一个动作要重复几次时，不必复制很多行输出。这里的 for 会依次取出范围中的每个数，临时交给 number，再执行大括号里面的代码。一个点一个点连接的一到三，包含一和三两个端点。所以 number 先是一，再是二，最后是三。每次拿到不同值，是理解这个循环的关键。

循环处理完范围里的所有值以后，才走到下面的完成。不要把最后一句也误看成循环内部。Kotlin 还有不包含上界的写法，例如零 until 三得到零、一、二，也有倒序和步长的写法。本课先用包含端点的范围把执行过程走清楚。读循环时，先写下这一轮的变量值，再判断这一轮会输出什么，往往比直接猜总结果稳妥。

```kotlin
fun main() {
    for (number in 1..3) {
        println(number)
    }
    println("完成")
}
```

预期结果：
```text
1
2
3
完成
```

画面要点：范围 1..3 包含两端；每轮 number 得到一个新值；循环结束后执行后续语句

### kt-04-05 累计一组数字

现在不输出每一项，而是把它们加起来。先准备一个总和，初始值是零。循环依次拿到八十、九十和七十。这里的 listOf 暂时理解成把几项数据放在一起，下一章会专门学习集合。总和会反复修改，因此用 var；每轮得到的 score 是当前那一项，不需要我们自己写索引去找。

加等号表示，把当前总和加上这一轮的成绩，再保存回 total。第一轮后总和是八十，第二轮是一百七十，第三轮是二百四十。注意总和应该在循环外面初始化；如果每轮都重新设为零，就留不住前面累计的结果。最后输出二百四十。很多统计需求的骨架都是这样：准备初始值，逐项更新，循环结束后使用最终值。

```kotlin
fun main() {
    var total = 0
    for (score in listOf(80, 90, 70)) {
        total += score
    }
    println(total)
}
```

预期结果：
```text
240
```

画面要点：循环外准备累计值；每轮把一项加入总和；不要每轮重新清零

### kt-04-06 while 与停止条件

for 适合依次处理已知范围或集合。while 则是在每一轮开始前先检查条件，条件仍然成立就继续。这里 attempts 从一开始，只要不超过三，就输出一次尝试。它不像 for 那样自动取下一个元素，我们需要自己决定循环中哪些状态会改变。条件为假时，循环体一次也不会进入。

这一行的两个加号，把 attempts 增加一。它让条件最终有机会变成假。若忘记更新，attempts 会一直是一，程序就可能不停输出。学习循环时必须同时检查开始值、继续条件和状态更新。还可以使用 break 提前结束整个循环，或用 continue 跳过这一轮的剩余步骤，但要确认这些跳转不会绕过必要的更新。不要用无限重复来代替明确的结束设计。

```kotlin
fun main() {
    var attempts = 1
    while (attempts <= 3) {
        println("第 $attempts 次尝试")
        attempts++
    }
}
```

预期结果：
```text
第 1 次尝试
第 2 次尝试
第 3 次尝试
```

画面要点：每轮开始前检查条件；循环中应有走向结束的变化；两个加号表示增加一

### kt-04-07 练习：跳过一轮以后

请计算最后的 total。范围是一到四，包含四。当 n 等于三时会执行 continue，它不会结束整个循环，只跳过当前这一轮后面的步骤。建议你按一、二、三、四列出四轮，再分别记录总和有没有变化。特别留意第四轮是否还会执行。现在留四秒，自己算一次。

（四秒独立思考，答案在下一页揭晓）

```kotlin
fun main() {
    var total = 0
    for (n in 1..4) {
        if (n == 3) continue
        total += n
    }
    println(total)
}
```

画面要点：列出每轮 n 的值；continue 只跳过当前轮

### kt-04-08 答案：一加二加四

第一轮 n 是一，条件不成立，所以继续累计。第二轮同样加入二。第三轮 n 是三，执行 continue，后面的加法被跳过。这里不是给总和减三，也不是把整个循环提前结束，而是这一轮不执行剩下的那条加法。理解跳转的作用范围，比只记英文单词更重要。

第四轮仍然会进入，所以再加入四，最后总和是七。若把 continue 改成 break，那么第三轮会直接结束循环，四也不会加入，总和就成了三。两者差异可以用同一张逐轮记录表验证。到这里，你已经能让程序按条件分路，也能让一个步骤重复执行。下一步把一组有明确用途的步骤取一个名字，变成可以反复使用的函数。

```kotlin
fun main() {
    var total = 0
    for (n in 1..4) {
        if (n == 3) continue
        total += n
    }
    println(total)
}
```

预期结果：
```text
7
```

画面要点：跳过 3，但仍处理 4；最后总和是 7；break 会结束整个循环

## 函数与作用范围

### kt-05-01 把重复步骤取一个名字

如果同一套步骤需要多次使用，可以把它们放进函数。这里用 fun 定义 greet，名字后面的小括号暂时是空的，表示这次不需要额外提供数据。大括号里写这个函数实际要做的事。定义函数是在说明做法，不等于立刻执行函数里面的所有代码。main 是入口，程序仍然从它开始。

main 里面两次写 greet 加小括号，表示调用这个函数两次。每次调用，都会执行一次欢迎语输出。以后欢迎语需要修改，只改函数里面一处即可。函数不是为了把代码随便切碎，而是给一个完整任务取清楚的名字。一个好名字应该让别人只看调用位置，就大致知道这个步骤的作用。

```kotlin
fun greet() {
    println("欢迎学习 Kotlin")
}
fun main() {
    greet()
    greet()
}
```

预期结果：
```text
欢迎学习 Kotlin
欢迎学习 Kotlin
```

画面要点：定义说明做法，调用才执行；同一函数可以多次调用；名字应表达任务

### kt-05-02 参数把数据交给函数

如果每次问候的人不同，就把姓名作为参数交给函数。参数写在函数名后面的小括号里，用名字加冒号再加类型。这里告诉读者，需要一份 String 类型的姓名。函数内部使用 name，代表这一次收到的姓名。参数不是固定只能叫 name，你可以按数据含义取名字。定义时写类型，可以让调用者知道应该提供什么。

第一次调用时传入小林，第二次传入小陈，于是两次输出不同的问候。你可以把参数理解为这次执行任务需要的材料。传入的值和函数里的参数名字不必同名，重要的是位置、名称和类型匹配。不要在函数内部重新写死某一个姓名，那就失去了接收参数的意义。把会变化的材料交给参数，把稳定的处理步骤留在函数里。

```kotlin
fun greet(name: String) {
    println("你好，$name")
}
fun main() {
    greet("小林")
    greet("小陈")
}
```

预期结果：
```text
你好，小林
你好，小陈
```

画面要点：参数是本次调用需要的材料；定义参数时写明类型；每次调用可以传不同的值

### kt-05-03 返回值把结果交回来

函数不一定只负责显示文字，也可以算好一个结果再交回来。这里参数是原成绩，函数后面的冒号 Int 表示返回整数。return 把加五后的结果交给调用位置，并结束这次函数执行。参数和返回值方向不同：参数是外面交进来的材料，返回值是函数交出去的结果。把这两个方向分清，读代码会顺很多。

调用 addBonus 时，八十交给 score，函数返回八十五，然后 result 保存这个结果，最后再输出。输出和返回不是同一件事。只在函数里面 println，并不会自动让调用者拿到那个数。若函数只做事情而没有有意义的结果，返回类型是 Unit，通常可以省略。想把结果用于后续计算，就应该明确返回，而不是只让人眼看到输出。

```kotlin
fun addBonus(score: Int): Int {
    return score + 5
}
fun main() {
    val result = addBonus(80)
    println(result)
}
```

预期结果：
```text
85
```

画面要点：参数进入函数，返回值离开函数；return 同时结束本次调用；输出不等于返回

### kt-05-04 默认参数与具名调用

常见情况都加五分，可以给 bonus 设置默认值。调用者不提供这项时，使用默认的五；明确提供时，使用这一次给出的值。默认参数不是让参数变成随意类型，也不是让函数自己猜业务规则，而是在定义中把一种常用选择写清楚。是否应该默认加分，仍然由需求决定。

第一条调用只给原成绩，因此输出八十五。第二条把参数名也写出来，明确说明八十是原成绩，十是奖励分，因此输出九十。这叫具名调用，多个参数含义相近时尤其容易阅读。对于简单返回一个表达式的函数，也可以用等号写成单表达式形式。先把普通函数写熟，再追求简洁，不必第一次就把所有语法缩到最短。

```kotlin
fun finalScore(score: Int, bonus: Int = 5): Int {
    return score + bonus
}
fun main() {
    println(finalScore(80))
    println(finalScore(score = 80, bonus = 10))
}
```

预期结果：
```text
85
90
```

画面要点：默认值用于未显式提供的参数；具名调用写清数据用途；清楚比一味简短更重要

### kt-05-05 练习：原成绩会自动变吗

请预测最后输出八十还是八十一。函数确实算出了加一后的值，但调用位置有没有接住它？这一次函数接收的是整数值，我们没有在外面重新给 score 赋值。不要把函数名字读起来像修改动作，就认为外部变量一定被修改了。先找返回值去了哪里，再判断结果。

（四秒独立思考，答案在下一页揭晓）

```kotlin
fun increase(value: Int): Int {
    return value + 1
}
fun main() {
    val score = 80
    increase(score)
    println(score)
}
```

画面要点：函数计算结果去了哪里；检查外部有没有重新赋值

### kt-05-06 答案：接住返回值才会使用它

原题输出八十。函数算出了八十一，但这个返回值没有被保存，也没有被继续使用，所以原来的 score 仍然是八十。参数 value 只在这个函数的范围内有效，main 不能直接拿它的名字来用。不同函数可以有同名的局部变量，它们也不因此自动变成同一份变量。名字的可用范围，通常由它所在的代码块决定。

左边展示一种修正：用 nextScore 接住返回结果。现在先输出旧成绩八十，再输出新成绩八十一。保留两份数据，也能让变化看得清楚。函数内部有自己的局部步骤，外部通过参数和返回值与它协作。这是组织程序的重要边界。后面处理集合、空值和对象时，也会不断用到这个输入、处理、返回结果的基本结构。

```kotlin
fun increase(value: Int): Int {
    return value + 1
}
fun main() {
    val score = 80
    val nextScore = increase(score)
    println(score)
    println(nextScore)
}
```

预期结果：
```text
80
81
```

画面要点：原题返回值没有被使用；局部名字有自己的范围；修正后保留旧值与新值

## 字符串与集合

### kt-06-01 把多份成绩放在一起

如果班里有很多学生，不适合给每个成绩都起一个单独的变量名。listOf 可以把几项数据放进一个有顺序的列表。这里依次放入八十、九十和七十。方括号里的数字叫索引，用来指定位置。第一个位置是零，第二个位置是一，第三个位置是二。它不是成绩的名次，也不是学生编号，而是列表里的位置。

size 告诉我们元素数量，这里是三。last 取出最后一个元素，所以得到七十。不要把数量三当成最后一个合法索引，这个列表最后的位置是二。直接访问不存在的位置会发生运行错误，后面会介绍更稳妥的读取方式。列表中存放同一种用途的数据，通常也使用一致的类型。类型推断会帮助我们，但不能代替对数据含义的设计。

```kotlin
fun main() {
    val scores = listOf(80, 90, 70)
    println(scores[0])
    println(scores.size)
    println(scores.last())
}
```

预期结果：
```text
80
3
70
```

画面要点：列表按顺序保存多项数据；索引从 0 开始；数量与最后索引不同

### kt-06-02 只读列表与可变列表

listOf 返回只读列表接口，不能通过这个接口直接调用添加和删除。确实需要修改内容时，可以使用 mutableListOf。这里先放两项成绩，再用 add 加入七十。不要把只读接口理解成对背后所有数据的绝对冻结承诺。本课只是用两种常见创建方式，帮助你把读取和修改的需求区分清楚。

接着把索引零的位置改成八十五，再删除索引一的元素。删除后，后面的元素会向前接上。最终列表里剩八十五和七十。虽然 scores 用 val 声明，仍然能修改可变列表的内容，因为我们没有让 scores 重新指向另一份列表。这正是前面留下的区别：名字能不能重新赋值，和它所指对象的内容能不能变，是两个不同问题。

```kotlin
fun main() {
    val scores = mutableListOf(80, 90)
    scores.add(70)
    scores[0] = 85
    scores.removeAt(1)
    println(scores)
}
```

预期结果：
```text
[85, 70]
```

画面要点：mutableListOf 支持增删改；删除后位置可能变化；val 不等于对象内容绝对不变

### kt-06-03 遍历列表并统计

现在把列表和循环连起来。for 会依次拿到每个成绩，放进本轮的 score，再加入总和。若只需要处理每个值，就不必自己计算零到几的索引。这样可以减少把数量当位置的错误。总和在循环外创建，每一轮保存之前累计的结果。请在心里走一遍：八十，一百七十，二百四十。

循环结束后，把总和转成 Double，再除以元素数量，得到平均分八十点零。这里明确知道列表不为空，所以数量不是零。实际数据可能为空时，应先决定没有成绩要显示什么，再写除法。集合自带 average 等统计方法，但现在先手工走通步骤，有助于理解这些方法替我们做了什么。简洁写法应该建立在理解过程之后。

```kotlin
fun main() {
    val scores = listOf(80, 90, 70)
    var total = 0
    for (score in scores) {
        total += score
    }
    val average = total.toDouble() / scores.size
    println(average)
}
```

预期结果：
```text
80.0
```

画面要点：优先直接遍历元素；总和在循环外初始化；计算平均值前考虑空集合

### kt-06-04 按姓名查询成绩

列表适合按位置读取。但如果需求是根据姓名查成绩，用姓名和成绩组成对应关系会更直接。mapOf 创建这种映射，也常叫字典或映射表。to 把左边的键和右边的值配成一项。这里用姓名作键、成绩作值，所以查询时方括号里写姓名，而不是从零开始的索引。真实班级可能重名，正式系统通常改用学号作为键。

查小林得到八十五，查不存在的小王会得到 null，表示这次没有找到值。它不是分数零，也不是空字符串。你不能因为返回结果看着像一个数字，就完全忽略找不到的情况。下一章会专门学习这种可能有值、也可能没有值的类型。需要增删映射时可以用 mutableMapOf，同一个键再次赋值会替换原来的对应值，不会保留两条相同键的记录。

```kotlin
fun main() {
    val scores = mapOf("小林" to 85, "小陈" to 92)
```

## 空值与空安全

### kt-07-01 没有结果也是一种情况

假设学生还没有填写昵称。我们需要表达没有昵称这件事，而不是伪造一个普通姓名。null 就用来表示这里没有值。类型后面的问号，表示这个名字允许保存正常值，也允许保存 null。所以 String 和 String 加问号是不同的类型。前者正常情况下必须有字符串，后者把可能缺失这件事写进了类型。

再看成绩，零是一个真实的分数，不代表没有录入。Int 加问号既能保存整数零，也能保存 null，因此可以区分这两种情况。空字符串也是有值，只不过里面没有字符。设计程序时先想清楚这些状态，后面判断才不会混乱。空安全不是保证程序永远没有任何错误，而是让许多没有检查空值的操作，在编译阶段就更早暴露。

```kotlin
fun main() {
    val nickname: String? = null
    val score: Int? = 0
    println(nickname)
    println(score)
}
```

预期结果：
```text
null
0
```

画面要点：类型后的问号表示允许 null；null、零、空字符串不同；缺失状态要明确表达

### kt-07-02 安全调用与默认值

如果昵称可能没有值，就不能想当然地直接读取长度。问号加点叫安全调用：左边不是 null 才继续读取，若左边是 null，整个结果就得到 null。这里 nickname 没有值，因此 length 也没有值。它不会为了让程序继续，就自动假定长度为零，因为那会把未填写和填写了空串混在一起。

需要给用户一个可显示的默认内容时，用问号加冒号。它的意思是，左边有值就用左边，否则用右边的默认值。这里显示未填写。这个符号常被称为 Elvis 运算符，记不住名字也没关系，先记住它在处理没有值的情况。安全调用负责有值时再往下做，默认值处理负责没有值时用什么代替，两个动作各自有用途。

```kotlin
fun main() {
    val nickname: String? = null
    val length = nickname?.length
    val display = nickname ?: "未填写"
    println(length)
    println(display)
}
```

预期结果：
```text
null
未填写
```

画面要点：安全调用：有值才继续；默认值：null 时使用右边；不要把 null 自动当作 0

### kt-07-03 用判断排除空值

除了安全调用，也可以把有值和没有值分成两条路线。这里明确判断 nickname 不等于 null。进入成立的分支后，编译器能根据这个稳定的局部值和前面的判断，知道它在这条路线里不是空值，于是允许直接读取长度。这种根据条件缩小可能类型的能力，常叫智能转换。先看判断给了什么保证，再理解名字。

没有值时则显示另一条提示。这个例子中的 nickname 是局部 val，很容易推断；对于可能被其他代码改变的属性，编译器未必能给出同样的保证。初学时不要把某一处能自动判断，推广成任何地方都能省略检查。先用简单稳定的局部值练习，必要时把读取结果保存下来，再判断和使用。

```kotlin
fun main() {
    val nickname: String? = "小林"
    if (nickname != null) {
        println(nickname.length)
    } else {
        println("没有昵称")
    }
}
```

预期结果：
```text
2
```

画面要点：先判断不为空，再读取；局部稳定值便于智能转换；保证只在相应范围内有效

### kt-07-04 把不合法输入变成可处理的结果

前面直接调用 toInt 时，输入不合法会抛出异常。toIntOrNull 提供另一种处理方式：转换成功就给出整数，失败就返回 null。这里的中文八十五不是这个转换函数接受的整数格式，因此 score 没有整数值。名字中的 OrNull 已经提醒我们，调用后要检查结果，不能直接拿去加五。

接着用 if 区分失败和成功。失败时给出清楚的输入提示，成功时才进行加分。我们没有把错误文字悄悄变成零分，因为零分可能是合法成绩。若程序确实需要默认值，也可以用前面学的默认值运算符，但要明确默认值是否符合业务含义。处理用户输入时，不应该为了让代码短一点，就把错误数据伪装成正常数据。

```kotlin
fun main() {

    val score = text.toIntOrNull()
    if (score == null) {
        println("请输入阿拉伯数字")
    } else {
        println(score + 5)
    }
}
```

预期结果：
```text
请输入阿拉伯数字
```

画面要点：toIntOrNull 失败时返回 null；先判断转换是否成功；错误输入不要伪装成 0 分

这份列表只有两项，现在查询索引五。使用的是 getOrNull，随后先安全读取长度，再给没有结果的情况准备负一。请预测最终输出什么，会不会发生索引越界。按读取位置、得到姓名、读取长度、选择默认值这四个小步骤分析，不要一次跳到最终答案。

### kt-08-03 限制不合适的修改

如果成绩必须在零到一百之间，让外部随意写一个负数就不合适。private 把这个属性限制在类内部使用，外部改为通过 updateScore 提交新成绩。这里先检查 value 是否处于范围中，合法才保存。in 除了用于循环，也能用来询问一个值是否在范围内。这个练习对不合法值选择保持原值，真实项目还应给调用者明确的失败反馈。

外部通过公开的方法提交八十五，再通过 currentScore 读取。最后的方法使用单表达式写法，等号右边就是返回结果。我们控制了哪些细节可以直接访问、哪些操作要经过规则检查，这叫封装。它的目的不是把代码藏得越深越好，而是避免别人绕过必要的约束。初学时，先把数据有效性的规则写在一个集中位置。


### kt-08-04 用 data class 表达一条记录

这里两个等号进行内容比较，结果是 true。输出整条记录时，会显示包含类型名和属性的文字。不要把 data class 理解成自动把所有属性都变成不可修改，我们仍然需要自己选择 val 或 var。普通类默认的相等行为也不和 data class 完全一样，不能只看两份对象长得像，就猜比较结果。按照数据用途选择清楚的表达方式，比堆很多类层次更重要。

### kt-08-05 复制记录与共享对象

如果需要保留原成绩，又想得到修正版，可以调用 data class 提供的 copy。这里明确只把新记录的 score 改成八十五，姓名沿用原值。它会产生一份新的 Student，所以 original 仍然保存八十。和直接让另一个名字引用同一个对象不同，copy 在这里创建的是另一份外层记录。

## 集合处理与扩展函数

### kt-09-01 把小处理步骤当作数据

现在希望每位同学都加五分。可以自己写循环，也可以告诉列表，对每一项都执行同一种转换。map 后面的大括号就写这次要做的转换。箭头左边的 score 是当前元素，右边是这一个元素应该变成的结果。这样的小段函数写法叫 lambda。先按对每项做什么来阅读，不要被名字吓住。

map 收集每一项的新结果，组成新列表，所以 improved 是八十五、九十五和七十五。原来的 scores 仍然是八十、九十和七十。这里处理的是整数，不涉及前面讲的共享可变对象的内部修改。lambda 可以交给其他函数使用，这也让处理步骤本身能作为参数。我们先在集合的具体例子里认识这种能力，不展开复杂函数类型声明。

```kotlin
fun main() {
    val scores = listOf(80, 90, 70)
    val improved = scores.map { score -> score + 5 }
    println(improved)
    println(scores)
}
```

预期结果：
```text
[85, 95, 75]
[80, 90, 70]
```

画面要点：map 把每项转换成新结果；箭头左边是当前元素；这里得到新列表，原列表未改

### kt-09-02 筛选符合条件的元素

如果不是改分数，而是只想保留及格成绩，就使用 filter。它后面的小处理步骤必须回答一个真假问题：这一项要不要留下？当前成绩至少六十时得到 true，就保留原来的这一项。和 map 不同，它的任务是决定保留与否，不是把每个元素变成另一个结果。区分这两个问题，会比背两个英文名字更牢。

五十五和四十没有留下，八十和九十二保留，因此新列表有两项。筛选后顺序仍然沿用原列表中这些元素的先后关系。这里的 lambda 也可以用默认名字 it 来简写，但刚入门时写出 score 更容易看懂。有些短写法很好用，前提是没有让读者费更多力气猜当前这个 it 指的究竟是什么。

```kotlin
fun main() {
    val scores = listOf(55, 80, 92, 40)
    val passed = scores.filter { score -> score >= 60 }
    println(passed)
    println(passed.size)
}
```

预期结果：
```text
[80, 92]
2
```

画面要点：filter 根据真假条件保留元素；保留的是原元素；有意义的参数名便于阅读

### kt-09-03 按顺序连接处理步骤

把两个步骤接起来时，从上往下读。先从原成绩中保留至少六十分的元素，得到八十和九十二。这里的 it 代表当前这一项，因为只有一个参数，Kotlin 允许用这个默认名字。每一段里的 it 只属于这一小段函数，不是一个贯穿整个程序的全局变量。先把中间结果写在纸上，有助于理解数据怎样流动。

接着给留下的每项加五，得到八十五和九十七。顺序也会影响业务含义：先加分再筛选，五十五可能达到六十；先筛选再加分，五十五已经被排除。代码链条很短，也不意味着业务顺序可以随意。列表上的这些常见操作会产生中间结果，本课不把它们和后续可能学习的惰性序列混为一谈。先确保含义正确，再考虑性能设计。

```kotlin
fun main() {
    val scores = listOf(55, 80, 92)
    val result = scores
        .filter { it >= 60 }
        .map { it + 5 }
    println(result)
}
```

预期结果：
```text
[85, 97]
```

画面要点：从上到下追踪中间结果；it 是当前小函数的单个参数；筛选与转换的先后可能影响结果

### kt-09-04 为已有类型增加一种方便写法

同一个是否及格的判断经常要写，可以把它定义成 Int 的扩展函数。函数名前面先写接收它的类型，再加点。函数内部的 this 表示这一次接收调用的那个整数。这里就是询问这个整数是否至少六十。扩展函数让调用位置读起来像一个现成操作，但并没有真的去修改整数类型原来的源码。

于是八十五调用时为真，四十调用时为假。扩展函数仍然受正常的访问规则限制，不能借这个语法随意读取别的类的私有内部数据。也不必为了看起来像方法，就把每个工具函数都改成扩展。它更适合表达与接收类型关系明确的小操作。是否方便阅读，是否容易找到定义，比语法看起来花哨更值得优先考虑。

```kotlin
fun Int.isPassing(): Boolean {
    return this >= 60
}
fun main() {
    println(85.isPassing())
    println(40.isPassing())
}
```

预期结果：
```text
true
false
```

画面要点：扩展函数提供一种便利调用写法；this 是本次接收调用的值；不会修改原类型的源码

### kt-09-05 练习：先转换，再筛选

请预测最终列表里有几项，各是什么。这里先加二，再筛选至少六十。最容易漏掉的是原来的五十八，先做哪一步决定它有没有机会被留下。请写出 map 之后的完整中间列表，然后才对这个中间列表执行 filter。不要把前一页的先筛选后加分顺序直接套到这里。

（四秒独立思考，答案在下一页揭晓）

```kotlin
fun main() {
    val scores = listOf(58, 60, 90)
    val result = scores.map { it + 2 }.filter { it >= 60 }
    println(result)
}
```

画面要点：先写 map 的结果；filter 处理前一步的输出

### kt-09-06 答案：三项都能留下

加二以后，中间列表是六十、六十二和九十二。filter 接收到的是这份新结果，三项都至少六十，所以全部留下。原来五十八是否及格，不能直接决定最终是否留下，因为筛选发生在加分之后。我们需要按代码写出的实际顺序推导，而不是按脑子里习惯的业务顺序猜。

最后输出六十、六十二和九十二组成的列表。若改成先 filter 再 map，最初的五十八会被先排除，结果就只剩六十二和九十二。这两种写法都能运行，但表示两种规则。到这里，你已经能读懂 Kotlin 中常见的集合处理链。以后遇到更多现成方法，也可以先问清它接收什么、对每项做什么、最后返回什么。

```kotlin
fun main() {
    val scores = listOf(58, 60, 90)
    val result = scores.map { it + 2 }.filter { it >= 60 }
    println(result)
}
```

预期结果：
```text
[60, 62, 92]
```

画面要点：加二后的值参与筛选；结果包含 60、62、92；业务顺序应写清楚

## 错误处理与综合实践

### kt-10-01 程序运行时也可能失败

编译通过以后，运行时仍可能失败。比如把 hello 当作整数转换，转换函数会抛出格式异常。try 把可能失败的操作包起来。异常出现时，这条正常执行路线会中断，程序寻找能处理它的 catch。它不是普通返回值，也不是自动给一个零。我们需要明确决定遇到这种情况应该怎样继续。

这里 catch 接住的是 NumberFormatException，也就是这次转换可能产生的格式问题，然后显示请输入整数。不要把所有异常都随意吞掉而不提示，也不要用异常处理掩盖自己写错的索引或计算。对于普通用户输入，前面介绍的 toIntOrNull 往往更直接；对于文件读写等可能失败的操作，再按需要捕获合适的异常。

```kotlin
fun main() {
    val text = "hello"
    try {
        println(text.toInt())
    } catch (e: NumberFormatException) {
        println("请输入整数")
    }
}
```

预期结果：
```text
请输入整数
```

画面要点：编译成功不保证运行成功；try 放可能失败的操作；catch 明确处理相应异常

### kt-10-02 主动拒绝不符合规则的值

异常不仅来自库，也可以用于拒绝不符合前提的调用。require 用来检查一个条件，成立就继续，不成立就抛出参数不合法异常。后面的大括号提供错误说明。这里要求成绩在零到一百之间。这样的检查表达的是调用这项操作必须满足的规则，而不是把不合法的一百二十偷偷改成一百。

main 中传入一百二十，检查失败，所以进入相应的 catch，显示成绩不合法。Kotlin 也可以显式使用 throw 抛出异常，入门先认识检查条件、失败、处理这条路径。是否用异常表达失败，要看失败是不是正常业务中的常见结果。找不到姓名通常可用 null，调用前提被破坏则可用明确的参数检查。不要把所有不同情况都揉成同一种失败。

```kotlin
fun checkScore(score: Int) {
    require(score in 0..100) { "成绩应在 0 到 100 之间" }
}
fun main() {
    try {
        checkScore(120)
    } catch (e: IllegalArgumentException) {
        println("成绩不合法")
    }
}
```

预期结果：
```text
成绩不合法
```

画面要点：require 表达调用前提；条件不满足会抛出异常；正常缺失与错误前提分别设计

### kt-10-03 读取与写入本地文件

程序关闭以后还想保留数据，就需要存到文件等外部位置。这里使用 Kotlin 在 JVM 上能够调用的文件工具。import 说明要使用哪个现成类型，File 用来表示一个文件路径。相对路径通常从程序当前的工作目录出发，不保证永远是源代码所在的文件夹。配套示例在独立的临时目录里运行，避免碰到你已有的同名文件。

writeText 把这段文字写入文件，已有内容会被覆盖，所以正式使用前要确认路径和用途。这里的反斜线加 n 表示换行。readText 再把整个文件读成字符串，最后输出两行学生信息。文件不存在、没有权限或存储设备出问题，都可能让读写失败，需要在合适位置处理 I O 异常。这个小例子用于入门，不代表所有大文件都应该一次性读入内存。

```kotlin
import java.io.File
fun main() {
    val file = File("scores.txt")
    file.writeText("小林,85\n小陈,92")
    val text = file.readText()
    println(text)
}
```

预期结果：
```text
小林,85
小陈,92
```

画面要点：import 引入需要的现成类型；相对路径基于工作目录；writeText 会覆盖已有内容

### kt-10-04 综合：组织学生记录

现在回到课程开头的小需求。每位学生的姓名和成绩，放在一条 Student 记录里。多条学生记录，再放进一个列表。类解决一条记录内部的数据组织，集合解决多条记录放在一起的问题。不要把这些结构看成互相替代的选项，它们可以一层层组合。先想清楚数据长什么样，再决定下一步要做什么处理。

筛选时，it 不再是一个整数，而是一位 Student，所以用点读取它的 score。保留及格学生以后，再遍历输出姓名和成绩。小林和小王留下，小陈暂时没有留下。原始 students 仍保存三位学生，这一步并没有删除原列表里的记录。读取代码时不断问当前元素是哪种类型，才能正确理解同样一个 it 在不同集合里代表什么。

```kotlin
data class Student(val name: String, val score: Int)
fun main() {
    val students = listOf(
        Student("小林", 85), Student("小陈", 55),
        Student("小王", 90)
    )
    val passed = students.filter { it.score >= 60 }
    for (s in passed) println("${s.name}：${s.score}")
}
```

预期结果：
```text
小林：85
小王：90
```

画面要点：记录保存一人的相关数据；列表保存多份记录；lambda 参数类型来自当前集合

### kt-10-05 综合：给统计过程一个名字

把平均分过程放进一个函数。参数的 List 后面，用尖括号说明里面装 Student。这里不展开泛型理论，先把它读成学生列表。返回类型是 Double 加问号，表示可能有平均分，也可能没有结果。空列表先返回 null，因为没有成绩时强行给出零分，容易让使用者误以为真的统计出平均零分。

列表非空时，先把每位学生变成对应的成绩，再调用 average 求平均。main 用默认值运算符处理没有结果的情况。第一条输出八十五点零，第二条输出暂无成绩。这个程序把函数、类、列表、集合转换和空安全连在一起。每个部件都很小，但组合起来就能解决完整需求。程序设计并不总是发明新语法，更多时候是在选择清楚的数据与步骤。

```kotlin
data class Student(val name: String, val score: Int)
fun average(students: List<Student>): Double? {
    if (students.isEmpty()) return null
    return students.map { it.score }.average()
}
fun main() {
    val students = listOf(
        Student("小林", 80), Student("小陈", 90)
    )
    println(average(students) ?: "暂无成绩")
    println(average(emptyList()) ?: "暂无成绩")
}
```

预期结果：
```text
85.0
暂无成绩
```

画面要点：List<Student> 是学生列表；空列表明确返回 null；调用者处理有结果或无结果

### kt-10-06 练习：能运行就够了吗

最后一道题，这段代码能运行，但它是否合理完成了成绩录入？用户输入 hello，程序把转换失败的结果换成零，然后告诉用户你的成绩是零。请分开回答两个问题：程序技术上会输出什么，这个输出有没有表达真实的录入情况。不是每道纠错题都必须由编译器报错。

（四秒独立思考，答案在下一页揭晓）

```kotlin
fun main() {
    val text = "hello"
    val score = text.toIntOrNull() ?: 0
    println("你的成绩：$score")
}
```

画面要点：先判断实际输出；再检查业务含义是否真实

### kt-10-07 答案：不要掩盖不合法的输入

原题技术上会显示你的成绩是零，但这不是真正读到的成绩。修正时保留转换失败的 null，先处理没有得到整数的情况，再检查整数是否位于零到一百之间。左边的 when 把几种情况按顺序列出来。只有前面已经排除了 null，后面的范围检查才是在检查一份实际整数。

最后的 else 才显示合法成绩。这样不合法文字、超范围整数和正常成绩各有自己的处理。当前输入 hello，所以输出请输入整数。一个可靠的小程序，不只是能沿着最理想的输入走通，也应该把常见失败讲清楚。你已经具备阅读这段程序需要的所有基础，可以试着把固定文字改成 readln，再分别输入三类数据验证。

```kotlin
fun main() {
    val text = "hello"
    val score = text.toIntOrNull()
    when {
        score == null -> println("请输入整数")
        score !in 0..100 -> println("成绩超出范围")
        else -> println("你的成绩：$score")
    }
}
```

预期结果：
```text
请输入整数
```

画面要点：先判断转换成功与否；再判断业务范围是否合法；只有合法成绩才进入正常处理
