## 01 变量：给数据起一个名字｜01:00–04:00

### 01-1 保存一个分数

<!-- rust-check: {"id":"01-1","kind":"run","stdout":"80\n"} -->
【画面】逐行出现下面的代码。先显示声明，再显示输出。

```rust
fn main() {
    let score = 80;
    println!("{score}");
}
```

运行结果：`80`。

【口播】

假设小林这次考了八十分。我们希望后面还能使用这个分数，就给它起一个名字，叫 score，也就是“成绩”。

第一行里的 let，表示我们要创建一个变量。等号右边的八十，是这个变量最初保存的值。以后写 score，就可以用到这个八十。

下一行负责输出。双引号里的大括号告诉 Rust：这里要显示 score 的值。所以运行后看到的是八十，而不是 score 这几个字母。

如果你学过 C，可能会写 int score 等于八十。Rust 这里没有写 int，是因为编译器可以根据代码判断它是整数。我们把这种自动判断叫作“类型推断”。它只是帮我们少写一些内容，数据依然有确定的类型。

以后遇到类型不够明确的地方，我们也可以自己写出来。等会儿就会看到。

### 01-2 什么时候需要 mut

<!-- rust-check: {"id":"01-2","kind":"error","error":"E0384"} -->
【画面】在刚才的变量后增加一次赋值，标出第二行错误。

```rust
fn main() {
    let score = 80;
    score = 85;
    println!("{score}");
}
```

【口播】

现在老师发现少算了五分，想把成绩改成八十五。直接写 score 等于八十五，可以吗？

在 Rust 中，这样写会报错。因为用 let 创建的变量，默认不允许重新赋值。你可以读取它、拿它做计算，但不能直接把它保存的值改掉。

如果确实要修改，我们就在变量名字前加上 mut。

<!-- rust-check: {"id":"01-3","kind":"run","stdout":"85\n"} -->
【画面】只突出新增的 `mut` 和修改后的输出。

```rust
fn main() {
    let mut score = 80;
    score += 5;
    println!("{score}");
}
```

【口播】

这样就可以了。mut 在这里可以理解为：这个变量接下来允许修改。第二行给它增加五，最终输出八十五。

Rust 要求我们明确写出这一点，读代码的人也更容易看出哪些数据会变化。不需要修改，就先不加 mut；需要修改，再加上它。作为初学者，按这个顺序写就很好。

### 01-3 同一个名字，也可以重新声明

<!-- rust-check: {"id":"01-4","kind":"run","stdout":"85\n"} -->
【画面】突出第二次出现的 `let`。

```rust
fn main() {
    let score = 80;
    let score = score + 5;
    println!("{score}");
}
```

【口播】

这里没有 mut，却同样能输出八十五。原因是第二行又写了一次 let。

它创建了一个新的变量，只是也叫 score。等号右边先用原来的八十计算，得到八十五；从这一行往后，这个名字就表示新的值了。这种同名重新声明，叫作“遮蔽”。

先不用记复杂定义。看见重新赋值，就检查有没有 mut；看见又写了 let，就知道是在声明新变量。新变量还可以使用不同的类型，原变量的类型并没有被修改。

另外，像课程的满分这种固定设置，可以使用 const。例如 const MAX_SCORE 冒号 u32 等于一百。const 后面需要写类型，名字通常用大写字母。它的值必须能在编译时确定。今天先把它理解为一个固定的程序设置。

### 01-4 小练习

<!-- rust-check: {"id":"01-5","kind":"run","stdout":"6\n"} -->
【画面】问题：“会报错，还是输出一个数字？”

```rust
fn main() {
    let count = 3;
    let count = count * 2;
    println!("{count}");
}
```

【口播】

现在你来试一试。这段代码没有 mut，能运行吗？如果能，输出什么？

【停顿】4 秒。

【口播】

可以运行，输出六。第二行有 let，创建的是一个新的同名变量。它先用原来的三乘以二，再把结果保存下来。

变量这一节，我们先记住三个写法：let 保存数据，mut 允许修改，重复写 let 可以重新声明。接下来看看这些变量能保存哪些数据。

## 02 基本类型：程序里的数据也分种类｜04:00–08:00

### 02-1 数字、真假和字符

<!-- rust-check: {"id":"02-1","kind":"run","stdout":"18 88.5 true 林\n"} -->
【画面】每次只突出一个变量。右侧写中文说明。

```rust
fn main() {
    let age: u32 = 18;
    let average: f64 = 88.5;
    let passed: bool = true;
    let initial: char = '林';
    println!("{age} {average} {passed} {initial}");
}
```

【口播】

一名学生的信息，可能包含年龄、平均分、是否及格，以及一个姓名用字。这些内容不完全一样，我们用不同类型来表示。

先看 age 后面的冒号。冒号后面写的是类型。u32 用来保存非负整数；这里的年龄是十八。名字里的三十二，表示这种整数使用三十二个二进制位。你暂时不用计算范围，只要知道：类型决定了能保存多大、什么样的数。

如果数据可能出现负数，可以选择 i32，例如零下五度。这里的 i 表示有符号整数，u 表示无符号整数。Rust 还提供其他大小的整数类型。今天不背整张范围表，先熟悉 i32 和 u32。

平均分可能有小数，所以这里使用 f64，也就是一种浮点数类型。对于一般课堂练习，先用它就可以。浮点数表示的是近似值，像反复计算小数时，不要期待每一步都像纸上的十进制运算一样完全精确。

是否及格用 bool。它只有 true 和 false 两种值，可以理解为“是”和“否”。这两个单词没有引号。

最后，单引号里的“林”是一个 char，可以保存常见的一个汉字，也可以保存一个英文字母。它与 C 中通常只有一个字节的 char 不同，不要直接套用 C 的大小理解。双引号用于一段文字，单引号用于一个 char。我们后面会专门学习字符串。

### 02-2 整数运算与转换

<!-- rust-check: {"id":"02-2","kind":"run","stdout":"2 2.5 300\n"} -->
【画面】先呈现两个除法，再呈现类型转换。

```rust
fn main() {
    let whole = 5 / 2;
    let decimal = 5.0 / 2.0;
    let small: u8 = 100;
    let large: u16 = 200;
    let total = u16::from(small) + large;
    println!("{whole} {decimal} {total}");
}
```

【口播】

这里有一个熟悉的小问题。五除以二，为什么有时得到二，有时得到二点五？

第一行是整数除法，小数部分不会保留下来，所以得到二。第二行两边都是浮点数，得到二点五。这一点与 C/C++ 的常见写法类似。

再看下面两个整数。small 使用 u8，large 使用 u16。虽然它们都表示非负整数，但类型不同，Rust 不会在这个加法里自动替我们转换。

我们先把 small 转成 u16，再相加。画面中的 from 可以理解为：根据这个较小的整数，创建一个 u16 数值。u8 的所有取值都能放进 u16，因此这次转换不会丢掉数据。

Rust 还有 as 这种转换写法，但把大范围类型转成小范围类型时，数值可能被截断。初学时，先别为了让报错消失就到处加 as。先问一句：转换后的类型装得下吗？

### 02-3 把几个数据放在一起

<!-- rust-check: {"id":"02-3","kind":"run","stdout":"18 85\n85 3\n80\n"} -->
【画面】第一屏显示元组，第二屏显示数组与切片。完整程序如下。

```rust
fn main() {
    let student = (18, 85);
    let (age, score) = student;
    println!("{age} {score}");
    let scores = [80, 85, 90];
    println!("{} {}", scores[1], scores.len());
    let first_two = &scores[..2];
    println!("{}", first_two[0]);
}
```

【口播】

如果想把年龄和成绩临时放在一起，可以使用小括号，这样的一组数据叫作“元组”。它里面可以放不同类型的值。下一行用两个名字，把两个位置上的数据分别取出来。

如果我们要保存三门课的成绩，就使用中括号。这样的数据叫作“数组”。同一个数组中的元素类型一致，而且长度是固定的。画面里这个数组有三个成绩，不能直接增加第四个。后面学习 Vec 时，这个限制就会有另一种解决办法。

数组从零开始编号。第一个位置是零，第二个位置是一，所以 scores 中括号一取到八十五。len 告诉我们元素的数量，这里是三。

最后一行多了一个 & 和一个范围。先把它理解为：从这个数组里借用前两个元素。两个点后面的二不包含在范围里，因此选中的是位置零和位置一。

得到的 first_two 是一个“切片”，可以理解为查看原数组中的一段。它没有把那一段复制成新数组。& 的详细含义，我们在所有权一节再讲。

还有一种特殊的类型，写成空的小括号，叫作“单元类型”。函数没有返回有用的结果时，就会用到它。接下来讲函数时，我们马上会见到。

### 02-4 小练习

<!-- rust-check: {"id":"02-4","kind":"run","stdout":"90 4\n"} -->
【画面】问题：“输出的两个数字分别是多少？”

```rust
fn main() {
    let scores = [60, 75, 90, 95];
    println!("{} {}", scores[2], scores.len());
}
```

【口播】

这里输出哪个成绩？数组长度又是多少？

【停顿】4 秒。

【口播】

输出九十和四。位置从零开始，位置二是第三个成绩。数组一共有四个元素。

如果访问位置四呢？这个数组没有第五个元素。越界访问会失败，而不是让你放心地读取旁边的内存。在直接写出的常量索引中，编译器有时就能发现问题；运行时才确定的非法索引，也会让程序发生 panic，通常会停止当前执行。这类失败不等于“读到了零”。

这一节不用记完所有类型，先把数据分成几类：整数、小数、真假、字符，以及放在一起的一组数据。知道自己要保存什么，再选择类型。

## 03 函数：把一件事写成可重复使用的步骤｜08:00–11:00

### 03-1 输入与输出

<!-- rust-check: {"id":"03-1","kind":"run","stdout":"85\n"} -->
【画面】用箭头展示“80、5 → add_bonus → 85”。

```rust
fn add_bonus(score: i32, bonus: i32) -> i32 {
    return score + bonus;
}

fn main() {
    let result = add_bonus(80, 5);
    println!("{result}");
}
```

【口播】

刚才给成绩增加五分，直接写一行计算就够了。如果很多地方都要做这件事，我们可以把它写成一个函数。

fn 表示定义函数。add_bonus 是它的名字，可以理解为“增加奖励分”。小括号中写两个输入：原成绩 score，以及奖励分 bonus。函数里的这两个名字，叫作“参数”。

参数名字后面需要写类型，这里都是 i32。调用时传入八十和五，它们会分别对应到这两个参数。不要只看变量名字，还要看位置：第一个值对应第一个参数，第二个值对应第二个参数。

箭头后面的 i32 表示函数返回一个整数。函数算出八十五，return 把这个结果交回调用它的地方。main 里的 result 接住结果，再打印出来。

跟 C/C++ 相比，这里的信息基本一样，只是摆放顺序不同。Rust 用 fn 开头，把返回类型写在参数列表后面。

### 03-2 最后一行为什么可以没有 return

<!-- rust-check: {"id":"03-2","kind":"run","stdout":"85\n"} -->
【画面】只改动函数内部最后一行。

```rust
fn add_bonus(score: i32, bonus: i32) -> i32 {
    score + bonus
}

fn main() {
    println!("{}", add_bonus(80, 5));
}
```

【口播】

Rust 还有一种常见写法：把计算结果放在函数最后一行，不写 return，也不在这一行末尾写分号。

意思是，把最后算出的这个值作为函数结果返回。这里仍然得到八十五。

为什么要特别提醒分号？因为在这种写法中，分号会改变这一行的作用。没有分号，结果留给外面使用；加上分号，就只是执行这一步计算，没有把这个整数当成函数最后的结果交出去。

你以后会听到“表达式”这个词。可以先用一个简单判断来理解：这一段代码能不能提供一个值？score 加 bonus 能提供一个整数值，所以它是表达式。我们暂时不用背术语之间的长篇区别，先把最后一行的写法写对。

当然，明确写 return 的版本也正确。刚开始觉得哪一种更清楚，就先用哪一种。阅读别人代码时，两种都要认识。

### 03-3 只做事、不返回成绩

<!-- rust-check: {"id":"03-3","kind":"run","stdout":"欢迎学习 Rust\n"} -->
【画面】显示一个没有返回类型箭头的函数。

```rust
fn welcome() {
    println!("欢迎学习 Rust");
}

fn main() {
    welcome();
}
```

【口播】

有些函数只负责显示信息，不需要返回数字。这里就没有写返回类型箭头。

严格说，它的返回类型是刚才见过的空小括号，也就是单元类型。你可以理解为：调用完成了，但没有一个成绩、姓名之类的结果需要接住。它不是某个指向内存的空指针。

## 04 if：让程序根据情况作决定｜11:00–13:00

### 04-1 判断是否及格

<!-- rust-check: {"id":"04-1","kind":"run","stdout":"及格\n"} -->
【画面】突出条件及真正执行的分支。

```rust
fn main() {
    let score = 75;
    if score >= 60 {
        println!("及格");
    } else {
        println!("还需要努力");
    }
}
```

【口播】

我们有了成绩，接下来判断是否及格。if 后面放条件：成绩是否大于等于六十。

如果条件成立，就执行上面这对大括号里的代码；如果不成立，就执行 else 后面的代码。这里的成绩是七十五，所以输出“及格”。

与 C/C++ 很接近。Rust 的条件外面不要求加小括号，但每个分支的大括号要保留。

还有一个值得提前知道的区别：Rust 要求条件的结果是 bool，也就是真或假。不能直接写 if score，靠零和非零决定走哪个分支。如果你想判断分数不是零，就明确写 score 不等于零。

这能让意图更清楚：是在判断一个数，还是在判断一个条件。

### 04-2 根据条件选出一个值

<!-- rust-check: {"id":"04-2","kind":"run","stdout":"及格\n"} -->
【画面】突出 `let result = if ...`，显示两条分支汇到 `result`。

```rust
fn main() {
    let score = 75;
    let result = if score >= 60 {
        "及格"
    } else {
        "还需要努力"
    };
    println!("{result}");
}
```

【口播】

我们也可以先选出一句文字，再统一输出。这里把整个 if 写在等号右边。

条件成立，提供“及格”；否则，提供“还需要努力”。选出的结果被放进 result。这也说明 if 可以提供一个值，我们称它为“if 表达式”。

注意两个分支最后都没有分号。这一点和函数最后一行返回结果很像。整个变量声明结束时，才在最后补上分号。

两个分支提供的值，类型要一致。你不能一条分支给一个整数，另一条给一段文字，然后让同一个变量有时是数字、有时是字符串。

### 04-3 小练习

<!-- rust-check: {"id":"04-3","kind":"error","error":"E0308"} -->
【画面】问题：“把条件改成 false，能解决问题吗？”

```rust
fn main() {
    let value = if true {
        1
    } else {
        "没有成绩"
    };
    println!("{value}");
}
```

【口播】

这段代码能运行吗？如果把 true 改成 false，结果会不会不同？

【停顿】4 秒。

【口播】

两种情况都会报错。因为两条分支的类型不一致，编译器在运行前就会检查这一点。条件今天走哪一边，不会取消这个要求。

可以把两个分支都改成文字，例如“有成绩”和“没有成绩”。如果真正需要表示有一个数字或没有数字，后面 Option 一节会给我们更合适的写法。

## 05 所有权：交出去、复制一份，还是借一下｜13:00–22:00

### 05-1 先看一个让人意外的赋值

<!-- rust-check: {"id":"05-1","kind":"run","stdout":"80 80\n"} -->
【画面】两个独立小框，都显示整数 `80`。

```rust
fn main() {
    let score = 80;
    let another = score;
    println!("{score} {another}");
}
```

【口播】

下面是 Rust 中很重要的一节。我们先不背规则，先看两段代码。

第一段把 score 赋给 another。最后两个名字都能使用，也都输出八十。对这种普通整数来说，赋值复制了它的值。

现在换一份数据。这一次记录学生姓名。

<!-- rust-check: {"id":"05-2","kind":"error","error":"E0382"} -->
【画面】先突出赋值，再突出最后一行中的 `name`。箭头由 `name` 指向 `another`。

```rust
fn main() {
    let name = String::from("小林");
    let another = name;
    println!("{name}");
}
```

【口播】

String 是一种保存文字的类型。这里先把 String::from 理解为“创建一份可以自己管理的文字”。字符串一节会把它讲得更完整。

同样写 another 等于 name，这次后面再使用 name，却会报错。问题不在文字内容，也不在输出语句，而在第二行发生了什么。

对于这个 String，赋值把数据的管理责任交给了 another。原来的 name 不能再作为这份文字的拥有者来使用。我们把这件事叫作“移动”，英文是 move。

你可以想象一本需要归还的书，原来由小林保管，现在完整交给小周。交接后，负责归还的是小周。程序里的文字不会因为这次赋值就自动多出两份。

这个比喻只是帮助理解责任的转移。这里不是说电脑一定把每一个字符从一个地方搬到了另一个地方。

### 05-2 为什么需要这种规则

【画面】用一份文字数据，连接“谁负责使用与清理？”；交接后只保留一个负责者。

【口播】

像 String 这样的数据，运行时可能需要申请内存来保存文字。用完以后，这部分内存需要清理。

如果两个变量都以为自己负责清理同一份数据，就可能重复清理；如果没人负责，又可能一直占着内存。Rust 用一套规则，提前检查谁负责这一份数据。

这套规则叫作“所有权”。在刚才的简单例子里，name 最初拥有 String，赋值后 another 接手。另一个重要规则是：拥有者离开它的作用范围时，会自动清理它负责的数据。

“作用范围”不神秘，就是这个变量在代码中可以被使用的那一段。你已经在 C 的大括号里见过类似范围。Rust 把这种范围与数据清理联系起来。

如果 String 没有被交出去，一个局部变量通常会在所在范围结束时被清理；如果已经交给了新的拥有者，就由新拥有者负责。我们今天先把这两个例子看明白，不需要展开内存管理的全部细节。

现在回到报错。想输出这份姓名，使用 another 就可以。想保留两个独立的副本，又该怎么办？

### 05-3 明确地复制一份

<!-- rust-check: {"id":"05-3","kind":"run","stdout":"小林 小林\n"} -->
【画面】两份独立的文字，分别属于 `name` 与 `another`。

```rust
fn main() {
    let name = String::from("小林");
    let another = name.clone();
    println!("{name} {another}");
}
```

【口播】

这里增加了 clone。它表示明确创建一个副本。

对于 String，这次会复制文字内容。因此两个变量各自拥有一份数据，后面两个名字都能继续使用。

整数赋值时那种自动复制，对应一个名字叫 Copy。像今天用过的普通整数、bool 和 char，都支持这种复制。String 不支持 Copy，但我们可以主动调用 clone。

不要把它记成“所有短的数据都会复制，所有长的数据都会移动”。是否支持 Copy，由类型决定。我们先记住常见例子：普通整数会复制，String 和后面要讲的 Vec 通常会移动。

也不要为了消除所有权错误，到处加 clone。复制一大段文字或一大组数据，可能有额外开销。如果只是想看一眼数据，我们还有更自然的办法。

### 05-4 函数也可能把数据接走

<!-- rust-check: {"id":"05-4","kind":"error","error":"E0382"} -->
【画面】显示 `name → show_name`，在调用后的使用处标出错误。

```rust
fn show_name(name: String) {
    println!("{name}");
}

fn main() {
    let name = String::from("小林");
    show_name(name);
    println!("{name}");
}
```

【口播】

这里定义一个显示姓名的函数。它的参数类型直接写 String。

调用时传入 name，也会发生移动。函数接走这份数据，因此 main 后面再次使用原来的 name 会报错。这个函数结束时，它接收的 String 也会被清理。

所以，“传给函数”并不总等于“让函数临时看看”。还要看参数类型。如果直接接收 String，它就取得这份数据的所有权。

但我们的实际需求只是显示一下姓名。显示完，还想在 main 中继续用。为这个需求复制整份文字并不必要，我们可以把它借给函数。

### 05-5 借用：使用一下，拥有者不变

<!-- rust-check: {"id":"05-5","kind":"run","stdout":"小林\n小林\n"} -->
【画面】保留 `name` 与文字的连接，另画一条临时查看箭头到函数。

```rust
fn show_name(name: &String) {
    println!("{name}");
}

fn main() {
    let name = String::from("小林");
    show_name(&name);
    println!("{name}");
}
```

【口播】

我们在两处增加 &。函数参数里的 &String，表示接收对 String 的引用。调用时的 &name，表示借用 name 所拥有的数据。

“引用”可以理解为一个用来访问已有数据的方式。这里没有复制整份姓名，也没有把姓名的拥有者换掉。函数只是借它来显示一下。

这种使用已有数据、又不接走所有权的做法，叫作“借用”。刚才数组切片前面的 &，也和借用有关。

所以，现在函数显示完，main 里的 name 仍然可以继续用，最终姓名会显示两次。

如果你见过 C++ 的引用，这种用法会有熟悉感。Rust 还会检查借用是否合法、被借用的数据能不能一直有效。我们下面只用两条简单规则来看它。

### 05-6 只读取，可以一起看；要修改，需要单独改

<!-- rust-check: {"id":"05-6","kind":"run","stdout":"小林 小林\n"} -->
【画面】两条读取箭头都指向同一份文字。

```rust
fn main() {
    let name = String::from("小林");
    let first = &name;
    let second = &name;
    println!("{first} {second}");
}
```

【口播】

第一条规则：同时有几个人只读取这份数据，是可以的。像大家一起看投影上的成绩，没有人改它，就不会互相影响。

这里 first 和 second 都是只读引用。它们都能显示同一个姓名，不需要复制整份 String。

第二条规则：如果要通过引用修改数据，就需要使用 &mut，而且在这段修改借用还要被使用的期间，不能同时有其他有效的借用与它冲突。

这句话看起来长，我们通过一个小例子拆开。

<!-- rust-check: {"id":"05-7","kind":"run","stdout":"小林同学\n"} -->
【画面】先突出两个 `mut`，再逐行显示调用与输出。

```rust
fn add_suffix(name: &mut String) {
    name.push_str("同学");
}

fn main() {
    let mut name = String::from("小林");
    add_suffix(&mut name);
    println!("{name}");
}
```

【口播】

我们希望在姓名后面增加“同学”两个字。push_str 的作用是把一段文字接到末尾。

main 中的 name 要允许修改，所以声明时加 mut。函数也要通过借用来修改文字，所以参数写 &mut String，调用时写 &mut name。

这两处各自表达一件事：这个变量允许改，这次借用也允许改。完成修改后，拥有者依然是 main 里的 name。最终输出“小林同学”。

可以把这种借用理解为：这段修改操作需要单独使用数据。Rust 不允许一边还有人在依赖旧的读取，一边又让其他地方修改它。

### 05-7 借用什么时候结束

<!-- rust-check: {"id":"05-8","kind":"error","error":"E0502"} -->
【画面】标出从 `view` 的建立到最后一次使用的区间；中间修改落在区间内。

```rust
fn main() {
    let mut name = String::from("小林");
    let view = &name;
    name.push_str("同学");
    println!("{view}");
}
```

【口播】

这里先建立只读引用 view，最后还要使用它。中间却想修改原来的 String，因此发生冲突，代码不能通过编译。

修正思路很简单：先完成读取，再做修改。

<!-- rust-check: {"id":"05-9","kind":"run","stdout":"小林\n小林同学\n"} -->
【画面】读借用区间在第一次输出后结束，再出现修改箭头。

```rust
fn main() {
    let mut name = String::from("小林");
    let view = &name;
    println!("{view}");
    name.push_str("同学");
    println!("{name}");
}
```

【口播】

这个版本可以运行。第一次显示“小林”，然后增加后缀，再显示“小林同学”。

虽然 view 的名字仍然写在这对大括号里，但后面已经不会再用到它。编译器能够看出这个借用不需要继续保留，因此允许后面的修改。

刚开始遇到借用报错时，不用立刻背一整段规则。先顺着代码看：谁在读，谁在改，读完之后是不是还会再使用那个引用？很多基础问题，调整操作顺序就能解决。

如果你学过 C++ 的 std::move，再补充一个区别。std::move 本身主要是改变表达式的形式，真正的数据转移要看后续操作。Rust 中发生移动后，编译器会阻止继续使用已经交出数据的原值。这两者不能直接画等号。没学过 C++ 移动语义的同学，先跳过这句也完全不影响后面的学习。

## 06 结构体：把一名学生的信息放在一起｜22:00–26:00

### 06-1 从两个变量到一份学生信息

<!-- rust-check: {"id":"06-1","kind":"run","stdout":"小林 80\n"} -->
【画面】姓名与成绩两个小框，合并进一个标有 `Student` 的框。

```rust
struct Student {
    name: String,
    score: u32,
}

fn main() {
    let student = Student {
        name: String::from("小林"),
        score: 80,
    };
    println!("{} {}", student.name, student.score);
}
```

【口播】

刚才我们单独保存姓名和成绩。如果程序里有很多学生，哪个姓名对应哪个分数，就需要组织得更清楚。

我们可以定义一个 Student，把一名学生的相关信息放在一起。struct 就是定义“结构体”的关键字。如果你用过 C 的 struct，这里的目的很熟悉。

大括号里列出这份信息由哪些部分组成。name 保存姓名，score 保存成绩。结构体中的这些部分，叫作“字段”。每个字段都写名字和类型，中间用冒号连接。

下面用 Student 后面的一对大括号创建一名学生。姓名填“小林”，成绩填八十。写字段名能让代码更清楚，也不容易把两个值放错位置。

使用字段时，在变量后面加点。student 点 name 就是这名学生的姓名，student 点 score 就是这名学生的成绩。最后我们把两项都显示出来。

这比单独准备很多相似的变量名字更容易管理。后面把许多 Student 放进一个 Vec，就能表示一个班的学生。

### 06-2 给学生信息增加一个方法

<!-- rust-check: {"id":"06-2","kind":"run","stdout":"true\n"} -->
【画面】沿用 `Student`。第一屏显示类型与方法，第二屏显示创建和调用。

```rust
struct Student { name: String, score: u32 }
impl Student {
    fn passed(&self) -> bool {
        self.score >= 60
    }
}
fn main() {
    let student = Student {
        name: String::from("小林"), score: 80,
    };
    println!("{}", student.passed());
}
```

【口播】

现在希望每名学生都能回答一个问题：自己是否及格。

我们用 impl Student，给 Student 添加相关功能。在里面定义 passed。它看起来像函数，但可以通过具体的学生来调用，这样的函数通常叫作“方法”。

括号里的 &self，先用最直白的话理解：借用当前这名学生的信息。self 就是调用这个方法的那一名学生，前面的 & 表示我们只借来查看。

方法读取 self 的成绩，判断它是否大于等于六十，然后返回 true 或 false。调用 student 点 passed 时，就拿这名 student 的成绩来判断。

这也呼应了上一节：只读取，不需要把整名学生的信息交出去，更不需要复制一份。

### 06-3 修改方法与创建函数

<!-- rust-check: {"id":"06-3","kind":"run","stdout":"小林 85\n"} -->
【画面】第一屏显示 `impl` 中的两个功能，第二屏显示 `main`。定义沿用前面的字段。

```rust
struct Student { name: String, score: u32 }
impl Student {
    fn new(name: String, score: u32) -> Self {
        Self { name, score }
    }
    fn add_bonus(&mut self, bonus: u32) {
        self.score += bonus;
    }
}
fn main() {
    let mut student = Student::new(String::from("小林"), 80);
    student.add_bonus(5);
    println!("{} {}", student.name, student.score);
}
```

【口播】

这里增加两个功能。先看 add_bonus，它要修改成绩，所以使用 &mut self。调用后，八十分变成八十五分。main 里的 student 也要声明为 mut，因为这份学生信息会被修改。

再看 new。它接收姓名和成绩，创建一名 Student。这里的 Self，首字母大写，表示当前正在编写的这个类型，也就是 Student。

new 没有 self 参数，因为调用它时还没有某一名学生，我们正在创建学生。因此写 Student 双冒号 new。它叫作“关联函数”。new 是大家常用的名字，你也可以给自己的创建函数起别的名字。

其中的 Self 大括号里只写了 name 和 score，是因为参数名字恰好与字段名字一致。它相当于把参数 name 填进 name 字段，把参数 score 填进 score 字段。

现在可以把三种 self 的用法并排看一眼：&self 借来读取，&mut self 借来修改，直接写 self 则接收这个对象本身，通常会取得它的所有权。今天先把前两种用熟，已经能写不少方法。

### 06-4 根据已有信息创建另一名学生

<!-- rust-check: {"id":"06-4","kind":"run","stdout":"小周 80\n80\n"} -->
【画面】突出新填写的姓名，以及 `..first`。

```rust
struct Student { name: String, score: u32 }
fn main() {
    let first = Student {
        name: String::from("小林"), score: 80,
    };
    let second = Student {
        name: String::from("小周"),
        ..first
    };
    println!("{} {}", second.name, second.score);
    println!("{}", first.score);
}
```

【口播】

有时新数据的大部分字段和原来一样，可以只填不同的字段，其他字段从已有对象取。这就是画面中的两个点 first，叫作“结构体更新语法”。

这里给第二名学生填写新姓名，成绩沿用第一名学生的八十。成绩是整数，会复制，所以第一名学生的成绩仍能使用。

如果没有重新填写姓名，原来的 String 姓名被取走，就会发生移动。更新语法不会保证自动复制整个结构体。遇到这一类代码，依然回到上一节：具体取走的是哪一个字段，它会复制，还是移动？

### 06-5 小练习

【画面】沿用 `Student` 与 `add_bonus`。问题：“下面缺少哪一个关键词？”

```text
let student = Student::new(String::from("小林"), 80);
student.add_bonus(5);
```

【口播】

假设方法定义都和刚才一样，这两行代码哪里需要修改？

【停顿】4 秒。

【口播】

在 student 前面加 mut。因为 add_bonus 会修改学生的成绩，调用它时需要可变借用。修改后的完整版本就是刚才那个输出八十五的程序。

结构体这一节的核心很简单：相关的数据放在一起，相关的操作也可以放在一起。字段负责保存信息，方法负责使用这些信息。

## 07 枚举：把可能出现的几种情况写清楚｜26:00–29:00

### 07-1 成绩单现在处于哪一种状态

<!-- rust-check: {"id":"07-1","kind":"run","stdout":"成绩：85\n"} -->
【画面】三张状态卡：“还没交”“批改中”“已出分”，最后一张携带分数。

```rust
enum ExamState {
    NotSubmitted,
    Checking,
    Finished(u32),
}
fn main() {
    let state = ExamState::Finished(85);
    match state {
        ExamState::NotSubmitted => println!("还没交"),
        ExamState::Checking => println!("批改中"),
        ExamState::Finished(score) => println!("成绩：{score}"),
    }
}
```

【口播】

结构体适合把几项信息组合在一起。还有一种常见需求：一件事可能处在几种情况中的某一种。

例如一份作业，可能还没有提交，可能正在批改，也可能已经给出成绩。我们用 enum 把这几种情况列出来，这叫作“枚举”。

与 C 中常见的枚举相比，Rust 的每一种情况还可以附带数据。Finished 后面的小括号里写 u32，表示“已经完成”这个状态还带着一个分数。

因此创建 Finished 八十五时，状态与成绩就在一起。你不会把“还没提交”误写成一个已经有成绩的普通状态。这样的数据设计，能帮助我们表达真实情况。

枚举不要求一个值同时包含所有情况。这里的 state，只处于 Finished 这一种情况。

### 07-2 用 match 分别处理

【画面】沿用上方代码；逐个突出 `match` 的三条分支，最后进入 `Finished(score)`。

【口播】

接下来要根据状态显示信息，我们用 match。你可以先把它理解为：看看当前是哪一种情况，再执行对应的代码。

左边写要匹配的情况，右边箭头后面写找到这种情况时要做的事情。前两种分别显示“还没交”和“批改中”。

到了 Finished 这一种，括号里的 score 会接住它附带的分数。接住以后，右边就能使用这个 score，所以最终输出“成绩：八十五”。

Rust 会检查这些分支有没有把可能出现的情况处理完整。如果我们漏掉“批改中”，它会提醒我们。实际程序中，这能避免新增加一种状态，却忘记更新处理代码。

有时确实只关心其中一种情况，可以用下划线来接住其他情况。下划线表示“其余情况统一这样处理”，不表示它们不存在。只有准备好统一处理时，才使用它。

## 08 Option：没有结果，也是一种需要表达的情况｜29:00–33:00

### 08-1 没有成绩，不等于零分

<!-- rust-check: {"id":"08-1","kind":"run","stdout":"还没有成绩\n"} -->
【画面】两张卡：“Some(85)：有成绩”“None：还没有成绩”。

```rust
fn main() {
    let score: Option<u32> = None;
    match score {
        Some(value) => println!("成绩：{value}"),
        None => println!("还没有成绩"),
    }
}
```

【口播】

我们要记录一名学生的成绩，但老师还没有批改完。这时应该存什么？

直接存零不太合适。因为零分也是一个真实成绩，和“暂时没有成绩”含义不同。我们需要把这两件事分开。

Rust 提供 Option 来表示这种情况。它只有两种选择：Some，表示有值；None，表示没有值。Some 里面带着真正的数据。

这里 Option 后面的 u32 表示：如果有成绩，那么成绩是一种 u32 整数。这个尖括号的写法暂时看懂就够了，泛型一节会解释为什么这样写。

如果已经有成绩，可以写 Some 八十五。还没有成绩，就写 None。Some 和 None 是 Rust 已经提供的名字，不需要我们自己定义。

使用时，把有成绩和没成绩分别处理。有成绩，就从 Some 中取出 value；没成绩，就显示“还没有成绩”。这里保存的是 None，所以执行第二条分支。

这和刚才带数据的枚举是一回事：Some 带着一个值，None 不带值。你并没有突然遇到一套完全新的思路。

【口播】

有时我们只想在有成绩时显示一下，没有成绩就先不做任何事。可以使用 if let。

这行可以读成：如果 score 是 Some，那么把里面的值取出来，叫作 value，然后执行大括号中的代码。

它和普通 if 不完全一样。普通 if 检查真或假；if let 是看看一个值是不是我们指定的这种形式，并顺便取出里面的数据。

不用为了简短就马上替换所有 match。需要处理两种情况时，写 match 更清楚；只关心一种情况时，if let 很方便。先选最容易读懂的写法。

### 08-4 为什么不能随手 unwrap

<!-- rust-check: {"id":"08-4","kind":"panic"} -->
【画面】先显示代码，再显示“能编译；运行到 unwrap 时发生 panic”。

```rust

    let score: Option<u32> = None;
    println!("{}", score.unwrap());
}
```

【口播】

你还会看到一个名字相近的方法，叫 unwrap。它不提供默认值，而是直接要求：这里必须有一个值。

如果实际是 Some，就能取出里面的数据；如果实际是 None，就会发生 panic。在这个普通程序中，程序会在这里失败退出。

注意，这段代码能够编译。问题是在运行时取不到值。它和前面忘记 mut、分支类型不一致那种编译错误，是不同阶段的错误。

初学时处理 Option，优先用 match 或 if let，把没有值的情况想清楚。等你能够明确说明“为什么这里一定有值”，再考虑是否需要 unwrap。遇到报错就增加 unwrap，通常没有真正解决问题。

## 09 Vec：人数会变化，就用动态数组｜33:00–37:00

### 09-1 创建、增加和删除

<!-- rust-check: {"id":"09-1","kind":"run","stdout":"3\n取出：90\n2\n"} -->
【画面】成绩方格从两个增加到三个，再取出最后一个。

```rust
fn main() {
    let mut scores = vec![80, 85];
    scores.push(90);
    println!("{}", scores.len());
    let last = scores.pop();
    if let Some(value) = last {
        println!("取出：{value}");
    }
    println!("{}", scores.len());
}
```

【口播】

刚才的普通数组，长度固定。如果学生人数会增加，成绩数量会变化，我们使用 Vec。

Vec 可以理解为一组能增减元素的数据，通常叫作“动态数组”。如果你用过 C++ 的 vector，它解决的是相似问题。

这里用 vec 加感叹号、中括号，创建一组初始成绩：八十和八十五。和 println 一样，感叹号是这个写法的一部分，先照着写就好。

push 把九十加到末尾，所以长度变成三。pop 从末尾取出一个元素，因此取出九十后，长度又变成二。

为什么 pop 的结果需要用 Some 来取呢？因为一个 Vec 可能已经是空的。空的时候，没有最后一个元素可以取。所以 pop 返回 Option：有元素，就是 Some；没有，就是 None。

这正是上一节说的，有结果和没有结果要区分开。你不必为每个新方法发明一种错误约定，看到 Option，就沿用相同的处理思路。

同一个 Vec 中的元素类型一致。它可以有一个、十个、一百个成绩，但不能随意把整数成绩与 String 姓名混放进去。需要多项学生信息时，就把 Student 作为元素类型。

### 09-2 读取一个位置：索引与 get

<!-- rust-check: {"id":"09-2","kind":"run","stdout":"85\n这个位置没有成绩\n"} -->
【画面】位置 `1` 对应第二项；位置 `8` 超过现有范围。

```rust
fn main() {
    let scores = vec![80, 85, 90];
    println!("{}", scores[1]);
    match scores.get(8) {
        Some(value) => println!("{value}"),
        None => println!("这个位置没有成绩"),
    }
}
```

【口播】

和数组一样，Vec 也从零开始编号。中括号一取到第二个成绩，也就是八十五。

但如果访问的位置可能不存在，我们可以使用 get。它不会直接要求那个位置一定有元素，而是返回 Option。

这里查询位置八。现有成绩只有三个，所以得到 None，程序显示“这个位置没有成绩”。

如果用中括号直接访问这个不存在的位置，就会发生越界失败。对于用户输入的编号这类不确定的位置，get 往往更便于正常处理。

需要补充一点：get 返回的是对元素的引用，也就是借用其中的数据。看到 Some 中的 value，不要默认以为整个元素已经被复制出来。我们仍然在读取原来的集合。

### 09-3 依次读取，或者依次修改

<!-- rust-check: {"id":"09-3","kind":"run","stdout":"80\n85\n90\n81\n86\n91\n"} -->
【画面】一屏只显示一个循环；小箭头依次经过每个成绩。

```rust
fn main() {
    let mut scores = vec![80, 85, 90];
    for score in &scores {
        println!("{score}");
    }
    for score in &mut scores {
        *score += 1;
    }
    for score in &scores {
        println!("{score}");
    }
}
```

【口播】

要把所有成绩显示出来，可以使用 for。这里可以读成：依次借用 scores 中的每个成绩，每次把当前这个成绩叫作 score，然后输出它。

&scores 表示借用整个集合来遍历，遍历后原集合仍然能用。只读取时，用这一种就很自然。

如果要给每个成绩增加一分，遍历时改成 &mut scores。这时每次拿到的 score，是一个允许修改元素的引用。

所以修改时前面多了一个星号。这里的星号表示：修改这个引用所指向的那一个成绩。你在 C 中可能见过类似符号，但我们现在只需要把它和“通过引用改原数据”联系起来。

最后再次读取集合，能看到八十一、八十六、九十一。

还有一种写法是直接 for score in scores，不加 &。对于这里的 Vec，它会把整个集合交给这次遍历，遍历完不能继续使用原来的 scores。想遍历后还保留集合，初学时先使用带 & 的版本。

遍历借用集合期间，也不要同时 push 新元素。增加元素可能让集合重新安排存储位置，与正在使用的引用发生冲突。需要增加元素时，可以先完成遍历，再统一增加。

## 10 字符串：保存文字，也要注意文字如何编码｜37:00–41:00

### 10-1 String 与 &str 先怎样区分

<!-- rust-check: {"id":"10-1","kind":"run","stdout":"Rust\n小林同学\n小林同学\n"} -->
【画面】左侧“String：自己拥有的一段文字”，右侧“&str：借来查看的一段文字”。

```rust
fn show(text: &str) {
    println!("{text}");
}
fn main() {
    let fixed = "Rust";
    let mut name = String::from("小林");
    name.push_str("同学");
    show(fixed);
    show(&name);
    println!("{name}");
}
```

【口播】

前面我们一直在用姓名，现在把保存文字的两种常见类型讲清楚。

String 可以自己拥有一份文字，而且内容可以增长。声明为 mut 后，就能像刚才那样在末尾追加“同学”。

&str 则是借来查看的一段文字，通常叫作“字符串切片”。通过这个 &str，我们读取文字，不通过它修改内容。

双引号直接写出的 Rust，在这个例子中就是 &str。它所引用的文字来自程序里写好的内容。&str 也可以来自已有的 String，不仅仅是这种直接写出的文字。

如果一个函数只是显示文字，参数写 &str 很常见。上面的 show，既能接收固定文字，也能接收从 String 借来的内容。传 &name 时，Rust 能帮我们把对 String 的这次借用用于 &str 参数。

相比上一节为了认识借用而写的 &String，&str 更适合这种“只需要读取一段文字”的函数。你不用现在理解全部转换细节，先记这个实用选择：自己保存可增长的文字，用 String；函数只是读取文字，通常使用 &str。

### 10-2 拼接文字

<!-- rust-check: {"id":"10-2","kind":"run","stdout":"小林，欢迎\n，欢迎\n"} -->
【画面】突出 `first` 被用于新字符串，`second` 只被借用。

```rust
fn main() {
    let first = String::from("小林");
    let second = String::from("，欢迎");
    let message = first + &second;
    println!("{message}");
    println!("{second}");
}
```

【口播】

想把两段文字接起来，有几种做法。前面用过 push_str，它会修改已有的 String，把新文字加在后面。

这里使用加号创建拼接结果。左边的 first 会被这个操作接走，右边的 second 用 & 借来读取。因此后面能继续使用 second，但不能继续使用已经移动的 first。

这说明看起来很熟悉的加号，也可能涉及所有权。阅读字符串拼接代码时，仍然要看哪一份数据被交出去。

如果想保留两个原字符串，并写出一句组合文字，可以使用 format，比如把两个名字放进大括号。它会创建新的 String，在这种常见用法中不会接走原来的字符串。需要哪种效果，就选择哪种写法。

### 10-3 为什么中文不能随手按一个字节取

<!-- rust-check: {"id":"10-3","kind":"run","stdout":"4\n中\nA\n"} -->
【画面】“中”占三个字节，“A”占一个字节。字幕明确写“字节数≠字符数”。

```rust
fn main() {
    let text = "中A";
    println!("{}", text.len());
    for ch in text.chars() {
        println!("{ch}");
    }
}
```

【口播】

现在有一段文字“中 A”。肉眼看到两个常见字符，但 len 得到四，这是为什么？

Rust 的字符串使用 UTF-8 保存。你可以先把 UTF-8 理解为一种把文字转换成字节的编码方式。不同字符需要的字节数可能不同。

这里“中”需要三个字节，英文字母 A 需要一个字节，所以总共四个字节。String 和 str 的 len，统计的是字节数量。

如果想依次读取字符，使用 chars。这个例子会先得到“中”，再得到“A”。如果使用 bytes，则是依次读取组成文字的各个字节，适合需要处理编码数据的情况。

对今天的普通汉字和英文字母，用 chars 逐个读取就符合我们的需要。复杂表情可能由多个部分组成，不能把每个显示出来的图形都当成一个 char。今天先处理普通文字，复杂情况留到以后再学。

【口播】

这也是 Rust 不允许直接写 text 中括号零来取得“第一个字符”的原因之一。字符串不像整数数组那样，每个位置都对应一个固定大小的字符。

不确定边界时，先按 chars 读取；需要按字节范围取切片时，也可以用 get 查询合法范围，查询失败会返回 None。不要用猜出来的字节位置去截中文。

## 11 HashMap：根据姓名查成绩｜41:00–45:00

### 11-1 从位置查找，改成按名字查找

<!-- rust-check: {"id":"11-1","kind":"run","stdout":"小林：80\n"} -->
【画面】两列表格“姓名 → 成绩”，高亮查询的姓名。

```rust
use std::collections::HashMap;
fn main() {
    let mut scores = HashMap::new();
    scores.insert("小林", 80);
    scores.insert("小周", 90);
    match scores.get("小林") {
        Some(score) => println!("小林：{score}"),
        None => println!("没有找到这名学生"),
    }
}
```

【口播】

Vec 很适合按位置保存一组成绩。现在想输入“小林”，就查出小林的分数，我们可以使用 HashMap，中文叫“哈希表”。

先别着急研究它内部怎么查找。把它看成一张对应表：左边是一项用于查找的信息，右边是与它对应的数据。

在这个例子中，姓名是“键”，成绩是“值”。insert 把一组键和值放进表里。get 根据键查询，结果仍然是 Option，因为这名学生可能没有记录。

查询到小林，就显示八十。查不到，就显示“没有找到这名学生”。你看，虽然换了一种集合，有值与没值的处理方式仍然沿用 Option。

最上面的 use，表示我们要使用标准库 collections 里的 HashMap。Vec 和 String 在常用代码中可以直接写，HashMap 通常先写这条引入语句。

如果你学过 C++ 的 unordered_map，会发现需求非常接近：都适合根据键寻找对应的值。今天不讲哈希算法，我们先把基本操作用起来。

### 11-2 同一个名字再次插入，会发生什么

<!-- rust-check: {"id":"11-2","kind":"run","stdout":"85\n"} -->
【画面】“小林 → 80”被更新为“小林 → 85”，不增加第二条同名记录。

```rust
use std::collections::HashMap;
fn main() {
    let mut scores = HashMap::new();
    scores.insert("小林", 80);
    scores.insert("小林", 85);
    if let Some(score) = scores.get("小林") {
        println!("{score}");
    }
}
```

【口播】

同一个键，在这张表里只有一个当前对应值。再次插入小林和八十五，原来的八十会被替换。

所以，HashMap 并不表示“一个姓名自动对应一串历史成绩”。如果要保存历史记录，可以让值本身是一组成绩，例如一个 Vec。这是以后可以继续练习的数据设计。

如果只想在没有记录时添加初始值，就要换一种操作。下面用统计次数来说明。

### 11-3 出现一次，就加一

<!-- rust-check: {"id":"11-3","kind":"run","stdout":"2\n"} -->
【画面】逐次展示“没有记录 → 0 → 1 → 2”；突出 `entry` 与 `or_insert`。

```rust
use std::collections::HashMap;
fn main() {
    let names = ["小林", "小周", "小林"];
    let mut counts = HashMap::new();
    for name in names {
        let count = counts.entry(name).or_insert(0);
        *count += 1;
    }
    if let Some(count) = counts.get("小林") {
        println!("{count}");
    }
}
```

【口播】

这里有一份签到名单，小林出现了两次。我们想统计每个名字出现多少次。

entry 可以理解为：找到这个名字对应的那一格。or_insert 零表示：如果这一格还没有记录，就先填零；如果已经有记录，就保留原来的数。

这一整行返回允许修改那个数的引用，所以后面使用星号，让原来的计数增加一。

第一次遇到小林，没有记录，先放零，再加一，变成一。第二次遇到小林，原来已经是一，不会重新归零，再增加一次，变成二。

代码看起来比“先查、再判断、再写回去”短了一些，但理解时还是按照刚才的具体步骤来想。先看有没有记录，再对当前计数加一。

HashMap 本身也需要 mut，因为我们在增加和修改其中的内容。

### 11-4 放进表里的 String 会怎么样

<!-- rust-check: {"id":"11-4","kind":"error","error":"E0382"} -->
【画面】`name` 的文字进入表格，最后一行标出移动后的使用错误。

```rust
use std::collections::HashMap;
fn main() {
    let name = String::from("小林");
    let mut scores = HashMap::new();
    scores.insert(name, 80);
    println!("{name}");
}
```

【口播】

前面的姓名是直接写出的文字引用。如果我们自己创建一个 String 姓名，再把它直接插入表里，会发生移动。

这时表接管了姓名，原来的 name 不能继续使用。值如果也是 String，同样要考虑移动；像八十这种普通整数，会复制。

这不是 HashMap 专门发明的新规则，还是之前的所有权规则。想保留独立副本，可以在插入时 clone；如果数据设计适合借用，也可以使用引用，但需要保证原数据一直有效。今天先把直接拥有 String 的版本理解清楚。

### 11-5 小练习

<!-- rust-check: {"id":"11-5","kind":"run","stdout":"9\n"} -->
【画面】问题：“已经有记录时，or_insert 会覆盖它吗？”

```rust
use std::collections::HashMap;
fn main() {
    let mut counts = HashMap::new();
    counts.insert("小林", 2);
    let count = counts.entry("小林").or_insert(0);
    *count += 7;
    println!("{count}");
}
```

【口播】

原来已经记录了两次。执行 or_insert 零之后，再加七，结果是多少？

【停顿】4 秒。

【口播】

结果是九。因为原来的记录存在，or_insert 不会覆盖它。原来的二继续增加七，得到九。

这一节记住三个操作就够了：insert 放入或更新，get 查询，entry 配合 or_insert 处理“有就使用，没有就初始化”。有了这些操作，我们已经可以写简单的成绩查询和次数统计。

## 12 泛型：做法一样，类型可以不同｜45:00–49:00

### 12-1 为什么想写一份代码，多处使用

【画面】两组数据：“两门课的分数：80、90”“两名学生的名字：小林、小周”；都指向“组成一对”。

【口播】

前面我们为具体类型写函数。如果想把两个成绩组成一对，可以写一个接收整数的函数。想把两个姓名组成一对，又可以写一个接收文字的函数。

但这两个函数的做法完全一样：接收两个值，再把它们放在一起。只因为类型不同，就复制整份函数，有些重复。

我们希望把共同的做法写一次，具体类型在使用时再确定。这个办法叫作“泛型”。

先不要把它想成很复杂的功能。它回答的是一个朴素问题：这段代码能不能不只适用于一种数据类型？

### 12-2 用 T 表示暂时还没确定的类型

<!-- rust-check: {"id":"12-1","kind":"run","stdout":"80 90\n小林 小周\n"} -->
【画面】先显示函数，再分别展示两次调用，标出每次 `T` 对应的类型。

```rust
fn make_pair<T>(first: T, second: T) -> (T, T) {
    (first, second)
}
fn main() {
    let (left, right) = make_pair(80, 90);
    println!("{left} {right}");
    let (left, right) = make_pair("小林", "小周");
    println!("{left} {right}");
}
```

【口播】

函数名后面的尖括号里写 T，表示我们给“待确定的类型”起了一个名字。

两个参数都使用 T，返回的元组也由两个 T 组成。第一次传入两个整数，这次调用的 T 就是整数类型。第二次传入两个文字引用，这次调用的 T 就是文字引用类型。

所以，同一个函数定义可以处理这两组数据。编译器通常能根据传入的值确定具体类型，我们不必每次手动填写。

这里有个重要细节：在一次调用中，同一个 T 表示同一种类型。它不表示“每个位置都随便放”。给第一个参数传整数，第二个参数传文字，这个函数就不能按当前定义使用。

如果确实需要两种不同类型，可以定义两个类型名字，比如 T 和 U。今天先把单个 T 看懂，不急着把写法扩展得很长。

如果你以后学习 C++ 模板，会发现它们都能帮助复用不同类型上的代码。但 Rust 的泛型还会要求我们明确说明类型需要具备哪些能力，下面就能看到。

### 12-3 结构体和方法也可以使用泛型

<!-- rust-check: {"id":"12-2","kind":"run","stdout":"85\n小林\n"} -->
【画面】同一个 `Record` 框里，先放成绩，再放文字。方法只借来读取内容。

```rust
struct Record<T> {
    value: T,
}
impl<T> Record<T> {
    fn value(&self) -> &T {
        &self.value
    }
}
fn main() {
    let score = Record { value: 85 };
    let name = Record { value: "小林" };
    println!("{}", score.value());
    println!("{}", name.value());
}
```

【口播】

泛型也可以放在结构体上。这里的 Record 表示一份记录，里面有一个 value，具体类型用 T 表示。

放进去八十五，就得到保存整数的 Record；放进去“小林”，就得到保存文字引用的 Record。它们使用相同的定义，但具体类型不同。

给这种结构体写方法时，也要在 impl 后面声明 T，再说明方法属于 Record T。

value 方法返回 &T，也就是借用里面的内容。它没有把内容取走，所以这份记录仍然保留自己的数据。看见不熟悉的类型名字时，仍然可以先看 &：这里是在借用。

这种写法在标准库里很常见。Vec 的尖括号里写元素类型，Option 的尖括号里写可能装着的值的类型。它们就是我们早已用过的泛型类型。

### 12-4 不是每种类型都能比较大小

<!-- rust-check: {"id":"12-3","kind":"error","error":"E0369"} -->
【画面】突出 `left > right`，提示“只知道 T，还不知道能不能比较”。

```rust
fn larger<T>(left: T, right: T) -> T {
    if left > right { left } else { right }
}
fn main() {
    println!("{}", larger(80, 90));
}
```

【口播】

这个函数想返回两个值中较大的一个。我们把参数写成 T，是不是就可以了？

还不行。T 没有说明这个类型能比较大小。对整数来说，大于号没有问题；但我们自己定义的一份学生信息，到底怎样算“更大”？按年龄，还是按成绩？编译器不能替我们猜。

因此泛型函数需要明确说明：它要求类型能做哪些操作。这个要求叫作“约束”。下一节的 trait，就是表达这类能力的一种方式。

修正时，给 T 增加一条“支持大小比较”的要求，具体名字写在画面上。先理解它的用途，不用现在背下这个英文名字。

<!-- rust-check: {"id":"12-4","kind":"run","stdout":"90\n"} -->
【画面】只强调新增的 `: PartialOrd`。

```rust
fn larger<T: PartialOrd>(left: T, right: T) -> T {
    if left > right { left } else { right }
}
fn main() {
    println!("{}", larger(80, 90));
}
```

【口播】

这次就能输出九十。我们没有改变选择较大值的步骤，只是把函数对类型的要求写清楚了。

这个示例适合今天的普通整数；对浮点数的特殊值等情况，还需要进一步定义比较行为。初学时先用整数理解这条规则。

### 12-5 小练习

【画面】沿用 `make_pair`。问题：“下面哪一次调用符合定义？”

```text
make_pair(80, 90)
make_pair(80, "小林")
```

【口播】

函数的两个参数都写 T。哪一种调用可以？

【停顿】4 秒。

【口播】

第一种可以。第二种不可以，因为同一次调用中的两个 T 需要是相同类型，一个整数和一个文字引用不一致。

泛型这一节，先记住两句话：T 是一个类型位置，具体使用时才确定；需要对 T 做某种操作，就要说明它具备对应能力。

## 13 trait：先说明能做什么，再写具体怎么做｜49:00–53:00

### 13-1 不同的数据，都想显示一句介绍

【画面】一名学生、一门课程，都连接到“给出一句介绍”。

【口播】

我们继续看一个实际需求。学生可以给出一句介绍，课程也可以给出一句介绍。它们的数据字段不一样，生成介绍的方式也不同。

但使用它们的地方，可能只关心一件事：你能不能给我一句介绍？

Rust 用 trait 来描述这种共同能力，中文通常叫作“特征”。你可以先把它看成一份约定：实现这个 trait 的类型，要提供哪些功能。

trait 不要求不同类型拥有相同字段，也不要求它们用同样的方法计算结果。我们统一的是对外能做的事情。

### 13-2 先写约定，再让 Student 实现它

<!-- rust-check: {"id":"13-1a","kind":"part","group":"13-1","stdout":"学生：小林\n"} -->
【画面｜第一屏】定义“能给出介绍”这项能力。

```rust
trait Introduce {
    fn introduction(&self) -> String;
}

struct Student {
    name: String,
}
```

【口播】

这里定义 Introduce。里面写一个方法的名字、参数和返回类型，暂时不写具体过程。

这份约定说：如果一个类型实现 Introduce，它就要能够借用自己的数据，返回一份 String 介绍。

接下来由 Student 说明具体怎么做。

<!-- rust-check: {"id":"13-1b","kind":"part","group":"13-1"} -->
【画面｜第二屏】承接上一屏定义，展示 Student 的具体实现。

```rust
impl Introduce for Student {
    fn introduction(&self) -> String {
        format!("学生：{}", self.name)
    }
}
```

【口播】

impl Introduce for Student，可以读成“让 Student 实现 Introduce”。

在里面把 introduction 的具体过程补上。我们使用姓名，组合出“学生：小林”这样一份文字。

如果换成 Course 课程类型，就可以根据课程名称返回“课程：Rust 基础”。约定相同，具体实现可以不同。

### 13-3 函数只要求你能给出介绍

<!-- rust-check: {"id":"13-1c","kind":"part","group":"13-1"} -->
【画面｜第三屏】承接前两屏，显示通用函数与调用。

```rust
fn show<T: Introduce>(item: &T) {
    println!("{}", item.introduction());
}
fn main() {
    let student = Student { name: String::from("小林") };
    show(&student);
}
```

【口播】

现在写一个 show 函数。它不要求参数必须是 Student，只要求类型 T 实现 Introduce。

这个要求就是刚才说的泛型约束。因为约定里有 introduction 方法，函数才能放心调用它。

参数写 &T，表示借来读取。调用 show 时，传入学生的引用，Student 中的姓名没有被接走。最终我们看到“学生：小林”。

这就是 trait 与泛型配合的常见思路：泛型让代码不局限于一个类型，trait 说明这些类型需要具备的共同能力。

如果你学过 C++ 接口或相关设计，可以拿来辅助理解。但现在不需要研究继承结构或运行时调用方式，这个例子先在编译时确认类型是否具备所需方法。

### 13-4 可以提供一个默认做法

<!-- rust-check: {"id":"13-2","kind":"run","stdout":"欢迎学习 Rust\n"} -->
【画面】trait 中的方法有默认函数体；Student 的实现可以先留空。

```rust
trait Welcome {
    fn welcome(&self) {
        println!("欢迎学习 Rust");
    }
}
struct Student;
impl Welcome for Student {}
fn main() {
    let student = Student;
    student.welcome();
}
```

【口播】

trait 中的方法也可以提供默认做法。这里的 welcome 已经写好了如何显示欢迎语。

Student 说明自己实现 Welcome，如果不另外提供同名方法，就使用这个默认版本。有特殊需要时，也可以在实现中写自己的版本。

这里为了集中展示这个规则，Student 暂时没有字段。不要把这段与前面的 Student 定义拼在同一个程序里，它们是两个独立例子。

默认方法的用处是减少重复。很多类型都需要相同动作，就先写一份；少数类型需要不同动作，再分别调整。

### 13-5 where 与 derive：先认识常用写法

<!-- rust-check: {"id":"13-3","kind":"run","stdout":"Student { score: 85 }\n"} -->
【画面】第一屏显示 `derive(Debug)` 与结构体；第二屏显示 `where` 和调用。

```rust
#[derive(Debug)]
struct Student {
    score: u32,
}
fn show<T>(item: &T)
where
    T: std::fmt::Debug,
{
    println!("{item:?}");
}
fn main() {
    let student = Student { score: 85 };
    show(&student);
}
```

【口播】

如果约束比较长，我们可以把它放到 where 后面。这里的要求是：T 支持 Debug，也就是能够以一种便于检查的形式显示出来。

where 没有改变函数要做的事情，只是换个位置写类型要求。和 T 冒号 Debug 表达的是同一类约束。

结构体上面的 derive Debug，告诉编译器帮我们生成这个结构体所需的 Debug 实现。打印时使用带问号的格式，就能看到结构体名字和字段内容。

其他常见名字还有 Clone、Copy、PartialEq。分别与复制副本、简单复制、相等比较有关。今天先认识它们；真正需要某项能力时，再确认它能否用于自己的字段。

例如一个带 String 字段的结构体，不能因为想方便，就直接要求它支持 Copy。字段类型也要满足相应要求。

【画面】沿用 Introduce 与 Student；新增 `struct Course;`，但没有任何实现。问题：“show 能直接接收 Course 吗？”

【口播】

假设 Course 目前只是一个类型，还没有实现 Introduce。把它的引用传给刚才的 show，可以吗？

不可以。show 要求传入类型实现 Introduce。名字叫课程，或者我们认为它应该能介绍自己，都不够；要在代码中真正实现这个约定。

## 14 生命周期：借来的数据，使用时必须还在｜53:00–58:00

### 14-1 先看一个不能留下来的引用

<!-- rust-check: {"id":"14-1","kind":"error","error":"E0597"} -->
【画面】姓名所在的小范围结束后，文字框消失；外面的引用箭头变为红色。

```rust
fn main() {
    let view;
    {
        let name = String::from("小林");
        view = &name;
    }
    println!("{view}");
}
```

【口播】

最后一个新主题是生命周期。这个名字听上去抽象，但今天只从一个问题开始：借来的数据，到了使用的时候，是否还在？

这里在内层大括号里创建姓名，再让外面的 view 借用它。内层范围结束时，name 拥有的 String 被清理。

但我们还想在外面通过 view 显示姓名。这时它所依赖的数据已经不在了。这样的引用叫作“悬垂引用”，也就是指向不再有效的数据。

Rust 会在编译时阻止这个例子。所以它不是先运行、再显示乱码，而是根本不让这一段代码进入正常运行。

想修正，最直接的方法是把 name 放到外层，让它在输出时仍然存在。

<!-- rust-check: {"id":"14-2","kind":"run","stdout":"小林\n"} -->
【画面】姓名与引用都在外层范围中，姓名保持有效直到输出之后。

```rust
fn main() {
    let name = String::from("小林");
    let view = &name;
    println!("{view}");
}
```

【口播】

这一版可以运行。数据由 name 拥有，我们通过 view 借用它，显示时数据仍然有效。

“生命周期”可以先理解为某个值或引用在程序中有效的范围。借用的数据必须活得足够久，至少覆盖我们使用引用的那段范围。

这不是要求所有数据永远存在。使用结束以后，正常清理就可以。关键是顺序：不能把需要依赖的数据先清理，再拿引用去访问。

### 14-2 函数返回的引用来自哪里

【画面】函数左边两个输入，右边一个输出；输出箭头可能连向任意一个输入。

【口播】

很多时候，编译器能自己判断引用关系，我们不需要写额外标记。

但如果一个函数接收两个文字引用，并返回其中一个，函数声明就需要说明：返回的引用与哪些输入有关。

我们写一个例子，比较两段文字的字节长度，返回较长的那段文字的引用。这里只读取，并不创建新的 String。

<!-- rust-check: {"id":"14-3","kind":"run","stdout":"Zhou\n"} -->
【画面】先显示普通函数结构，再突出三处 `'a`；旁边始终保留输入输出箭头。

```rust
fn longer<'a>(left: &'a str, right: &'a str) -> &'a str {
    if left.len() >= right.len() {
        left
    } else {
        right
    }
}
fn main() {
    let first = String::from("Lin");
    let second = String::from("Zhou");
    let result = longer(&first, &second);
    println!("{result}");
}
```

【口播】

函数里的比较过程已经熟悉了：left 更长或一样长，就返回 left；否则返回 right。

新增的是单引号 a。它是一个生命周期标记。这里把两个输入和输出用同一个标记联系起来。

怎么理解这个联系？输出可能借用第一个输入，也可能借用第二个输入。调用者使用结果时，需要保证相关的借用范围足够。对这个声明来说，我们应当在两份输入数据都仍然有效的范围里使用结果。

在 main 中，两份 String 都已经创建，而且显示 result 时它们都还在，所以没有问题。最后输出 Zhou。

这里最重要的不是字母 a。换一个名字也可以。重要的是：同一个标记表达了输入引用和输出引用之间的有效范围关系。

它不会创建新的文字，不会复制字符串，也不会延长哪个 String 的实际寿命。它只是让函数把这种关系写清楚，供编译器检查。

### 14-3 标注不能让已经结束的数据继续活着

<!-- rust-check: {"id":"14-4","kind":"error","error":"E0597"} -->
【画面】第一屏保留 `longer` 定义；第二屏显示内层创建 `second`，外层使用结果，标出冲突。

```rust
fn longer<'a>(left: &'a str, right: &'a str) -> &'a str {
    if left.len() >= right.len() { left } else { right }
}
fn main() {
    let first = String::from("Lin");
    let result;
    {
        let second = String::from("Zhou");
        result = longer(&first, &second);
    }
    println!("{result}");
}
```

【口播】

现在把第二份文字放进内层范围。它在右大括号处就被清理，但 result 还想在外面使用。

函数声明已经有生命周期标记，为什么仍然报错？因为标记只能描述关系，不能把数据变成永久存在。

返回结果可能依赖 second，所以不能让 second 结束之后还使用这个结果。这个示例中，返回的也正是那份更长的 second。

修正时，可以把输出放进内层范围，在 second 结束之前完成使用；也可以把 second 放到外层，让它实际存活得更久。如果需要独立保存结果，还可以创建自己的 String 副本。

这些修改改变了数据实际保存和使用的方式。仅仅增加一个单引号标记，不能修复悬垂引用。学习生命周期时，最值得记住的就是这句话。

### 14-4 为什么很多函数没有写标记

<!-- rust-check: {"id":"14-5","kind":"run","stdout":"小林\n"} -->
【画面】唯一一个输入引用指向输出引用，中间无需选择来源。

```rust
fn as_text(name: &String) -> &str {
    name.as_str()
}
fn main() {
    let name = String::from("小林");
    let view = as_text(&name);
    println!("{view}");
}
```

【口播】

这个函数接收对 String 的引用，用 as_str 得到它的文字切片，再返回这个借来的切片。

这里只存在一个输入引用，输出来自谁很明确。Rust 按固定规则，允许我们省略相应的生命周期标记。省略的是写法，不是有效性检查。

初学时先认识两种常见情况：函数只有一个输入引用，输出引用通常与它关联；方法有 &self 或 &mut self 时，省略标记的输出引用通常与 self 关联。

如果有多个输入引用，又没有这样的 self 可以确定来源，就常常需要自己写出关系，像刚才的 longer。

所以，省略标记并不表示这些数据都存在同样长的时间。它只是让编译器根据明确的规则，帮我们补上引用之间的关系。

现在不用为了显得规范，给每个 & 都加一串标记。先用自然、清楚的函数签名。编译器要求你补充关系时，再回来看输出到底依赖哪份输入。

### 14-5 结构体也可以保存引用

<!-- rust-check: {"id":"14-6","kind":"run","stdout":"小林\n"} -->
【画面】`name` 拥有文字，`tag` 只保存查看文字的引用。

```rust
struct NameTag<'a> {
    text: &'a str,
}
fn main() {
    let name = String::from("小林");
    let tag = NameTag { text: &name };
    println!("{}", tag.text);
}
```

【口播】

这个 NameTag 保存一段借来的姓名。它没有拥有自己的 String，所以字段写 &str。

结构体名字后面的标记，与字段里的标记对应，说明这份名牌依赖借来的文字。在使用名牌时，原来的文字必须仍然有效。

这里显示 tag 时，name 还在，所以可以运行。如果原来的 name 已经结束，却想留下 tag 来使用，就会遇到类似的错误。

如果你的实际需求是“这张名牌要独立保存姓名”，通常把字段改成 String 会更直接。先决定数据由谁保存，再选择拥有数据还是借用数据。生命周期标记是把这个选择说清楚的一部分。

### 14-6 小练习

【画面】回到本节第一段错误代码。问题：“在引用旁边写上生命周期标记，能让内层 name 延长存在吗？”

【口播】

最后这道题，只需要回答一个概念。内层的 String 在范围结束时被清理，我们能不能靠增加生命周期标记，让它继续存在？

【停顿】4 秒。

【口播】

不能。标记描述引用之间的关系，不改变数据实际何时被清理。要修正，需要真正调整数据保存的位置、使用位置，或者创建独立拥有的数据。

如果今天只记住生命周期的这一点，就很好：借来的引用，不能比它依赖的数据使用得更久。

## 15 综合回顾：把基础内容连成一个小程序｜58:00–60:00

### 15-1 一份学生成绩记录

<!-- rust-check: {"id":"15-1a","kind":"part","group":"15-1","stdout":"小林：80\n"} -->
【画面｜第一屏】数据与方法。

```rust
struct Student {
    name: String,
    score: Option<u32>,
}
impl Student {
    fn passed(&self) -> bool {
        match self.score {
            Some(score) => score >= 60,
            None => false,
        }
    }
}
```

【口播】

我们把今天学过的基础连起来。Student 保存姓名和成绩。姓名用 String，成绩用 Option，因为有的学生暂时还没有成绩。

passed 方法先看有没有成绩，再判断是否及格。这个演示把“没有成绩”当成暂时不进入及格名单；真实业务中，也可以设计一个单独的待批改状态。

方法只读取信息，所以使用 &self，没有接走学生数据。

<!-- rust-check: {"id":"15-1b","kind":"part","group":"15-1"} -->
【画面｜第二屏】把学生放进 Vec，再借用遍历；承接上一屏定义。

```rust
fn main() {
    let students = vec![
        Student { name: String::from("小林"), score: Some(80) },
        Student { name: String::from("小周"), score: None },
    ];
    for student in &students {
        if student.passed() {
            if let Some(score) = student.score {
                println!("{}：{score}", student.name);
            }
        }
    }
}
```

【口播】

再把两名学生放进 Vec。小林有八十分，小周还没有成绩。for 借用这组学生，逐个查看；if 判断是否及格，if let 取出已有的成绩。

最终显示“小林：八十”。这个程序没有很长，但变量、类型、函数、条件、结构体、Option、Vec、字符串和借用，已经合作完成了一件事。

如果想按姓名快速查询，可以增加 HashMap。想表示待提交、批改中、已完成这些情况，可以使用枚举。想让同一套记录适用于不同类型，用泛型；想统一不同类型提供的某种功能，用 trait。

最后，所有权帮我们确认谁管理数据，借用让我们使用已有数据，生命周期检查让引用在使用时保持有效。

这些内容不需要一天内全都熟练。你可以先自己改三处：给小周补上一个成绩；再增加第三名学生；把及格线改成七十分。每次只改一点，运行一次，看看变化是否符合预期。

遇到编译错误，先找它指出的那一行，再问具体问题：这里需要修改变量吗？两边类型一致吗？数据是不是已经交出去了？引用依赖的数据还在吗？这几个问题，往往比背错误编号更有帮助。

今天，我们用一小时建立了 Rust 基础的第一张地图。接下来多写几个小程序，把同样的写法用在真实需求中。听懂一次是开始，自己改对一次，就会记得更牢。
