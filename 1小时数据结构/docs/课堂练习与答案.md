# 课堂练习与答案

每题在成片中提供四秒思考时间。代码的完整上下文见同编号 C++ 示例。

## 复杂度 · Complexity

题目：现在判断一小段代码。第一段循环把计数器加了 n 次，第二段循环也加了 n 次。这里 n 等于四，所以可以先预测最后输出多少，再判断当 n 增大时，工作量是线性增长还是平方增长。不要只数代码中出现了几个 for，要看第二个循环是在第一个里面执行，还是等第一个结束后才开始。请写下输出和增长标签，然后我们一起核对。

```cpp
int n = 4, count = 0;
for (int i = 0; i < n; ++i) ++count;
for (int j = 0; j < n; ++j) ++count;
cout << count << "\n";
```

答案与解释：输出是八，增长方式是线性级别。第一个循环执行四次，结束后，第二个循环再执行四次，总共八次。把四换成 n，总工作量是二乘 n，而不是 n 的平方。在增长标签里，我们忽略固定倍数，所以仍然记作大 O 括号 n。这个例子也提醒我们，复杂度分析要跟着实际执行顺序走。以后看到嵌套循环，也别马上套平方：如果内层每次只走三步，总次数仍然与外层次数成正比。反过来，一行看起来很短的库函数，也可能在内部扫描很多元素。先解释它做了什么，再说代价，比机械记住某种代码形状更可靠。下面开始看数组，刚才的按位置访问和完整扫描，会马上派上用场。

```text
8
```

## 数组与动态数组 · Arrays and Vectors

题目：请跟踪这个动态数组。最初是十、二十、三十，随后在下标一的位置插入九十九。问题有两个：现在下标二保存什么，长度又是多少。先把插入后的整排元素写出来，再读取指定下标，避免把原来的位置直接当成新位置。这里插入发生在 begin 加一之前，也就是原来二十的前面。请先预测两项输出，再核对答案。

```cpp
vector<int> a{10, 20, 30};
a.insert(a.begin() + 1, 99);
cout << a[2] << " " << a.size() << "\n";
```

答案与解释：输出是二十和四。插入后的顺序是十、九十九、二十、三十，所以下标二对应第三个元素二十，长度从三变成四。原来的二十并没有被覆盖，它只是向后移动了一个位置。这个区别在写插入操作时很重要：赋值通常是替换已有元素，插入则是新增一个元素并调整后续位置。也不要把某个元素的值和它的下标绑定成永久关系，排序、插入、删除以后，位置都可能变化。再想一步，如果你只是在末尾添加新成绩，动态数组通常很合适；如果经常在开头插入，反复移动大量元素就可能成为主要代价。接下来我们看链表，它用连接表示先后顺序，给插入和删除提供了另一种思路。

```text
20 4
```

## 链表 · Linked Lists

题目：这次三个节点是局部对象，分别保存十、二十、三十。p 指向第一个节点，执行这一句连接修改后，从 a 出发还能依次访问到哪些值。请画出箭头再判断，不要误以为每一个已经创建的节点，都一定还在这条链的可达路径上。本题没有 delete，也没有移动节点的物理位置，改变的只是一个 next。

```cpp
Node c{30, nullptr}, b{20, &c}, a{10, &b};
Node* p = &a;
p->next = p->next->next;
for (Node* q = &a; q; q = q->next)
    cout << q->value << " ";
cout << "\n";
```

答案与解释：输出是十、三十。等号右边先取得原来第二个节点的后继，也就是 c，然后把这个位置写入 a 的 next。从 a 出发，路径就绕过了 b。注意，b 这个局部对象仍然存在，直到离开自己的作用域；从链中不可达，并不等于对象已经销毁。本例不能对 b 使用 delete，因为它不是用 new 单独申请的。这里我们是为了把连接和内存释放分开理解。实际实现动态链表时，要同时管好这两件事，避免丢掉仍需释放的节点，也避免继续访问已经释放的节点。现在回顾数组和链表：数组擅长按下标定位，链表擅长在已知连接位置时调整局部关系。没有一种结构只凭名字，就能在所有任务中更快。

```text
10 30
```

## 栈与队列 · Stacks and Queues

题目：同样的两个数，放进栈和队列以后，取出的顺序可能不同。这里先加入三，再加入七，随后各自移除一个元素。最后打印栈顶和队头，它们分别是什么。建议把栈画成上下叠放，把队列画成从左到右排队。先确认刚才移除的是哪一个值，再看剩下的元素，不要把查看和移除混成同一步。

```cpp
stack<int> s;
queue<int> q;
s.push(3); s.push(7);
q.push(3); q.push(7);
s.pop(); q.pop();
cout << s.top() << " " << q.front() << "\n";
```

答案与解释：输出是三和七。栈最后加入的是七，所以先移除七，剩下三。队列最早加入的是三，所以先移除三，剩下七。两者保存的数据类型相同，加入顺序也相同，但操作规则不同，结果就不同。你可以用撤销和排队来记忆：撤销通常先撤掉最近做的动作，排队则先处理等得最久的任务。以后看到一个问题，不必先背某个容器的全部成员函数，先说清楚谁应该先出来。如果新任务需要比老任务更早处理，就未必还是普通队列，我们后面会用堆来处理优先级。还有，标准库的栈和队列都可以由底层容器适配而来，学习规则时先分清行为，再研究具体实现的代价。

```text
3 7
```

## 哈希表 · Hash Tables

题目：表中只有 A 对应三。我们通过方括号读取不存在的 B，再读取表的大小。先判断这两项输出，不要把方括号当成只读操作。最后一个问题也请一起想：如果业务只允许查询，不能悄悄增加记录，应该换成哪一种接口。这里我们明确使用整数作为值，因此新插入值的默认状态也是本题判断的一部分。

```cpp
unordered_map<string,int> m{{"A",3}};
cout << m["B"] << "\n";
cout << m.size() << "\n";
```

答案与解释：先输出零，再输出二。B 不存在时，方括号把它加入表中，并给整数值做默认初始化，得到零。因此读取结束后，表里有 A 和 B 两个键。这个例子不需要猜哈希表内部把键放在哪个桶，只需要掌握接口的可观察行为。如果换成 find，找不到时得到结束位置，表的大小不会改变。这里还能练一个通用读题顺序：先看元素类型，再看初始状态，接着逐句追踪操作有没有副作用，最后才读输出。不要因为语法看起来像数组下标，就假设所有容器都具有相同行为。哈希表解决的是按键快速定位；如果还需要按键从小到大访问，接下来要讲的有序树结构，会提供另一种方向。

```text
0
2
```

## 树与二叉搜索树 · Trees and Binary Search Trees

题目：这次用一棵只有三个节点的小树。根是八，左孩子是四，右孩子是十二。请根据中序遍历的规则，预测打印顺序。别根据节点在代码里先声明还是后声明来猜，要根据树上的连接和函数里的执行顺序来判断。再想一个补充问题：如果把三个值随意交换位置，中序遍历还一定会从小到大吗。

```cpp
Tree left{4,nullptr,nullptr};
Tree right{12,nullptr,nullptr};
Tree root{8,&left,&right};
inorder(&root);
cout << "\n";
```

答案与解释：输出是四、八、十二。中序函数先处理左子树，打印四，再回到根打印八，最后处理右子树，打印十二。声明 left、right、root 的先后，并不会替代这套访问规则。如果只是交换节点保存的值，却不再满足搜索树的大小约束，中序遍历仍然按左、根、右进行，但输出未必有序。这道题要同时分清两件事：遍历决定访问次序，搜索树约束决定这些位置上的值满足怎样的大小关系。学习树的操作时，可以把纸上的当前节点圈出来，再按函数调用画返回箭头，不必一开始试图在脑中同时追踪所有递归层。下一种结构同样能画成树，却只维护局部的优先级关系，它就是堆。

```text
4 8 12
```

## 堆与优先队列 · Heaps and Priority Queues

题目：优先队列先加入四、九、六，移除一次堆顶，再加入八，最后读取堆顶。请按操作顺序预测最终输出，不要只对最后加入的值下结论。注意这里使用默认比较规则，较大的整数优先；如果换成普通队列，行为会不同。先把移除发生时，容器里最大的值写出来，再处理后面的插入。

```cpp
priority_queue<int> pq;
for (int x : {4, 9, 6}) pq.push(x);
pq.pop();
pq.push(8);
cout << pq.top() << "\n";
```

答案与解释：最终输出八。最初九的优先级最高，第一次 pop 移除的是九，剩下四和六。加入八之后，八比剩下的值都大，所以成为新的堆顶。这里不需要先知道四和六在底层数组中的具体布局，只要使用优先队列的规则，就能判断结果。也不要把 pop 想成删除最近加入的六，那是把栈的规则带进来了。我们已经看过几种不同的先后关系：数组强调位置，栈强调最近加入，队列强调最早加入，优先队列强调比较规则。如果需求发生变化，合适的结构也会跟着变化。下面处理的关系更一般，不再只是排成一列或者逐层分支，而是多个地点之间互相连接，这就进入了图。

```text
8
```

## 图与图的遍历 · Graphs and Traversals

题目：仍然使用这一张无权无向图。A 连接 B、C，B 和 C 都连接 D，D 连接 E。从 A 到 E，最少需要经过几条边。请画出一条路线，并判断用队列逐层展开，还是沿任意一条路深走，就能保证首次得到最少边数。这里问的是边的数量，不是访问到 E 之前总共打印过几个顶点。

```cpp
// A=0, B=1, C=2, D=3, E=4
// A-B, A-C, B-D, C-D, D-E
cout << hops(0, 4) << "\n";
```

答案与解释：答案是三，例如 A 到 B，再到 D，最后到 E。路线经过四个顶点，但连接它们的是三条边。广度优先先确定一步可达的 B 和 C，再确定两步可达的 D，最后确定三步可达的 E。D 虽然可能通过 B 或 C 发现，只要在首次入队时做好标记，就不必重复加入队列。注意，哪一条三步路线被先记录下来，可能依赖邻居的排列，但最少边数仍然是三。深度优先也可能碰巧先找到这条路线，却不能因此推广成它总会先找到最短路。分析算法时，要区分某次运行恰好成功，以及根据处理规则可以保证什么。至此，数组、链、树和图几种组织关系已经串起来，下面再看在有序数据中怎样减少查找范围。

```text
3
```

## 二分查找 · Binary Search

题目：继续使用左闭右开、寻找第一个不小于目标位置的实现。数组是一、二、二、二、五，查找二，最后返回哪个下标。请特别留意相等时，我们让右边界向左收，而不是立刻返回当前中点。也可以把每一步的 lo、hi、mid 写成三列，检查候选范围有没有严格缩小。

```cpp
vector<int> a{1,2,2,2,5};
cout << findIndex(a,2) << "\n";
```

答案与解释：输出一。初始区间是零到五之前，中点下标二，值等于二，于是把右边界收缩到二。接着中点下标一，也等于二，右边界继续收缩到一。最后检查下标零，值是一，小于目标，左边界移到一。左右边界相遇，得到下标一，再验证这里确实是二。整个过程中，我们始终没有丢掉第一个目标位置，也始终让范围变小。这就是边界约定的价值。另一种遇到相等就立即返回的写法，也可能是合法二分查找，但它没有承诺返回第一个重复位置。写程序时不要把两种约定混在一起。接下来看看有序数据从哪里来，也就是排序。

```text
1
```

## 基础排序 · Sorting

题目：数组是四、一、三、二。我们只执行选择排序的第一轮：从整个范围找一个最小值，再与第一个元素交换。请预测交换后的完整数组。注意题目只做一轮，不能直接把最终升序结果当成答案。把 best 最后指向哪里，以及交换会影响哪两个位置写出来，会更容易看清。

```cpp
vector<int> a{4,1,3,2};
int best=0;
for (int j=1; j<(int)a.size(); ++j)
    if (a[j]<a[best]) best=j;
swap(a[0],a[best]);
for (int x:a) cout << x << " ";
cout << "\n";
```

答案与解释：输出是一、四、三、二。最小值一原先位于下标一，所以与下标零的四交换，另外两个位置没有变化。第一轮只保证最小值已经到了最前面，还要继续在后面的未排序部分重复操作。这个例子提醒我们，算法每一步通常只建立一部分保证，不会因为执行了一次交换，就神奇地完成全部任务。回顾几种排序：选择排序反复找最小值，插入排序把新元素插进已有顺序，归并排序合并有序的两半，快速排序围绕基准划分范围。实际使用时，通常调用成熟接口，并检查比较规则、稳定性和空间要求。理解这些区别，能够帮助你解释现象，也能避免把一种算法的性能结论随意套到另一种做法上。

```text
1 4 3 2
```

## 综合应用与回顾 · Putting It Together

题目：最后一道题，不用写长程序。新成绩持续到来，我们每次只想知道当前最高分，还会取走这个最高分。你会在每次新增后重新完整排序，还是维护一个优先队列，为什么。再加一个需求，按姓名查某个同学的成绩：仅靠同一个普通堆，是否也能直接高效完成。请分别说出两项操作需要的能力，而不是只回答一个容器名字。

答案与解释：第一项可以优先考虑最大优先队列。它把当前最大值放在堆顶，查看很方便，插入和移除通常只需沿树高调整，没有必要为了拿出一个最大值，每次都重新把全部记录排好序。第二项是按姓名定位记录，普通堆没有提供这种高效任意查找保证，可以再维护姓名到成绩的映射，并明确两份数据怎样保持一致。今天你已经接触到数据结构的主要骨架。课后建议按三个层次练习：先用小数据在纸上推演，再运行程序核对结果，最后自己补上空输入、边界和重复值的测试。优先把动态数组、链表接链、栈和队列、二分查找以及图的遍历写熟，再继续学习平衡树和更多图算法。能解释每一步为什么正确，比只记住一张复杂度表更扎实。
