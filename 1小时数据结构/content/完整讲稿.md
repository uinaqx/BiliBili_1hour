## 导学 · Introduction

### 00-01 从保存一组成绩开始

同学们好，这一小时，我们用一些能跑起来的小程序，学习数据结构的基础。先想一个很普通的需求：老师要保存全班成绩，有时按第几位同学查分，有时按姓名查分，还想找出最高分。数据都是成绩，但做的事情不同，合适的组织方式也会不同。数据结构，就是研究怎样安排数据，才能方便地完成这些操作。我们会先看数组，再看链表、栈和队列，然后走向哈希表、树、堆和图，最后把查找与排序连起来。你需要认识变量、函数、循环和简单指针，不需要先背一大串定义。每到一个新结构，我们都问三件事：数据怎样放，操作怎样做，代价大不大。学完后，你应该能看懂基本实现，说明运行结果，也能为一个具体需求选择合适的工具。

画面要点：先理解需求，再选择结构；看清数据、操作与代价；C++ 示例＋图解＋练习

### 00-02 先看规则，再看实现

学习时，我们把两层意思分开。第一层是规则，例如排队时先到的先处理。第二层是实现，例如用数组还是链起来的节点保存队伍。只要遵守相同规则，实现可以不同。你会看到标准库容器，也会看到几段手写代码。标准库帮助我们把结构用起来，手写代码帮助我们理解里面发生了什么。遇到代码时，先读输入和目标，再跟踪正在变化的下标、指针或者容器，最后核对结果。课堂小题会留四秒钟，建议先在纸上写一个预测。答错没有关系，重点是指出哪一步想错了。后面的例子都采用很小的数据，方便逐步推演；分析效率时，再把数据量想象成几千、几万。不要因为四个数字跑得快，就认为所有做法处理十万条数据都一样。

画面要点：规则决定行为；实现决定具体代价；先预测，再核对原因

## 复杂度 · Complexity

### 01-01 把输入规模当作一把尺子

先看怎样描述程序要做多少工作。这里有四个成绩，程序从左到右求和。循环每次处理一个元素，四个元素就处理四次。如果人数变成一百，就处理一百次。我们用字母 n 表示输入规模，也就是这次有多少个元素。时间复杂度关注的是，规模增大时，主要工作量怎样增长，而不是在某台电脑上恰好跑了几毫秒。这个求和程序的工作量与人数成正比，我们把它记成线性级别，写作大 O 括号 n。这里的符号先当成一张增长标签，不必一开始纠结数学定义。请注意，循环里还做了加法和取值，不是只有一次操作；这些固定倍数不会改变它随着人数成比例增长的特点。先抓住增长方式，再去比较实际常数，会更容易理解。

```cpp
vector<int> a{72, 88, 95, 81};
int sum = 0;
for (int x : a) {
    sum += x;
}
cout << sum << "\n";
```

运行结果：
```text
336
```

画面要点：n 表示输入元素个数；求和要看每个元素；线性增长：O(n)

### 01-02 常数、线性与平方

再比较三种任务。第一种是直接读取数组中指定位置的元素，只要下标有效，就能按位置定位，通常把它的访问代价看作常数级别。第二种是把所有元素各看一遍，是线性级别。第三种是给每个元素都配上另一个元素，形成所有有序组合。外层走 n 次，每次内层又走 n 次，总次数就是 n 乘 n，属于平方级别。屏幕上的四个元素会产生十六个组合。如果变成一百个，就会产生一万个。这里不是说两个循环一定不好，而是说要看循环各自走多少次，以及它们是嵌套还是先后执行。两个循环先后各走一遍，只是把一遍工作做了两次，仍然是线性增长。判断复杂度，先算重复次数，再贴标签。

```cpp
int n = 4;
int count = 0;
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < n; ++j) {
        ++count;
    }
}
cout << count << "\n";
```

运行结果：
```text
16
```

画面要点：嵌套 n×n 是平方增长；先后 n＋n 仍为线性；看次数，不只看循环层数

### 01-03 每次减半为什么是对数

还有一种很常见的增长方式：每做一步，就把剩下的范围减半。假设现在有十六个候选位置，减半后剩八个，再减半剩四个，然后是两个、一个。规模从十六缩到一个，只需要四次减半。把规模扩大到一千零二十四，也只需要十次。我们把这种步数随着规模缓慢增加的情况，称为对数级别，写成大 O 括号 log n。这里可以先把 log 理解成，连续减半需要多少步。以后学二分查找和树的高度时，这个想法会反复出现。对数并不意味着程序里必须调用一个数学函数；它描述的是步骤数量。也不要把减半循环和旁边另一个完整扫描混为一谈，整个算法的代价，要把各部分都看进去。

```cpp
int n = 16;
int steps = 0;
while (n > 1) {
    n /= 2;
    ++steps;
}
cout << steps << "\n";
```

运行结果：
```text
4
```

画面要点：16→8→4→2→1；连续减半需要 4 步；减半的步数是 O(log n)

### 01-04 时间之外，还要看额外空间

程序的代价不只有时间，还包括额外用了多少存储。刚才求和只需要几个计数变量。无论有多少成绩，这些变量的数量不随人数增长，额外空间可以看作常数级别。如果为了保留原数据，再复制出一个同样大小的数组，额外空间就随人数成比例增长。屏幕上复制后修改副本，原数组仍然是三，副本变成九十九。这里讨论的是为了完成任务额外申请的空间，题目是否把输入本身算进去，要先讲清约定。以后遇到递归，还要记得函数调用也需要保存现场，不能因为代码里没有新建数组，就断定额外空间一定是常数。时间和空间往往要一起取舍，有时多保存一些信息，确实能减少重复查找。

```cpp
vector<int> a{3, 5, 7};
vector<int> b = a;
b[0] = 99;
cout << a[0] << " " << b[0] << "\n";
```

运行结果：
```text
3 99
```

画面要点：额外变量：O(1)；复制 n 个元素：O(n)；递归调用也占空间

### 01-q 课堂练习：两段循环的代价

现在判断一小段代码。第一段循环把计数器加了 n 次，第二段循环也加了 n 次。这里 n 等于四，所以可以先预测最后输出多少，再判断当 n 增大时，工作量是线性增长还是平方增长。不要只数代码中出现了几个 for，要看第二个循环是在第一个里面执行，还是等第一个结束后才开始。请写下输出和增长标签，然后我们一起核对。

（四秒思考；随后核对答案）

```cpp
int n = 4, count = 0;
for (int i = 0; i < n; ++i) ++count;
for (int j = 0; j < n; ++j) ++count;
cout << count << "\n";
```

运行结果：
```text
8
```

画面要点：先预测输出；两个循环是否嵌套？；再判断随 n 怎样增长

### 01-a 答案：先后执行仍然是线性

输出是八，增长方式是线性级别。第一个循环执行四次，结束后，第二个循环再执行四次，总共八次。把四换成 n，总工作量是二乘 n，而不是 n 的平方。在增长标签里，我们忽略固定倍数，所以仍然记作大 O 括号 n。这个例子也提醒我们，复杂度分析要跟着实际执行顺序走。以后看到嵌套循环，也别马上套平方：如果内层每次只走三步，总次数仍然与外层次数成正比。反过来，一行看起来很短的库函数，也可能在内部扫描很多元素。先解释它做了什么，再说代价，比机械记住某种代码形状更可靠。下面开始看数组，刚才的按位置访问和完整扫描，会马上派上用场。

```cpp
int n = 4, count = 0;
for (int i = 0; i < n; ++i) ++count;
for (int j = 0; j < n; ++j) ++count;
cout << count << "\n";
```

运行结果：
```text
8
```

画面要点：4＋4＝8；总次数是 2n；忽略固定倍数：O(n)

## 数组与动态数组 · Arrays and Vectors

### 02-01 连续存放，按下标定位

数组把同一种类型的元素连续放在一起。你可以把它想成一排编号座位，知道编号，就能计算出对应位置。屏幕上有四个成绩，下标从零开始，因此下标二对应第三个元素九十五，不是第二个元素。读取有效下标对应的元素，代价通常是常数级别。C++ 的普通数组长度在这里已经确定，不能直接在末尾再放一个新元素。数组也不会因为你想访问的位置不存在，就自动补出一把新椅子。初学时，建议把元素和下标分成两排写出来，尤其检查第一个位置是零，最后一个位置是长度减一。数组的优势是定位清楚、存放紧凑；它的限制也来自这种连续安排，后面讲插入时，我们就会看到需要搬动元素的原因。

```cpp
int scores[]{72, 88, 95, 81};
cout << scores[2] << "\n";
cout << sizeof(scores) / sizeof(scores[0]);
cout << "\n";
```

运行结果：
```text
95
4
```

画面要点：连续保存同类型元素；下标 2 是第 3 个元素；有效下标访问：O(1)

### 02-02 vector 管理可变化的长度

如果成绩会不断增加，可以用标准库的动态数组 vector。它把一段连续存储交给容器管理，并记录当前有多少个有效元素。屏幕上最初有三个成绩，向末尾追加八十一后，长度变成四；随后移除末尾元素，又回到三个。你不需要在每次追加时手工申请和释放整段数组，不过仍然要理解里面可能发生的搬迁。这里先把 size 理解成已经坐人的座位数，把 capacity 理解成目前准备好的座位总数。两者可以不同。扩容时具体准备多少个新座位，属于实现策略，不能假定所有平台都一定翻倍。日常写代码，先通过容器的成员函数完成操作，再根据这些操作的代价选择用法，会比自己随意管理一块内存更稳妥。

```cpp
vector<int> scores{72, 88, 95};
scores.push_back(81);
cout << scores.size() << "\n";
scores.pop_back();
cout << scores.size() << "\n";
```

运行结果：
```text
4
3
```

画面要点：size 是有效元素数量；capacity 是已备空间；容器负责管理底层存储

### 02-03 在中间插入，后面的元素要让位

现在有十、二十、三十，我们想把十五放在十的后面。因为动态数组仍然要求元素连续排列，原来的二十和三十就需要向后移动，为十五腾出位置。屏幕中的 begin 加一，表示第二个元素之前的位置。插入后顺序是十、十五、二十、三十。接着删除下标二的元素，也就是二十，后面的三十又需要向前补位。因此，在数组中间插入和删除，通常要移动一段元素，不能只因为代码是一行，就说它是常数代价。位置越靠前，可能需要移动的元素越多。即使已经预留足够容量，避免了整段扩容，这些为了维持顺序而发生的移动，仍然可能存在。请把扩容搬家和中间让位看成两件不同的事。

```cpp
vector<int> a{10, 20, 30};
a.insert(a.begin() + 1, 15);
for (int x : a) cout << x << " ";
cout << "\n";
a.erase(a.begin() + 2);
for (int x : a) cout << x << " ";
cout << "\n";
```

运行结果：
```text
10 15 20 30 
10 15 30
```

画面要点：中间插入要向后让位；删除后要向前补位；最坏需要移动 O(n) 个元素

### 02-04 末尾追加的平均代价

动态数组追加元素时，有两种情况。如果预备空间还够，直接把新元素放到末尾，工作很少。如果已经放满，就需要申请更大的连续空间，再把原来的元素迁移过去，这一次追加可能要处理很多旧元素。因此，不能说每一次追加都一定是常数代价。不过，常见动态数组通过合理增长容量，让扩容不必在每次追加时发生。把一长串追加操作合起来分析，平均摊到每次，就可以得到摊还常数的结论。这里的摊还不是随机概率平均，而是把少数昂贵操作的代价分摊到整个操作序列。知道大概人数时，可以提前 reserve，减少扩容次数，但 reserve 本身不代表创建了那么多个有效成绩，长度仍然要看 size。

```cpp
vector<int> a;
a.reserve(100);
cout << a.size() << "\n";
a.push_back(80);
cout << a.size() << "\n";
```

运行结果：
```text
0
1
```

画面要点：单次扩容可能是 O(n)；连续追加：摊还 O(1)；reserve 不增加 size

### 02-05 访问之前先检查边界

数组和动态数组都要注意边界。三个元素的有效下标是零、一、二，因此下标三已经越界。这里使用 at 访问，它会检查边界，并在越界时抛出异常。我们把异常接住，输出一条固定提示，便于核对。方括号访问通常不做这种检查；越界访问不是可靠地得到零，也不是保证马上报错，而是可能产生未定义行为。所以课堂不会通过实际运行危险的越界代码来猜结果。另一个常见误会是，预留了容量，就能直接访问那些位置。有效下标取决于长度，而不是容量。写循环时，用小于 size，而不是小于等于 size。以后换成别的结构，也要先检查操作是否满足条件，例如队列非空时才能读取队头。

```cpp
vector<int> a{10, 20, 30};
try {
    cout << a.at(3) << "\n";
} catch (const out_of_range&) {
    cout << "out_of_range\n";
}
```

运行结果：
```text
out_of_range
```

画面要点：有效下标：0 到 size−1；at 会检查边界；容量不等于有效长度

### 02-q 课堂练习：插入后的位置

请跟踪这个动态数组。最初是十、二十、三十，随后在下标一的位置插入九十九。问题有两个：现在下标二保存什么，长度又是多少。先把插入后的整排元素写出来，再读取指定下标，避免把原来的位置直接当成新位置。这里插入发生在 begin 加一之前，也就是原来二十的前面。请先预测两项输出，再核对答案。

（四秒思考；随后核对答案）

```cpp
vector<int> a{10, 20, 30};
a.insert(a.begin() + 1, 99);
cout << a[2] << " " << a.size() << "\n";
```

运行结果：
```text
20 4
```

画面要点：写出插入后的完整顺序；下标从 0 开始；再读取位置和长度

### 02-a 答案：下标表示当前位置

输出是二十和四。插入后的顺序是十、九十九、二十、三十，所以下标二对应第三个元素二十，长度从三变成四。原来的二十并没有被覆盖，它只是向后移动了一个位置。这个区别在写插入操作时很重要：赋值通常是替换已有元素，插入则是新增一个元素并调整后续位置。也不要把某个元素的值和它的下标绑定成永久关系，排序、插入、删除以后，位置都可能变化。再想一步，如果你只是在末尾添加新成绩，动态数组通常很合适；如果经常在开头插入，反复移动大量元素就可能成为主要代价。接下来我们看链表，它用连接表示先后顺序，给插入和删除提供了另一种思路。

```cpp
vector<int> a{10, 20, 30};
a.insert(a.begin() + 1, 99);
cout << a[2] << " " << a.size() << "\n";
```

运行结果：
```text
20 4
```

画面要点：10、99、20、30；a[2] 是 20，长度是 4；插入与覆盖不是一回事

## 链表 · Linked Lists

### 03-01 用连接表示先后关系

链表不要求所有元素连续摆放。它把数据放在一个个节点中，每个节点除了自己的值，还保存下一个节点的位置。这里 next 是一个指针，可以先把它理解成通往下一站的路标。最后一个节点的 next 是空指针，表示后面没有节点了。head 保存第一个节点的位置，沿着 next 就能依次看到十、二十、三十。为了先看清连接，这一页用三个局部节点搭成链条，它们的生命周期都覆盖这次遍历，不需要手工释放。链表的顺序由指针连接决定，不由节点在内存里离得近不近决定。和数组相比，它不擅长直接跳到第几个元素，却可以在已经找到连接位置时，通过修改少数指针调整局部关系。

```cpp
Node c{30, nullptr};
Node b{20, &c};
Node a{10, &b};
Node* head = &a;
for (Node* p = head; p; p = p->next) {
    cout << p->value << " ";
}
cout << "\n";
```

运行结果：
```text
10 20 30
```

画面要点：节点保存值和 next；head 指向第一个节点；顺序由连接决定

### 03-02 找到第几个节点需要逐个走

如果要读取单链表的第三个节点，不能像数组那样直接通过下标算出地址。你需要从头开始，先走到第二个，再走到第三个。一般地，查找靠后的节点可能要经过很多次连接，因此按位置查找通常是线性代价。这也解释了为什么链表不是数组的全面升级。它多保存指针，访问时还要沿连接跳转；连续数组往往在缓存利用方面更有优势，实际速度不能只看一句复杂度标签。我们选结构时，要把常做的操作说具体。是经常按位置读取，还是已经持有某个节点后，在它附近插入。尤其要注意，知道要找的值，不等于已经拿到了那个节点的指针。为了先找到它而发生的遍历，也要算进整个任务的代价。

```cpp
Node c{30, nullptr}, b{20, &c}, a{10, &b};
Node* p = &a;
p = p->next;
p = p->next;
cout << p->value << "\n";
```

运行结果：
```text
30
```

画面要点：按位置读取需要沿链走；查找通常是 O(n)；已知值不等于已知节点

### 03-03 插入时先接好后半段

现在在十和三十之间插入二十。已知 p 指向十，先新建一个节点，让新节点的 next 指向原来的后半段，也就是三十。然后再把 p 的 next 改成新节点。请记住这个顺序的理由：先把后半段的位置保存好，再改前面的连接。如果一开始就覆盖唯一保存后半段的位置，就可能把那段链丢掉。屏幕上的写法把新节点的值和 next 一起初始化，所以第一句结束时，新节点已经知道后面是谁。这次我们用了 new 申请节点，遍历结束后通过 clear 逐个释放，完整示例里提供了这段清理代码。已知插入位置时，局部接链只需要固定数量的指针修改；如果还需要从头寻找位置，整个任务仍然可能是线性代价。

```cpp
Node* head = new Node{10, new Node{30, nullptr}};
Node* p = head;
Node* node = new Node{20, p->next};
p->next = node;
for (Node* q = head; q; q = q->next)
    cout << q->value << " ";
cout << "\n";
clear(head);
```

运行结果：
```text
10 20 30
```

画面要点：新节点先连接后半段；再修改前面的 next；找位置和改连接分开算

### 03-04 删除要保留后继并释放节点

删除单链表里的一个节点，也要先想清楚连接会怎样变化。这里我们已经知道待删节点的前一个节点 p，先用 old 保存待删节点，再让 p 直接连接 old 的后继。这样二十就从链中摘下，十直接通向三十。最后，如果这个节点原来由 new 单独申请，而且没有别的地方继续使用它，就应释放它。释放之后不能再通过 old 读取成员，所以连接调整必须在前面完成。代码最后还要清理剩余节点。对于单链表，删除通常需要知道前驱；只有待删节点本身，并不能在所有情况下直接完成同样的操作，特别是尾节点。双向链表还保存前一个节点的连接，能支持更多局部操作，但也多用空间，多维护一份关系。

```cpp
Node* head = new Node{10,
    new Node{20, new Node{30, nullptr}}};
Node* p = head;
Node* old = p->next;
p->next = old->next;
delete old;
for (Node* q = head; q; q = q->next)
    cout << q->value << " ";
cout << "\n";
clear(head);
```

运行结果：
```text
10 30
```

画面要点：先接回后继节点；再释放被摘下的节点；释放后不能再解引用

### 03-q 课堂练习：一次断开连接

这次三个节点是局部对象，分别保存十、二十、三十。p 指向第一个节点，执行这一句连接修改后，从 a 出发还能依次访问到哪些值。请画出箭头再判断，不要误以为每一个已经创建的节点，都一定还在这条链的可达路径上。本题没有 delete，也没有移动节点的物理位置，改变的只是一个 next。

（四秒思考；随后核对答案）

```cpp
Node c{30, nullptr}, b{20, &c}, a{10, &b};
Node* p = &a;
p->next = p->next->next;
for (Node* q = &a; q; q = q->next)
    cout << q->value << " ";
cout << "\n";
```

运行结果：
```text
10 30
```

画面要点：画出修改前后的箭头；从 a 沿 next 遍历；断链是否等于销毁对象？

### 03-a 答案：跳过二十，不等于销毁它

输出是十、三十。等号右边先取得原来第二个节点的后继，也就是 c，然后把这个位置写入 a 的 next。从 a 出发，路径就绕过了 b。注意，b 这个局部对象仍然存在，直到离开自己的作用域；从链中不可达，并不等于对象已经销毁。本例不能对 b 使用 delete，因为它不是用 new 单独申请的。这里我们是为了把连接和内存释放分开理解。实际实现动态链表时，要同时管好这两件事，避免丢掉仍需释放的节点，也避免继续访问已经释放的节点。现在回顾数组和链表：数组擅长按下标定位，链表擅长在已知连接位置时调整局部关系。没有一种结构只凭名字，就能在所有任务中更快。

```cpp
Node c{30, nullptr}, b{20, &c}, a{10, &b};
Node* p = &a;
p->next = p->next->next;
for (Node* q = &a; q; q = q->next)
    cout << q->value << " ";
cout << "\n";
```

运行结果：
```text
10 30
```

画面要点：路径变成 a→c；b 仍是活着的局部对象；断开连接与释放要分清

## 栈与队列 · Stacks and Queues

### 04-01 栈：最后放入的先取出

栈可以先想成一叠盘子。新盘子放到最上面，取盘子也从最上面拿，所以最后放入的，反而最先取出。这个规则叫后进先出。程序先压入十，再压入二十，此时栈顶是二十。移除栈顶后，十才重新露出来。标准库的 stack 提供 push、top 和 pop，分别表示压入、查看栈顶、移除栈顶。请注意，pop 只负责移除，不会直接返回被移除的值。如果需要保存那个值，要先读 top，再做 pop。栈只允许我们通过栈顶完成这些操作，正是这种限制让它适合处理撤销、嵌套和函数调用的先后关系。读取或者移除之前，应确认栈非空；空栈没有一个可以合法读取的栈顶。

```cpp
stack<int> s;
s.push(10);
s.push(20);
cout << s.top() << "\n";
s.pop();
cout << s.top() << "\n";
```

运行结果：
```text
20
10
```

画面要点：后进先出：LIFO；top 查看，pop 移除；操作前先确认非空

### 04-02 用栈检查括号是否配对

看一个栈真正派上用场的例子。读到左括号，就把它压入栈，表示还有一个等待配对的开始。读到右括号，就应该取出最近一个尚未配对的左括号。为什么用最近的，因为括号是从里面向外闭合的。这里只处理圆括号，先把核心流程看清。如果遇到右括号时栈已经空了，说明没有对应的左括号，可以立刻判错。读完整段文字后，栈还必须为空，否则还有左括号没有被关闭。代码同时检查了这两个方向，所以不会把只有左括号、没有右括号的字符串误判为正确。整个过程每个字符只进出栈有限次，时间随字符数量线性增长，最坏额外空间也可能与字符数量成正比。

```cpp
bool balanced(const string& text) {
    stack<char> s;
    for (char c : text) {
        if (c == '(') s.push(c);
        else if (c == ')') {
            if (s.empty()) return false;
            s.pop();
        }
    }
    return s.empty();
}
```

运行结果：
```text
true false
```

画面要点：左括号入栈；右括号匹配最近的左括号；结束时还要检查栈为空

### 04-03 队列：先到的先处理

队列像在窗口排队，先到的人先接受服务。新的元素从队尾加入，处理时从队头取走，这叫先进先出。屏幕里依次加入十、二十，队头是十；处理掉十以后，二十成为新队头。标准库 queue 的 front 查看队头，push 在队尾加入，pop 移除队头。同样，pop 不会返回那个值，需要时先读取，再移除。它与栈最大的区别，不是元素长得不一样，而是允许访问和移除的位置不同。后来我们讲图的广度优先搜索时，会把刚发现的地点加入队尾，把最早等待的地点取出来继续处理，利用的正是这个顺序。只要任务要求先来先服务，就可以先考虑队列，而不是立刻去想一种复杂的排序方法。

```cpp
queue<int> q;
q.push(10);
q.push(20);
cout << q.front() << "\n";
q.pop();
cout << q.front() << "\n";
```

运行结果：
```text
10
20
```

画面要点：先进先出：FIFO；队尾加入，队头移除；front 查看队头

### 04-04 循环队列复用已经空出的格子

如果用数组实现队列，每次取走队头就把所有元素左移，会做很多没必要的搬动。另一个办法是，让一个下标记录队头位置，再用一个下标记录下次写入的位置。队头前进后，前面空出的格子以后还能再次使用。下标走到数组末尾时，取模回到开头，这就是循环队列的基本想法。屏幕用三个格子模拟：先放十和二十，处理掉十，再放三十和四十，最后从队头看到的是二十、三十、四十。这里另外保存数量 count，用它区分空队和满队；不要仅凭两个下标相等就猜状态。完整生产代码还需要封装边界检查。我们先理解为什么取模可以回绕，以及为什么逻辑队头不一定在物理下标零。

```cpp
int a[3]{}, head=0, tail=0, count=0;
a[tail]=10; tail=(tail+1)%3; ++count;
a[tail]=20; tail=(tail+1)%3; ++count;
head=(head+1)%3; --count;
a[tail]=30; tail=(tail+1)%3; ++count;
a[tail]=40; tail=(tail+1)%3; ++count;
for(int i=0; i<count; ++i)
    cout << a[(head+i)%3] << " ";
cout << "\n";
```

运行结果：
```text
20 30 40
```

画面要点：移动下标，避免整体搬动；取模使下标回到开头；额外计数区分空与满

### 04-q 课堂练习：栈和队列同时操作

同样的两个数，放进栈和队列以后，取出的顺序可能不同。这里先加入三，再加入七，随后各自移除一个元素。最后打印栈顶和队头，它们分别是什么。建议把栈画成上下叠放，把队列画成从左到右排队。先确认刚才移除的是哪一个值，再看剩下的元素，不要把查看和移除混成同一步。

（四秒思考；随后核对答案）

```cpp
stack<int> s;
queue<int> q;
s.push(3); s.push(7);
q.push(3); q.push(7);
s.pop(); q.pop();
cout << s.top() << " " << q.front() << "\n";
```

运行结果：
```text
3 7
```

画面要点：画出两种加入顺序；各自移除了谁？；再读栈顶和队头

### 04-a 答案：规则不同，剩下的值不同

输出是三和七。栈最后加入的是七，所以先移除七，剩下三。队列最早加入的是三，所以先移除三，剩下七。两者保存的数据类型相同，加入顺序也相同，但操作规则不同，结果就不同。你可以用撤销和排队来记忆：撤销通常先撤掉最近做的动作，排队则先处理等得最久的任务。以后看到一个问题，不必先背某个容器的全部成员函数，先说清楚谁应该先出来。如果新任务需要比老任务更早处理，就未必还是普通队列，我们后面会用堆来处理优先级。还有，标准库的栈和队列都可以由底层容器适配而来，学习规则时先分清行为，再研究具体实现的代价。

```cpp
stack<int> s;
queue<int> q;
s.push(3); s.push(7);
q.push(3); q.push(7);
s.pop(); q.pop();
cout << s.top() << " " << q.front() << "\n";
```

运行结果：
```text
3 7
```

画面要点：栈移除最后加入的 7；队列移除最先加入的 3；结果：3 7

## 哈希表 · Hash Tables

### 05-01 从姓名直接寻找成绩

假设老师要按姓名查成绩。用普通数组保存一排姓名和分数，每次可能要逐个比较。哈希表提供另一种思路：先用一个计算规则把姓名映射到某个位置附近，再到那里核对真正的姓名。这个计算规则叫哈希函数，可以先把它想成分拣规则。C++ 的 unordered_map 用来保存键和值的对应关系，这里键是姓名，值是成绩。屏幕先保存 Lin 和 Mei 的分数，再查询 Lin，得到八十八。键是用于查找的标识，值是与它关联的数据，两者的角色要分清。哈希表不要求姓名事先排好序，也不承诺遍历时按姓名或者插入顺序出现。需要稳定输出顺序时，应当自己指定查询顺序，或者选择满足顺序要求的结构。

```cpp
unordered_map<string, int> grades;
grades["Lin"] = 88;
grades["Mei"] = 95;
cout << grades.at("Lin") << "\n";
cout << grades.size() << "\n";
```

运行结果：
```text
88
2
```

画面要点：键用于查找，值保存数据；哈希函数帮助定位；遍历顺序没有排序保证

### 05-02 发生碰撞，仍要核对真正的键

用一个有限的位置集合保存很多可能的键，不同的键可能被分到同一处，这叫碰撞。为了看清它，先用一个简化规则：整数对四取余，决定进入哪一个桶。十和十四都会进入编号二的桶，但它们显然不是同一个数。屏幕里的小模型在桶中保存一串元素，查询时还要逐个核对真正的值。这个模型只是帮助理解碰撞，不能据此断定所有标准库实现都采用相同细节。哈希表之所以通常查得快，是因为在合适的分布和负载条件下，候选范围比较小。如果很多键集中在一起，查询仍然可能退化。请记住，哈希值相同不表示键相同，哈希表也不是绝对不会逐个比较。这样的边界说明，比简单记住一个快字更重要。

```cpp
vector<vector<int>> buckets(4);
for (int x : {10, 14, 7})
    buckets[x % 4].push_back(x);
for (int x : buckets[2]) cout << x << " ";
cout << "\n";
```

运行结果：
```text
10 14
```

画面要点：10 和 14 都进入桶 2；碰撞后仍比较真正的键；桶模型用于解释原理

### 05-03 查询不应意外新增数据

使用哈希表时，一个很容易忽略的行为是方括号查询。对于 unordered_map，如果键不存在，方括号会插入这个键，并创建默认值。屏幕里本来只有 Lin 的成绩，读取 Missing 以后，返回零，表的大小也从一变成二。这不等于系统确认这位同学考了零分，只是默认整数值恰好是零。如果你只想判断有没有记录，可以用 find，把没有找到的情况单独处理。这样查询不会因为缺少键而新增一条成绩。另一种方式是使用 at，让缺少键时的异常明确暴露，再按需要处理。选择接口时，要看它有没有改变数据的副作用。对于真实的业务，缺少成绩和成绩为零，通常是完全不同的两种情况。

```cpp
unordered_map<string,int> grades{{"Lin",88}};
auto it = grades.find("Mei");
cout << (it == grades.end()) << "\n";
cout << grades.size() << "\n";
cout << grades["Missing"] << "\n";
cout << grades.size() << "\n";
```

运行结果：
```text
1
1
0
2
```

画面要点：find 不新增缺失的键；方括号可能插入默认值；缺少记录不等于成绩为 0

### 05-04 平均很快，但要说明前提

哈希表常见的查询和插入，平均情况下可以看成常数级别，但最坏情况可能是线性级别。这里的平均，是对哈希表现作出的性能描述，不能保证每个具体请求都一样快。另外，插入时可能调整桶的数量，这次操作还会涉及已有元素。对于初学者，先记住三点就够用：哈希分布要合适，元素不能过度挤在少数位置，标准库允许在需要时重新组织存储。我们再看一个典型用途，统计每个值出现多少次。逐个读取成绩，用成绩作为键，把对应计数加一。对于还没出现过的键，默认零再加一，正好符合这个任务的要求。相同的方括号行为，在查询缺失成绩时可能是陷阱，在统计次数时又是很方便的工具。

```cpp
vector<int> scores{80, 90, 80, 70, 90, 80};
unordered_map<int,int> count;
for (int x : scores) ++count[x];
cout << count.at(80) << " " << count.at(90);
cout << "\n";
```

运行结果：
```text
3 2
```

画面要点：常见操作平均 O(1)；最坏可能 O(n)；统计时默认 0 很方便

### 05-q 课堂练习：没有找到会怎样

表中只有 A 对应三。我们通过方括号读取不存在的 B，再读取表的大小。先判断这两项输出，不要把方括号当成只读操作。最后一个问题也请一起想：如果业务只允许查询，不能悄悄增加记录，应该换成哪一种接口。这里我们明确使用整数作为值，因此新插入值的默认状态也是本题判断的一部分。

（四秒思考；随后核对答案）

```cpp
unordered_map<string,int> m{{"A",3}};
cout << m["B"] << "\n";
cout << m.size() << "\n";
```

运行结果：
```text
0
2
```

画面要点：B 原先是否存在？；方括号会不会修改表？；只读查询可以用 find

### 05-a 答案：默认值与容器大小都要看

先输出零，再输出二。B 不存在时，方括号把它加入表中，并给整数值做默认初始化，得到零。因此读取结束后，表里有 A 和 B 两个键。这个例子不需要猜哈希表内部把键放在哪个桶，只需要掌握接口的可观察行为。如果换成 find，找不到时得到结束位置，表的大小不会改变。这里还能练一个通用读题顺序：先看元素类型，再看初始状态，接着逐句追踪操作有没有副作用，最后才读输出。不要因为语法看起来像数组下标，就假设所有容器都具有相同行为。哈希表解决的是按键快速定位；如果还需要按键从小到大访问，接下来要讲的有序树结构，会提供另一种方向。

```cpp
unordered_map<string,int> m{{"A",3}};
cout << m["B"] << "\n";

```

运行结果：
```text

2
```

画面要点：默认整数值为 0；表中现在有 A、B 两个键；输出：0，再输出 2

## 树与二叉搜索树 · Trees and Binary Search Trees

### 06-01 从上下级关系认识树

文件夹里面还有文件夹，学校里面有学院，学院里面有班级，这些都可以用层次关系来描述。树就是很适合表达这种层次的结构。最上面的入口叫根，一个节点直接连接的下一层节点叫它的孩子，反过来叫父节点。没有孩子的节点叫叶子。二叉树进一步限制每个节点最多有两个孩子，通常称为左孩子和右孩子，但这并没有规定它们的数值大小。屏幕上根节点是八，左边和右边各有一棵更小的树。你会发现一个重要特点：一棵树的左右部分，仍然可以用同样的方法理解。这为递归提供了自然入口。先别着急背遍历次序，先能指出根、孩子和叶子，再看怎样按某种规则访问所有节点。

```cpp
Tree a{2,nullptr,nullptr}, b{6,nullptr,nullptr};
Tree c{10,nullptr,nullptr}, d{14,nullptr,nullptr};
Tree l{4,&a,&b}, r{12,&c,&d}, root{8,&l,&r};
cout << root.value << " ";
cout << root.left->value << " ";
cout << root.right->value << "\n";
```

运行结果：
```text
8 4 12
```

画面要点：根是访问的入口；叶子没有孩子；二叉树不自动保证有序

### 06-02 递归：把同样的事情交给子树

递归不是让程序凭空猜出答案，而是把同一种操作交给更小的部分，并说明什么时候停下。这里统计节点数量。如果收到的是空指针，说明这部分没有节点，返回零。否则，当前节点算一个，再加左子树的节点数和右子树的节点数。请把空指针的判断放在读取成员之前，否则还没确认节点存在，就已经访问了它。对于图里的七个节点，函数最后返回七。整棵树中，每个真实节点都会被处理一次，因此时间是线性级别。额外空间主要来自同时存在的递归调用，通常与树的高度有关；如果树几乎退化成一条长链，调用层数也会明显增多。写递归时，先找停止条件，再检查每次是否走向更小的子问题。

```cpp
int countNodes(Tree* p) {
    if (!p) return 0;
    return 1 + countNodes(p->left)
             + countNodes(p->right);
}
```

运行结果：
```text
7
```

画面要点：空树返回 0；当前 1＋左边＋右边；递归深度取决于树高

### 06-03 三种深度遍历看访问根的时机

前序、中序、后序这些名字，可以先围绕一个问题来记：什么时候访问当前这棵树的根。前序是先访问根，再处理左子树和右子树。中序是先处理左子树，再访问根，最后处理右子树。后序则把根放到两个子树之后。屏幕中的中序函数先递归左边，再打印当前值，最后递归右边。对子树也采用相同规则，整个过程才能连起来。图里从最左侧的二开始，接着四、六、八、十、十二、十四。这里得到从小到大的顺序，还依赖这棵树另外满足搜索树的大小规则；不是任意二叉树做中序遍历，都一定会排序。把遍历规则和数据的排列规则分开，能避开一个很常见的误解。

```cpp
void visitInorder(Tree* p) {
    if (!p) return;
    visitInorder(p->left);
    cout << p->value << " ";
    visitInorder(p->right);
}
```

运行结果：
```text
2 4 6 8 10 12 14
```

画面要点：前序：根、左、右；中序：左、根、右；后序：左、右、根

### 06-04 二叉搜索树按比较结果选择方向

二叉搜索树在二叉树的基础上，再加一个大小约定。本课示例不保存重复键：一个节点左子树中的值都比它小，右子树中的值都比它大。要找十，从根八开始比较，十更大，向右走到十二；十比十二小，再向左走，就找到了十。代码每次只选择一边继续，不需要扫描另一整棵子树。如果一路走到空位置仍然没遇到目标，就说明不存在。请注意，大小规则针对整个左子树和整个右子树，不只是直接孩子。比如根八的左边，不能藏着一个十三，只因为它恰好比自己的父节点大，就说整棵树合法。理解了全局约束，才知道为什么每次比较都能安全排除另一边。

```cpp
bool contains(Tree* p, int target) {
    while (p) {
        if (target == p->value) return true;
        p = target < p->value ? p->left : p->right;
    }
    return false;
}
```

运行结果：
```text
true false
```

画面要点：本例不存重复键；左边全小，右边全大；比较一次，选择一个方向

### 06-05 树高决定搜索要走多远

搜索树的一次查找，最多要沿着一条根到叶子的路径走，所以代价与树高有关。节点分布比较均衡时，层数增长得慢，查找可以达到对数级别。但如果按一、二、三、四这样的顺序，简单地插入一棵没有平衡机制的搜索树，新节点可能一直出现在右边，最后看起来像一条链，查找就退化成线性级别。因此，不能看到二叉搜索树几个字，就保证所有操作都是对数时间。平衡搜索树会额外维护高度或颜色等信息，把树高控制住；标准库的有序关联容器提供对数级别操作，但不要求你在这节入门课里实现整套平衡机制。先牢牢记住：结构的名字说明规则，性能还取决于规则维护得怎样。

```cpp
Tree d{4,nullptr,nullptr};
Tree c{3,nullptr,&d};
Tree b{2,nullptr,&c};
Tree a{1,nullptr,&b};
int steps = 0;
for (Tree* p=&a; p; p=p->right) ++steps;
cout << steps << "\n";
```

运行结果：
```text
4
```

画面要点：查找代价与树高有关；失衡可能退化成一条链；不能无条件承诺 O(log n)

### 06-q 课堂练习：中序访问顺序

这次用一棵只有三个节点的小树。根是八，左孩子是四，右孩子是十二。请根据中序遍历的规则，预测打印顺序。别根据节点在代码里先声明还是后声明来猜，要根据树上的连接和函数里的执行顺序来判断。再想一个补充问题：如果把三个值随意交换位置，中序遍历还一定会从小到大吗。

### 06-a 答案：先左边，再根，最后右边

输出是四、八、十二。中序函数先处理左子树，打印四，再回到根打印八，最后处理右子树，打印十二。声明 left、right、root 的先后，并不会替代这套访问规则。如果只是交换节点保存的值，却不再满足搜索树的大小约束，中序遍历仍然按左、根、右进行，但输出未必有序。这道题要同时分清两件事：遍历决定访问次序，搜索树约束决定这些位置上的值满足怎样的大小关系。学习树的操作时，可以把纸上的当前节点圈出来，再按函数调用画返回箭头，不必一开始试图在脑中同时追踪所有递归层。下一种结构同样能画成树，却只维护局部的优先级关系，它就是堆。

## 堆与优先队列 · Heaps and Priority Queues

### 07-01 只需要快速得到最高优先级

有时我们不要求把所有成绩立刻排好序，只希望反复拿到当前最高分。这样的任务可以考虑堆。最大堆要求每个父节点的值，不小于自己的孩子，因此最大的值一定在根上。它还把节点从上到下、从左到右紧凑填满，形成完全二叉树，方便用数组保存。这里的堆是数据结构，不要和程序里分配动态内存时说的堆区混为一谈。C++ 的 priority_queue 默认把较大的值放在最高优先级，加入七十五、九十、八十二后，top 得到九十。移除它以后，结构会调整，让八十二成为新的最高优先级。优先队列不是普通队列的先到先处理，而是根据比较规则决定谁先出来。

```cpp
priority_queue<int> pq;
pq.push(75);
pq.push(90);
pq.push(82);
cout << pq.top() << "\n";
pq.pop();
cout << pq.top() << "\n";
```

运行结果：
```text
90
82
```

画面要点：最大堆：父节点不小于孩子；根保存当前最大值；优先级决定移除顺序

### 07-02 数组下标表示父子关系

完全二叉树可以按层从左到右放进数组，不需要每个节点都保存两个指针。采用从零开始的下标时，下标 i 的左孩子在二乘 i 加一，右孩子在二乘 i 加二；非根节点的父亲在 i 减一，再整除二的位置。屏幕数组依次保存九十、七十五、八十二、六十、六十五，因此下标一对应七十五，它的两个孩子是下标三和四，也就是六十和六十五。读取孩子之前，仍然要确认下标没有超出长度。堆的形状紧凑，插入新值时从末尾开始，必要时一路向上交换；移除根时把最后一个值移到根，再向下调整。每次主要沿一条树高方向的路径走，因此插入和移除通常需要对数级别的调整工作。

```cpp
vector<int> heap{90, 75, 82, 60, 65};
int i = 1;
int left = 2*i + 1, right = 2*i + 2;
cout << heap[left] << " " << heap[right];
cout << "\n";
cout << (i - 1) / 2 << "\n";
```

运行结果：
```text
60 65
0
```

画面要点：左孩子：2i＋1；右孩子：2i＋2；非根父节点：(i−1)/2

### 07-03 堆不是完整排序的数组

堆只要求父节点与孩子之间满足优先级关系，并没有要求整个底层数组从左到右有序。比如九十、七十五、八十二就是合法最大堆的开头，虽然七十五出现在八十二前面。如果想得到完整的降序结果，可以反复读取堆顶再移除，但这会逐步消耗容器里的元素。屏幕把三个值全部取出，顺序是九十、八十二、七十五。仅查看堆顶通常是常数代价，插入和移除堆顶通常是对数代价。要查询一个任意值是否存在，普通堆没有搜索树那种按大小选择左右方向的规则，不能直接照搬搜索树的查找方法。选择工具时，先问自己是要任意查找、完整排序，还是不断取得当前最优先的一个元素。

```cpp
priority_queue<int> pq;
for (int x : {75, 90, 82}) pq.push(x);
while (!pq.empty()) {
    cout << pq.top() << " ";
    pq.pop();
}
cout << "\n";
```

运行结果：
```text
90 82 75
```

画面要点：堆数组不等于排序数组；top 通常 O(1)；插入、移除堆顶 O(log n)

### 07-q 课堂练习：新元素的优先级

优先队列先加入四、九、六，移除一次堆顶，再加入八，最后读取堆顶。请按操作顺序预测最终输出，不要只对最后加入的值下结论。注意这里使用默认比较规则，较大的整数优先；如果换成普通队列，行为会不同。先把移除发生时，容器里最大的值写出来，再处理后面的插入。

（四秒思考；随后核对答案）

```cpp
priority_queue<int> pq;
for (int x : {4, 9, 6}) pq.push(x);
pq.pop();
pq.push(8);
cout << pq.top() << "\n";
```

运行结果：
```text
8
```

画面要点：默认较大的整数优先；pop 移除了哪一个？；再比较新加入的 8

### 07-a 答案：先移除九，再得到八

最终输出八。最初九的优先级最高，第一次 pop 移除的是九，剩下四和六。加入八之后，八比剩下的值都大，所以成为新的堆顶。这里不需要先知道四和六在底层数组中的具体布局，只要使用优先队列的规则，就能判断结果。也不要把 pop 想成删除最近加入的六，那是把栈的规则带进来了。我们已经看过几种不同的先后关系：数组强调位置，栈强调最近加入，队列强调最早加入，优先队列强调比较规则。如果需求发生变化，合适的结构也会跟着变化。下面处理的关系更一般，不再只是排成一列或者逐层分支，而是多个地点之间互相连接，这就进入了图。

```cpp
priority_queue<int> pq;
for (int x : {4, 9, 6}) pq.push(x);
pq.pop();
pq.push(8);
cout << pq.top() << "\n";
```

运行结果：
```text
8
```

画面要点：第一次移除 9；剩下 4、6，再加入 8；新的堆顶是 8

## 图与图的遍历 · Graphs and Traversals

### 08-01 地点和道路构成连接关系

现在想象一张校园地图。图书馆、教学楼和食堂可以看成地点，地点之间的道路表示连接。在图里，地点叫顶点，连接叫边。前面学的树强调层次，图则允许更一般的连接，例如同一个地点从多条路线都能到达，也可能绕一圈回到起点。道路只能单向通行时，可以用有向边；双向通行可以用无向边。边还可以附带距离或者时间，这叫权重。我们接下来的例子采用五个地点和无向边，每条边只表示可以直接走过去，不附带不同距离。先统一这个约定，后面才能准确讨论最少经过几条边。不要把图的数据结构和屏幕上的图片混为一谈，同一张逻辑地图可以画成不同形状，连接关系才是关键。

```cpp
vector<vector<int>> g{{1,2},{0,3},{0,3},
                      {1,2,4},{3}};
for (int v : g[0])
    cout << char('A' + v) << " ";
cout << "\n";
```

运行结果：
```text
B C
```

画面要点：顶点表示对象，边表示连接；本课例子是无权无向图；A 到 B、C 有直接连接

### 08-02 邻接表与邻接矩阵

怎样把连接关系放进程序里。邻接表给每个顶点保存一份邻居清单。这里编号零代表 A，清单里的一和二表示 B 和 C。无向图中，一条连接通常会在两端的清单中各出现一次，所以统计清单项数，会得到边数的两倍。邻接矩阵则准备一个顶点数乘顶点数的表格，用某个格子记录两点是否相连。矩阵适合直接检查一对地点有没有边，但地点很多、道路很少时，很多格子都是空的。邻接表保存顶点入口和实际连接，空间通常是顶点数加边数的量级；矩阵通常需要顶点数平方的空间。选择哪一种，要看图有多稠密，以及主要做什么查询。为了方便遍历，我们接下来使用邻接表。

```cpp
vector<vector<int>> g{{1,2},{0,3},{0,3},
                      {1,2,4},{3}};
int entries = 0;
for (const auto& list : g) entries += list.size();
cout << g.size() << " " << entries / 2 << "\n";
```

运行结果：
```text
5 5
```

画面要点：邻接表保存实际邻居；本图有 5 个顶点、5 条边；无向边在清单中出现两次

### 08-03 广度优先：先近后远地展开

从 A 出发，先看与 A 一步可达的地点，再看需要两步、三步才能到达的地点，这就是广度优先的基本想法。它使用队列：最早发现、还没处理的地点，先取出来继续展开。代码先把 A 标记为已发现并入队，然后不断取队头，检查它的邻居。遇到没见过的邻居，立刻标记并入队。为什么在入队时就标记，因为同一个地点可能被不同的路同时发现，若一直等到出队才标记，就可能重复进入队列。按照屏幕清单中的邻居顺序，访问顺序是 A、B、C、D、E。改变同一层邻居的排列，具体访问顺序可能变化，但先处理较近层的性质不变。使用邻接表时，整个遍历的工作量与顶点和边的总数同一个量级。

```cpp
queue<int> q;
vector<int> seen(5);
seen[0]=1; q.push(0);
while (!q.empty()) {
    int u=q.front(); q.pop();
    cout << char('A'+u) << " ";
    for (int v : g[u]) if (!seen[v]) {
        seen[v]=1;
        q.push(v);
    }
}
cout << "\n";
```

运行结果：
```text
A B C D E
```

画面要点：使用队列按发现顺序处理；入队时就标记已发现；邻接表遍历：O(V＋E)

### 08-04 无权图里的最少边数

广度优先还有一个重要用途：在每条边代价相同的图里，求从起点到各点最少经过多少条边。把起点距离设为零，从一个已知地点发现新邻居时，新距离就是当前距离加一。由于队列先处理较近的层，第一次发现某个地点时，就已经找到了最少边数。图中 A 到 D 可以经过 B，也可以经过 C，都是两条边；再到 E，要多走一条，所以是三。这里初始的负一表示尚未到达，不是道路长度为负。请特别注意结论的条件：如果道路有不同时间或距离，最少边数不一定等于总路程最短，不能直接把普通广度优先的结论套过去。先问清楚每条边代表什么，再选择算法。

```cpp
vector<int> dist(5, -1);
queue<int> q;
dist[0]=0; q.push(0);
while (!q.empty()) {
    int u=q.front(); q.pop();
    for (int v : g[u]) if (dist[v]==-1) {
        dist[v]=dist[u]+1;
        q.push(v);
    }
}
cout << dist[4] << "\n";
```

运行结果：
```text
3
```

画面要点：起点距离是 0；首次发现时设置距离；只在等代价边下求最少步数

### 08-05 深度优先：沿一条路先走下去

深度优先采用另一种策略，沿着当前道路继续走，直到没有尚未访问的邻居，再返回上一层，尝试别的路。递归调用可以帮助保存这条尚未走完的路径。函数一开始先标记当前地点，然后依次递归没见过的邻居。按照这里的邻接表顺序，从 A 会先到 B，再到 D，接着 C，回到 D 后再到 E。因为图里可能有环，已访问标记不能省，否则沿道路绕回去，就可能反复递归。深度优先可以用来检查可达性、寻找连通部分，也常作为更复杂图算法的基础，但它找到的第一条路径，不保证是边数最少的路径。使用邻接表时，遍历同样是顶点数加边数的量级；递归太深还要注意调用栈的空间限制。

```cpp
void dfs(int u, vector<int>& seen) {
    seen[u]=1;
    cout << char('A'+u) << " ";
    for (int v : g[u])
        if (!seen[v]) dfs(v, seen);
}
```

运行结果：
```text
A B D C E
```

画面要点：先沿当前路径深入；访问标记防止绕环重复；第一条路径不保证最短

### 08-q 课堂练习：到 E 最少走几条边

仍然使用这一张无权无向图。A 连接 B、C，B 和 C 都连接 D，D 连接 E。从 A 到 E，最少需要经过几条边。请画出一条路线，并判断用队列逐层展开，还是沿任意一条路深走，就能保证首次得到最少边数。这里问的是边的数量，不是访问到 E 之前总共打印过几个顶点。

（四秒思考；随后核对答案）

// A=0, B=1, C=2, D=3, E=4
// A-B, A-C, B-D, C-D, D-E

画面要点：数的是边，不是顶点；写出 A 到 E 的一条路线；所有边的代价相同

### 08-a 答案：三条边，逐层确定距离

答案是三，例如 A 到 B，再到 D，最后到 E。路线经过四个顶点，但连接它们的是三条边。广度优先先确定一步可达的 B 和 C，再确定两步可达的 D，最后确定三步可达的 E。D 虽然可能通过 B 或 C 发现，只要在首次入队时做好标记，就不必重复加入队列。注意，哪一条三步路线被先记录下来，可能依赖邻居的排列，但最少边数仍然是三。深度优先也可能碰巧先找到这条路线，却不能因此推广成它总会先找到最短路。分析算法时，要区分某次运行恰好成功，以及根据处理规则可以保证什么。至此，数组、链、树和图几种组织关系已经串起来，下面再看在有序数据中怎样减少查找范围。

```cpp
// A=0, B=1, C=2, D=3, E=4
// A-B, A-C, B-D, C-D, D-E
cout << hops(0, 4) << "\n";
```

运行结果：
```text
3
```

画面要点：A→B→D→E：3 条边；BFS 先处理距离较近的层；首次入队就应标记

## 二分查找 · Binary Search

### 09-01 先有顺序，才能排除一半

二分查找最适合从一个已经有序的范围中定位目标。看中间值，如果它小于目标，那么它左边以及它自己，都不可能是第一个不小于目标的位置，可以整体排除。反过来，中间值不小于目标，就保留它以及左边的候选位置。每次排除一大块范围，这就是前面讲过的连续减半。这里的数据已经从小到大排列，目标二十七位于下标四。请不要把一排没有排序的成绩直接交给二分查找，再期待可靠结果。为了一次查询先把全部数据排好序，也要把排序代价算进去；如果之后会在同一批有序数据上查很多次，前面的准备就更可能值得。选算法时，既要检查输入前提，也要看整个任务，而不只是最后那段短循环。

```cpp
vector<int> a{3,8,12,20,27,31,40};
cout << findIndex(a,27) << "\n";
cout << findIndex(a,9) << "\n";
```

运行结果：
```text
4
-1
```

画面要点：本例要求从小到大有序；每次排除一部分范围；查询步骤为 O(log n)

### 09-02 用左闭右开统一边界

二分查找最容易出错的地方，是边界含义写着写着变了。这份实现使用左闭右开区间，lo 对应的位置还在范围里，hi 对应的位置不在范围里。起初范围是零到数组长度之前。只要 lo 小于 hi，就还有候选位置。中间值小于目标时，mid 自己也不能作为答案，于是 lo 移到 mid 加一。否则把 hi 移到 mid，保留 mid 这个候选位置。循环结束时，lo 和 hi 相遇，lo 是第一个不小于目标的位置；还要检查它是否越界，以及值是否真的等于目标。中点用左边加上差的一半，避免直接把两个大下标相加。遇到重复值时，这个版本会返回目标第一次出现的位置，因为相等时仍然保留左边的候选范围。

```cpp
int findIndex(const vector<int>& a, int target) {
    int lo=0, hi=static_cast<int>(a.size());
    while (lo < hi) {
        int mid=lo+(hi-lo)/2;
        if (a[mid] < target) lo=mid+1;
        else hi=mid;
    }
    if (lo < static_cast<int>(a.size())
        && a[lo] == target) return lo;
    return -1;
}
```

运行结果：
```text
4
```

画面要点：区间是 [lo, hi)；每次更新都必须缩小范围；退出后还要验证目标存在

### 09-03 空数组与重复值也要验证

一个查找函数不能只在普通例子上看起来正确。空数组时，初始左右边界都是零，循环应该直接跳过，不能读取第零个元素。目标比所有元素都大时，最终位置可能等于数组长度，所以也要先检查边界，再读取数值。这里使用逻辑与的短路规则，让越界检查挡在前面。再看重复值，数组是一、二、二、二、五，查找二会返回下标一，也就是第一个二。这是本实现明确采用的行为，不是所有二分查找写法都必须返回同一个重复位置。验证时，可以把空输入、只有一个元素、目标不存在，以及目标出现在边界的情况都试一遍。先把约定写清楚，再检查这些边界，比反复背一段看似熟悉的模板更有用。

```cpp
vector<int> empty;
vector<int> a{1,2,2,2,5};
cout << findIndex(empty,2) << "\n";
cout << findIndex(a,2) << "\n";
cout << findIndex(a,9) << "\n";
```

运行结果：
```text
-1
1
-1
```

画面要点：空数组应返回未找到；本实现返回第一个匹配位置；先检查边界，再读取元素

### 09-q 课堂练习：查找重复的二

继续使用左闭右开、寻找第一个不小于目标位置的实现。数组是一、二、二、二、五，查找二，最后返回哪个下标。请特别留意相等时，我们让右边界向左收，而不是立刻返回当前中点。也可以把每一步的 lo、hi、mid 写成三列，检查候选范围有没有严格缩小。

（四秒思考；随后核对答案）

```cpp
vector<int> a{1,2,2,2,5};

```

运行结果：
```text

```

画面要点：相等时继续保留左边；本版本寻找第一个位置；从 0 开始数下标

### 09-a 答案：返回第一次出现的位置

输出一。初始区间是零到五之前，中点下标二，值等于二，于是把右边界收缩到二。接着中点下标一，也等于二，右边界继续收缩到一。最后检查下标零，值是一，小于目标，左边界移到一。左右边界相遇，得到下标一，再验证这里确实是二。整个过程中，我们始终没有丢掉第一个目标位置，也始终让范围变小。这就是边界约定的价值。另一种遇到相等就立即返回的写法，也可能是合法二分查找，但它没有承诺返回第一个重复位置。写程序时不要把两种约定混在一起。接下来看看有序数据从哪里来，也就是排序。

```cpp
vector<int> a{1,2,2,2,5};
cout << findIndex(a,2) << "\n";
```

运行结果：
```text
1
```

画面要点：依次检查下标 2、1、0；边界最后在 1 相遇；结果验证后返回 1

## 基础排序 · Sorting

### 10-01 选择排序：每轮找一个最小值

先看一种容易手工推演的排序。选择排序每一轮，从还没排好的部分找最小值，把它放到这一轮的开头。第一轮确定第零个位置，第二轮确定第一个位置，依次向后推进。屏幕上的五、二、四、一，第一轮先找出一，再与最前面的五交换。要特别区分当前候选最小位置 best 和当前扫描位置 j，发现更小值时，更新的是候选位置，而不是立即结束扫描。外层每推进一格，内层仍然要查看后面的一段，比较次数累加起来是平方级别。即使数据原来已经有序，这个简单版本通常仍然做差不多数量的比较。它的优点是思路直观，适合练习下标和循环；实际处理大量数据时，我们还有更高效的选择。

```cpp
vector<int> a{5,2,4,1};
for (int i=0; i<(int)a.size(); ++i) {
    int best=i;
    for (int j=i+1; j<(int)a.size(); ++j)
        if (a[j]<a[best]) best=j;
    swap(a[i],a[best]);
}
for (int x:a) cout << x << " ";
cout << "\n";
```

运行结果：
```text
1 2 4 5
```

画面要点：每轮确定一个最小值；best 保存候选位置；比较次数通常是 O(n²)

### 10-02 插入排序：把新元素插进有序部分

插入排序可以想成整理手中的纸牌。左边已经有序，拿起右边的下一张牌，把比它大的牌向后挪，最后把它放进空出的合适位置。这里先用 key 保存当前值，否则向后移动时，可能把它原来的位置覆盖。j 从前一个元素开始往左看，只要还没越过边界，而且那个元素大于 key，就继续右移。循环结束以后，空位在 j 加一，不一定就是 j 本身。最坏情况下，例如原来接近倒序，需要大量移动，代价是平方级别。但如果原来已经有序，这个版本每轮很快就能停止，整体接近线性。可见同一种算法，在不同输入上也可能表现不同；描述性能时，要说清楚是在讨论最坏情况还是某类输入。

```cpp
vector<int> a{5,2,4,1};
for (int i=1; i<(int)a.size(); ++i) {
    int key=a[i], j=i-1;
    while (j>=0 && a[j]>key) {
        a[j+1]=a[j];
        --j;
    }
    a[j+1]=key;
}
for (int x:a) cout << x << " ";
cout << "\n";
```

运行结果：
```text
1 2 4 5
```

画面要点：左边始终保持有序；先保存 key，再移动元素；已排序输入可能更省工作

### 10-03 归并排序：先分开，再合并

归并排序先把范围分成两半，分别排好序，再把两段有序数据合成一段。代码中的停止条件是范围里最多只有一个元素，这种情况本来就有序。合并时，只需比较两段尚未取出的第一个元素，先取较小的那个；一段取完，就接上另一段的剩余部分。完整示例里的合并函数会使用临时数组，工作量与本轮合并的元素总数成正比。每一层合并，总共处理的仍然是这批元素，而分成两半的层数是对数级别，所以常见归并排序的时间是 n 乘 log n。代价是通常需要线性大小的辅助存储。这里遇到相同值时先取左段，有助于保留原先的相对顺序。我们下一页会比较另一种划分数据的思路。

```cpp
void mergeSort(vector<int>& a, int l, int r) {
    if (r-l <= 1) return;
    int mid=l+(r-l)/2;
    mergeSort(a,l,mid);
    mergeSort(a,mid,r);
    mergeRange(a,l,mid,r);
}
```

运行结果：
```text
1 2 4 5
```

画面要点：两半分别排序；线性合并两个有序段；常见实现：O(n log n)

### 10-04 快速排序的核心是划分

快速排序先选一个基准，把较小的元素放到一边，另一边保存其余元素，再分别处理两边。这里演示的是一次划分，不是整次排序。选择最后的四作为基准，把二和一移到前面，最后让四落到它本轮确定的位置。注意，二和一这段还没有内部排好，所以一次划分后，不代表整个数组已经有序。划分比较均衡时，重复处理能得到平均 n 乘 log n 的时间表现。但如果反复出现极不均衡的划分，简单实现的最坏情况可能退化到平方级别。选择基准和处理坏情况的方法，会明显影响实际效果。不要把学习划分思想，和猜测某个标准库版本内部到底用了哪种完整实现混在一起，我们随后会直接按标准库给出的保证来使用 sort。

```cpp
int partitionOnce(vector<int>& a, int l, int r) {
    int pivot=a[r-1], i=l;
    for (int j=l; j<r-1; ++j) {
        if (a[j]<pivot) swap(a[i++],a[j]);
    }
    swap(a[i],a[r-1]);
    return i;
}
```

运行结果：
```text
2
2 1 4 5
```

画面要点：本页只做一次划分；基准 4 落到下标 2；左右两段还需分别处理

### 10-05 日常排序使用标准库接口

理解了几种基本思路后，实际写程序通常可以直接使用标准库 sort。它接收一个左闭右开的范围，默认按从小到大排列。屏幕里的 begin 和 end，分别表示范围的开始，以及最后一个元素之后的位置。对于通常的顺序版本，标准要求比较次数为 n 乘 log n 的量级，不能简单把它等同于一个没有坏情况保护的朴素快速排序。排序后，原来某个下标上的值可能已经改变，所以如果还需要原始顺序，应当先保存副本，或者把原始位置作为数据的一部分一起保存。这里再次看到，选择标准库接口并不意味着完全不用理解算法，恰恰是知道它的输入条件、可观察行为和性能保证，才不容易误用。

```cpp
vector<int> a{5,2,4,1};
sort(a.begin(), a.end());
for (int x : a) cout << x << " ";
cout << "\n";
```

运行结果：
```text
1 2 4 5
```

画面要点：范围是 [begin, end)；默认按从小到大排序；sort 不保证保留相等项顺序

### 10-06 稳定性：相等项是否保持原顺序

假设三个记录依次是 A 八十分、B 七十分、C 八十分，只按分数排序。排序后，B 应该在前面，但同为八十分的 A 和 C，谁先谁后呢。如果仍然保留它们原来的相对顺序，就叫稳定排序。这里使用 stable_sort，并且比较规则只看分数，所以结果是 B、A、C。普通 sort 不保证相等项保持原顺序，即使某次运行碰巧没变，也不能当成接口承诺。稳定性说的是相等关键字记录的先后，不是程序会不会崩溃，也不是排序结果会不会随便乱掉。比较函数这里使用严格的小于；把相等也判成小于，不是让排序更完整，反而会破坏比较规则应满足的条件。排序前先说清楚按什么比较，以及相等时有没有额外要求。

```cpp
vector<Student> a{{"A",80},{"B",70},{"C",80}};
stable_sort(a.begin(), a.end(), lowerScore);
for (const Student& s : a)
    cout << s.name << ":" << s.score << " ";
cout << "\n";
```

运行结果：
```text
B:70 A:80 C:80
```

画面要点：相等分数仍保持 A 在 C 前；stable_sort 保证稳定性；比较规则使用严格小于

### 11-02 组合工具，完成一段成绩统计

看一个小程序，把几种工具自然地放在一起。动态数组保存输入顺序，哈希表统计每个成绩出现几次，优先队列帮助我们取最高的两个成绩。先扫描所有成绩，每个成绩的计数加一，同时放入优先队列。八十分一共出现两次，所以第一项输出是二。接着读取并移除最高分九十五，再读取下一项九十。注意这里保留重复成绩，如果两个同学同得九十五，两份成绩会分别占据位置；如果题目要求不同分数中的前两名，就必须先改变去重规则。程序看起来不长，但结构各自承担的任务很明确。学习数据结构的一个实际目标，就是把大需求拆成几个清楚的小操作，再用合适的容器组合起来。

vector<int> scores{80,95,80,72,90};

for (int x:scores) {
    ++frequency[x];

```

```

### 11-a 答案与课后练习路线

第一项可以优先考虑最大优先队列。它把当前最大值放在堆顶，查看很方便，插入和移除通常只需沿树高调整，没有必要为了拿出一个最大值，每次都重新把全部记录排好序。第二项是按姓名定位记录，普通堆没有提供这种高效任意查找保证，可以再维护姓名到成绩的映射，并明确两份数据怎样保持一致。今天你已经接触到数据结构的主要骨架。课后建议按三个层次练习：先用小数据在纸上推演，再运行程序核对结果，最后自己补上空输入、边界和重复值的测试。优先把动态数组、链表接链、栈和队列、二分查找以及图的遍历写熟，再继续学习平衡树和更多图算法。能解释每一步为什么正确，比只记住一张复杂度表更扎实。
