### x86-64：让3加上5

```asm
mov eax, 3
add eax, 5
ret
```

先看左侧第一条指令，把数值三送进EAX。EAX是一个三十二位寄存器视图，它与六十四位的RAX共享底层存储。这里的数据很小，用三十二位就足够表达。立即数直接写在指令中，寄存器名则说明目标位置。读这一行时，把来源、目标和位宽各指出一次。

再执行ADD，把五加到EAX原有的三，结果八写回同一个目标。随后RET把执行接续回调用者，本例按约定通过RAX给出整数结果。右侧状态卡来自这几条机器指令的逐步执行。先关注数据怎么变化，后面再展开函数入口和返回地址的细节。

本页总结：

- EAX是RAX的低32位视图。
- MOV把3写入EAX，ADD把5加到目标。
- 此例返回RAX=8，RET接续到调用者。
- Intel写法通常先写目标，再写来源。

### AArch64：用三操作数表达同一任务

```asm
mov x0, #3
add x0, x0, #5
ret
```

换成AArch六十四，先把三送入X零。X零是一个六十四位通用寄存器，后面的W零会表示同一位置的低三十二位。立即数前面的井号是这套语法的常见标记。名称虽然变了，第一步仍然是在一个明确的位置准备数据。

第二条ADD写出三个操作数：第一个X零接收结果，第二个X零提供原值，最后的五是另一个来源。因此它把三与五相加，再写回X零。相同任务可以采用不同指令形式。学习两套架构时，先对齐数据流，再记录语法与寄存器名称的差异，理解会更稳定。

本页总结：

- X0是64位通用寄存器，W0是其低32位视图。
- ADD X0,X0,#5明确写出目标和两个来源。
- #标记本课A64写法中的立即数。
- 结果X0=8，通过RET返回。

## 寄存器、位宽与数据表示

### RAX、EAX与AL的写入范围

```asm
mov rax, 0x1234567800001234
mov al, 0x56
mov eax, 7
ret
```

先把一份六十四位数放进RAX，低十六位是一二三四。再执行写AL的指令，只把最低八位改成五六，其他位置保留原来的位。这适合观察寄存器的不同视图：它们访问同一份存储，只是覆盖范围不同。读取结构字段或处理单个字节时，这些较窄视图仍然很有用。

第三条写EAX，把七放入低三十二位，同时让RAX高三十二位成为零。因此最终RAX就是七。把八位、十六位和三十二位写入的规则分别记清。看到EAX时，先标它操作的是三十二位数据，再依据整份代码的六十四位运行背景继续分析。

本页总结：

- RAX为64位；EAX为低32位；AL为低8位。
- 写AL保留其余位，本例低字节改为56h。
- 写EAX会把RAX高32位清零。
- 位宽选择与处理器运行模式分开记录。

### X寄存器与W寄存器

```asm
movz x0, #0x1234, lsl #48
movk x0, #0x5678, lsl #32
movk x0, #0x1234
mov w0, #7
ret
```

AArch六十四也提供六十四位与三十二位视图。这里用几条指令先在X零中准备一份较长的数，让高位有明确内容。X零与W零指向同一份寄存器存储，所以观察两者时，要同时记住共享关系与访问宽度。

随后把七写入W零，X零的高三十二位随之清零，最终X零也读成七。这与前一页写EAX的结果相似。对照学习时，可以把这类相同规则先放在一起，再单独记住两套指令的语法差异。后续读取三十二位数组元素时，还会用到这个扩展效果。

本页总结：

- X0与W0共享存储，分别提供64位和32位视图。
- MOVZ/MOVK可分段准备较长常数。
- 写W0会把X0高32位清零。
- 本例最终X0=7。

### A64怎样准备较长的常数

```asm
movz x0, #0x1234, lsl #48
movk x0, #0x5678, lsl #32
movk x0, #0x11
ret
```

A六十四的单条指令固定为三十二位，常数怎样编码要遵守对应指令的形式。这里先用MOVZ，把一二三四放到最高的十六位片段，其余位置清零。移位四十八位，表示这个片段从整个六十四位数的第几位开始放置。

接着MOVK把五六七八写入下一片段，并在最低片段写入一一，其他位置继续保留。最后得到屏幕上列出的完整数值。平时看到MOV这样的汇编写法，还要留意它可能是汇编器提供的别名或伪指令；读实际机器码时，再确认最终生成了哪种编码。

本页总结：

- MOVZ先写入一个16位片段，并清其余位。
- MOVK保留其他位置，只替换选定片段。
- LSL #48/#32表示该片段放入哪个位置。
- 本例组成1234567800000011h。

### 零寄存器与专用角色

```asm
mov x0, #9
mov xzr, x0
mov x1, #5
add x2, xzr, x1
ret
```

先把九送进X零，再把它写向XZR。XZR提供一个固定的零来源，写到这个目标的结果会被丢弃，所以X零仍保存九。这样的寄存器让清零、比较或忽略结果的指令形式更规整。接着把五放进X一，为后面的运算准备另一个来源。

最后让XZR与X一相加，结果五送进X二。分析时把零来源和普通可保存数据的寄存器区分开。AArch六十四还会在特定编码位置解释SP或零寄存器，写代码时使用指令支持的明确名称。本课的栈操作都采用SP，返回位置则通过X三十观察。

本页总结：

- 读取XZR得到0，向XZR写入的结果被丢弃。
- X0仍保存9，X2最终为5。
- SP保存栈位置，PC记录执行位置。
- 寄存器编号的具体解释由指令编码决定。

## 内存访问与地址计算

### x86-64的读取与写回

```asm
mov eax, [rdi]
add eax, 1
mov [rdi+4], eax
ret
```

RDI中放的是本例数据起点的地址。方括号表示按这个地址访问内容，目标EAX让这次读取的宽度成为四个字节。内存里的七八、五六、三四、一二按小端组合，得到一二三四五六七八。小端把数值的低字节放在较低地址。

加一以后，EAX变成一二三四五六七九。再把它写入RDI加四指向的位置，后面的四个字节就收到这份结果。记录内存题时，把地址列和数据列分开；读取会取得一份值，写回则改变目标位置。左下结果检查对应程序完整执行后的状态。

本页总结：

- RDI给出本例内存起点200000h。
- MOV EAX,[RDI]读取4字节。
- 加1后把结果写到起点后4字节。
- 内存按字节编址，本例采用小端数据。

### AArch64的Load与Store

```asm
ldr w0, [x1]
add w0, w0, #1
str w0, [x1, #4]
ret
```

AArch六十四把这个过程写得更明确。LDR先从X一指向的位置取出四字节数据，放进W零。随后ADD只处理寄存器和允许的立即数。先把读取和计算拆开，你就能直接看到数据在进入运算前经过了哪一步。

最后STR把W零保存到X一加四的位置。这个例子与前页完成同样任务，但使用了独立的加载和存储指令。对照两套代码时，先把读取、计算、写回三个动作排成相同顺序，再看哪些动作能由某条指令合并表达。

本页总结：

- LDR W0从X1指向的位置读取4字节。
- ADD在寄存器之间完成计算。
- STR W0把结果写回X1+4。
- 加载、运算、存储按三个动作追踪。

### x86-64的基址、下标与LEA

```asm
lea rax, [rdi+rsi*4+8]
mov ecx, [rax]
ret
```

数组元素的位置常由起点、下标和元素大小决定。这里RDI是起点，RSI为一，元素间距四字节，另外再加八字节。代入以后得到起点后十二字节的位置。LEA把计算结果交给RAX，适合观察地址表达式自身的结果。

接着MOV才按RAX指向的位置读取四字节，得到数组中的四十。地址计算与内存读取在两条指令里分别完成。遇到结构偏移和数组下标混合的形式，也按同样顺序处理：先写各项单位，算出字节偏移，再按访问宽度取值。

本页总结：

- 地址表达式为基址+下标×4+8。
- RDI=200000h，RSI=1，得到20000Ch。
- LEA保存计算出的地址，随后MOV读取内容。
- 本例该位置的32位元素为40。

### A64的移位变址与偏移

```asm
add x2, x0, x1, lsl #2
ldr w3, [x2, #8]
ret
```

A六十四先用ADD配合左移，计算起点加下标乘四。下标左移两位，在这个非负下标例子中就对应乘四字节的元素间距。X二保存起点后四字节的地址，方便后续继续组合其他固定偏移。

LDR再使用X二加八的地址，读取四字节到W三，最终得到四十。A六十四的访存形式有各自允许的立即数和变址组合，写代码时按对应指令的规则选择。这两页的重点是把所有偏移换成字节，并把保存地址的寄存器与接收数据的寄存器分别记录。

本页总结：

- LSL #2把下标乘4。
- ADD先形成基址+下标×4。
- LDR再加8字节偏移并读取W3。
- 地址与结果分别为200004h和40。

### x86-64的零扩展与符号扩展

```asm
movzx eax, byte [rdi]
movsx rdx, byte [rdi]
ret
```

内存只有一个字节八零，它按无符号解释是128，按八位补码解释是负128。先用MOVZX读取这个字节并补零，EAX接收128，写EAX又把RAX的高位清零。这样得到的六十四位值仍表示无符号的128。

再用MOVSX把同一个字节扩展到RDX。最高位为一，所以高位复制为一，整个六十四位结果表示负128。原始字节保持相同，变化的是我们选择的解释与扩展规则。读取字符、窄整数或结构字段时，把这一步明确写出来，后面的加法和比较才会沿用正确的数值。

本页总结：

- 同一字节80h可按无符号128或有符号−128解释。
- MOVZX补零，RAX得到128。
- MOVSX复制符号位，RDX得到64位−128。
- 扩展方式取决于数据类型和后续任务。

### AArch64的字节加载与扩展

```asm
ldrb w0, [x1]
ldrsb x2, [x1]
ret
```

A六十四直接把扩展方式写进加载指令。LDRB从内存取一个字节，按补零方式放入W零，结果为128。W零写入后，X零的高三十二位也清零，所以读取完整X零时仍然得到128。

LDRSB使用X二作为目标，把同一个字节按符号扩展到六十四位，得到负128。读题时同时圈出指令名称和目标寄存器宽度。仅看原始字节还不足以完成数值还原，加载方式和后续有符号或无符号操作也共同决定程序怎样使用它。

本页总结：

- LDRB W0读取字节并补零。
- LDRSB X2把字节符号扩展到64位。
- 本例分别得到128与−128。
- W目标与X目标还决定扩展到的宽度。

## 算术运算、位操作与条件码

### x86-64的加法与进位

```asm
mov eax, 0xffffffff
add eax, 1
ret
```

先让EAX的三十二位全为一。把它按无符号整数解释，就是这个宽度的最大值。加一后，完整数学结果需要第三十三位，寄存器保留低三十二位零，进位写入CF。这样可以同时观察保存下来的位串，以及运算产生的进位信息。

这次CF为一，ZF也为一，因为保存的结果等于零。有符号解释则把原来的全一看成负一，负一加一得到零，所以这里的OF为零。读标志题时先写位宽，再选无符号或有符号解释，最后分别核对目标值与所需标志。

本页总结：

- 按32位计算FFFFFFFFh+1。
- 低32位结果为0，CF=1，ZF=1。

## 比较、选择与循环

### x86-64的有符号与无符号关系

- write的调用号属于操作系统接口。
- Linux x64与A64的write号分别为1和64。
- 判断迁移程序时需要分别核对什么。

### 区分指令和系统调用号 · 答案

指令写法与行为由目标指令集规定，函数交接由ABI规定，系统调用号和系统调用参数则按目标操作系统接口准备。因此迁移时要分别核对计算指令、调用约定和系统服务，逐层完成对应。

本页总结：

- 指令集：寄存器与机器指令。
- ABI：函数参数、返回值与保护责任。
- OS接口：系统调用号与参数。
- 分层核对后再做实际运行验证。

## 双架构综合实践与回顾

### 给同一个任务写清输入输出

最后把前面的知识连成一个任务：接收数组起点与长度，同时求总和与最大值。每个元素是无符号三十二位，总和使用六十四位累计。先把累计值与最大候选清零，再在每轮完成读取、累加、比较和推进。

为了直观看到两个结果，本课这份内部示例明确约定双输出位置：x八六用RAX与RDX，A六十四用X零与X一。它们的输入仍按前面给定的基础整数规则准备。真实C结构体返回还要查对应ABI分类；当前先根据已经写清的任务接口核对功能。

本页总结：

- 输入为3个uint32_t元素：3、5、7。
- 用64位寄存器累计总和。
- 另一个寄存器保存当前无符号最大值。
- 本课双输出约定：x64用RAX/RDX，A64用X0/X1。

### x86-64：总和与最大值

```asm
xor eax, eax
xor edx, edx
test rsi, rsi
jz done
next: mov ecx, [rdi]
add rax, rcx
cmp rcx, rdx
cmova rdx, rcx
add rdi, 4
dec rsi
jnz next
done: ret
```

先看初始化与入口检查，RAX累计值为零，RDX最大候选为零，长度为零时直接返回。非零长度才读当前元素。三十二位加载把元素补零为六十四位来源，接着ADD更新总和，再比较当前元素和最大候选。

CMOVA在无符号大于成立时更新最大值，相等或较小时继续保留。指针加四，计数减一，所有路径都推进到下一轮。输入三、五、七时，总和依次为三、八、十五，最大值依次为三、五、七。最后RAX为十五，RDX为七。

本页总结：

- RAX累计，RDX保存最大候选。
- 每轮用ECX读取uint32_t并补零。
- CMOVA按无符号大于决定是否更新最大值。
- 完整结果：总和15，最大值7。

### A64：相同任务与不同指令组织

```asm
mov x2, #0
mov x3, #0
cbz x1, done
next: ldr w4, [x0], #4
add x2, x2, x4
cmp x4, x3
csel x3, x4, x3, hi
subs x1, x1, #1
b.ne next
done: mov x0, x2
mov x1, x3
ret
```

A六十四先把X二和X三清零，并检查长度。每轮LDR读取W四，然后推进指针；X二加上这个零扩展后的元素，再让当前值与X三比较。这里用CSEL在无符号大于条件下选择新的候选，否则选回旧值。

SUBS更新剩余数量，B点NE控制下一轮。结束后把总和复制到X零，把最大值复制到X一。三、五、七最终得到十五与七。对照两页，算法步骤完全可以逐项对应：入口、读取、累计、候选更新、推进和返回。

本页总结：

- X2累计，X3保存最大候选。
- LDR W4后变址读取并推进指针。
- CSEL按HI条件更新候选，SUBS提供循环条件。
- 结束时X0=15，X1=7。
