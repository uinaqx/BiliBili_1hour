## 课程导学与程序结构

### go-01-01 课程知识总览

同学们好，欢迎来到一小时学习 Go 基础语法。这一页列出了本课要掌握的内容。我们先认识变量、常量和数据类型，知道怎样保存姓名与成绩。再用运算符完成计算，通过输入输出和使用程序的人交流。接着用分支处理不同情况，用循环重复执行步骤。数组与切片保存一组数据，映射和字符串帮助我们查询信息、处理文字。

在这些基础上，我们会用函数组织步骤，认识多返回值和延迟执行；再通过指针与结构体理解怎样传递和修改数据。最后认识方法、接口和包，学习 Go 怎样明确处理错误，并把知识连成一个学生成绩小程序。课程从零开始，每次先看具体代码和运行结果，再总结规则。遇到练习先预测，四秒后一起核对。先把基础语法走清楚，再学习并发和网络开发。

画面要点：变量、常量、类型与输入输出；分支循环、数组切片、映射字符串；函数、指针结构体、方法接口与错误

### go-01-02 第一个 Go 程序

先看一个完整的小程序。第一行说明这份文件属于 main 包，main 包用于构建可以启动执行的程序。包可以先理解为把相关代码组织在一起的方式。第二行引入 fmt，它是 Go 自带的工具包，提供显示文字等功能。这里不是随便给程序加两句装饰，而是在说明代码属于哪里，以及接下来要使用哪一套现成工具。

func 表示定义函数，main 是程序开始执行的位置。大括号里的 Println 会显示括号中的内容，并在输出后换行。所以结果是你好，Go，双引号本身不会显示。源文件通常以点 go 结尾。本课把这份文件叫 main.go。平时每条语句放一行，不需要自己在行尾加分号；函数这一行的左大括号要和函数头放在同一行，不要按其他语言习惯另起一行。

```go
package main
import "fmt"
func main() {
    fmt.Println("你好，Go")
}
```

预期结果：
```text
你好，Go
```

画面要点：package 声明所属的包；import 引入需要的工具；main 函数是启动入口

### go-01-03 练习：文字还是计算

请预测这个程序会显示几行，每一行是什么。第一句使用 Print，第二句使用 Println，最后一句的算式没有放在双引号里。先不要根据源代码有几行，就判断结果也一定有几行。需要分别考虑输出以后是否换行，以及小括号里面究竟是文字还是要计算的数值。现在独立想四秒。

（四秒独立思考，答案在下一页揭晓）

```go
func main() {
    fmt.Print("你好")
    fmt.Println("，小林")
    fmt.Println(80 + 5)
}
```

画面要点：Print 输出后不自动换行；引号区分文字与算式

### go-01-04 答案：按顺序执行每一步

前两句合起来显示你好，小林。Print 只负责输出，后面的 Println 接在同一行继续输出，然后才换行。程序会按这里写出的顺序执行，不会自己调换两次输出。你可以把第一句也改成 Println，看看问候语怎样分到两行。看结果有变化，再回头解释哪条规则造成变化，是很好的入门练习方法。

最后显示八十五。没有引号的加法会先计算，再交给输出函数；把整个算式放进双引号，就只是显示文字。这份程序可以使用 go run main.go 运行，也可以先用 go build 构建，再启动生成的程序。代码格式可以交给 gofmt 整理，但格式工具不会替你改正业务逻辑。以后读每个例子，都先问它保存什么、执行哪些步骤、最后得到什么结果。

```go
func main() {
    fmt.Print("你好")
    fmt.Println("，小林")
    fmt.Println(80 + 5)
}
```

预期结果：
```text
你好，小林
85
```

画面要点：先执行前面的语句；无引号的算式先计算；运行、构建与格式整理各有用途

## 变量常量与数据类型

### go-02-01 给数据起一个名字

假设程序要多次使用一个学生的姓名和成绩，每次直接写小林和八十，很难看出数据的用途。我们可以给它们起名字。var 表示声明变量，后面先写变量名，再写类型，等号右边是最初保存的值。name 保存姓名，score 保存成绩。等号在这里表示赋值，不是数学中要求左右两边永远相等的等式。

下面输出 name 和 score 时，没有给变量名加双引号，所以程序取出里面保存的内容，分别显示小林和八十。若写成引号里的 score，就只会显示这个英文单词。变量名尽量说明含义，例如总分、人数和平均分，不要全部用没有含义的单个字母。名字、类型和当前的值是三件不同的事，先把它们分清楚，后面读程序就容易很多。

```go
func main() {
    var name string = "小林"
    var score int = 80
    fmt.Println(name)
    fmt.Println(score)
}
```

预期结果：
```text
小林
80
```

画面要点：变量保存数据，名字表达用途；Go 把类型写在名字后面；使用变量名取出当前值

### go-02-02 类型推断与短变量声明

右边已经提供一个值时，Go 往往可以判断类型，所以 var name 后面省略了 string。函数里面还有一种常见写法：冒号加等号，同时声明变量并给它初始值。这里 score 根据八十被推断为整数类型。短变量声明只能写在函数内部，不能直接放在包的最外层。写得短不等于取消了类型检查。

第三个步骤把已有成绩改成八十五，用的是普通等号。因为我们是在更新已有变量，不是在同一层再声明一遍。Println 可以接收多个值，它会用空格把这里的姓名和成绩分开显示。初学时要特别留意有没有冒号：同样看起来是在给数据取名字，声明新变量和修改旧变量却不是同一个动作。这个差异在嵌套代码块里还会影响变量的作用范围。

```go
func main() {
    var name = "小林"
    score := 80
    score = 85
    fmt.Println(name, score)
}
```

预期结果：
```text
小林 85
```

画面要点：有初始值时可以推断类型；:= 在函数内声明并赋初值；= 修改已经存在的变量

### go-02-03 没有显式赋值时的零值

声明变量时，如果已经写明类型，也可以暂时不提供初始值。Go 会给它对应的零值。整数的零值是零，布尔值是 false，字符串是空字符串。这不是一块没有规则的随机内容。零值让许多简单数据可以先声明，再根据后续步骤更新，不过零值是不是符合业务含义，仍然需要你自己判断。

这里用格式化输出把三项放到一行。先观察结果：零、false 和一对空双引号。带引号的空字符串方便我们看出，它确实没有字符，而不是输出漏掉了。百分号后面的字母是输出格式，下一章会专门练习。现在先记住，零分可能是真实成绩，如果还需要表达尚未录入，就不能只靠一个默认的零来区分。

```go
func main() {
    var score int
    var passed bool
    var name string
    fmt.Printf("%d %t %q\n", score, passed, name)
}
```

预期结果：
```text
0 false ""
```

画面要点：整数、布尔、字符串各有零值；零值不是随机内容；零值不一定等于业务上的缺失

### go-02-04 常量表示不应改变的值

及格线通常是本次规则中的固定值，可以用 const 声明常量。这样写能告诉读者，这里不是准备在运行过程中反复修改的数据。比较成绩时使用 passScore，比在很多位置都直接写六十，更容易看清数字的含义。常量也不是只能保存数字，下面的消息文字同样可以声明为常量。

运行后先得到 true，再显示成绩已保存。常量不能像普通变量一样重新赋值，而且常量的值要满足编译期能够确定等规则，不能把任意一次函数调用的结果都随手变成 const。初学先使用明确的数字和文字常量，不展开常量表达式的细节。命名固定规则的好处，是以后修改需求时更容易找到应当调整的地方。

```go
func main() {
    const passScore = 60
    score := 85
    fmt.Println(score >= passScore)
    const message = "成绩已保存"
    fmt.Println(message)
}
```

预期结果：
```text
true
成绩已保存
```

画面要点：const 声明常量；常量不能重新赋值；固定规则应取有含义的名字

### go-02-05 常见基本类型

数据除了有名字，还分种类。人数常用 int 保存整数，平均分常用 float64 保存小数，是否及格用 bool 保存真或假。这里都依靠右边的值推断类型。带小数点的普通数值会推断成 float64，true 和 false 没有双引号，它们不是两段普通文字。类型帮助编译器判断哪些操作可以执行。

单引号里的 A 表示一个字符对应的码点值，这里推断为 rune。你会看到按字符方式显示是 A，按整数方式显示是六十五。rune 用来处理 Unicode 码点，后面字符串一章再结合中文解释。双引号则保存字符串。Go 还提供不同宽度的整数和浮点数，入门先把 int、float64、bool、string 与 rune 用清楚，不必第一次就背完所有名字。

```go
func main() {
    count := 3
    average := 86.5
    passed := true
    letter := 'A'
    fmt.Println(count, average, passed)
    fmt.Printf("%c %d\n", letter, letter)
}
```

预期结果：
```text
3 86.5 true
A 65
```

画面要点：int、float64、bool 用于常见数据；双引号表示字符串；rune 可表示 Unicode 码点

### go-02-06 转换与作用范围

三个人的总分是二百五十一，要算带小数的平均分，就先把两个整数转换成 float64，再进行除法。类型名后面的小括号，在这里表示转换。Go 不会在任意整数和小数之间都自动替你完成混合计算，要求不同类型配合时，要明确写出意图。转换得到新值，并不会永久改变原来 total 和 count 的类型。

结果带有小数。变量能在哪些位置使用，还受到它声明范围的限制。函数内部声明的普通局部变量，不能直接拿到另一个函数里用。Go 也会检查声明后没有使用的普通局部变量，所以随手保存一个值却一直不用，可能会阻止编译。不要为了绕过提醒就乱删代码，先判断这份数据是否真的需要，或者是不是漏掉了使用它的步骤。

```go
func main() {
    total := 251
    count := 3
    average := float64(total) / float64(count)
    fmt.Println(average)
}
```

预期结果：
```text
83.66666666666667
```

画面要点：参与计算前明确转换类型；转换不会改写原变量类型；局部变量有自己的使用范围

### go-02-07 练习：变量能随时换类型吗

这段程序想把分数换成评价文字。请判断它能不能通过编译。score 的声明没有直接写 int，是不是就意味着它以后可以保存任意类型？这里问的是能否编译，不是评价文字是否好看。请先确认最初的值让 Go 推断出了什么类型，再看第二次赋值是不是符合要求。

（四秒独立思考，答案在下一页揭晓）

```go
func main() {
    score := 80
    score = "优秀"
    fmt.Println(score)
}
```

画面要点：类型推断不等于没有类型；先判断能否通过编译

### go-02-08 答案：分数和评价分别保存

原题不能通过编译。score 根据初始值被推断为 int，并不是一个可以随时更换类型的容器。把文字直接赋给它，不符合这个变量的类型要求。左边展示一种更清楚的修正：分数仍然放在 score，评价另外放在 label。它们有不同含义，本来就适合分开保存。

现在输出八十和优秀。不要把 Go 的冒号等号理解成动态类型开关，也不要因为某个错误消失了，就认为业务建模一定正确。我们始终先看数据含义，再选择类型和操作。到这里，变量、常量、初始值、零值和类型转换已经有了具体印象。下一章让数据参与计算，并学习怎样把输入和输出写得更清楚。

```go
func main() {
    score := 80
    label := "优秀"
    fmt.Println(score, label)
}
```

预期结果：
```text
80 优秀
```

画面要点：原题是编译错误；变量的类型不会随意变化；不同含义的数据分开命名

## 运算符与输入输出

### go-03-01 常见运算与计算顺序

加减乘除让原来的数值得到新的结果。第一行先做九十乘二，再加八十，因为乘法通常先于加法。第二行用小括号要求先算括号里面，所以顺序不同。程序中的乘法使用星号，除法使用斜线。初学时不确定顺序，就加上表达意图的小括号，不要让读者靠猜测理解你的计算。

前两项分别得到二百六十和三百四十。最后的百分号在这里表示取余数，不是百分比。十七除以五，可以完整分成三组，还剩二，因此输出二。余数可以用于判断奇偶，或决定每隔几轮做一次事情。这里先使用非负整数理解含义；遇到负数和溢出等情况，还要另外核对规则。先说清每一步正在计算什么，比看到错误就随便换符号更有效。

```go
func main() {
    total := 80 + 90*2
    grouped := (80 + 90) * 2
    fmt.Println(total)
    fmt.Println(grouped)
    fmt.Println(17 % 5)
}
```

预期结果：
```text
260
340
2
```

画面要点：先乘除，后加减；括号明确计算顺序；百分号在这里表示余数

### go-03-02 比较与逻辑运算

程序可以比较两个值，得到真或假的结果。成绩是否至少六十，就是一个比较。判断相等使用两个等号，赋值则使用一个等号，两者作用不同。这里的比较不会修改成绩，而是在提出一个问题。真假结果可以直接输出，也可以交给后面要学的条件判断。Go 的条件需要明确的布尔值，不能随便拿整数代替真假。

两个与号表示并且，两边都为真才成立。两个竖线表示或者，至少一边为真就成立。感叹号把真假反过来。这里成绩及格，而且到场，所以第二条也为真；没有不及格，也没有缺席，所以最后为假。条件太复杂时，可以先分别保存几个有意义的小条件，再把它们组合。看得懂每个小问题，比把所有逻辑挤成一大行更容易排查。

```go
func main() {
    score := 85
    attended := true
    fmt.Println(score >= 60)
    fmt.Println(score >= 60 && attended)
    fmt.Println(score < 60 || !attended)
}
```

预期结果：
```text
true
true
false
```

画面要点：两个等号判断相等；并且、或者、取反组合条件；比较结果是 bool

### go-03-03 让输出格式更清楚

Println 适合快速显示几个值。想把姓名、分数和说明排成固定格式，可以使用 Printf。第一个参数是格式文字，百分号后面的小写 s 对应字符串，小写 d 对应整数。后面的参数按照这些位置依次填进去。格式和数据数量、类型应当对应，不要把所有格式符都当成可以随便替换的装饰。

输出小数时，点一加小写 f 表示这里保留一位小数显示，于是八十六点二六显示为八十六点三。格式化只改变这一次的显示，不会把原来的 average 永久改成这个值。若以后还要用原值继续计算，它仍然保留原来的数值。另外，Printf 不会自动加换行，反斜线加 n 是这里主动写出的换行。想清楚显示和数据本身的区别，可以避免很多误解。

```go
func main() {
    name := "小林"
    score := 85
    average := 86.26
    fmt.Printf("%s：%d 分\n", name, score)
    fmt.Printf("平均分：%.1f\n", average)
}
```

预期结果：
```text
小林：85 分
平均分：86.3
```

画面要点：Printf 按格式填入数据；显示精度不改变原变量；换行由反斜线 n 明确给出

### go-03-04 读取键盘输入

之前的数据都写在源代码里，现在让使用程序的人输入。先准备保存姓名的变量，再调用 Scan。名字前面的与号表示把这个变量的位置交给输入工具，让它把读到的内容写进去。这里先认识这个用途，指针一章会进一步解释。Scan 会把输入按空白分开读取，所以这个例子适合一个不含空格的姓名，不是一次读入任意长的整行文章。

Scan 会交回两个结果，一个说明成功读取了多少项，另一个说明是否发生错误。先看到的 if 是错误检查，下一章会详细讲它。err 不是 nil 时，显示输入失败并结束，避免把失败后的结果当成正常数据继续使用。假设输入小林，读取一项成功，就输出一和小林。Go 中不少操作会同时返回结果和错误，我们会逐步把这种写法读熟。

```go
func main() {
    var name string
    count, err := fmt.Scan(&name)
    if err != nil {
        fmt.Println("输入失败")
        return
    }
    fmt.Println(count, name)
}
```

预期结果：
```text
1 小林
```

画面要点：Scan 读取按空白分隔的数据；与号提供写入变量的位置；先检查错误，再使用结果

### go-03-05 读取整数并检查成功与否

如果提前声明的目标变量是 int，Scan 就按整数读取，不需要先手动保存成字符串。这里准备一份成绩，读取一项数据。输入的内容必须符合整数格式。把目标变量的类型写清楚，就相当于告诉输入工具这一次需要怎样的数据；但使用者是否真的照要求输入，程序仍然必须检查。

条件的意思是，发生错误，或者没有成功读到一项，就提示请输入整数并结束。只有检查通过，才给成绩加五并输出。输入八十会得到八十五，输入普通字母就会走提示路线。不要忽略错误结果，再把默认的零分当成用户输入的成绩。先检查、后使用，是 Go 里很值得从第一个程序就建立的习惯。

```go
func main() {
    var score int
    count, err := fmt.Scan(&score)
    if err != nil || count != 1 {
        fmt.Println("请输入整数")
        return
    }
    fmt.Println(score + 5)
}
```

预期结果：
```text
85
```

画面要点：目标变量决定读取类型；检查错误和读取项数；失败时不继续使用假数据

### go-03-06 练习：先除法，还是先转换

请预测三条输出。第二条和第三条都写了 float64，也都按一位小数显示，但转换发生的位置不同。先在纸上算出每个小括号里面的结果，再进行后续步骤。特别想清楚，整数除法丢掉的小数，能不能靠最后一次转换恢复。现在先独立思考四秒。

（四秒独立思考，答案在下一页揭晓）

```go
func main() {
    fmt.Println(5 / 2)
    fmt.Printf("%.1f\n", float64(5/2))
    fmt.Printf("%.1f\n", float64(5)/2)
}
```

画面要点：先确认除法两边的类型；注意转换发生在计算之前还是之后

### go-03-07 答案：丢掉的小数不会回来

第一条是两个整数相除，得到整数二。第二条也先进行这个整数除法，再把二转换成小数类型，按一位小数显示为二点零。转换只是把已经得到的数值换一种类型表达，不知道之前被截掉的小数是什么，也不会替我们重新做一次原本想要的除法。

第三条先把五转成 float64，再进行这次除法，因此结果是二点五。这里的整数常量二可以按这个运算需要的类型使用，和两个已经有确定不同类型的变量混合计算，还要区分。对入门练习，先记住需要小数结果就要在计算前把类型处理好。检查一个意外结果时，沿着真实的计算顺序往前找原因，不要只盯着最后的显示格式。

```go
func main() {
    fmt.Println(5 / 2)
    fmt.Printf("%.1f\n", float64(5/2))
    fmt.Printf("%.1f\n", float64(5)/2)
}
```

预期结果：
```text
2
2.0
2.5
```

画面要点：整数除法先得到 2；事后转换只能得到 2.0；先转换再除法得到 2.5

## 分支与循环

### go-04-01 用 if 选择路线

当程序需要根据情况做决定，就用 if。这里先判断成绩是否至少六十。条件为真时，执行这一支大括号中的输出。Go 不要求给这个条件再套一对小括号，但条件结果必须是 bool。成绩是七十五，所以会走及格这一支。把条件读成一句明确的问题，有助于检查大于号和小于号有没有写反。

条件为假时才执行 else 的部分，这里两支不会同时输出。else 要和前面的大括号放在同一行，避免受到换行时自动补分号的规则影响。若失败时无需做任何事，可以不写 else。缩进帮助我们看层次，真正决定哪几条语句属于分支的，是大括号的范围。不要因为一行看起来缩进了，就以为它一定受上面的判断控制。

```go
func main() {
    score := 75
    if score >= 60 {
        fmt.Println("及格")
    } else {
        fmt.Println("继续努力")
    }
}
```

预期结果：
```text
及格
```

画面要点：条件需要 bool；成立与不成立走不同分支；else 与前面的大括号同一行

### go-04-02 分成多档并控制变量范围

如果需要优秀、及格和未及格三档，可以用 else if 继续判断。这里第一行还带一个简短的初始化语句，先准备 score，再用分号分开后面的条件。这份变量的使用范围限定在整个判断结构中，后面的 else if 和 else 也能使用它，但判断结构结束以后就不能直接拿这个局部名字继续用。

八十八不够九十，就继续检查是否至少六十，成立后输出及格，不再执行后面的分支。条件的排列顺序很重要。如果把至少六十放在最前面，九十五也会先被这一项接住。分档之前先明确边界，再按适当顺序书写。用短初始化不是必须的，初学也可以先把变量声明在上面一行，等熟悉作用范围后再选更合适的写法。

```go
func main() {
    if score := 88; score >= 90 {
        fmt.Println("优秀")
    } else if score >= 60 {
        fmt.Println("及格")
    } else {
        fmt.Println("未及格")
    }
}
```

预期结果：
```text
及格
```

画面要点：else if 按顺序继续判断；可在 if 前半部分初始化变量；局部变量的范围到判断结构结束

### go-04-03 用 switch 处理多种情况

多种情况也可以用 switch。这里没有在 switch 后面放一个固定目标值，而是让各个 case 自己提供判断条件。程序从上往下寻找第一项成立的情况。八十八不满足第一项，就继续往下。另一个常见形式是 switch 后面写一个值，再用 case 匹配不同取值，选择哪种形式取决于问题本身。

第二项成立，输出及格。Go 中普通的 case 执行完就结束这次选择，默认不会自动接着执行下一个 case，所以这里不必在每项末尾再写 break。default 处理其他项都没有匹配的情况。不要把其他语言中对 switch 的习惯直接搬过来。本课不展开主动贯穿后续分支的特殊写法，先把默认、清楚的执行过程掌握好。

```go
func main() {
    score := 88
    switch {
    case score >= 90:
        fmt.Println("优秀")
    case score >= 60:
        fmt.Println("及格")
    default:
        fmt.Println("未及格")
    }
}
```

预期结果：
```text
及格
```

画面要点：按顺序选择第一个匹配项；普通 case 不会自动继续下一项；default 处理其余情况

### go-04-04 for 的开始、条件与更新

要重复执行一项任务，不必复制很多条语句。for 这一行分成三部分：先把 n 设为一，每轮开始前检查是否不超过三，一轮结束后再把 n 增加一。两个加号表示增加一。它在 Go 中是一条独立的更新语句，不能随意塞进其他表达式里面。先按开始、检查、执行、更新这个顺序走一轮，再继续下一轮。

n 为一、二、三时，分别输出对应数字。更新成四以后，条件不成立，循环结束，再输出完成。这里循环体可能重复很多次，后面的完成只执行一次。读循环不要一下子凭印象猜结果，先列出每轮变量的值，再记录这一轮执行了什么。尤其要检查条件里是否包含等号，它会影响边界那一次是否进入循环。

```go
func main() {
    for n := 1; n <= 3; n++ {
        fmt.Println(n)
    }
    fmt.Println("完成")
}
```

预期结果：
```text
1
2
3
完成
```

画面要点：开始值、继续条件、更新分开看；每轮开始前检查条件；循环结束后才执行后续语句

### go-04-05 只按条件继续循环

Go 的 for 还有更简洁的形式，只在后面写继续条件。这里每一轮都先问尝试次数是否不超过三，成立就输出一次尝试。你不需要再寻找一个叫 while 的关键字来完成同一件事。无论写法长短，条件检查发生在哪里，哪些数据会在循环中变化，都要读清楚。

这一行让尝试次数增加，条件最终才能变成假。若忘记更新，次数可能一直是一，程序就会不停重复。for 后面什么条件都不写，也能构成持续循环，但要在里面有明确的结束设计。对于零基础练习，请同时检查开始状态、继续条件和更新动作，不要只看到屏幕在输出，就认为循环一定写对了。

```go
func main() {
    attempts := 1
    for attempts <= 3 {
        fmt.Println("第", attempts, "次尝试")
        attempts++
    }
}
```

预期结果：
```text
第 1 次尝试
第 2 次尝试
第 3 次尝试
```

画面要点：for 可以只写继续条件；Go 不用 while 关键字；循环需要能走向结束的变化

### go-04-06 提前结束与跳过一轮

有时需要在中途跳转。continue 表示这一轮后面的步骤不做了，继续进行下一轮。这里 n 为二时，不执行本轮的输出，但循环没有完全结束。对于这种三段式 for，后面的更新动作仍然会执行，所以 n 还会继续变化。不要把 continue 理解为重新从头声明所有变量。

break 则结束这一层循环。n 为四时直接退出，因此不会输出四，也不会继续到五。最后只显示一和三。若有多层循环，需要另外确认跳转影响的是哪一层，不要看到一个 break 就认为所有循环全部结束。入门先把一层循环的完整轨迹走熟，再去组合更复杂的嵌套结构。

```go
func main() {
    for n := 1; n <= 5; n++ {
        if n == 2 { continue }
        if n == 4 { break }
        fmt.Println(n)
    }
}
```

预期结果：
```text
1
3
```

画面要点：continue 跳过当前轮的剩余步骤；break 结束这一层循环；逐轮记录比猜结果更稳妥

### go-04-07 练习：跳过一次累计

请算最后的 total。n 从一开始，条件允许它到四。第三轮会执行 continue，所以你要判断本轮加法有没有机会执行，以及第四轮是否还会到来。建议按一、二、三、四列出表格，再写每轮结束后的总和。不要把跳过一轮和结束整个循环混成一件事。

（四秒独立思考，答案在下一页揭晓）

```go
func main() {
    total := 0
    for n := 1; n <= 4; n++ {
        if n == 3 { continue }
        total += n
    }
    fmt.Println(total)
}
```

画面要点：列出每轮 n 的取值；累计值保留在循环外

### go-04-08 答案：一加二再加四

第一轮加入一，第二轮加入二。第三轮 n 等于三，执行 continue，当前轮后面的加法被跳过。更新动作之后，第四轮仍然会执行。我们只是这一轮不加入三，没有把 total 清零，也没有退出整个循环。这几个动作的差别，要通过具体执行步骤去理解。

第四轮加入四，最后总和是七。若把 continue 换成 break，就会在第三轮直接结束，最后只累加一和二，得到三。total 放在循环外声明，才能保留已经累计的结果。如果每轮都重新初始化为零，看到的就不再是完整总和。现在你已经能控制路线和重复次数，接下来把多份成绩组织成一组数据。

```go
func main() {
    total := 0
    for n := 1; n <= 4; n++ {
        if n == 3 { continue }
        total += n
    }
    fmt.Println(total)
}
```

预期结果：
```text
7
```

画面要点：三被跳过，四仍然加入；最终总和是 7；break 的结果会不同

## 数组与切片

### go-05-01 用数组保存固定数量的数据

一个班级有多位同学，不适合给每份成绩都起一个单独的变量名。数组可以把固定数量、相同元素类型的数据放在一起。这里的方括号三说明长度，int 说明每项是整数，大括号里面列出初始值。读取时方括号里的零表示第一个位置。数组索引从零开始，不是从一开始，也不是学生的真实编号。

len 返回元素数量，这里是三，整个数组显示八十、九十和七十。最后一个合法位置是二，不是数量三，不能访问越界的位置。数组的长度也是类型的一部分，三项整数数组和四项整数数组不是同一个类型。数量固定是它的重要特征；若需要方便地增减一组数据，后面会使用切片。先把固定长度、元素类型和位置编号三件事分开理解。

```go
func main() {
    scores := [3]int{80, 90, 70}
    fmt.Println(scores[0])
    fmt.Println(len(scores))
    fmt.Println(scores)
}
```

预期结果：
```text
80
3
[80 90 70]
```

画面要点：数组长度固定，元素类型一致；索引从 0 开始；len 得到数量，不是最后位置

### go-05-02 数组赋值会复制元素

把一个数组赋给另一个变量，会复制这个数组的值。这里 backup 最初也有八十、九十和七十，然后我们只把 backup 的第一个元素改成九十九。这一步修改的是复制之后那份数组，不会自动回到 scores 里修改原来的第一项。不要仅仅因为两边内容相同，就判断它们一定共享同一份元素。

所以先输出的原数组仍然以八十开头，后一份以九十九开头。这个例子元素都是整数，可以直观看到独立的数组值。若元素本身还包含指向其他对象的信息，则要另外考虑里面是否共享数据，不要把外层复制直接推广成所有内部数据都完全独立。下一页学习切片时，行为就和这里不同，需要重新看它究竟保存了什么。

```go
func main() {
    scores := [3]int{80, 90, 70}
    backup := scores
    backup[0] = 99
    fmt.Println(scores)
    fmt.Println(backup)
}
```

预期结果：
```text
[80 90 70]
[99 90 70]
```

画面要点：数组赋值复制数组值；这里修改备份不影响原数组；不能把这条结论随便套给切片

### go-05-03 切片可以共享底层元素

这里方括号里不写固定长度，创建的是整数切片。切片可以先理解为，看向一段底层元素的一个窗口。第二行从位置一取到位置三之前，得到九十和七十。左边界包含，右边界不包含，所以取到两项。切出一段数据不等于把这些元素全部重新复制一份，这个差异必须单独记住。

part 的位置零对应原切片的位置一。把它改成九十五后，原来的 scores 中同一个底层元素也会变成九十五。于是两份输出分别是八十、九十五、七十，以及九十五、七十。不是变量名之间发生了神秘联系，而是两个窗口看到了同一处数据。需要互不影响的元素副本时，要明确分配新空间并复制，不能只写一次切片赋值就认为已经独立。

```go
func main() {
    scores := []int{80, 90, 70}
    part := scores[1:3]
    part[0] = 95
    fmt.Println(scores)
    fmt.Println(part)
}
```

预期结果：
```text
[80 95 70]
[95 70]
```

画面要点：切片窗口可指向同一底层数据；切片范围左含右不含；共享元素的一处修改可被另一处看到

### go-05-04 长度、容量与追加

make 可以准备一个切片。这里长度是二，表示当前有两个可以直接用索引访问的元素，它们最初都是零。容量是四，说明从这个起点往后，底层空间能容纳到四项。容量不是当前元素数量，所以此时不能因为容量四，就直接访问索引三。先把当前可见的元素和后面预留的空间分开理解。

append 追加七十，并返回更新后的切片，所以要把结果接回 scores。现在长度变成三，容量仍是四。空间足够时可能继续使用原来的底层存储，不够时会分配新的空间。不要依赖容量一定按某个固定倍数增长，也不要假设追加前后的切片永远共享或永远独立。把 append 的返回值接住，是使用这个操作的基本要求。

```go
func main() {
    scores := make([]int, 2, 4)
    scores[0], scores[1] = 80, 90
    scores = append(scores, 70)
    fmt.Println(scores)
    fmt.Println(len(scores), cap(scores))
}
```

预期结果：
```text
[80 90 70]
3 4
```

画面要点：len 是当前元素数量；cap 表示可容纳范围；append 的返回值要接住

### go-05-05 range 得到位置和值

range 可以让循环依次处理数组或切片中的元素。这里每轮得到两个东西：index 是位置，score 是这一轮的元素值。于是依次看到零对应八十，一对应九十，二对应七十。需要位置和值时，这种写法比自己维护一个额外计数器更容易读。前面的两个名字都由我们自己选择，不要求一定叫 index 和 score。

如果不需要其中一个结果，可以把不需要的位置写成下划线，它表示明确忽略。要注意，这里的 score 是本轮拿到的值副本，改这个整数变量，并不会直接修改切片里的那一项。真正要修改原元素时，可以使用 scores 加方括号索引。range 帮我们取出数据，但不会自动替我们决定要修改副本还是修改原位置。

```go
func main() {
    scores := []int{80, 90, 70}
    for index, score := range scores {
        fmt.Println(index, score)
    }
}
```

预期结果：
```text
0 80
1 90
2 70
```

画面要点：range 可同时给出索引和值；下划线明确忽略某个结果；元素值副本与原元素位置不同

### go-05-06 修改原元素与复制切片

要给原切片每一项加五，可以只让 range 提供索引，然后修改 scores 中那个位置。这样改到的才是实际元素。更新以后，两项成绩是八十五和九十五。对于只需要读取的任务，可以直接取值；对于需要修改元素的任务，先确认你是否正在使用正确的位置。不要把一个临时变量改了，却期待原列表自动跟着改变。

接着用 make 准备同样长度的新空间，再用 copy 把元素复制过去。copy 返回实际复制的项数，这里是二。修改备份的第一项以后，原切片仍以八十五开头，备份以九十九开头。copy 只会复制目标长度和来源长度允许的那些项，并不会替目标无限扩容。所以先准备足够的目标长度，再复制，是这里得到完整独立元素副本的关键。

```go
func main() {
    scores := []int{80, 90}
    for i := range scores { scores[i] += 5 }
    backup := make([]int, len(scores))
    count := copy(backup, scores)
    backup[0] = 99
    fmt.Println(scores, backup, count)
}
```

预期结果：
```text
[85 95] [99 95] 2
```

画面要点：按索引修改真正的元素；make 新空间，再 copy 元素；copy 返回实际复制项数

### go-05-07 练习：这个窗口对应哪里

请预测两条输出。先在原切片下方标出零、一、二三个位置，再标出 part 这个窗口包含哪两项。part 的第一个位置，不等于原切片的第一个位置。最后再判断，切片范围里的右边界三是否也被包含进来了。把窗口和底层元素画出来，再想修改会被谁看到。

（四秒独立思考，答案在下一页揭晓）

```go
func main() {
    scores := []int{80, 90, 70}
    part := scores[1:3]
    part[0] = 95
    fmt.Println(scores[1])
    fmt.Println(len(part))
}
```

画面要点：先画原位置，再画切片窗口；右边界不包含在结果中

### go-05-08 答案：共享原来的第二项

窗口从原位置一开始，所以 part 的位置零对应 scores 的位置一。把这个位置改成九十五，两边读到的都是同一个修改后的元素。因此第一条输出九十五。它不是完整数组赋值那种独立复制，也不是原来九十这个整数名字自己变了，而是我们通过另一个窗口修改了实际存储位置。

范围一到三之前包含两个位置，所以长度是二。切片的大部分入门问题，都可以从起点、长度、容量和是否共享底层元素四件事拆开分析。需要独立副本时用明确的新空间和复制；需要追加时接住 append 的返回值。下一章再认识另一种数据组织方式，它不靠位置查询，而是通过姓名这样的键找到对应值。

```go
func main() {
    scores := []int{80, 90, 70}
    part := scores[1:3]
    part[0] = 95
    fmt.Println(scores[1])
    fmt.Println(len(part))
}
```

预期结果：
```text
95
2
```

画面要点：窗口首项对应原位置 1；修改后原位置 1 为 95；窗口长度为 2

## 映射与字符串

### go-06-01 按姓名查询成绩

列表适合按位置读取，如果需求是根据姓名查成绩，用键和值的对应关系会更直接。map 后面的方括号说明键类型，后面的 int 说明值类型。这里姓名是字符串键，成绩是整数值。查询时写姓名，而不是从零开始的索引。真实系统若存在重名，应当考虑使用学号等更稳定的标识。

查小林得到八十五。查不存在的小王，这次会得到整数类型的零值，也就是零，而不是自动报出找不到。len 得到已经保存的键值项数量，这里是二。不要直接把这次查到的零理解成小王真的考了零分。映射中是否存在这个键，需要另外判断。遍历映射的顺序也不作保证，不能依赖它总按姓名或插入顺序排列。

```go
func main() {
    scores := map[string]int{"小林": 85, "小陈": 92}
    fmt.Println(scores["小林"])
    fmt.Println(scores["小王"])
    fmt.Println(len(scores))
}
```

预期结果：
```text
85
0
2
```

画面要点：map 用键关联值；键和值分别有类型；找不到键时读取到值类型的零值

### go-06-02 区分零分与没有记录

同一个查询可以接住两个结果。第一个是值，第二个通常命名为 ok，表示有没有找到这个键。小林的记录确实存在，只是分数为零，所以得到零和 true。这两个结果要一起读，才能区分实际零分和查不到记录。Go 用多返回结果把不同信息分开交回来，后面函数一章也会用到这种能力。

delete 删除指定键对应的记录。删除以后再查询，数值仍然是零，但 ok 变成 false。这里第二次接收结果用普通等号，因为这两个变量已经声明过，不是在同一层又创建一遍。向同一个键重新赋值会更新它对应的值，而不是再增加一条相同键的独立记录。设计查询功能时，优先处理是否找到，再决定怎样使用值。

```go
func main() {
    scores := map[string]int{"小林": 0}
    score, ok := scores["小林"]
    fmt.Println(score, ok)
    delete(scores, "小林")
    score, ok = scores["小林"]
    fmt.Println(score, ok)
}
```

预期结果：
```text
0 true
0 false
```

画面要点：第二个结果说明键是否存在；delete 删除对应记录；查询成功与否不能只看数值

### go-06-03 空映射与可写映射

只声明一个 map 变量而没有创建实际映射时，它的零值是 nil。可以从 nil 映射读取，得到对应值类型的零值，也可以查看长度。但不能直接向 nil 映射写入一项，否则会发生运行时错误。不要把能够读取理解成已经有可写的存储结构。这是 map 入门中很常见的一个坑。

make 创建可写的空映射，然后再给小林保存八十五，查询就能得到八十五。使用带内容的映射字面量也能直接创建实际映射。这里的 nil 可以先理解为目前没有实际映射，和一个已经创建但没有任何项的空映射，需要区分。Go 中不同类型对 nil 的操作规则不完全一样，不能从某一处读取安全，就推广成所有 nil 操作都安全。

```go
func main() {
    var scores map[string]int
    fmt.Println(scores == nil)
    fmt.Println(scores["小林"])
    scores = make(map[string]int)
    scores["小林"] = 85
    fmt.Println(scores["小林"])
}
```

预期结果：
```text
true
0
85
```

画面要点：nil map 可以读取；向 nil map 写入会发生运行错误；make 创建可写的空映射

### go-06-04 字节、码点与字符串遍历

Go 的字符串保存字节，常见中文文字通常按 UTF 八编码。这里的 Go 两个英文字母各占一个字节，语占三个，所以 len 得到五。按 Unicode 码点计数则是三。码点也不总等于人眼看到的完整符号数量，一些组合文字和表情还要另外处理。入门先把字节数量和这里的文字码点数量区分开。

对字符串使用 range，会依次解码出码点，同时给出它开始的字节位置。这里依次看到位置零的 G、位置一的 o、位置二的语。直接用字符串索引读到的是单个字节，不要把中文的某个字节当成完整文字。字符串切片也按字节边界取数据，切错位置可能得到不完整的 UTF 八内容。需要按码点处理时，可以考虑转换成 rune 切片再操作。

```go
func main() {
    text := "Go语"
    fmt.Println(len(text), utf8.RuneCountInString(text))
    for position, ch := range text {
        fmt.Printf("%d %c\n", position, ch)
    }
}
```

预期结果：
```text
5 3
0 G
1 o
2 语
```

画面要点：len(string) 得到字节数；range 按 UTF-8 解码码点；range 的位置仍是字节位置

### go-06-05 使用常见字符串工具

字符串处理中有很多现成工具，不需要自己从每个字节重新写起。TrimSpace 得到去掉两端空白的新字符串。它不会自动把原来的 text 改掉，所以这里用 clean 接住结果。Go 的字符串不能通过索引直接改某个字节；需要变化时，通常构造新的字符串，或使用适合修改的其他结构。

Contains 询问是否包含指定文字，返回一个真假值。Split 按逗号把姓名和成绩文字分开，得到一个字符串切片。两项看起来分别是姓名和数字，但第二项仍然是字符串，不会因为长得像数字就自动变成整数。后面错误处理一章会使用转换函数，并检查转换失败的情况。调用标准库之前先确认输入和返回类型，通常比猜函数名字更可靠。

```go
func main() {
    text := " Go基础 "
    clean := strings.TrimSpace(text)
    fmt.Println(clean)
    fmt.Println(strings.Contains(clean, "Go"))
    parts := strings.Split("小林,85", ",")
    fmt.Println(parts[0], parts[1])
}
```

预期结果：
```text
Go基础
true
小林 85
```

画面要点：字符串工具通常得到新值；Contains 返回真假；Split 的结果仍是字符串数据

### go-06-06 练习：两次零值含义一样吗

请预测两次输出的值和 ok。映射中只保存了小林，分数恰好是零；第一次查询的是小王，第二次才是小林。不要只比较两个数值是否相同，还要考虑有没有实际记录。查询没有找到时，我们看到的是该值类型的零值，不是程序凭空创建了一条成绩记录。

（四秒独立思考，答案在下一页揭晓）

```go
func main() {
    scores := map[string]int{"小林": 0}
    value, ok := scores["小王"]
    fmt.Println(value, ok)
    value, ok = scores["小林"]
    fmt.Println(value, ok)

```

画面要点：同时判断值与是否存在；映射里只有小林这一项

### go-06-07 答案：存在与数值分开判断

第一次小王不存在，因此值是整数零值，ok 为 false。查询这个不存在的键，并不会因为读了一次，就自动给映射插入小王。是否存在是一份独立信息，必须明确接住并检查。若业务要区分没有录入与真实零分，只看返回的整数就会丢掉这层含义。

第二次小林确实存在，所以同样是零，但 ok 为 true。这两次结果表达的事实不同，应该给使用者不同的反馈。数组、切片和映射现在都能保存多项数据，不过它们回答的问题不同：固定位置、动态窗口，或者按键查询。理解要怎样使用数据，再选择合适的结构，比一开始就追求某种听起来高级的类型更重要。

```go
func main() {
    scores := map[string]int{"小林": 0}
    value, ok := scores["小王"]
    fmt.Println(value, ok)
    value, ok = scores["小林"]
    fmt.Println(value, ok)
}
```

预期结果：
```text
0 false
0 true
```

画面要点：小王：0 与 false；小林：0 与 true；查询缺失不会自动插入记录

## 函数与延迟执行

### go-07-01 参数把数据交给函数

如果一套步骤需要多次使用，可以给它取一个名字，定义成函数。这里 greet 接收一份姓名，类型写在参数名后面。大括号里说明收到姓名以后该做什么。定义函数是在说明做法，不表示程序一启动就把每个函数都执行一遍。程序仍然从 main 开始，再由调用关系决定接下来进入哪里。

main 里面调用两次，分别提供小林和小陈，因此显示两句不同的问候。函数的参数可以理解为这次完成任务需要的材料。把会变化的数据作为参数，把稳定步骤写进函数，可以减少重复。参数名和外部变量名不需要相同，重要的是传入的数据类型和含义符合要求。函数名字也应说明任务，不要只为了把代码切短而随意拆开。

```go
func greet(name string) {
    fmt.Println("你好，" + name)
}
func main() {
    greet("小林")
    greet("小陈")
}
```

预期结果：
```text
你好，小林
你好，小陈
```

画面要点：定义说明做法，调用才执行；参数是本次任务的材料；Go 把参数类型写在名字后面

### go-07-02 返回值把结果交回来

函数不一定只负责显示文字，也可以算好结果交回来。这里有原成绩和奖励分两个整数参数，类型相同时可以合写。参数小括号后面的 int 说明返回一个整数。return 把加法结果交回调用位置，并结束这次调用。输入参数和返回结果的方向相反，一个是材料进来，一个是结果出去。

调用时传入八十和五，函数返回八十五，再由 result 接住并输出。输出和返回不是一回事。函数内部只做 Println，不会自动让外面得到那个数用于继续计算。Go 也没有一般意义上的默认参数和同名函数重载，不要期待漏写一个必需参数时，函数自己猜出你想要的值。先把一次调用需要的材料和交回的结果写清楚。

```go
func addBonus(score, bonus int) int {
    return score + bonus
}
func main() {
    result := addBonus(80, 5)
    fmt.Println(result)
}
```

预期结果：
```text
85
```

画面要点：返回类型写在参数列表后面；return 返回结果并结束调用；输出不等于返回

### go-07-03 一次交回多个结果

Go 的函数可以同时返回多个结果，这和前面读取输入、查询映射时的写法一致。这里第一个结果是整数商，第二个结果说明这次操作是否成功。人数为零时，先返回零和 false，避免真的进行除零。这个零只是失败路径中的占位结果，不能单独拿它来判断成功与否。

人数不为零时，返回计算结果和 true。main 按相同顺序接住它们，这里输出五和 true。多个返回值不会自动合成某个随便拆的通用列表，要按函数声明的数量和类型接收。Go 中很多可能失败的操作，会返回正常结果和 error，我们将在最后一章集中处理。现在先把一项负责结果、一项说明状态的结构读清楚。

```go
func divide(total, count int) (int, bool) {
    if count == 0 { return 0, false }
    return total / count, true
}
func main() {
    result, ok := divide(10, 2)
    fmt.Println(result, ok)
}
```

预期结果：
```text
5 true
```

画面要点：多个返回类型写在一对括号里；调用处按顺序接收；失败路径的占位结果不能单独使用

### go-07-04 可变数量的参数

有时函数要接收数量不固定的整数，可以在最后一个参数的类型前写三个点。函数内部把这些值当作整数切片处理，所以能用 range 逐项累计。这里的下划线明确忽略位置，只使用每个值。可变参数要放在参数列表最后，不是让所有参数都变成没有类型限制的任意材料。

第一次直接提供一、二、三，得到六。已经有一个切片时，可以在切片后写三个点，把其中元素作为这些可变参数传入，得到一百七十。函数定义里的三个点和调用时切片后面的三个点，位置不同、用途相关。先按收到一组值和交出一组元素来理解，不必把它们当成神秘的缩写。

```go
func sum(values ...int) int {
    total := 0
    for _, value := range values { total += value }
    return total
}
func main() {
    scores := []int{80, 90}
    fmt.Println(sum(1, 2, 3))
    fmt.Println(sum(scores...))
}
```

预期结果：
```text
6
170
```

画面要点：可变参数类型前写三个点；函数内按切片处理；已有切片用尾部三个点展开

### go-07-05 defer 在函数退出时执行

defer 表示把一次调用先登记下来，等当前函数准备结束时再执行。它常用于安排收尾操作。这里先登记两次输出，并不会立刻把两句话都打印出来。注意它等待的是函数退出，不是任意一对内层大括号结束。把执行时机和代码写在什么位置分开，是理解 defer 的第一步。

普通输出先执行，显示处理中。main 结束时再执行登记的调用，而且后登记的先执行，所以先显示后登记，再显示先登记。还有一个重要细节：这次调用需要的实参会在登记时准备好，通常不是退出时才重新读取参数表达式。先用这些简单输出认识顺序，处理文件等资源时，也要先确认获取成功，再安排正确的收尾动作。

```go
func main() {
    defer fmt.Println("先登记")
    defer fmt.Println("后登记")
    fmt.Println("处理中")
}
```

预期结果：
```text
处理中
后登记
先登记
```

画面要点：defer 等当前函数退出时执行；多个 defer 后登记的先执行；调用实参在登记时求值

### go-07-06 练习：延迟输出的是哪个值

请预测输出顺序和两个分数。普通输出发生在成绩改成九十以后，但 defer 那次调用的参数，是什么时候准备的？这里没有匿名函数，也没有让另一个函数在最后再去读取变量；它直接登记一次 Println 调用。把准备参数和真正输出两个时机分开想。

```go
func main() {

    defer fmt.Println(score)
    score = 90
    fmt.Println(score)

```

画面要点：先执行普通输出；defer 调用的参数在登记时准备

### go-07-07 答案：登记时已经准备了八十

先执行的是普通输出，此时 score 已经变成九十，所以第一行是九十。defer 不会让后面的正常语句全部停止，也不会因为写在前面就抢先输出。它只是安排当前函数退出前还要完成的一项调用。程序按正常路线走到函数末尾，再开始这些收尾步骤。

登记时传给那次 Println 的整数值是八十，因此最后显示八十。后面重新给 score 赋值，并没有改变那次调用已经准备好的整数参数。若以后看到 defer 配合其他函数、指针或闭包，仍要根据实际参数和求值时机分析，不要把这个具体结论套成所有延迟操作都永远保存独立副本。下一章继续区分值复制与指向原数据的操作。

```go
func main() {
    score := 80
    defer fmt.Println(score)
    score = 90
    fmt.Println(score)
}
```

预期结果：
```text
90
80
```

画面要点：普通输出先显示 90；延迟调用保存的是当时的整数实参；最后显示 80

## 指针与结构体

### go-08-01 保存一个变量的位置

前面输入时用过与号，现在把它解释清楚。score 保存一个整数，与号 score 得到能指向这份整数的位置。pointer 保存的就是这样的指针值。它不是又存了一份分数，而是让我们知道可以通过哪里访问原来的数据。这里的指针类型会根据 score 推断成指向整数的类型，写出来就是星号 int。

星号放在指针表达式前面，表示访问它指向的值。所以给星号 pointer 赋八十五，会修改原来的 score。随后两次读取都是八十五。不要把取得指针、复制一个普通整数和复制指针本身混成同一件事。Go 不提供普通指针任意加减来移动位置的操作；指针为 nil 时也不能直接解引用。入门先围绕有效变量的位置理解，不必猜测具体地址数字。

```go
func main() {
    score := 80
    pointer := &score
    *pointer = 85
    fmt.Println(score)
    fmt.Println(*pointer)
}
```

预期结果：
```text
85
85
```

画面要点：与号取得指向变量的指针；星号访问指向的值；通过有效指针可以修改原变量

### go-08-02 值参数与指针参数

Go 的参数按值传递。第一次调用把整数八十交给 addLocal，函数内部修改的是这个参数的局部值，不会自动修改 main 里的 score，所以输出仍是八十。函数名字叫加分，不保证外面的变量就一定改变。要看参数到底是什么，以及函数实际修改了哪一处数据。

第二个函数接收指向整数的指针，通过它访问原来的成绩，所以会把 main 里的分数改成八十五。这里传过去的仍然是一份指针值，只是两边能通过它找到同一处原数据，并不是 Go 突然改成了另一种任意的传参规则。需要函数计算新值时，可以返回结果；确实需要修改原数据时，再明确使用合适的指针操作。

```go
func addLocal(score int) { score += 5 }
func addOriginal(score *int) { *score += 5 }
func main() {
    score := 80
    addLocal(score)
    fmt.Println(score)
    addOriginal(&score)
    fmt.Println(score)
}
```

预期结果：
```text
80
85
```

画面要点：普通整数参数是值副本；指针参数能访问指向的原数据；Go 的参数仍然按值传递

### go-08-03 把一位学生的信息放在一起

姓名和成绩属于同一位学生，可以用结构体组织在一起。type 给这个类型取名，struct 后面的大括号列出字段。每个字段有自己的名字和类型。Student 描述一份学生记录应该长什么样，不是某一位具体学生本身。把相关数据放在一起，有助于避免名单和成绩分别移动以后，位置对应错乱。

这里根据字段名创建一份具体记录，姓名是小林，成绩是八十。点加字段名可以读取或更新其中的数据。使用字段名初始化，能清楚看出每个值填到哪里。Go 这里不要求先调用某个内置的构造器；这个直接写出结构体值的形式叫结构体字面量。没有明确填写的字段，也会得到各自类型的零值。

```go
type Student struct {
    Name string
    Score int
}
func main() {
    student := Student{Name: "小林", Score: 80}
    fmt.Println(student.Name, student.Score)
}
```

预期结果：
```text
小林 80
```

画面要点：struct 把相关字段组织在一起；类型说明结构，变量保存具体值；点加字段名访问数据

### go-08-04 结构体赋值也是值复制

因此输出八十和九十。还要保留一个边界：如果结构体字段中放的是切片、映射或指针，复制外层结构体以后，里面仍可能关联到共享的数据。当前例子用字符串和整数，先把分数字段的独立修改看清楚。不要从外层有了一个新变量名，就推断所有内部数据都自动得到深层独立副本。

```go
type Student struct {
```

### go-08-05 通过结构体指针修改原记录

如果函数要修改原来的学生记录，就可以接收指向 Student 的指针。这里通过 student 点 Score 写入八十五。Go 允许对结构体指针直接使用字段的点写法，访问时会处理相应的间接访问，不需要每次都把显式解引用和括号写全。先根据参数类型确认它指向原记录，再看字段修改发生在哪里。

main 创建一份八十分记录，把它的位置交给 setScore，调用以后原记录变成八十五。如果函数参数改成普通 Student，就只会修改本次收到的结构体副本。指针不是让代码看起来更复杂的装饰，它表达了访问哪一份数据的关系。和返回一个新值相比，修改原记录会产生不同的使用方式，应该让调用者能清楚看出意图。

```go
type Student struct { Score int }

func main() {

    setScore(&s)
    fmt.Println(s.Score)
}
```

预期结果：
```text

```

画面要点：结构体指针可以用点访问字段；指针参数能修改原记录；值参数与指针参数的效果不同

## 方法与接口

### go-09-01 把操作和数据联系起来

前面用结构体保存学生信息，再写函数处理它。现在可以把某项操作和学生类型联系起来，这就是方法。函数名字前面多了一对括号，里面的 s 是这次操作接收的学生值，叫接收者。这里判断这位学生的成绩是否至少六十分。先理解这仍然是一套处理步骤，只是明确写出了它围绕哪种数据工作。

调用时写学生变量、点、方法名，再加小括号。这个学生八十分，因此返回 true。这里接收者是一个 Student 值，方法拿到的是值副本。接收者的名字可以自己选择，不必固定叫 s。方法和前面普通函数都要按声明使用参数和返回值。看到一个点，也要分清是在读取字段，还是正在调用一项操作。

```go
type Student struct { Score int }
func (s Student) Passed() bool {
    return s.Score >= 60
}
func main() {
    student := Student{Score: 80}
    fmt.Println(student.Passed())
}
```

预期结果：
```text
true
```

画面要点：接收者说明方法围绕哪种数据工作；值接收者收到一个值副本；点加方法名和括号进行调用

### go-09-02 修改原记录的方法

如果方法要给原来的学生加分，接收者可以写成指向 Student 的指针。方法通过这个指针找到原记录，再修改里面的成绩。这里和上一章通过结构体指针更新字段，是同一个道理。并不是所有方法都会修改对象，要看接收者和方法体究竟做了什么。单纯计算一个新结果时，也可以返回结果给调用者。

student 是能够取得地址的变量，这里可以直接写 student 点 AddBonus，Go 会按这次方法调用需要处理取地址，结果变成八十五。这个便利写法并不意味着所有值和指针在所有位置都能互换。现在先掌握两条：只读取并计算，可以考虑值接收者；确实需要修改原记录，要明确使用合适的指针接收者。参数传递仍然按值进行。

```go
type Student struct { Score int }
func (s *Student) AddBonus(bonus int) {
    s.Score += bonus
}
func main() {
    student := Student{Score: 80}
    student.AddBonus(5)
    fmt.Println(student.Score)
}
```

预期结果：
```text
85
```

画面要点：指针接收者可以修改原记录；这里可直接通过变量调用；不要把便利调用理解为处处可互换

### go-09-03 只说明需要什么能力

假设显示函数只需要一项能力：能够提供一段介绍文字。我们可以用接口写出这个要求。Reporter 里面列出 Report 方法，它不接收额外参数，返回字符串。show 不必知道传入数据有哪些字段，只按接口承诺调用这个方法。接口先关注能做什么，结构体先关注保存什么，两者解决的问题不同。

Student 提供了符合这个要求的方法，所以这里可以把学生值交给 show，最终显示小林。Go 不需要另外写一个声明说自己实现了这个接口，方法符合要求就可以。符合要求包括方法名字、参数和返回结果，不能只看名字相似。有一个叫 Name 的字段，也不等于自动拥有 Report 方法。入门先把接口理解成一份明确的操作约定。

```go
type Reporter interface { Report() string }
type Student struct { Name string }
func (s Student) Report() string { return s.Name }
func show(r Reporter) { fmt.Println(r.Report()) }
func main() {
    student := Student{Name: "小林"}
    show(student)
}
```

预期结果：
```text
小林
```

画面要点：接口列出一组方法要求；方法符合要求即可实现接口；字段不等于方法

## 错误处理与综合实践

### go-10-01 把文字转换成整数

输入和文件读到的内容常常是文字，要先转换成数字才能计算。strconv 包里的 Atoi 会尝试把十进制整数字符串变成 int，同时返回错误。err 等于 nil 表示这次没有错误；不等于 nil 时，先提示并结束当前函数。不要在还不知道转换成功与否时，就把返回的数字当作有效成绩继续计算。

这里文字八十五能成功转换，增加五分后显示九十。反过来，把整数变成日常十进制文字，可以使用 Itoa，第二行显示八十五。特别注意，直接写 string 加一个整数的类型转换，表示生成相应字符的字符串，并不是把数字写成十进制文本。选择转换方式时，要先明确目标是计算用的整数，还是展示给人看的文字。

```go
func main() {
    text := "85"
    score, err := strconv.Atoi(text)
    if err != nil {
        fmt.Println("请输入整数")
        return
    }
    fmt.Println(score + 5)
    fmt.Println(strconv.Itoa(score))
}
```

预期结果：
```text
90
85
```

画面要点：Atoi 返回整数和错误；先判断 err，再使用结果；Itoa 把整数变成十进制文字

### go-10-02 把失败原因交给调用者

我们自己的函数也可以返回错误。这里约定成绩必须在零到一百之间，超出时返回一份描述原因的错误；合法时返回 nil。error 是 Go 中表示错误的接口类型，入门先把它当作一种能交回失败原因的约定。把规则写进检查函数，可以让不同调用位置使用同一份判断，而不是各自复制一套条件。

调用者传入一百二十，收到错误后显示成绩超出范围。这种预期内的失败用返回值明确处理，和越界访问造成的运行时异常不同。Go 不用普通的 try、catch 语句来接住每一次解析失败。返回错误不会自动退出整个程序，也不会自动显示文字，下一步怎样提示、重试或结束，要由调用者根据任务决定。

```go
func checkScore(score int) error {
    if score < 0 || score > 100 {
        return errors.New("成绩超出范围")
    }
    return nil
}
func main() {
    err := checkScore(120)
    if err != nil { fmt.Println(err) }
}
```

预期结果：
```text
成绩超出范围
```

画面要点：失败返回错误，成功返回 nil；调用者决定提示、重试或结束；预期失败与运行时异常要区分

### go-10-03 把一小份数据写入文件

程序退出后，普通变量不会替我们永久保存成绩，可以把一小份文字写入文件。os 包提供这里的文件操作。WriteFile 接收路径、字节数据和文件权限参数；这里的路径相对程序运行的工作目录。同名文件如果已经存在，内容会被覆盖，所以练习应在自己的测试目录进行，不要指向重要文件。先检查写入是否成功。

ReadFile 把整个文件读成字节切片，同时也返回错误。读取成功以后，把字节内容转成字符串再输出，看到两位学生的成绩。这里适合演示小文件，不意味着所有大文件都应该一次读入内存。写入和读取都可能因为路径或权限失败，不能只检查其中一次。我们现在的目标是把内存里的文字和磁盘上的文件建立清楚的联系。

```go
func main() {
    data := []byte("小林,85\n小陈,92")
    err := os.WriteFile("scores.txt", data, 0600)
    if err != nil { fmt.Println("写入失败"); return }
    saved, err := os.ReadFile("scores.txt")
    if err != nil { fmt.Println("读取失败"); return }
    fmt.Print(string(saved))
}
```

预期结果：
```text
小林,85
小陈,92
```

画面要点：相对路径基于程序工作目录；WriteFile 会覆盖同名文件；写入和读取都要检查错误

### go-10-04 组合计算与错误返回

现在把前面的知识连起来，写一个计算平均分的函数。输入是一组整数成绩，输出是小数结果和错误。先处理没有成绩的情况，返回一份说明原因的错误，避免除以零。失败路径里的零只是占位结果，调用者必须结合错误判断是否能使用。先处理不能继续的条件，会让后面的正常计算更容易阅读。

有成绩时，先用循环累计总分，再把总分和人数分别转成浮点数进行除法，返回平均分和 nil。这里不能先做整数除法，再期待转换把已经丢失的小数补回来。配套完整程序用八十和九十测试，得到平均分八十五点零。这个函数只负责计算，不直接读取键盘，也不决定怎样显示，让同一份规则可以在不同位置使用。

```go
func average(scores []int) (float64, error) {
    if len(scores) == 0 {
        return 0, errors.New("没有成绩")
    }
    total := 0
    for _, score := range scores { total += score }
    return float64(total) / float64(len(scores)), nil
}
```

预期结果：
```text
平均分：85.0
```

画面要点：空切片先返回错误；转换为浮点数后再相除；计算与显示分别负责

### go-10-05 在入口依次组织小步骤

调用函数的主程序可以保持简短：先准备成绩切片，接收平均分和错误，再根据错误决定是否继续。这里输入八十和九十，因此走成功路径。理解一个稍长的程序时，不必一次把每个细节都记住，可以先从入口看它依次调用哪些步骤，再走进需要研究的函数。把输入、处理和输出分清，会更容易定位问题。

最后按一位小数显示平均分八十五点零。想扩展为学生管理，可以用结构体保存姓名和成绩，用切片保存多位学生，用映射按姓名查询，用函数和方法组织操作，再用文件保存结果。这些内容不是互相无关的十张知识卡片，而是在同一个需求里各负其责。先做能正确运行的小程序，再一次增加一项功能，并检查原来的行为是否仍然正确。


预期结果：


画面要点：接收结果后先判断错误；入口按顺序组织各个步骤；一次扩展一个功能

### go-10-07 答案：先检查转换，再检查范围

上一页会输出成绩、冒号和零，但是这个零不能代表用户真的输入了零分。转换已经失败，程序却把错误丢掉，导致显示一个看起来正常的假结果。现在先保留错误，发现 hello 不是整数就提示请输入整数，并结束本次处理。对于可能失败的操作，可靠的程序需要明确面对失败，而不是只把错误变量换成下划线。

即使转换成功，也还要判断成绩范围。比如文字一百二十能变成整数，但不符合这套成绩规则。因此格式检查和业务检查是两层不同的问题。当前输入在第一层就被拦住，后面这些分支不会执行。修正程序时，要追问哪一步的假设不成立，再把检查放在第一次使用结果以前。这样比等最后出现奇怪输出再猜原因更有效。

```go
func main() {
    score, err := strconv.Atoi("hello")
    if err != nil {
        fmt.Println("请输入整数")
        return
    }
    if score < 0 || score > 100 {
        fmt.Println("成绩超出范围")
        return
    }
    fmt.Println("成绩：", score)
}
```

预期结果：
```text

```

画面要点：原代码输出 0，但输入并未成功；先验证转换，再验证成绩范围；本例只显示请输入整数

课后可以做三步练习：先把两份固定成绩改成键盘输入，再保存多位学生并计算平均分，最后把记录写入文件、重新读取。每一步先写出你预期的输入和输出，再运行比较。遇到错误先找位置，区分编译失败、运行时异常和结果不符合需求。今天不展开并发和网络，把这些基础规则真正用起来，就是下一阶段继续学习 Go 的起点。
